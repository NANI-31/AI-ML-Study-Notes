#### 1. BaseModel Fundamentals & Architecture

- **Target Folder:** `GEN AI/9. Pydantic/01_basemodel_fundamentals/`
- **Core API & Methods:** `BaseModel`, `__init__`, `repr()`, attribute access, `model_fields`, `model_extra`, `copy()` vs. `model_copy()`
- **Core Topics:** Pydantic v2 Core architecture (pydantic-core in Rust), difference between Pydantic models vs. Python standard `dataclasses` vs. dictionaries vs. `NamedTuple`, mutability vs. immutability, field introspection, and error handling with `ValidationError`.
- **Real-World / AI Applications:** Defining initial domain schemas, data contract boundaries between external API inputs and internal application logic.

---

#### 2. Field Customization & Numerical/String Constraints

- **Target Folder:** `GEN AI/9. Pydantic/02_fields_constraints/`
- **Core API & Methods:** `Field()`, `default`, `default_factory`, constraints: `gt`, `ge`, `lt`, `le`, `multiple_of`, `min_length`, `max_length`, `pattern` (regex), metadata: `title`, `description`, `examples`, `deprecated`
- **Core Topics:** Fine-grained value constraints, difference between static `default` and dynamic `default_factory`, regex string validation, propagating descriptions to documentation, and avoiding mutable default value traps.
- **Real-World / AI Applications:** Bounding temperature ranges $[0.0, 2.0]$ and token limits in LLM parameter configs, validating user input forms (usernames, age bounds).

---

#### 3. Optional, Required & Nullable Fields

- **Target Folder:** `GEN AI/9. Pydantic/03_optional_defaults/`
- **Core API & Methods:** Ellipsis `...`, `PydanticUndefined`, `Optional[T]`, `T | None`, `Field(default=None)`, `Field(default=...)`
- **Core Topics:** The critical difference between a **required field that accepts None** (`Field(...) : str | None`) vs. an **optional field with default None** (`str | None = None`), handling omitted vs. explicit null inputs, and modern Python 3.10+ union syntax.
- **Real-World / AI Applications:** Handling nullable database fields, partial LLM responses where optional fields like metadata or confidence scores may be omitted.

---

#### 4. Nested Models & Recursive Data Structures

- **Target Folder:** `GEN AI/9. Pydantic/04_nested_recursive_models/`
- **Core API & Methods:** Model-inside-model composition, `list[Model]`, `dict[str, Model]`, `model_rebuild()`, self-referencing forward references
- **Core Topics:** Hierarchical data modeling, cascading validation across nested trees, resolving forward references via `model_rebuild()` in Pydantic v2, and modeling recursive tree/graph structures (e.g., folder hierarchies, comment threads).
- **Real-World / AI Applications:** Representing multi-turn conversational chat histories (`list[ChatMessage]`), complex document chunks with nested source metadata in RAG systems.

---

#### 5. Specialized Data Types & Enum Integration

- **Target Folder:** `GEN AI/9. Pydantic/05_types_enums/`
- **Core API & Methods:** `EmailStr`, `HttpUrl`, `AnyUrl`, `UUID`, `SecretStr`, `IPvAnyAddress`, `datetime`, `date`, `timedelta`, `Decimal`, `Literal`, `Enum`, `IntEnum`, `StrEnum`
- **Core Topics:** Built-in network and format validation (`pydantic[email]`), data security with `SecretStr` (preventing API keys from leaking in logs/reprs), currency precision with `Decimal`, and constraining choices with `Literal` and `StrEnum`.
- **Real-World / AI Applications:** Securing OpenAI/Claude API keys with `SecretStr`, restricting agent routing decisions to fixed enum states (`"search"`, `"calculator"`, `"final_answer"`).

---

#### 6. Field Validators (`@field_validator`)

- **Target Folder:** `GEN AI/9. Pydantic/06_field_validators/`
- **Core API & Methods:** `@field_validator`, `@classmethod`, parameters: `mode='before'`, `mode='after'`, `mode='plain'`, `mode='wrap'`, `ValidationInfo` (`info.data`, `info.field_name`)
- **Core Topics:** Pydantic v2 validator architecture (migration from v1 `@validator`), pre-validation string sanitization vs. post-validation type checking, accessing sibling fields via `ValidationInfo.data`, and re-raising `ValueError` / `PydanticCustomError`.
- **Real-World / AI Applications:** Sanitizing LLM outputs (stripping markdown backticks from JSON strings), normalizing phone numbers and email domains.

---

#### 7. Model Validators (`@model_validator`)

- **Target Folder:** `GEN AI/9. Pydantic/07_model_validators/`
- **Core API & Methods:** `@model_validator(mode='before')`, `@model_validator(mode='after')`, `self`, input dictionaries, cross-field validation logic
- **Core Topics:** Validating dependencies across multiple fields (e.g., `start_date < end_date`), mutating incoming raw payload dictionaries before parsing (`mode='before'`), and enforcing complex business rules on the instantiated model (`mode='after'`).
- **Real-World / AI Applications:** Validating LLM function calling arguments where mutually exclusive parameters cannot both be present, password confirmation matching.

---

#### 8. Serialization & Data Export (`model_dump`)

- **Target Folder:** `GEN AI/9. Pydantic/08_serialization_dump/`
- **Core API & Methods:** `model_dump()`, `model_dump_json()`, parameters: `include`, `exclude`, `exclude_unset`, `exclude_defaults`, `exclude_none`, `by_alias`, `mode='json'/'python'`, `@field_serializer`, `@model_serializer`
- **Core Topics:** Exporting models to Python dicts and JSON strings, optimizing payload size by omitting unset fields (`exclude_unset=True`), custom field serializers (`@field_serializer`), and ISO-8601 datetime serialization formatting.
- **Real-World / AI Applications:** Preparing minimal JSON payloads for external HTTP webhooks, stripping null fields before sending prompt payloads to LLM APIs.

---

#### 9. Deserialization & Robust Parsing (`model_validate`)

- **Target Folder:** `GEN AI/9. Pydantic/09_deserialization_parsing/`
- **Core API & Methods:** `model_validate()`, `model_validate_json()`, `model_validate_strings()`, `from_attributes=True` (ORM mode), `TypeAdapter`
- **Core Topics:** Instantiating models from raw Python dicts, strings, and byte payloads; direct JSON-to-Rust parser acceleration; reading ORM / SQLAlchemy objects using `from_attributes=True`; parsing primitive/collection types using `TypeAdapter[list[int]]`.
- **Real-World / AI Applications:** Parsing raw LLM generated text directly into type-safe objects via `model_validate_json()`, bridging SQL database entities to API response models.

---

#### 10. Field Aliases & Naming Conventions

- **Target Folder:** `GEN AI/9. Pydantic/10_aliases_naming/`
- **Core API & Methods:** `Field(alias=...)`, `validation_alias`, `serialization_alias`, `AliasGenerator`, `AliasChoices`, `AliasPath`, `to_camel`, `to_snake`
- **Core Topics:** Separating input aliases from output aliases, handling reserved Python keywords (e.g., `from`, `class`, `global`), resolving nested dictionary payloads via `AliasPath`, and automated snake_case $\leftrightarrow$ camelCase conversions via `AliasGenerator`.
- **Real-World / AI Applications:** Consuming external third-party APIs with camelCase JSON schemas while preserving PEP 8 snake_case in Python codebases.

---

#### 11. Model Configuration (`ConfigDict`)

- **Target Folder:** `GEN AI/9. Pydantic/11_model_config_configdict/`
- **Core API & Methods:** `model_config = ConfigDict(...)`, parameters: `extra='forbid'/'ignore'/'allow'`, `frozen=True`, `validate_assignment=True`, `str_strip_whitespace=True`, `arbitrary_types_allowed=True`, `populate_by_name=True`
- **Core Topics:** Replacing v1 inner `class Config` with v2 `ConfigDict`, securing APIs by forbidding extra unexpected fields (`extra='forbid'`), creating hashable/immutable models with `frozen=True`, and runtime reassignment validation.
- **Real-World / AI Applications:** Preventing prompt injection attacks from injecting arbitrary fields via `extra='forbid'`, creating frozen state dictionaries for LangGraph nodes.

---

#### 12. Strict Mode & Type Coercion Dynamics

- **Target Folder:** `GEN AI/9. Pydantic/12_strict_mode_coercion/`
- **Core API & Methods:** `strict=True`, `ConfigDict(strict=True)`, `StrictInt`, `StrictStr`, `StrictFloat`, `StrictBool`, `Field(strict=True)`
- **Core Topics:** Lax mode (default automatic coercion like `"123"` $\to 123$, `1` $\to \text{True}$) vs. Strict mode (zero coercion), security and data integrity implications, field-level vs. model-level strictness, and strict boolean parsing pitfalls.
- **Real-World / AI Applications:** Financial transaction validation where implicit rounding or string-to-number casting causes data corruption, strict API payload enforcement.

---

#### 13. Generic Models & Custom Types with `Annotated`

- **Target Folder:** `GEN AI/9. Pydantic/13_generics_custom_types/`
- **Core API & Methods:** `Generic[T]`, `TypeVar`, `APIResponse[T]`, `Annotated`, `AfterValidator`, `BeforeValidator`, `PlainValidator`, `WrapValidator`
- **Core Topics:** Building reusable generic API envelopes (e.g., standardized `{ success: bool, data: T, error: Optional[str] }`), modular and composable validation pipelines using Python's `typing.Annotated`, and decoupling validation logic from models.
- **Real-World / AI Applications:** Standardized pagination containers across microservices, creating reusable validated domain types like `PositiveInt` or `SanitizedHTML`.

---

#### 14. JSON Schema Generation & Tool Calling

- **Target Folder:** `GEN AI/9. Pydantic/14_json_schema_tool_calling/`
- **Core API & Methods:** `model_json_schema()`, `schema_generator`, schema customization via `json_schema_extra`, OpenAI / Anthropic Tool definitions
- **Core Topics:** Generating standard JSON Schema (Draft 2020-12) from Pydantic models, injecting parameter descriptions and examples into schema definitions, and converting Pydantic models directly into function call declarations for LLMs.
- **Real-World / AI Applications:** Defining OpenAI Assistant function calling schemas, generating OpenAPI documentation in FastAPI, tool declarations for autonomous agents.

---

#### 15. Pydantic for LLM Structured Outputs & AI Agents

- **Target Folder:** `GEN AI/9. Pydantic/15_llm_structured_outputs_agents/`
- **Core API & Methods:** OpenAI Structured Outputs (`client.beta.chat.completions.parse`), LangChain `with_structured_output()`, LangGraph agent state typing, RAG response schemas with citations, Instructor library patterns
- **Core Topics:** Guaranteed schema adherence with LLMs, error handling and automated retry loops when models return malformed JSON, validating multi-agent message passing, and structuring RAG responses (answer + list of retrieved source chunk citations).
- **Real-World / AI Applications:** Information extraction (parsing unstructured invoices, resumes, medical records into validated entities), reliable agent routing and state machines.
