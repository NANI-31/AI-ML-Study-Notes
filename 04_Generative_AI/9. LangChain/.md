#### 1. LangChain Architecture & Core Foundations

- **Target Folder:** `01_langchain_architecture_foundations/`
- **Core API & Abstractions:** `langchain-core` vs. `langchain` vs. `langchain-community` vs. provider packages (`langchain-openai`, `langchain-anthropic`); Message schemas (`HumanMessage`, `AIMessage`, `SystemMessage`, `ToolMessage`, `ChatMessage`); Message fields (`content`, `response_metadata`, `tool_calls`, `id`, `name`).
- **Core Concepts:** The modern LangChain ecosystem; LangChain vs. direct provider SDKs (OpenAI / Anthropic APIs) vs. LlamaIndex; Design trade-offs: Abstraction overhead vs. cross-model portability; Immutable message flows; Parametric memory vs. external state.
- **Failure Modes & Scenarios:** Diagnosing version mismatch bugs between legacy `langchain` and modern `langchain-core`; Resolving missing provider dependencies; Choosing when LangChain introduces unnecessary bloat vs. when its abstraction layers provide essential value.

#### 2. Models & Chat Interfaces

- **Target Folder:** `02_models_chat_interfaces/`
- **Core API & Abstractions:** `init_chat_model()` universal factory; `ChatOpenAI`, `ChatAnthropic`, `ChatGoogleGenerativeAI`, `ChatOllama`; Standard interface methods: `.invoke()`, `.batch()`, `.stream()`, `.ainvoke()`, `.abatch()`, `.astream()`; Configuration parameters (`temperature`, `max_tokens`, `stop`, `model_kwargs`, `streaming=True`, `max_retries`, `timeout`).
- **Core Concepts:** Legacy completion LLMs (`BaseLLM` / `predict()`) vs. Chat Models (`BaseChatModel`); Token consumption tracking and usage metadata; Dynamic runtime model selection; Multimodal inputs (passing base64 images and URLs inside `HumanMessage` content blocks); Reasoning models (o1/o3/Claude Extended Thinking) configuration.
- **Failure Modes & Scenarios:** Handling context window overflow errors; Managing API rate limits with exponential backoff; Token usage tracking discrepancies across streaming chunks; Diagnosing silent truncation caused by improper `max_tokens` settings.

#### 3. Prompt Engineering & Prompt Templates

- **Target Folder:** `03_prompts_templates_fewshot/`
- **Core API & Abstractions:** `PromptTemplate`, `ChatPromptTemplate`, `SystemMessagePromptTemplate`, `HumanMessagePromptTemplate`, `MessagesPlaceholder`; `FewShotPromptTemplate`, `FewShotChatMessagePromptTemplate`; Example selectors (`LengthBasedExampleSelector`, `SemanticSimilarityExampleSelector`).
- **Core Concepts:** Template variable interpolation (`input_variables`, `partial_variables`); Dynamic message injection via `MessagesPlaceholder(variable_name="history")`; Few-shot prompt construction with semantic example selection; Template serialization and versioning; Prompt sanitization and prompt injection defense.
- **Failure Modes & Scenarios:** Unmatched input variables raising `KeyError` during formatting; Misplaced `MessagesPlaceholder` corrupting system/human message order; Context window exhaustion caused by unconstrained few-shot example selection.

#### 4. Output Parsers & Structured Outputs

- **Target Folder:** `04_output_parsers_structured_outputs/`
- **Core API & Abstractions:** `.with_structured_output(schema, method="function_calling" | "json_mode")`; Pydantic v2 schemas (`BaseModel`, `Field`, `validator`, nested models); Classical parsers: `StrOutputParser`, `JsonOutputParser`, `PydanticOutputParser`; Auto-repairing parsers: `OutputFixingParser`, `RetryOutputParser`.
- **Core Concepts:** Why raw string responses fail in enterprise pipelines; Native provider function calling for schema enforcement vs. prompt-based JSON instructions; Extracting structured Pydantic objects directly from LLM calls; Handling enum constraints, optional fields, and nested schemas.
- **Failure Modes & Scenarios:** LLM outputting Markdown code fences (`json ... `) that break raw JSON decoders; Pydantic validation errors on missing required fields; Model hallucinating non-existent enum values; Graceful fallback when structured output generation fails.

#### 5. LCEL (LangChain Expression Language) & Runnables

- **Target Folder:** `05_lcel_runnables_composition/`
- **Core API & Abstractions:** The `|` pipe operator; `RunnableSequence`, `RunnableParallel` (dict syntax), `RunnableLambda`, `RunnablePassthrough`, `RunnableBranch`; Configuration methods: `.bind()`, `.with_config()`, `.with_retry()`, `.with_fallbacks()`.
- **Core Concepts:** Declarative pipeline composition; The unified Runnable interface contract (input $\to$ output); Synchronous vs. asynchronous execution; Streaming partial tokens across multi-step chains; Dynamic parameter binding (`.bind(temperature=0.2)`); Propagating runtime tags, metadata, and callbacks.
- **Failure Modes & Scenarios:** Type mismatch bugs across chain links (e.g., passing a `ChatPromptValue` into a function expecting a string); Loss of context when forgetting `RunnablePassthrough.assign()`; Unhandled asynchronous event loop blocking when mixing sync and async Runnables.

#### 6. Chain Patterns, Fallbacks & Dynamic Routing

- **Target Folder:** `06_chain_patterns_fallbacks_routing/`
- **Core API & Abstractions:** `create_stuff_documents_chain()`, `create_history_aware_retriever()`, `create_retrieval_chain()`; `.with_fallbacks([backup_model])`; Semantic routing via `RunnableBranch` and custom classifier functions.
- **Core Concepts:** Multi-step pipeline patterns: Preprocessing $\to$ Prompt $\to$ Model $\to$ Parser $\to$ Postprocessing; Dynamic intent routing (dispatching queries to SQL vs. Vector Search vs. General Chat); High-availability fallback chains (failing over from OpenAI to Anthropic/Ollama on outages); Map-reduce and refine document chains.
- **Failure Modes & Scenarios:** Fallback chains failing silently without notifying monitoring systems; Router classification ambiguities causing requests to fall into default catch-all branches; Map-reduce chains exhausting token limits during parallel mapping phases.

#### 7. Tools, Custom Functions & Tool Calling

- **Target Folder:** `07_tools_function_calling_pydantic/`
- **Core API & Abstractions:** `@tool` decorator, `StructuredTool.from_function()`, `BaseTool` subclassing; Pydantic `args_schema`; Model binding: `model.bind_tools([tools])`; `ToolMessage`, `AIMessage.tool_calls`, `tool_call_id`.
- **Core Concepts:** The tool interface: Name, description, and JSON schema; Docstring-based schema generation; Provider-native tool calling mechanics; Multi-tool calling and parallel tool execution; Community toolkits (`DuckDuckGoSearchResults`, `PythonREPLTool`, `SQLDatabaseToolkit`); Handling tool execution errors (`handle_tool_error=True`).
- **Failure Modes & Scenarios:** Poor tool docstrings causing models to select the wrong tool or hallucinate arguments; Type casting errors on tool input parameters; Security vulnerabilities from unsanitized shell/Python tool execution; Missing `tool_call_id` in `ToolMessage` causing API rejection.

#### 8. Agents & The ReAct Loop Architecture

- **Target Folder:** `08_agents_react_loop_architecture/`
- **Core API & Abstractions:** `create_tool_calling_agent()`, `create_react_agent()`; `AgentExecutor` (runtime execution loop); Agent state: `intermediate_steps`, `agent_scratchpad`, `AgentAction`, `AgentFinish`.
- **Core Concepts:** ReAct (Reasoning + Acting) loop: Thought $\to$ Action $\to$ Observation $\to$ Final Answer; Agents vs. Chains (dynamic decision making vs. deterministic pipelines); Tool selection, execution, and observation feedback; Loop constraints: `max_iterations`, `max_execution_time`, early stopping strategies (`force` vs. `generate`).
- **Failure Modes & Scenarios:** Infinite agent execution loops; Agents getting stuck repeatedly calling the same failing tool; Context window explosion from accumulating excessive tool outputs; Hallucinating tool names not present in the bound toolset.

#### 9. Memory, Chat History & State Persistence

- **Target Folder:** `09_memory_chat_history_state/`
- **Core API & Abstractions:** `ChatMessageHistory`, `InMemoryChatMessageHistory`; `RunnableWithMessageHistory`; External stores (`RedisChatMessageHistory`, `PostgresChatMessageHistory`); `trim_messages()` helper.
- **Core Concepts:** Conversational state management; Session ID isolation and factory patterns; Token-based message trimming (preserving initial system prompt while pruning oldest human/AI turns); Sliding window vs. summary memory; Migrating from legacy `ConversationBufferMemory` to modern LCEL `RunnableWithMessageHistory`.
- **Failure Modes & Scenarios:** Session state bleed across concurrent users; Token limit crashes caused by untrimmed conversation histories; Connection timeouts and serialization errors with external Redis/PostgreSQL message stores.

#### 10. Document Loaders & Text Splitters

- **Target Folder:** `10_document_loaders_text_splitters/`
- **Core API & Abstractions:** `Document(page_content, metadata)`; Loaders: `PyPDFLoader`, `UnstructuredLoader`, `CSVLoader`, `DirectoryLoader`, `WebBaseLoader`; Splitters: `CharacterTextSplitter`, `RecursiveCharacterTextSplitter`, `TokenTextSplitter`, `MarkdownHeaderTextSplitter`, `HTMLHeaderTextSplitter`.
- **Core Concepts:** Ingestion lifecycle; Chunk size vs. chunk overlap tuning; Semantic boundaries: Splitting on paragraphs, code blocks, and markdown headers; Preserving critical document metadata (source URLs, page numbers, timestamps); Chunk length measurement (character count vs. token count).
- **Failure Modes & Scenarios:** Splitting tables or code blocks mid-structure; Data loss from unparsed multi-column PDF layouts; Tokenizer mismatch when splitting on characters while the vector database/LLM enforces strict token limits.

#### 11. Vector Stores, Embeddings & Basic Retrievers

- **Target Folder:** `11_vectorstores_embeddings_retrievers/`
- **Core API & Abstractions:** Embeddings: `OpenAIEmbeddings`, `HuggingFaceEmbeddings`, `CohereEmbeddings`; Vector stores: `Chroma`, `FAISS`, `Pinecone`, `Qdrant`, `PGVector`; Retriever conversion: `vectorstore.as_retriever()`; Search types: `similarity`, `mmr` (Maximal Marginal Relevance).
- **Core Concepts:** Dense vector representations; Distance metrics (Cosine similarity, Dot product, Euclidean distance); Similarity search with scores; MMR diversification (balancing relevance vs. novelty with `lambda_mult`); Vector indexing API (`index()`) to prevent duplicate embeddings and stale chunks.
- **Failure Modes & Scenarios:** Dimension mismatch between embedding model and vector database index; Redundant re-embedding of unchanged documents driving up API costs; Retrieving duplicate near-identical chunks when standard similarity search is used instead of MMR.

#### 12. Advanced RAG & Retrieval Pipelines

- **Target Folder:** `12_advanced_rag_langchain_patterns/`
- **Core API & Abstractions:** `MultiQueryRetriever`, `ContextualCompressionRetriever`, `ParentDocumentRetriever`, `SelfQueryRetriever`, `EnsembleRetriever`; Rerankers: `CohereRerank`.
- **Core Concepts:** Multi-query expansion (generating alternative query perspectives); Contextual compression (extracting only query-relevant sentences before feeding the LLM); Parent-Document retrieval (searching small child chunks, retrieving large parent context); Self-querying (translating natural language into vector search + metadata filters); Reciprocal Rank Fusion (RRF) hybrid retrieval.
- **Failure Modes & Scenarios:** Compression models discarding critical context; MultiQuery latency bottlenecks from multiple sequential LLM calls; Metadata filter syntax errors across different vector database engines in SelfQuery pipelines.

#### 13. LangGraph: Stateful Graphs & Cyclic Architectures

- **Target Folder:** `13_langgraph_stateful_graphs_cycles/`
- **Core API & Abstractions:** `StateGraph`, `MessagesState`, custom `TypedDict` / Pydantic state; Node creation (`graph.add_node()`); Edge definitions (`graph.add_edge()`, `graph.add_conditional_edges()`); Reducer functions (`Annotated[list, add_messages]`); Compilation (`graph.compile()`).
- **Core Concepts:** Why LangGraph supersedes linear DAG chains; Cyclical execution for autonomous agent loops; Explicit immutable state models; State reducers for merging outputs without overwriting history; Conditional branching based on LLM routing decisions; Graph visualization via Mermaid.
- **Failure Modes & Scenarios:** Infinite graph loops without terminal condition edges; State mutation bugs where nodes return non-reducer compatible payloads; Deadlock states caused by unhandled conditional edge branches.

#### 14. LangGraph: Multi-Agent Systems & Human-in-the-Loop

- **Target Folder:** `14_langgraph_multiagent_human_in_loop/`
- **Core API & Abstractions:** Checkpointers: `MemorySaver`, `SqliteSaver`, `PostgresSaver`; Thread management (`{"configurable": {"thread_id": "1"}}`); `interrupt()` function; Multi-agent architectures (Supervisor, Network handoffs, Hierarchical teams).
- **Core Concepts:** State persistence across execution turns; Human-in-the-loop (HITL): Halting execution for human approval before calling destructive tools (financial transfers, database updates); Time travel: Rewinding state to earlier checkpoints, editing messages, and replaying execution branches; Multi-agent handoffs with specialized domain subagents.
- **Failure Modes & Scenarios:** State corruption during concurrent checkpoint writes; Missing `thread_id` causing sessions to collapse into a single global state; Agent handoff loops where two agents ping-pong requests indefinitely without solving the task.

#### 15. Observability, Tracing & LangSmith

- **Target Folder:** `15_observability_langsmith_tracing/`

- **Core Concepts:** Deep production observability; Tracing inputs, outputs, latency, and token consumption across complex nested chains and agent loops; Debugging tool call arguments and failures in production; Creating golden evaluation datasets in LangSmith; Automated evaluation metrics (correctness, groundedness, toxicity).
- **Failure Modes & Scenarios:** Synchronous callback handlers introducing latency into the user-facing request loop; Inadvertently leaking sensitive PII or API credentials into LangSmith traces; Lack of tracing obscuring which step in a 10-node graph introduced a hallucination.
