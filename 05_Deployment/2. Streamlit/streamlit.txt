22. Best Practices & Code Quality
22.1 Performance Best Practices
	1. Always cache heavy data transformations (@st.cache_data)
	2. Always cache database connections and models (@st.cache_resource)
	3. Batch input fields with st.form to minimize reruns
	4. Avoid storing large DataFrames directly in st.session_state
	5. Use st.empty() rather than full reruns for tickers
	6. Downsample large datasets before rendering charts
22.2 Code Structure Best Practices
	1. Separate business logic from UI rendering code
	2. Place reusable widgets in helper functions
	3. Maintain clean modular directory structure
	4. Centralize session state initialization
	5. Use type annotations across data loader functions
22.3 UI/UX Design Guidelines
	1. Use st.set_page_config(layout="wide") for complex dashboards
	2. Keep sidebar focused on global parameters and filters
	3. Use informative loading spinners and progress indicators
	4. Limit the number of top-level metrics per row to 3-4
	5. Provide helpful tooltips via help parameter

23. Common Streamlit Mistakes and Anti-Patterns
23.1 Common Runtime Mistakes
	1. Forgetting that the entire script runs from top to bottom
	2. Modifying widget key directly inside st.session_state
	3. Modifying cached data in-place leading to global mutations
	4. Calling st.set_page_config after other Streamlit commands
	5. Forgetting mandatory submit button inside st.form
	6. Using global Matplotlib plt without passing fig to st.pyplot
	7. Placing long-running blocking calls directly in the main thread
	8. Hardcoding absolute file paths instead of relative paths
	9. Hardcoding secrets and credentials inside application code
