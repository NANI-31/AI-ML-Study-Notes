# 15. ASYNC AND CONCURRENCY

Teach async/concurrency only when relevant to the current section.

When relevant, clearly distinguish:

## Synchronous route

```python
@app.get("/data")
def get_data():
    result = sync_operation()
    return result
```

## Asynchronous route

```python
@app.get("/data")
async def get_data():
    result = await async_operation()
    return result
```

Explain that FastAPI can execute normal synchronous path-operation functions in a threadpool.

Also explain this important distinction:

```python
@app.get("/data")
async def get_data():
    result = blocking_function()
    return result
```

The synchronous `blocking_function()` is **not automatically moved to a threadpool merely because the route is `async def`**.

It can block the event-loop thread.

Therefore distinguish:

```text
sync `def` route
      ↓
FastAPI can run it in a threadpool
```

from:

```text
async `def` route
      ↓
blocking synchronous function called directly
      ↓
can block the event loop
```

When relevant, discuss:

- async-native libraries
- `await`
- `asyncio.to_thread()`
- thread pools
- process workers
- dedicated inference workers

Never imply:

```text
async = automatically faster
```

Always distinguish:

```text
I/O-bound work
```

from:

```text
CPU-bound work
```

and:

```text
GPU/model inference
```
