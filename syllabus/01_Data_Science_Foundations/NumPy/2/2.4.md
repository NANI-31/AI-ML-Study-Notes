# Section: 2.4 Random Arrays (rand, randn, randint, seed, default_rng, sampling, shuffling)

## 1. Section Overview
Random array generation, stochastic simulation, and statistical sampling form the cornerstone of machine learning model weight initialization, Monte Carlo simulations, randomized cross-validation splitting, synthetic data synthesis, and data augmentation. In NumPy, random number generation spans two distinct architectural paradigms:
1. **Legacy Random API (`np.random.*`)**: Historic convenience functions dating back to early NumPy versions, including `np.random.rand()`, `np.random.randn()`, `np.random.randint()`, `np.random.choice()`, `np.random.shuffle()`, and global state management via `np.random.seed()`. These routines rely on a shared global Mersenne Twister (MT19937) pseudo-random number generator (PRNG).
2. **Modern Random Generator Architecture (NumPy 1.17+ / 2.0+)**: The decoupled `Generator` and `BitGenerator` architecture instantiated via `rng = np.random.default_rng()`, using the Permuted Congruential Generator (`PCG64`) as its default underlying bitstream engine. This modern API eliminates global state leaks, guarantees multi-threaded isolation, provides superior statistical properties, passes rigorous BigCrush battery tests, and offers faster execution.

In technical interviews, interviewers frequently use random arrays to evaluate whether a candidate relies on outdated legacy patterns (`np.random.seed`, `rand`, `randn`) or commands modern production standards (`default_rng`, `standard_normal`, `uniform`, `integers`). Understanding the differences between in-place shuffling (`shuffle`) and copy generation (`permutation`), sampling with versus without replacement (`choice`), statistical distributions, and thread-safe seeding is vital for any prospective data scientist, ML engineer, or quantitative analyst.

## 2. Topic-Wise Interview Concepts

### Topic 1: `np.random.rand(*dims)` vs `rng.uniform(low, high, size)`
- **Concept Definition**: Generates uniform random floating-point numbers over the continuous half-open interval $[0.0, 1.0)$.
- **Legacy API (`np.random.rand`)**: Takes dimension integers as separate positional arguments `*dims` (e.g., `rand(2, 3)`), deviating from NumPy's standard shape tuple convention. Modifies the global MT19937 state.
- **Modern API (`rng.uniform`)**: Accessed via `rng = np.random.default_rng()`. Accepts an explicit `size` tuple (e.g., `size=(2, 3)`), allows arbitrary range boundaries `[low, high)`, and executes using PCG64.
- **Core Interview Rule**: Never use `rand()` in new production code; use `default_rng().uniform()` for custom ranges or `default_rng().random()` for $[0.0, 1.0)$.

### Topic 2: `np.random.randn(*dims)` vs `rng.standard_normal(size)`
- **Concept Definition**: Generates standard normally distributed floating-point numbers with mean $\mu = 0$ and standard deviation $\sigma = 1$ ($\mathcal{N}(0, 1)$).
- **Legacy API (`np.random.randn`)**: Takes separate dimension arguments (e.g., `randn(3, 4)`). Uses Box-Muller transform or polar rejection methods over MT19937.
- **Modern API (`rng.standard_normal`)**: Accepts a standard `size` tuple. Employs the highly optimized **Ziggurat algorithm**, generating Gaussian variates significantly faster and with superior statistical tail properties.
- **Scaling Formula**: To generate general Gaussian variates $\mathcal{N}(\mu, \sigma^2)$, scale by $\sigma$ and shift by $\mu$: $X = \mu + \sigma \cdot \text{rng.standard_normal(size)}$.

### Topic 3: `np.random.randint(low, high=None, size=None)` vs `rng.integers(low, high=None, size=None, endpoint=False)`
- **Concept Definition**: Generates pseudorandom integers from a specified discrete uniform range.
- **Legacy API (`np.random.randint`)**: Generates integers over $[low, high)$ (exclusive of $high$).
- **Modern API (`rng.integers`)**: Provides explicit control over boundary inclusion via `endpoint=True/False`. Supports 64-bit and 32-bit integer dtypes natively. Uses unbiased Lemire or bit-mask division reduction algorithms to eliminate modulo bias.

### Topic 4: `np.random.seed(seed)` vs `np.random.default_rng(seed)`
- **Concept Definition**: Configures the initial deterministic state of the pseudo-random number generator to ensure reproducibility across runs.
- **Legacy API (`np.random.seed`)**: Modifies a mutable **global singleton** PRNG state. Calling it affects every third-party library or background thread running in the same Python process, introducing insidious cross-thread race conditions.
- **Modern API (`default_rng`)**: Instantiates an **isolated local Generator object** encapsulating its own state: `rng = np.random.default_rng(seed)`. Enables thread-safe parallel simulation and clean dependency injection.

### Topic 5: Random Sampling (`np.random.choice` vs `rng.choice`)
- **Concept Definition**: Generates a random sample from a given 1D array or integer range, with or without replacement, and with optional non-uniform probability weights $p$.
- **Replacement Mechanics**:
  - `replace=True` (default): Samples can be chosen multiple times (independent identically distributed draws).
  - `replace=False`: Samples are drawn without replacement (hypergeometric / permutation sampling). Length cannot exceed population size.
- **Probability Weights $p$**: Optional 1D array of probabilities summing to $1.0$ ($\sum p_i = 1$).

### Topic 6: Shuffling Arrays (`shuffle` vs `permutation`)
- **Concept Definition**: Randomly reorders elements of an array along a given axis.
- **In-place Shuffling (`shuffle`)**: Modifies the input array directly in-place along axis 0 and returns `None`. Mutates the original memory buffer.
- **Permutation (`permutation`)**: Leaves the original array intact and returns an independent, randomly reordered copy. If passed an integer $N$, it returns a randomly permuted array of integers from $0$ to $N-1$ (equivalent to shuffling `np.arange(N)`).

#### Question 1: What is the difference between `np.random.rand()` and `np.random.randn()`?
- **Direct Definition & Core Concept**: `np.random.rand()` generates numbers from a **uniform continuous distribution** over the interval $[0.0, 1.0)$, where all values have equal probability density. In contrast, `np.random.randn()` generates numbers from a **standard normal (Gaussian) distribution** with mean $\mu = 0$ and standard deviation $\sigma = 1$ ($\mathcal{N}(0, 1)$), producing a bell-shaped probability density curve.
- **Technical & Memory Mechanics**: For `rand()`, all outputs fall strictly within $0.0 \le x < 1.0$. For `randn()`, outputs are theoretically unbounded $(-\infty, \infty)$, with approximately $68.2\%$ of samples falling in $[-1, 1]$, $95.4\%$ in $[-2, 2]$, and $99.7\%$ in $[-3, 3]$. Both legacy functions accept dimension integers as unpacked positional arguments (e.g., `rand(2, 3)`), rather than a shape tuple.
- **Practical Application**:
  ```python
  import numpy as np

  # Uniform [0, 1): All positive
  u = np.random.rand(3)

  # Standard Normal: Can be negative or positive, centered around 0
  n = np.random.randn(3)
  print("Uniform (rand):", u)
  print("Gaussian (randn):", n)
  ```
- **Nuances & Pitfalls**: Never use `rand()` when initializing neural network weights; uniform distributions centered at $0.5$ introduce positive activation bias. Neural networks require zero-centered Gaussian distributions (`randn` or He/Xavier initialization).

#### Question 2: What is `np.random.default_rng()` and why was it introduced in modern NumPy?
- **Direct Definition & Core Concept**: `np.random.default_rng()` is the official factory function introduced in NumPy 1.17 to instantiate an isolated, object-oriented `Generator` using the modern `PCG64` BitGenerator engine, replacing legacy global functions.
- **Technical & Memory Mechanics**: Legacy functions like `np.random.rand` mutate a single shared global state based on the 1990s Mersenne Twister (MT19937) algorithm. MT19937 suffers from poor statistical properties (fails BigCrush test suites), has a massive 2.5 KB state size, is vulnerable to state reconstruction attacks, and causes race conditions in multi-threaded code. `default_rng()` uses PCG64 (Permuted Congruential Generator), which has a tiny state size (128 bits), passes all modern statistical randomness tests, generates Gaussian variates significantly faster via the Ziggurat algorithm, and provides isolated instances that cannot corrupt each other.
- **Practical Application**:
  ```python
  import numpy as np

  # Modern production best practice:
  rng = np.random.default_rng(seed=42)
  samples = rng.standard_normal((3, 3))
  print("Modern Generator Samples:\n", samples)
  ```
- **Nuances & Pitfalls**: Calling legacy functions like `np.random.seed(42)` does **not** seed instances created by `default_rng()`, and vice versa. They belong to completely separate RNG subsystems.

#### Question 3: How does `np.random.randint()` differ from `rng.integers()`?
- **Direct Definition & Core Concept**: Both generate pseudorandom discrete uniform integers, but `rng.integers()` is the modern API that provides superior statistical performance, eliminates modulo bias, and adds an explicit `endpoint` parameter.
- **Technical & Memory Mechanics**: In legacy `np.random.randint(low, high)`, the upper bound `high` is strictly excluded ($[low, high)$). In `rng.integers(low, high, endpoint=True)`, the upper bound is included ($[low, high]$). Furthermore, legacy `randint` suffers from modulo bias when mapping raw 32-bit random integers to arbitrary ranges. `rng.integers` employs Lemire's fast exact integer reduction algorithm, guaranteeing zero statistical bias.
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  # Inclusive dice roll [1, 6] using endpoint=True:
  dice = rng.integers(1, 6, size=5, endpoint=True)
  print("Dice rolls [1, 6]:", dice)
  ```
- **Nuances & Pitfalls**: If only a single boundary argument is provided, e.g., `rng.integers(10)`, the range is treated as $[0, 10)$, with the single argument serving as `high`, not `low`.

#### Question 4: What is the difference between `np.random.shuffle()` and `np.random.permutation()`?
- **Direct Definition & Core Concept**: `np.random.shuffle()` performs an **in-place mutation** of the input array and returns `None`. In contrast, `np.random.permutation()` allocates and returns an independent **shuffled copy**, leaving the original array completely untouched.
- **Technical & Memory Mechanics**: `shuffle(arr)` directly swaps rows in the existing memory buffer using the Fisher-Yates algorithm along axis 0. If you assign `x = np.random.shuffle(arr)`, `x` becomes `None`! `permutation(arr)` first copies the array and then shuffles the copy. Additionally, if `permutation()` is passed an integer scalar $N$, it returns a randomly permuted array of integers from $0$ to $N-1$.
- **Practical Application**:
  ```python
  import numpy as np

  a = np.array([1, 2, 3, 4, 5])
  # In-place shuffle:
  np.random.shuffle(a)
  print("a is modified in-place:", a)

  b = np.array([1, 2, 3, 4, 5])
  # Out-of-place permutation:
  c = np.random.permutation(b)
  print("b remains intact:", b, "| c is new shuffled copy:", c)
  ```
- **Nuances & Pitfalls**: In machine learning dataset shuffling where features $X$ and labels $y$ must stay synchronized, calling `shuffle(X)` and `shuffle(y)` separately completely destroys sample-to-label alignment! Permutation indices `idx = rng.permutation(len(X))` must be generated first and applied to both: `X[idx], y[idx]`.

#### Question 5: What is the purpose of setting a random seed, and what does it guarantee?
- **Direct Definition & Core Concept**: A random seed initializes the internal state registers of a deterministic pseudo-random number generator. It guarantees that subsequent sequences of generated numbers will be **100% bitwise reproducible** across identical runs.
- **Technical & Memory Mechanics**: Computers do not generate true random numbers; they compute deterministic mathematical sequences using recurrence relations ($X_{n+1} = f(X_n)$). The seed acts as $X_0$. Given identical initial state $X_0$ and identical software versions, the mathematical sequence of variates is completely deterministic. This is essential for debugging, regression testing, scientific peer review, and benchmark reproducibility.
- **Practical Application**:
  ```python
  import numpy as np

  rng1 = np.random.default_rng(123)
  rng2 = np.random.default_rng(123)

  print("Run 1:", rng1.random(3))
  print("Run 2:", rng2.random(3)) # Identical to Run 1
  ```
- **Nuances & Pitfalls**: Reproducibility is guaranteed across the same NumPy version and CPU architecture, but minor numerical differences in BLAS/LAPACK or floating-point SIMD implementations can cause divergence across different operating systems or hardware platforms (e.g., x86 vs ARM).

#### Question 6: How does `rng.choice()` work, and what is the difference between `replace=True` and `replace=False`?
- **Direct Definition & Core Concept**: `rng.choice()` draws random samples from a 1D population array or from the integer range $[0, a)$. The `replace` boolean parameter dictates whether selected elements are returned to the pool after each draw.
- **Technical & Memory Mechanics**:
  - `replace=True` (sampling with replacement): Each draw is independent. Elements can be selected multiple times. The sample size can be arbitrarily large, even exceeding the population size.
  - `replace=False` (sampling without replacement): Each selected element is removed from the pool. No duplicate selections can occur. The requested `size` cannot exceed the population size $N$; otherwise, a `ValueError: Cannot take a larger sample than population when 'replace=False'` is raised.
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  items = np.array(['A', 'B', 'C', 'D'])

  # With replacement: duplicates possible
  sample_with = rng.choice(items, size=6, replace=True)
  # Without replacement: unique items only
  sample_without = rng.choice(items, size=3, replace=False)

  print("With Replacement:", sample_with)
  print("Without Replacement:", sample_without)
  ```
- **Nuances & Pitfalls**: In bootstrap sampling (bagging/Random Forests), sampling with replacement (`replace=True`) is required. In train/test dataset splitting, sampling without replacement (`replace=False`) is mandatory.

#### Question 7: How do you sample with non-uniform probabilities using `rng.choice()`?
- **Direct Definition & Core Concept**: Non-uniform sampling is achieved by passing an array of probability weights to the `p` parameter, representing the categorical probability distribution over the population.
- **Technical & Memory Mechanics**: The probability array `p` must match the length of the 1D population array. All elements in `p` must be non-negative ($p_i \ge 0$), and their sum must equal $1.0$ ($\sum p_i = 1.0$). NumPy validates this within floating-point tolerance; if $\sum p_i \neq 1.0$, a `ValueError: probabilities do not sum to 1` is raised.
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  outcomes = np.array(["Heads", "Tails"])
  # Biased coin: 80% Heads, 20% Tails
  probabilities = np.array([0.8, 0.2])

  flips = rng.choice(outcomes, size=10, p=probabilities)
  print("Biased Flips:", flips)
  ```
- **Nuances & Pitfalls**: If probabilities come from empirical counts, normalize them explicitly: `p = counts / counts.sum()`. Never leave normalization to floating-point chance.

#### Question 8: How do you generate Gaussian random numbers with an arbitrary mean $\mu$ and standard deviation $\sigma$?
- **Direct Definition & Core Concept**: You generate general Gaussian numbers $\mathcal{N}(\mu, \sigma^2)$ by taking standard normal variates $Z \sim \mathcal{N}(0, 1)$ from `rng.standard_normal()`, multiplying by $\sigma$, and adding $\mu$: $X = \mu + \sigma \cdot Z$. Alternatively, call `rng.normal(loc=mu, scale=sigma, size=...)`.
- **Technical & Memory Mechanics**: Standard normal variates have $\mathbb{E}[Z] = 0$ and $\text{Var}(Z) = 1$. By the linearity of expectation and variance, $\mathbb{E}[\mu + \sigma Z] = \mu + \sigma \mathbb{E}[Z] = \mu$, and $\text{Var}(\mu + \sigma Z) = \sigma^2 \text{Var}(Z) = \sigma^2$. This linear transformation scales the standard deviation and shifts the distribution center.
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  mu = 100.0   # Desired mean
  sigma = 15.0 # Desired standard deviation

  # Method 1: Mathematical scaling
  samples_manual = mu + sigma * rng.standard_normal(size=1000)
  # Method 2: Direct API
  samples_api = rng.normal(loc=mu, scale=sigma, size=1000)

  print(f"Manual - Mean: {samples_manual.mean():.2f}, Std: {samples_manual.std():.2f}")
  print(f"API    - Mean: {samples_api.mean():.2f}, Std: {samples_api.std():.2f}")
  ```
- **Nuances & Pitfalls**: In `rng.normal(loc, scale)`, the `scale` parameter is the **standard deviation** $\sigma$, not the variance $\sigma^2$. If given variance $\sigma^2 = 25$, pass `scale=np.sqrt(25) = 5.0`.

#### Question 9: Why does `np.random.rand(2, 3)` take arguments differently than `np.zeros((2, 3))`?
- **Direct Definition & Core Concept**: `np.random.rand()` and `np.random.randn()` were designed in early NumPy to mimic MATLAB syntax, accepting dimensions as unpacked variable positional arguments (`*dims`), whereas standard NumPy array factories (`zeros`, `ones`, `empty`) accept a single shape tuple.
- **Technical & Memory Mechanics**: Passing `np.random.rand((2, 3))` (a tuple) raises a `TypeError: an integer is required`. This syntax inconsistency caused widespread confusion among developers. The modern API `default_rng()` fixed this historical artifact: `rng.random(size=(2, 3))` and `rng.standard_normal(size=(2, 3))` consistently accept standard NumPy shape tuples.
- **Practical Application**:
  ```python
  import numpy as np

  # Legacy quirk: unpacked arguments
  legacy = np.random.rand(2, 3)

  # Modern consistency: standard shape tuple
  rng = np.random.default_rng()
  modern = rng.random((2, 3))
  print("Shapes match:", legacy.shape == modern.shape) # True
  ```
- **Nuances & Pitfalls**: If you have a shape variable `shape = (10, 5)`, with legacy code you must unpack it: `np.random.rand(*shape)`. With modern `default_rng`, pass it directly: `rng.random(shape)`.

#### Question 10: How do you generate reproducible random numbers in a multi-threaded Python application?
- **Direct Definition & Core Concept**: In multi-threaded or parallel applications, each thread or process must be given its own independent `Generator` instance derived from independent, non-overlapping seed streams, avoiding the shared global `np.random.seed()`.
- **Technical & Memory Mechanics**: If multiple worker threads share a single PRNG or call `np.random.seed(42)` in parallel, they will experience lock contention, state collisions, or duplicate random streams (where every thread generates the exact same sequence). Modern NumPy provides `np.random.SeedSequence`, which algorithmically partitions entropy to spawn independent, statistically uncorrelated BitGenerators for each parallel worker.
- **Practical Application**:
  ```python
  import numpy as np
  from concurrent.futures import ThreadPoolExecutor

  def worker_task(rng_instance, worker_id):
      return rng_instance.random(3)

  # Spawn 4 independent PRNG streams using SeedSequence
  ss = np.random.SeedSequence(12345)
  child_seeds = ss.spawn(4)
  generators = [np.random.default_rng(s) for s in child_seeds]

  with ThreadPoolExecutor(max_workers=4) as executor:
      results = list(executor.map(worker_task, generators, range(4)))

  for i, res in enumerate(results):
      print(f"Worker {i} Randoms:", res)
  ```
- **Nuances & Pitfalls**: Never seed worker threads with `seed + i` (e.g., $42, 43, 44$). Linear increments in seeds can result in correlated initial random states. Always use `SeedSequence.spawn()`.

#### Question 11: What is the distribution produced by `rng.uniform(low=0.0, high=10.0, size=1000)`?
- **Direct Definition & Core Concept**: A continuous uniform distribution where every real number between $0.0$ and $10.0$ has an identical probability density $f(x) = \frac{1}{\text{high} - \text{low}} = 0.1$.
- **Technical & Memory Mechanics**: The theoretical mean is $\mathbb{E}[X] = \frac{\text{low} + \text{high}}{2} = 5.0$, and the theoretical variance is $\text{Var}(X) = \frac{(\text{high} - \text{low})^2}{12} = \frac{100}{12} \approx 8.333$ (standard deviation $\sigma \approx 2.887$).
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  u = rng.uniform(0.0, 10.0, size=100_000)
  print(f"Sample Mean: {u.mean():.3f} (Expected: 5.0)")
  print(f"Sample Std:  {u.std():.3f}  (Expected: {np.sqrt(100/12):.3f})")
  ```
- **Nuances & Pitfalls**: In `rng.uniform(low, high)`, the high boundary is strictly exclusive: $x \in [\text{low}, \text{high})$.

#### Question 12: How do you generate a random boolean mask in NumPy?
- **Direct Definition & Core Concept**: A random boolean mask can be constructed by comparing uniform random floats against a threshold probability $p$, or by sampling booleans directly via `rng.choice([True, False])`.
- **Technical & Memory Mechanics**: Evaluating `rng.random(size) < p` generates a boolean array where each entry has probability $p$ of being `True` (Bernoulli trial). This is completely vectorized in C, requiring only 1 byte per boolean (`bool_`).
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  # Generate 80% True / 20% False mask (e.g., for train/test split)
  mask = rng.random(10) < 0.8
  print("Boolean Mask:", mask)
  print("True Count:", np.sum(mask))
  ```
- **Nuances & Pitfalls**: Thresholding `rng.random() < p` is substantially faster than calling `rng.choice([True, False], p=[p, 1-p])` because it avoids discrete alias table lookups.

#### Question 13: What is the output shape of `rng.standard_normal((3, 4, 5))`?
- **Direct Definition & Core Concept**: A 3D tensor of shape `(3, 4, 5)` containing 60 independent standard normally distributed floating-point numbers.
- **Technical & Memory Mechanics**: The memory buffer allocated contains $3 \times 4 \times 5 = 60$ contiguous 64-bit floats ($480$ bytes). Elements are populated along C-contiguous memory strides.
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  tensor = rng.standard_normal((3, 4, 5))
  print("Shape:", tensor.shape, "| Total elements:", tensor.size)
  ```
- **Nuances & Pitfalls**: If you omit dimensions and call `rng.standard_normal()`, it returns a single Python `float` scalar rather than an array.

#### Question 14: What happens if `replace=False` and `size > len(population)` in `rng.choice()`?
- **Direct Definition & Core Concept**: NumPy raises a fatal `ValueError: Cannot take a larger sample than population when 'replace=False'`.
- **Technical & Memory Mechanics**: Sampling without replacement draws elements strictly from the available set without replenishing them. Once all $N$ elements are drawn, the population is exhausted. Requesting $N+1$ unique draws from a set of size $N$ is mathematically impossible (the pigeonhole principle).
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  population = [1, 2, 3]

  try:
      sample = rng.choice(population, size=5, replace=False)
  except ValueError as e:
      print("Caught expected error:", e)
  ```
- **Nuances & Pitfalls**: If you need to sample more items than exist in the population, you must set `replace=True`.

#### Question 15: How does `rng.shuffle()` behave on a 2D matrix?
- **Direct Definition & Core Concept**: `rng.shuffle()` shuffles an array **strictly along its first axis (axis 0)**. It reorders rows, but leaves the internal contents of each row completely intact.
- **Technical & Memory Mechanics**: For a 2D matrix of shape $(R, C)$, `rng.shuffle(matrix)` swaps row pointers/strides within the memory buffer. Row $i$ is moved to row $j$, but the column elements within that row remain in their original order. Columns are not shuffled.
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  grid = np.arange(12).reshape(4, 3)
  print("Original Grid:\n", grid)

  rng.shuffle(grid)
  print("After rng.shuffle (rows reordered, columns intact):\n", grid)
  ```
- **Nuances & Pitfalls**: If you need to shuffle elements across all axes or shuffle columns, you must transpose or flatten the array, shuffle, and reshape.

#### Question 16: Can `np.random.seed()` be set to a string or float?
- **Direct Definition & Core Concept**: No, `np.random.seed()` strictly requires an integer (or integer array), or `None` to read entropy from the operating system.
- **Technical & Memory Mechanics**: The pseudo-random bit generator requires integer bit registers (e.g., unsigned 32-bit integer). Passing a string or float raises a `TypeError: Cannot cast scalar from dtype('float64') to dtype('int64') according to the rule 'safe'` or `TypeError: 'str' object cannot be interpreted as an integer`.
- **Practical Application**:
  ```python
  import numpy as np

  # VALID:
  np.random.seed(42)

  # INVALID:
  # np.random.seed("my_seed") # Raises TypeError
  # np.random.seed(3.14159)   # Raises TypeError
  ```
- **Nuances & Pitfalls**: If you have a string identifier (e.g., experiment name `"exp_01"`), hash it to an integer using Python's `hash()` or `zlib.crc32(b"exp_01")` before passing it to the seed generator.

#### Question 17: How do you generate a random permutation of integers from 0 to $N-1$?
- **Direct Definition & Core Concept**: Call `rng.permutation(N)`. Passing an integer scalar $N$ directly generates a randomly shuffled array of integers from $0$ to $N-1$.
- **Technical & Memory Mechanics**: This is equivalent to `arr = np.arange(N); rng.shuffle(arr); return arr`, but executed in optimized compiled C code in a single step without allocating an explicit intermediate `arange` array in Python.
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng(seed=42)
  # Shuffled indices for 5 samples:
  shuffled_indices = rng.permutation(5)
  print("Permuted Indices:", shuffled_indices) # e.g. [2 4 1 0 3]
  ```
- **Nuances & Pitfalls**: This is the standard, idiomatic method for shuffling dataset indices in machine learning pipelines.

#### Question 18: What is the default data type produced by `rng.random()` and `rng.standard_normal()`?
- **Direct Definition & Core Concept**: Unconditionally `np.float64` (64-bit IEEE floating point).
- **Technical & Memory Mechanics**: BitGenerators generate 64 bits of raw random entropy at each step (e.g., PCG64 generates a `uint64` stream). NumPy masks and normalizes these 64 bits to construct standard IEEE 754 64-bit double-precision floats.
- **Practical Application**:
  ```python
  import numpy as np

  rng = np.random.default_rng()
  u = rng.random(5)
  n = rng.standard_normal(5)
  print("u dtype:", u.dtype) # float64
  print("n dtype:", n.dtype) # float64
  ```
- **Nuances & Pitfalls**: In deep learning on GPUs, 32-bit floats (`np.float32`) are preferred. You can request float32 directly in modern NumPy: `rng.standard_normal(5, dtype=np.float32)`.

#### Question 19: What happens if you call `np.random.default_rng()` without any seed?
- **Direct Definition & Core Concept**: If called without a seed (or with `seed=None`), `np.random.default_rng()` reads cryptographically secure random entropy from the operating system (`/dev/urandom` on Unix, `CryptGenRandom` on Windows) via `np.random.SeedSequence`.
- **Technical & Memory Mechanics**: A fresh, unpredictable seed is generated at runtime. Consecutive runs will produce completely different, statistically independent pseudo-random streams.
- **Practical Application**:
  ```python
  import numpy as np

  # Unseeded: fresh random state every execution
  rng = np.random.default_rng()
  ```

#### Question 21: Explain the architecture of `BitGenerator` vs `Generator` in modern NumPy.
- **Direct Definition & Core Concept**: Modern NumPy separates random number generation into two decoupled architectural layers: a **`BitGenerator`**, which generates raw streams of random unsigned integer bits, and a **`Generator`**, which consumes those raw bits and transforms them into statistical distributions (Normal, Uniform, Binomial, Poisson).
- **Technical & Memory Mechanics**:
  - `BitGenerator` (e.g., `PCG64`, `MT19937`, `Philox`, `SFC64`): Manages the internal state register and executes low-level recurrence relations to produce raw 64-bit unsigned integers (`uint64`).
  - `Generator` (e.g., returned by `default_rng()`): Takes a `BitGenerator` as its input engine and applies numerical algorithms (e.g., Ziggurat method for Gaussian, Lemire reduction for integers, alias tables for categorical choice) to produce structured multidimensional `ndarrays`.
  - This decoupling allows developers to swap the underlying PRNG engine (e.g., swapping `PCG64` for `Philox` in GPU/distributed environments) without altering any downstream statistical distribution code.
- **Practical Application**:
  ```python
  import numpy as np
  from numpy.random import Generator, PCG64, Philox

  # Standard default generator (PCG64 engine):
  rng_pcg = np.random.default_rng(42)

  # Custom generator with Philox engine (common in distributed computing):
  rng_philox = Generator(Philox(42))

  print("PCG64 Normal:", rng_pcg.standard_normal(2))
  print("Philox Normal:", rng_philox.standard_normal(2))
  ```
- **Nuances & Pitfalls**: In 99% of data science applications, calling `np.random.default_rng(seed)` is all you need; NumPy automatically wires `PCG64` to `Generator`.

#### Question 22: What is the Ziggurat algorithm and why does modern NumPy use it for normal distributions?
- **Direct Definition & Core Concept**: The Ziggurat algorithm is an extremely fast rejection-sampling algorithm used to generate variates from monotonic decreasing probability distributions, such as the Gaussian distribution.
- **Technical & Memory Mechanics**: Legacy NumPy used the Box-Muller transform or Marsaglia polar method, which compute expensive transcendental trigonometric and logarithmic functions (`cos`, `sin`, `log`, `sqrt`) for every generated pair of normal numbers. The Ziggurat algorithm covers the probability density function with a series of stacked horizontal rectangular layers (resembling a Mesopotamian ziggurat step pyramid) of equal volume. For over $98\%$ of samples, generating a Gaussian number requires only a single raw random integer, a bit shift, and an integer comparison—completely bypassing expensive floating-point functions.
- **Practical Application**:
  ```python
  import time
  import numpy as np

  N = 10_000_000
  rng = np.random.default_rng(42)

  # Modern Ziggurat algorithm:
  t0 = time.perf_counter()
  modern_samples = rng.standard_normal(N)
  t_modern = time.perf_counter() - t0

  # Legacy Box-Muller / Polar:
  t0 = time.perf_counter()
  legacy_samples = np.random.randn(N)
  t_legacy = time.perf_counter() - t0

  print(f"Modern Ziggurat: {t_modern:.4f}s | Legacy: {t_legacy:.4f}s ({t_legacy/t_modern:.2f}x faster)")
  ```
- **Nuances & Pitfalls**: Modern `rng.standard_normal()` is typically $2\times$ to $4\times$ faster than legacy `np.random.randn()` while providing superior statistical behavior in the distribution's extreme tails.

#### Question 24: What is modulo bias in integer random number generation, and how does `rng.integers()` prevent it?
- **Direct Definition & Core Concept**: Modulo bias occurs when uniform random bits from a finite integer space $[0, 2^B - 1]$ are mapped to a target range $[0, K)$ using the modulo operator `% K`, causing lower numbers to have a slightly higher probability of selection when $2^B$ is not evenly divisible by $K$.
- **Technical & Memory Mechanics**: Suppose a random generator produces numbers from $0$ to $255$ ($2^8 = 256$), and you map them to a 6-sided die ($K = 6$) via `val % 6`. $256 / 6 = 42.666$. The values $0, 1, 2, 3$ occur 43 times in the output space, while $4$ and $5$ occur only 42 times! This biases the die roll towards smaller numbers. Modern `rng.integers()` uses Lemire's exact rejection reduction method: it calculates the remainder of $2^B \pmod K$, and if a generated number falls within the incomplete final chunk, it rejects it and draws another bitstream, guaranteeing strictly uniform integer probabilities.
- **Practical Application**:
  ```python
  import numpy as np

  # rng.integers implements Lemire reduction with 0 modulo bias
  rng = np.random.default_rng(seed=42)
  rolls = rng.integers(1, 7, size=1_000_000)
  counts = np.bincount(rolls)[1:]
  print("Fair Die Proportions:", np.round(counts / len(rolls), 4))
  ```
- **Nuances & Pitfalls**: Legacy `np.random.randint()` had subtle modulo bias for ranges that did not divide powers of two. `rng.integers()` completely eliminates this bias.

#### Question 26: What is the Box-Muller transform and how did early NumPy use it?
- **Direct Definition & Core Concept**: The Box-Muller transform is a mathematical technique that transforms two independent uniform random variables $U_1, U_2 \sim \text{Uniform}(0, 1)$ into two independent standard normal variables $Z_0, Z_1 \sim \mathcal{N}(0, 1)$.
- **Technical & Memory Mechanics**: The transformation equations are:
  $$Z_0 = \sqrt{-2 \ln U_1} \cos(2\pi U_2)$$
  $$Z_1 = \sqrt{-2 \ln U_1} \sin(2\pi U_2)$$
  While mathematically elegant, computing square roots, natural logarithms, sines, and cosines requires significant CPU instruction cycles. Modern NumPy deprecated Box-Muller in favor of the Ziggurat algorithm in `default_rng()`, which evaluates Gaussian variates using integer table lookups.
- **Practical Application**:
  ```python
  import numpy as np

  def manual_box_muller(n_samples: int) -> np.ndarray:
      u1 = np.random.rand(n_samples)
      u2 = np.random.rand(n_samples)
      z0 = np.sqrt(-2.0 * np.log(u1)) * np.cos(2.0 * np.pi * u2)
      return z0

  samples = manual_box_muller(1000)
  print(f"Box-Muller Mean: {samples.mean():.3f}, Std: {samples.std():.3f}")
  ```
- **Nuances & Pitfalls**: If $U_1 = 0$, $\ln(0)$ evaluates to $-\infty$. Box-Muller implementations must clamp $U_1$ strictly above zero.

#### Question 30: How can you implement Stratified Sampling using NumPy random operations?
- **Direct Definition & Core Concept**: Stratified sampling ensures that subgroups (strata) of a population are represented proportionally in the sampled subset, maintaining exact class label balance.
- **Technical & Memory Mechanics**: Given class labels $y$, you iterate over each unique class $c$, extract the indices corresponding to that class using `np.where(y == c)[0]`, and sample a proportional number of indices from each subset without replacement using `rng.choice()`. The sampled indices are concatenated and shuffled.
- **Practical Application**:
  ```python
  import numpy as np

  def stratified_sample(y: np.ndarray, fraction: float, seed: int = 42) -> np.ndarray:
      rng = np.random.default_rng(seed)
      selected_indices = []
      
      for c in np.unique(y):
          class_indices = np.where(y == c)[0]
          sample_size = int(round(len(class_indices) * fraction))
          chosen = rng.choice(class_indices, size=sample_size, replace=False)
          selected_indices.append(chosen)
          
      all_idx = np.concatenate(selected_indices)
      return rng.permutation(all_idx) # Shuffle combined indices

  # Demonstration: Imbalanced dataset (90 Class 0, 10 Class 1)
  labels = np.array([0]*90 + [1]*10)
  stratified_idx = stratified_sample(labels, fraction=0.2)
  print("Sampled Label Distribution:", np.bincount(labels[stratified_idx])) # 18 of 0, 2 of 1
  ```
- **Nuances & Pitfalls**: Standard `rng.choice()` on the entire dataset will produce sample proportions that fluctuate statistically; stratified sampling guarantees exact class representation.

#### Question 35: How do you add random Gaussian noise to an image array for data augmentation?
- **Direct Definition & Core Concept**: Gaussian noise augmentation simulates sensor noise or grain by adding zero-mean Gaussian variates $\mathcal{N}(0, \sigma^2)$ to pixel values, followed by value clamping to the valid dynamic range.

  ```python
  import numpy as np

      # Cast to float to prevent uint8 overflow
      noisy = image.astype(np.float32) + rng.normal(0.0, sigma, size=image.shape)
      # Clamp to valid dynamic range and convert back
      return np.clip(noisy, 0, 255).astype(np.uint8)

  # Demonstration on synthetic 100x100x3 image
  clean_img = np.full((100, 100, 3), 128, dtype=np.uint8)
  augmented_img = add_gaussian_noise(clean_img, sigma=20.0)
  print("Clean pixel:", clean_img[0, 0, 0], "| Noisy pixel:", augmented_img[0, 0, 0])
  ```
- **Nuances & Pitfalls**: Forgetting to clamp with `np.clip` will cause pixel values $> 255$ to wrap around to small numbers during `uint8` conversion, creating severe visual distortion.

    ```python
            sampled_thetas = self.rng.beta(self.alpha, self.beta)
            return int(np.argmax(sampled_thetas))

            if reward == 1:
                self.alpha[arm] += 1
            else:
    ```

## 5. Mistakes to Avoid (10 Mistakes)

### 1. Assigning the Result of In-Place `shuffle()`
- **Mistake**: Writing `data = np.random.shuffle(data)`.
- **Why it happens**: Forgetting that Python in-place mutators return `None`.
- **Correct approach**: Call `np.random.shuffle(data)` without assignment, or use `data = np.random.permutation(data)`.
- **Example**:
  ```python
  # WRONG (data becomes None)
  data = np.random.shuffle(data)

  # RIGHT
  np.random.shuffle(data)
  ```

### 2. Shuffling Features and Labels Separately
- **Mistake**: Calling `rng.shuffle(X)` and then `rng.shuffle(y)`.
- **Why it happens**: Forgetting that each shuffle generates an independent random permutation.
- **Correct approach**: Generate a shared permutation index `idx = rng.permutation(len(X))` and slice `X[idx], y[idx]`.
- **Example**:
  ```python
  # WRONG (Desynchronizes labels)
  rng.shuffle(X)
  rng.shuffle(y)

  # RIGHT
  idx = rng.permutation(len(X))
  X, y = X[idx], y[idx]
  ```

### 3. Adding Gaussian Noise Directly to `uint8` Image Arrays
- **Mistake**: Adding float noise to an 8-bit image without casting.
- **Why it happens**: Forgetting that `uint8` overflows silently modulo 256.
- **Correct approach**: Cast image to `float32`, add noise, clip to $[0, 255]$, and cast back to `uint8`.
- **Example**:
  ```python
  # WRONG (Wraps 255 + 5 -> 4)
  # noisy = img_uint8 + noise

  # RIGHT
  noisy = np.clip(img_uint8.astype(np.float32) + noise, 0, 255).astype(np.uint8)
  ```

### 4. Passing a Shape Tuple to Legacy `rand()` or `randn()`
- **Mistake**: Calling `np.random.rand((3, 3))`.
- **Why it happens**: Expecting standard NumPy shape tuple syntax.
- **Correct approach**: Use unpacked arguments `np.random.rand(3, 3)` or modern `rng.random((3, 3))`.
- **Example**:
  ```python
  # WRONG (Raises TypeError)
  # arr = np.random.rand((3, 3))

  # RIGHT
  arr = rng.random((3, 3))
  ```

### 5. Assuming `np.random.seed()` Affects `default_rng()`
- **Mistake**: Calling `np.random.seed(42)` and expecting `rng = np.random.default_rng()` to be deterministic.
- **Why it happens**: Believing `seed()` sets global state for all NumPy RNGs.
- **Correct approach**: Pass the seed directly to the constructor: `np.random.default_rng(42)`.
- **Example**:
  ```python

  rng = np.random.default_rng()

  # RIGHT
  rng = np.random.default_rng(42)
  ```

### 6. Using `replace=False` with Sample Size Larger than Population
- **Mistake**: Calling `rng.choice(5, size=10, replace=False)`.
- **Why it happens**: Forgetting the pigeonhole principle.
- **Correct approach**: Set `replace=True`.
- **Example**:
  ```python

  # RIGHT

  ```

### 7. Non-Normalized Probability Weights in `choice()`
- **Mistake**: Passing raw integer counts or non-normalized weights to `p`.

- **Correct approach**: Normalize weights explicitly: `p = weights / weights.sum()`.

## 6. NumPy API Confusions (5 Confusions)

### Confusion 1: `np.random.seed()` vs `np.random.default_rng()`
- **API 1 (`np.random.seed`)**: Modifies a mutable global singleton PRNG state based on MT19937. Non-thread-safe.
- **API 2 (`np.random.default_rng`)**: Instantiates an isolated local `Generator` object based on PCG64. Fully thread-safe.
- **Key Difference**: Global side-effects vs local object encapsulation.
- **When to Use Which**: Never use `seed()` in modern code; always instantiate `default_rng(seed)`.
- **Code Comparison**:
  ```python
  import numpy as np

  # Legacy Global
  np.random.seed(42)
  val1 = np.random.rand()

  # Modern Local Object
  rng = np.random.default_rng(42)
  val2 = rng.random()
  ```

### Confusion 2: `np.random.shuffle()` vs `np.random.permutation()`
- **API 1 (`np.random.shuffle`)**: In-place mutation of the original array; returns `None`.
- **API 2 (`np.random.permutation`)**: Out-of-place shuffle; returns a brand new shuffled copy.
- **Key Difference**: In-place memory modification vs copy allocation.
- **When to Use Which**: Use `shuffle()` when memory is constrained and you want to mutate the buffer; use `permutation()` when the original array must be preserved or when generating index sequences from integer $N$.
- **Code Comparison**:
  ```python
  import numpy as np

  arr = np.array([1, 2, 3])
  np.random.shuffle(arr)      # arr is mutated, returns None
  copy_arr = np.random.permutation(arr) # arr unchanged, returns copy
  ```

### Confusion 3: `np.random.rand()` vs `np.random.randn()`
- **API 1 (`np.random.rand`)**: Continuous Uniform distribution in $[0.0, 1.0)$. All numbers non-negative.
- **API 2 (`np.random.randn`)**: Continuous Standard Normal distribution with $\mu=0, \sigma=1$. Zero-centered, positive and negative.
- **Key Difference**: Flat probability density vs bell-shaped Gaussian density.
- **When to Use Which**: Use `rand()` for probabilities and random sampling masks; use `randn()` for Gaussian noise, brownian motion, and neural network weights.
- **Code Comparison**:
  ```python
  import numpy as np

  u = np.random.rand(3)  # [0.41, 0.72, 0.01] (all >= 0)
  n = np.random.randn(3) # [-1.20, 0.45, -0.08] (centered at 0)
  ```

### Confusion 4: `rng.integers()` vs `np.random.randint()`
- **API 1 (`rng.integers`)**: Modern integer sampler. Supports `endpoint=True/False` and eliminates modulo bias via Lemire reduction.
- **API 2 (`np.random.randint`)**: Legacy integer sampler. Strictly half-open $[low, high)$ with subtle modulo bias on non-power-of-two ranges.
- **Key Difference**: Unbiased Lemire reduction vs legacy modulo division; endpoint control.
- **When to Use Which**: Always use `rng.integers()`.
- **Code Comparison**:
  ```python
  import numpy as np

  rng = np.random.default_rng()
  d1 = rng.integers(1, 6, endpoint=True) # Inclusive [1, 6]
  d2 = np.random.randint(1, 7)           # Exclusive [1, 7)
  ```

### Confusion 5: `rng.permutation()` vs `rng.permuted()`
- **API 1 (`rng.permutation`)**: Shuffles slices along axis 0 only, keeping internal slice elements intact.
- **API 2 (`rng.permuted`)**: Allows independent permutation of elements along *any* axis (e.g., shuffling columns within each row independently).
- **Key Difference**: Coarse row-level shuffling vs fine-grained independent element shuffling along arbitrary axes.
- **When to Use Which**: Use `permutation()` for dataset rows; use `permuted()` for scrambling features independently per sample.
- **Code Comparison**:
  ```python
  import numpy as np

  rng = np.random.default_rng(42)
  M = np.array([[1, 2], [3, 4]])
  p1 = rng.permutation(M)       # Swaps entire rows
  p2 = rng.permuted(M, axis=1)  # Shuffles columns within each row independently
  ```

### Question 2: Inverted Dropout Implementation in Custom PyTorch/NumPy Layers
- **Interview Question**: "When building deep neural network architectures from scratch, why is inverted dropout preferred over standard dropout, and how do you implement it efficiently using `default_rng()`?"
- **Answer**:
  - **Direct Definition & Core Concept**: Dropout randomly deactivates a fraction $p$ of neurons during training to prevent feature co-adaptation. Inverted dropout scales the retained activations by $\frac{1}{1 - p}$ during the training forward pass, ensuring that the expected activation magnitude remains invariant between training and inference ($\mathbb{E}[\text{train}] = \mathbb{E}[\text{eval}]$), requiring zero scaling operations at inference time.
  - **Technical & Memory Mechanics**: Generating a dropout mask requires evaluating Bernoulli random variables. In NumPy, calling `mask = rng.random(size) < (1.0 - p)` creates an optimized boolean array in a single C pass. Multiplying activations by this boolean mask deactivates units, and dividing by $(1.0 - p)$ scales the remaining activations in-place.
  - **Practical Implementation**:
    ```python
    import numpy as np

    class InvertedDropoutLayer:
        def __init__(self, drop_rate: float = 0.5, seed: int = None):
            self.drop_rate = drop_rate
            self.keep_rate = 1.0 - drop_rate
            self.rng = np.random.default_rng(seed)
            self.mask = None

        def forward(self, x: np.ndarray, training: bool = True) -> np.ndarray:
            if not training or self.drop_rate == 0.0:
                return x
            # Vectorized Bernoulli mask generation
            self.mask = (self.rng.random(x.shape, dtype=np.float32) < self.keep_rate)
            # Inverted scaling
            return (x * self.mask) / self.keep_rate

        def backward(self, grad_output: np.ndarray) -> np.ndarray:
            # Gradients flow only through active units
            return (grad_output * self.mask) / self.keep_rate
    ```
  - **Nuances & Pitfalls**: In standard (non-inverted) dropout, one must multiply activations by $(1 - p)$ during model inference. Inverted dropout eliminates this requirement, allowing raw model inference code to run without conditional branch checks.

### Question 3: Adversarial Synthetic Data Generation & Label Noise Injection
- **Interview Question**: "In robustness benchmarking for classification models, how do you inject controlled symmetric label noise (e.g., flipping $15\%$ of ground truth labels) across an imbalanced dataset of 100,000 samples using NumPy random functions?"
- **Answer**:
  - **Direct Definition & Core Concept**: Symmetric label noise corrupts supervised datasets by randomly replacing true class labels with incorrect alternatives, simulating annotator errors and evaluating classifier noise tolerance.
  - **Technical & Memory Mechanics**: First, draw a boolean corruption mask where each sample has probability $\eta$ of being corrupted: `corrupt_mask = rng.random(N) < noise_rate`. For corrupted samples, draw replacement labels from the remaining classes $\{0, 1, \dots, C-1\} \setminus \{y_i\}$. Rather than looping over individual samples, we sample integer offsets $k \in \{1, 2, \dots, C-1\}$ and compute the new label modulo $C$: $y_{\text{new}} = (y_{\text{orig}} + k) \pmod C$.
  - **Practical Implementation**:
    ```python
    import numpy as np

    def inject_symmetric_label_noise(y: np.ndarray, num_classes: int, noise_rate: float = 0.15, seed: int = 42) -> np.ndarray:
        rng = np.random.default_rng(seed)
        y_noisy = y.copy()
        n_samples = len(y)

        n_corrupted = np.sum(corrupt_mask)

        offsets = rng.integers(1, num_classes, size=n_corrupted)

        y_noisy[corrupt_mask] = (y[corrupt_mask] + offsets) % num_classes
        return y_noisy

    # Demonstration
    ```

### Question 4: Multi-Threaded Data Augmentation Pipeline in Computer Vision
- **Interview Question**: "When building a multi-worker PyTorch/NumPy data loader, why do PyTorch workers famously suffer from the 'duplicate augmentation bug' if worker seeds are not handled properly, and how do you resolve it using NumPy 1.20+?"
- **Answer**:
  - **Direct Definition & Core Concept**: PyTorch data loaders use Python `multiprocessing` with OS `fork`. When worker processes fork, they inherit the exact identical memory space of the parent process, including the global PRNG state of `np.random`.
  - **Technical & Memory Mechanics**: If data augmentation relies on legacy `np.random.*` calls, every single worker process executes transformations with the identical sequence of random numbers! Worker 0, Worker 1, Worker 2, and Worker 3 will apply the exact same crop offsets, rotation angles, and brightness noise to different images in the batch, destroying augmentation entropy.
  - **Practical Implementation**:
    ```python
    import numpy as np

    # PyTorch worker_init_fn best practice:
    def worker_init_fn(worker_id):
        # Base seed from PyTorch worker info
        initial_seed = np.random.get_state()[1][0] + worker_id
        # Modern SeedSequence creates independent stream for each worker
        ss = np.random.SeedSequence(initial_seed)
        # Store worker-local generator in global worker context
        global worker_rng
        worker_rng = np.random.default_rng(ss)

    # In transformation pipeline:
    def random_crop(img, crop_h, crop_w):
        # Use worker-local generator, NOT global np.random!
        top = worker_rng.integers(0, img.shape[0] - crop_h + 1)
        left = worker_rng.integers(0, img.shape[1] - crop_w + 1)
        return img[top:top+crop_h, left:left+crop_w]
    ```
  - **Nuances & Pitfalls**: Always configure PyTorch's `worker_init_fn` to initialize a modern `np.random.default_rng()` in each worker process to ensure independent augmentation paths.

### Question 5: Bootstrapped A/B Testing & Permutation Tests for Conversion Uplift
- **Interview Question**: "In an e-commerce platform evaluating a new checkout UI, Group A (Control) has 50,000 visitors with 2,500 conversions ($5.0\%$) and Group B (Treatment) has 50,000 visitors with 2,700 conversions ($5.4\%$). How do you implement a non-parametric permutation test in NumPy to compute the exact empirical p-value?"
- **Answer**:
  - **Direct Definition & Core Concept**: A two-sample permutation test evaluates the null hypothesis $H_0$ that Group A and Group B come from the identical underlying distribution. It pools all observations, repeatedly shuffles the group assignments, and measures how frequently the permuted conversion difference exceeds the observed difference.
  - **Technical & Memory Mechanics**: Concatenate both binary groups into a single pooled array of length $N = 100,000$. Under $H_0$, labels A and B are exchangeable. In each iteration, shuffle the pooled array (or sample without replacement) and compute $\Delta \bar{X}^* = \bar{X}_B^* - \bar{X}_A^*$. The empirical p-value is the fraction of resamples where $|\Delta \bar{X}^*| \ge |\Delta \bar{X}_{\text{obs}}|$.
  - **Practical Implementation**:
    ```python
    import numpy as np

    def two_sample_permutation_test(group_a, group_b, n_permutations=10000, seed=42):
        rng = np.random.default_rng(seed)
        obs_diff = np.mean(group_b) - np.mean(group_a)
        
        pooled = np.concatenate([group_a, group_b])
        n_a = len(group_a)
        n_total = len(pooled)
        
        diffs = np.empty(n_permutations, dtype=np.float64)
        for i in range(n_permutations):
            perm = rng.permutation(pooled)
            diffs[i] = np.mean(perm[n_a:]) - np.mean(perm[:n_a])
            
        p_value = np.mean(np.abs(diffs) >= np.abs(obs_diff))
        return obs_diff, p_value

    # Simulated checkout conversion data
    ctrl = np.array([1]*2500 + [0]*47500)
    treat = np.array([1]*2700 + [0]*47300)
    diff, p_val = two_sample_permutation_test(ctrl, treat, n_permutations=5000)
    print(f"Observed Uplift: +{diff*100:.2f}% | Permutation p-value: {p_val:.4f}")
    ```
  - **Nuances & Pitfalls**: Permutation tests are exact and non-parametric, requiring zero assumptions about normal distribution validity in conversion rates.

### Scenario 3: Temperature-Scaled Softmax Sampling
- **Code Snippet**:

  1. What mathematical operation is performed on line 6?
  2. What happens to `probs` if temperature $T \to 0$ vs $T \to \infty$?
  3. Identify a dangerous numerical instability on line 6.
  4. How should line 6 be refactored for production robustness?
- **Ideal Interview Answer**:
  - *Operation*: Line 6 computes the **Softmax probability distribution with temperature scaling $T$** over the vocabulary logits.
  - *Temperature Dynamics*: When $T \to 0$ (low temperature), the largest logit ($3.8$) dominates exponentially, making the distribution peak sharply (approaching greedy argmax).     exp_vals = np.exp(scaled - np.max(scaled)) # Numerically stable

## 15. Fresher Answer Patterns (4 Patterns)

### Pattern 1: Why should you use `default_rng()` instead of `np.random.seed()`?
- **Question**: "Why has NumPy deprecated the global `np.random.seed()` in favor of `np.random.default_rng()`?"
- **Weak Answer**: "`default_rng` is newer and faster, and `seed` is old."
- **Critique**: Fails to articulate the core architectural problems of global state, multi-threading race conditions, statistical flaws of Mersenne Twister, or BitGenerator decoupling.
- **Stronger Fresher Answer**:
  > "`np.random.seed()` configures a shared global singleton PRNG based on the legacy Mersenne Twister (MT19937) algorithm. This introduces two major engineering problems: first, modifying a global singleton causes hidden side-effects across imported libraries, unit test suites, and multi-threaded worker pools, leading to race conditions. Second, MT19937 fails modern statistical test batteries (like BigCrush) and generates Gaussian variates relatively slowly via Box-Muller transforms.
  >
  > In contrast, `np.random.default_rng()` instantiates an isolated, object-oriented `Generator` powered by the modern `PCG64` BitGenerator. It encapsulates its own 128-bit state register, ensuring thread safety and clean dependency injection. Furthermore, it generates normal variates significantly faster using the Ziggurat algorithm and eliminates modulo bias in integer sampling."

### Pattern 2: What is the difference between `rng.shuffle()` and `rng.permutation()`?
- **Question**: "What is the difference between `rng.shuffle()` and `rng.permutation()`, and when would you use each?"
- **Weak Answer**: "They both shuffle an array randomly."
- **Critique**: Completely ignores memory allocation, return values, in-place mutation, and integer sequence generation.
- **Stronger Fresher Answer**:
  > "The fundamental difference lies in memory mutation and return semantics.
  >
  > `rng.shuffle()` performs an **in-place mutation** of the array along its first axis (axis 0) and returns `None`. It operates directly on the underlying memory buffer without allocating new memory, which is ideal when working with large arrays under tight memory constraints. However, assigning its result to a variable (`arr = rng.shuffle(arr)`) is a classic bug that overwrites the array with `None`.
  >
  > In contrast, `rng.permutation()` leaves the original array untouched and returns a **brand new shuffled copy**. Additionally, if passed an integer scalar $N$, `rng.permutation(N)` returns a randomly shuffled array of integers from $0$ to $N-1$, which is the industry-standard idiom for shuffling dataset indices."

### Pattern 3: How do you shuffle a dataset $(X, y)$ without breaking label alignment?
- **Question**: "How do you shuffle a feature matrix $X$ and target vector $y$ in NumPy, and what mistake do beginners make?"
- **Weak Answer**: "You just call `shuffle(X)` and then `shuffle(y)`."
- **Critique**: Demonstrates a catastrophic lack of understanding that causes silent machine learning data corruption.
- **Stronger Fresher Answer**:
  > "Beginners often call `rng.shuffle(X)` followed by `rng.shuffle(y)`. This is a catastrophic bug because each call advances the PRNG state independently, applying two completely different random permutations. Sample $X_i$ ends up paired with an unrelated label $y_j$, destroying feature-label correspondence and causing models to train on pure noise.
  >
  > The correct approach is to generate a single shared permutation index array using `idx = rng.permutation(len(X))` and slice both arrays using that shared index: `X_shuffled, y_shuffled = X[idx], y[idx]`. This guarantees that every sample remains strictly synchronized with its ground truth label."

### Pattern 4: How does `rng.choice()` work with `replace=False` vs `replace=True`?
- **Question**: "When would you set `replace=False` vs `replace=True` in `rng.choice()`?"
- **Weak Answer**: "`replace=True` lets you pick items again, and `replace=False` doesn't."
- **Critique**: Lacks domain grounding in machine learning workflows, population limits, and statistical definitions.
- **Stronger Fresher Answer**:
  > "`rng.choice()` draws random samples from a population. The `replace` parameter governs whether selected elements are returned to the pool after each draw.
  >
  > We use **`replace=False` (sampling without replacement)** when unique elements are required. A prime real-world application is train/validation/test dataset splitting or lottery sampling, where a single sample cannot appear in multiple partitions. Under `replace=False`, the requested sample size cannot exceed the population size $N$.
  >
  > We use **`replace=True` (sampling with replacement)** when independent identically distributed (i.i.d.) draws are required. A classic application is **Bootstrap aggregation (bagging / Random Forests)**, where each bootstrap replica contains $N$ samples drawn with replacement, allowing duplicate samples to simulate empirical sampling variance. Here, sample size can be arbitrarily large."


## 16. Questions That Test Understanding (5 Questions)

### Question 1: Perturbation of Endpoint in Integer Random Sampling
- **Perturbation Scenario**: "Suppose you write `die = rng.integers(1, 6)`. What happens if you modify the call to `die = rng.integers(1, 6, endpoint=True)`? What are the possible output values and their theoretical probabilities in both cases?"
- **First Principles Analysis**:
  - `die = rng.integers(1, 6)`:
    - Default `endpoint=False`. The discrete uniform interval is half-open: $[1, 6)$.
    - The possible values are $\{1, 2, 3, 4, 5\}$. The number 6 is **never** generated.
    - Each of the 5 values has probability $P(X = k) = \frac{1}{5} = 20.0\%$.
  - `die = rng.integers(1, 6, endpoint=True)`:
    - The discrete uniform interval is closed: $[1, 6]$.
    - The possible values are $\{1, 2, 3, 4, 5, 6\}$.
    - Each of the 6 values has probability $P(X = k) = \frac{1}{6} \approx 16.67\%$.
- **Engineering Implication**: Omitting `endpoint=True` when simulating physical discrete systems (dice, days of week, lottery numbers) creates a silent off-by-one bug where the maximum boundary is never reachable.

---

### Question 2: Perturbation of Replacement in `rng.choice()`
- **Perturbation Scenario**: "Given an array `arr = np.array([1, 2, 3, 4, 5])`, what happens if you run `rng.choice(arr, size=5, replace=True)` vs `rng.choice(arr, size=5, replace=False)`? What happens if `size` is perturbed to `size=6` for both?"
- **First Principles Analysis**:
  - With `size=5, replace=True`:
    - Independent identically distributed draws. Duplicates are permitted.
    - The probability that all 5 draws are distinct is $\frac{5!}{5^5} = \frac{120}{3125} \approx 3.84\%$. In $\sim 96.16\%$ of runs, duplicates will appear.
  - With `size=5, replace=False`:
    - Sampling without replacement. Every draw removes an item.
    - The output is guaranteed to contain all 5 unique elements in random order (a random permutation of `arr`).
  - When `size=6`:
    - `replace=True`: Sizing to 6 succeeds normally, drawing 6 elements with duplicates.
    - `replace=False`: Raises a fatal `ValueError: Cannot take a larger sample than population when 'replace=False'`.
- **Engineering Implication**: Sizing rules are fundamentally tied to replacement semantics. Bootstrap resamples require `replace=True`; permutation and cross-validation splits require `replace=False`.

---

### Question 3: Perturbation of Axis in 2D Array Shuffling
- **Perturbation Scenario**: "Suppose `M = np.arange(9).reshape(3, 3)`. What happens when you run `rng.shuffle(M)` vs `rng.permuted(M, axis=1)`?"
- **First Principles Analysis**:
  - `rng.shuffle(M)`:
    - Shuffles strictly along axis 0 in-place.
    - Entire rows are swapped as atomic units (e.g., row 0 may become row 2).
    - The internal column relationship within any row is preserved (e.g., row `[0, 1, 2]` remains `[0, 1, 2]`).
  - `rng.permuted(M, axis=1)`:
    - Permutes elements along axis 1 (across columns) **independently for each row**.
    - Row 0 might be reordered to `[1, 0, 2]`, while Row 1 might be reordered to `[5, 3, 4]`.
    - Rows stay in their vertical positions, but their internal column contents are independently scrambled.
- **Engineering Implication**: `shuffle()` preserves intra-row feature correlations while reordering samples; `permuted(axis=1)` destroys intra-row feature correlations while preserving sample row positions (used in feature importance permutation testing).

### Question 4: Perturbation of Generator State via Sub-Process Forking
- **Perturbation Scenario**: "You set `np.random.seed(42)` in a main script and spawn 4 worker processes using `multiprocessing.Pool()`. What happens to the random numbers generated inside the workers? How does changing to `SeedSequence.spawn(4)` alter this?"
- **First Principles Analysis**:
  - With legacy `np.random.seed(42)` and `multiprocessing.Pool`:
    - OS `fork` clones the parent process memory, including the internal state vector of MT19937.
    - All 4 worker processes inherit the exact identical seed and state registers.
    - Each worker generates the identical sequence of numbers, resulting in 4 redundant duplicate runs.
  - With modern `SeedSequence.spawn(4)`:
    - A cryptographic hash function (SplitMix64) algorithmically generates 4 non-overlapping, orthogonal 128-bit initial states.

### 3. Linear Algebra & Mathematics
- **Question**: "In randomized numerical linear algebra (RandNLA), how are random Gaussian matrices generated by `rng.standard_normal()` used to compute low-rank matrix approximations (Randomized SVD)?"
- **Answer**:
  - Given a massive matrix $A \in \mathbb{R}^{M \times N}$, exact SVD has $O(M N^2)$ complexity.
  - Randomized SVD reduces this complexity by projecting $A$ onto a random low-dimensional subspace of rank $K \ll \min(M, N)$.
  - We generate a Gaussian random projection matrix $\Omega \in \mathbb{R}^{N \times K}$ using `rng.standard_normal((N, K))`.
  - We form sample matrix $Y = A \Omega \in \mathbb{R}^{M \times K}$, compute its QR decomposition $Y = Q R$ to obtain an orthonormal basis $Q$, and project $A$ into lower dimensional space: $B = Q^T A \in \mathbb{R}^{K \times N}$.
  - Computing exact SVD on the tiny matrix $B$ yields near-exact singular values in a fraction of the compute time.

## 24. Final Revision Summary

### Core Concepts at a Glance
- **Modern Architecture**: Always use `rng = np.random.default_rng(seed)`. Decouples `BitGenerator` (PCG64) from `Generator` statistical distributions.
- **Uniform vs Normal**: `rng.uniform(low, high)` for flat distributions; `rng.standard_normal()` for $\mathcal{N}(0, 1)$ via the fast Ziggurat algorithm.
- **In-Place vs Copy**: `rng.shuffle()` mutates in-place (returns `None`); `rng.permutation()` returns a new shuffled copy (or permutes $0..N-1$).
- **Replacement Semantics**: `replace=True` for independent bootstrap draws (duplicates allowed); `replace=False` for unique subsets (train/test splits).
- **Parallel Safety**: Use `SeedSequence.spawn(n_workers)` to eliminate PRNG collisions across multi-threaded or multi-process pools.

### Essential APIs Quick Reference
| Function | Distribution / Purpose | Crucial Parameter | Key Gotcha |
| :--- | :--- | :--- | :--- |
| `rng.random` | Uniform $[0, 1)$ | `size` | Standard shape tuple; NOT unpacked arguments |
| `rng.standard_normal` | Normal $\mathcal{N}(0, 1)$ | `size` | Scale by $\sigma$ and add $\mu$ for general normal |
| `rng.normal` | Normal $\mathcal{N}(\mu, \sigma^2)$ | `scale` | `scale` is standard deviation, NOT variance |
| `rng.integers`| Discrete Uniform | `endpoint` | Default `endpoint=False` excludes high |
| `rng.choice` | Categorical / Permutation | `replace` | Sizing cannot exceed population if `replace=False` |
| `rng.shuffle` | In-place Permutation | `axis=0` | Modifies array in-place and returns `None` |
| `rng.permutation`| Out-of-place Permutation | Input array / int | Passing integer $N$ returns permuted range $0..N-1$ |

### Top 5 Traps to Dodge
1. **Never assign the result of `rng.shuffle()`**: Overwrites array with `None`.
2. **Never shuffle $X$ and $y$ separately**: Destroys feature-label correspondence; shuffle shared permutation indices.
3. **Never add Gaussian noise directly to `uint8`**: Silent integer overflow wrap-around; cast, add, clip, and cast back.
4. **Never rely on `np.random.seed()` in multi-processing**: Causes duplicate streams; use `SeedSequence.spawn()`.
5. **Never use `np.random` for cryptography**: Non-cryptographic PRNG; use Python's `secrets` module for security tokens.
