# Section: 8.4 Splitting Arrays

## 1. Section Overview
In machine learning data pipelines, distributed computing, and computer vision, dividing large multidimensional arrays into smaller sub-arrays is as critical as joining them. Whether partitioning a feature matrix into training, validation, and test sets, implementing $K$-Fold cross-validation folds, decoupling fused transformer linear projections ($Q, K, V$), cropping high-resolution satellite imagery into uniform tiles, or separating multi-channel audio tracks, NumPy provides specialized splitting primitives: `np.split`, `np.array_split`, `np.vsplit`, `np.hsplit`, and `np.dsplit`.

A profound architectural property of NumPy\'s splitting functions is that they **return views whenever possible**. Unlike concatenation (which unconditionally allocates new memory and executes data copies), splitting an array along an axis simply creates sub-array descriptors that slice the original memory buffer with updated offsets and shapes. However, this zero-copy view mechanic introduces subtle memory management traps: retaining a single small slice from a 10 GB parent array keeps the entire 10 GB buffer pinned in memory, preventing garbage collection. Understanding the mathematical constraints of equal vs. unequal division, axis indexing rules, memory pinning behaviors, and slice view mechanics is essential for writing production-grade numerical software.

```
NUMPY SPLITTING TAXONOMY & DIVISION MECHANICS:

1. np.split(ary, indices_or_sections, axis=0):
   - Equal division or explicit boundary indices.
   - If integer N is passed, N MUST divide len(axis) EQUALLY.
   - Raises ValueError if division is not equal.
   - Returns list of VIEW sub-arrays.

2. np.array_split(ary, indices_or_sections, axis=0):
   - Tolerates UNEQUAL division!
   - For length L and N sections: first (L % N) sub-arrays have size (L // N + 1),
     remaining sub-arrays have size (L // N).
   - Never raises ValueError on non-divisible integers.

3. Dimensional Shorthands:
   - np.vsplit(ary, ...): Vertical split (axis 0). Requires ndim >= 2.
   - np.hsplit(ary, ...): Horizontal split. Axis 0 for 1D, axis 1 for 2D+.
   - np.dsplit(ary, ...): Depth split (axis 2). Requires ndim >= 3.
```

## 2. Comprehensive Core Concept Reference & Deep Exploration

### Mathematical and Partitioning Mechanics
Given an array $A$ with shape $(s_0, s_1, \dots, s_{D-1})$ split along axis $k \in [0, D-1]$ of length $L = s_k$:

1. **Integer Section Splitting ($N$ Sections)**:
   - For `np.split`, $L \pmod N \equiv 0$. Each sub-array has length $s_k\' = \frac{L}{N}$.
   - For `np.array_split`, let $q = \lfloor L / N \rfloor$ and $r = L \pmod N$.
     - The first $r$ sub-arrays have length $q + 1$.
     - The remaining $N - r$ sub-arrays have length $q$.
     - Example: Splitting length 10 into 3 sections yields sub-array lengths $[4, 3, 3]$ ($10 = 4 + 3 + 3$).

2. **1D Sequence Index Splitting (`indices = [i_0, i_1, ..., i_{M-1}]`)**:
   Splits into $M + 1$ sub-arrays defined by half-open slice intervals:
   $$A[:i_0], \quad A[i_0:i_1], \quad A[i_1:i_2], \quad \dots, \quad A[i_{M-1}:]$$
   If an index exceeds $L$, an empty sub-array is returned for that slice.

### Memory Layout and Zero-Copy View Mechanics
```
Original Array A (Buffer at 0x1000, shape=(6, 4), strides=(16, 4), float32):
[Row 0: 0x1000] [Row 1: 0x1010] [Row 2: 0x1020] [Row 3: 0x1030] [Row 4: 0x1040] [Row 5: 0x1050]

sub1, sub2 = np.split(A, 2, axis=0)

sub1 Descriptor:
- data pointer: 0x1000
- shape: (3, 4)
- strides: (16, 4)
- base: points to A (0x1000)

sub2 Descriptor:
- data pointer: 0x1030 (0x1000 + 3 * 16 bytes)
- shape: (3, 4)
- strides: (16, 4)
- base: points to A (0x1000)

ZERO BYTES OF NUMERIC DATA ALLOCATED OR COPIED!
```

### Splitting Function Comparison Table

| Function | Target Axis | Dimensionality Constraint | Unequal Integer Division | Output Type |
|---|---|---|---|---|
| `np.split` | Arbitrary `axis` | Any ($ndim \ge 1$) | **Raises `ValueError`** | List of views |
| `np.array_split` | Arbitrary `axis` | Any ($ndim \ge 1$) | **Allowed** ($L \% N$ balanced) | List of views |
| `np.vsplit` | Axis 0 (rows) | Requires $ndim \ge 2$ | Raises `ValueError` | List of views |
| `np.hsplit` | Axis 1 (2D+) or Axis 0 (1D)| Requires $ndim \ge 1$ | Raises `ValueError` | List of views |
| `np.dsplit` | Axis 2 (depth) | Requires $ndim \ge 3$ | Raises `ValueError` | List of views |

## 3. Comprehensive Multi-Category Interview Question Bank

### 3.A Theoretical & Foundational (Q1–Q20)

#### Q1: What is the primary functional difference between `np.split` and `np.array_split`?
- **Definition & Theoretical Intuition**: `np.split` strictly demands equal division when given an integer number of sections $N$. If the dimension length $L$ along the split axis is not evenly divisible by $N$ ($L \pmod N \neq 0$), `np.split` raises a `ValueError`. In contrast, `np.array_split` permits unequal division, distributing remainder elements evenly among the leading sub-arrays without error.
- **Technical & Memory Mechanics**: For length $L$ and sections $N$, `array_split` calculates integer quotient $q = L // N$ and remainder $r = L \% N$. The first $r$ partitions receive $q + 1$ elements, and the remaining $N - r$ partitions receive $q$ elements.
- **Self-Contained Code Snippet**:
```python
import numpy as np

arr = np.arange(10) # Length 10

# np.split fails because 10 is not divisible by 3:
try:
    np.split(arr, 3)
except ValueError as e:
    print(f"np.split failed as expected: {e}")

# np.array_split succeeds, producing sub-arrays of lengths 4, 3, 3:
splits = np.array_split(arr, 3)
print(f"array_split lengths: {[len(s) for s in splits]}")
print(f"Sub-arrays: {splits}")
```
- **Edge Cases, Pitfalls & Nuances**: When passing a list of boundary indices (e.g. `[3, 7]`) rather than an integer count, both `split` and `array_split` behave identically.

#### Q2: Do `np.split` and `np.array_split` return views or copies of the original array?
- **Definition & Theoretical Intuition**: They return **views**. Each sub-array in the returned list is a lightweight ndarray wrapper pointing directly into the parent array\'s existing physical memory buffer.
- **Technical & Memory Mechanics**: For each partition, NumPy calculates the byte offset from the parent data pointer: $offset = \sum start_k \cdot Stride_k$. It initializes a new `PyArrayObject` with `data = parent->data + offset`, `shape = sub_shape`, `strides = parent->strides`, and `base = parent`. No numeric buffer allocation occurs ($O(1)$ space).
- **Self-Contained Code Snippet**:
```python
import numpy as np

orig = np.array([10, 20, 30, 40])
s1, s2 = np.split(orig, 2)

print(f"s1 shares memory with orig: {np.shares_memory(orig, s1)}")
print(f"s1.base is orig:            {s1.base is orig}")

# Mutating sub-array mutates parent array!
s1[0] = 999
print(f"orig after mutating s1[0]:  {orig}")
assert orig[0] == 999
```
- **Edge Cases, Pitfalls & Nuances**: Modifying any sub-array directly mutates the parent array. If independence is required, call `.copy()` explicitly on each sub-array.

#### Q3: What is the memory leak / memory pinning risk associated with keeping sub-arrays from `np.split`?
- **Definition & Theoretical Intuition**: Because sub-arrays are views, their `.base` attribute holds a reference to the parent array. As long as a single small sub-array remains referenced in Python, the garbage collector cannot deallocate the parent array\'s entire memory buffer.
- **Technical & Memory Mechanics**: If you load a 10 GB dataset into memory, split it, and retain only a 1 MB sub-array, the entire 10 GB physical memory allocation remains pinned in RAM.
- **Self-Contained Code Snippet**:
```python
import numpy as np

def extract_small_chunk():
    # Allocate 80 MB parent array
    large_parent = np.ones((10000, 1000), dtype=np.float64)
    # Split into 10 chunks of 8 MB each
    chunks = np.split(large_parent, 10)
    # Return only the first chunk
    return chunks[0]

kept_chunk = extract_small_chunk()
print(f"kept_chunk size:   {kept_chunk.nbytes / 1e6:.1f} MB")
print(f"Pinned parent size: {kept_chunk.base.nbytes / 1e6:.1f} MB")
assert kept_chunk.base is not None
```
- **Edge Cases, Pitfalls & Nuances**: To safely release the parent buffer, decouple the sub-array using `.copy()`: `return chunks[0].copy()`. Once copied, `kept_chunk.base` becomes `None`, allowing the 80 MB parent to be freed immediately.

#### Q4: How does `indices_or_sections` interpret a 1D sequence of integers?
- **Definition & Theoretical Intuition**: When `indices_or_sections` is a sequence of integers $[i_0, i_1, \dots, i_{M-1}]$, the integers represent explicit split boundaries along the chosen axis. The array is sliced into $M + 1$ sub-arrays.
- **Technical & Memory Mechanics**: The resulting sub-arrays correspond exactly to Python slice ranges:
  $$arr[:i_0], \quad arr[i_0:i_1], \quad arr[i_1:i_2], \quad \dots, \quad arr[i_{M-1}:]$$
- **Self-Contained Code Snippet**:
```python
import numpy as np

data = np.arange(10)
# Split boundaries at index 2, 5, 8
sub_arrays = np.split(data, [2, 5, 8])

for idx, sub in enumerate(sub_arrays):
    print(f"Section {idx}: {sub}")

assert len(sub_arrays) == 4
assert np.array_equal(sub_arrays[0], data[:2])
assert np.array_equal(sub_arrays[1], data[2:5])
assert np.array_equal(sub_arrays[2], data[5:8])
assert np.array_equal(sub_arrays[3], data[8:])
```
- **Edge Cases, Pitfalls & Nuances**: The boundary list does not need to partition the array symmetrically. However, if indices are not sorted in ascending order, empty sub-arrays may be produced (e.g. slice `data[5:2]` produces an empty slice).

#### Q5: What happens if an index in `indices_or_sections` exceeds the dimension length?
- **Definition & Theoretical Intuition**: If a split index is greater than or equal to the length of the axis, NumPy does NOT raise an `IndexError`. Instead, it returns an empty sub-array (`size == 0`) for slices that begin beyond the array boundary.
- **Technical & Memory Mechanics**: Python slice semantics dictate that slicing beyond array length (e.g. `arr[10:15]` when `len(arr) == 6`) produces an empty array with matching secondary dimensions and length 0 along the sliced axis.
- **Self-Contained Code Snippet**:
```python
import numpy as np

arr = np.arange(5) # Length 5
sub_arrays = np.split(arr, [2, 10])

print(f"Number of sub-arrays: {len(sub_arrays)}")
print(f"Sub-array 0: {sub_arrays[0]} (shape: {sub_arrays[0].shape})")
print(f"Sub-array 1: {sub_arrays[1]} (shape: {sub_arrays[1].shape})")
print(f"Sub-array 2: {sub_arrays[2]} (shape: {sub_arrays[2].shape})")
assert sub_arrays[2].size == 0
```
- **Edge Cases, Pitfalls & Nuances**: Empty sub-arrays still retain their view relationship (`base is arr`) and dimensionality ($ndim$).

#### Q6: How does `np.vsplit` behave and what is its dimensionality requirement?
- **Definition & Theoretical Intuition**: `np.vsplit` splits an array vertically (row-wise), which is equivalent to `np.split(ary, indices_or_sections, axis=0)`. It requires the array to have at least two dimensions ($ndim \ge 2$).
- **Technical & Memory Mechanics**: If `ary.ndim < 2`, `vsplit` raises `ValueError: vsplit only works on arrays of 2 or more dimensions`. For 2D matrices, it divides rows among the output sub-arrays.
- **Self-Contained Code Snippet**:
```python
import numpy as np

mat = np.arange(12).reshape(6, 2)
# Split 6 rows into 3 groups of 2 rows each
top, mid, bot = np.vsplit(mat, 3)

print(f"Top shape: {top.shape}")
print(f"Mid shape: {mid.shape}")
print(f"Bot shape: {bot.shape}")
assert top.shape == (2, 2)
```
- **Edge Cases, Pitfalls & Nuances**: Never call `vsplit` on a 1D vector of shape `(N,)`. For 1D arrays, use `np.split(vec, ...)` or `np.hsplit(vec, ...)`.

#### Q7: How does `np.hsplit` handle 1-dimensional vs 2-dimensional arrays?
- **Definition & Theoretical Intuition**: For 1D arrays, `np.hsplit` splits along axis 0. For 2D or higher-dimensional arrays, `np.hsplit` splits along axis 1 (column-wise).
- **Technical & Memory Mechanics**: For a 2D matrix of shape `(H, W)`, `hsplit` partitions columns, equivalent to `np.split(ary, ..., axis=1)`. For 1D arrays of shape `(N,)`, it partitions elements along axis 0.
- **Self-Contained Code Snippet**:
```python
import numpy as np

# 1D Array handling
vec_1d = np.arange(6)
h_1d = np.hsplit(vec_1d, 2)
print(f"1D hsplit sub-shapes: {[s.shape for s in h_1d]}")

# 2D Array handling
mat_2d = np.arange(12).reshape(3, 4)
h_2d = np.hsplit(mat_2d, 2)
print(f"2D hsplit sub-shapes: {[s.shape for s in h_2d]}")
assert h_2d[0].shape == (3, 2)
```
- **Edge Cases, Pitfalls & Nuances**: This polymorphic behavior matches `np.hstack`, but can cause confusion if developers expect `hsplit` to strictly target axis 1.

#### Q8: What does `np.dsplit` do and what are its dimensional constraints?
- **Definition & Theoretical Intuition**: `np.dsplit` splits an array along the 3rd dimension ("depth" or axis 2). It requires the array to have at least three dimensions ($ndim \ge 3$).
- **Technical & Memory Mechanics**: Calling `dsplit` on arrays with $ndim < 3$ raises `ValueError: dsplit only works on arrays of 3 or more dimensions`. In computer vision, it is commonly used to separate RGB images into individual R, G, and B color planes.
- **Self-Contained Code Snippet**:
```python
import numpy as np

# 3D RGB image tensor (Height=10, Width=10, Channels=3)
rgb_tensor = np.random.randint(0, 256, (10, 10, 3), dtype=np.uint8)

# Split depth channels into individual planes:
r_plane, g_plane, b_plane = np.dsplit(rgb_tensor, 3)

print(f"R plane shape: {r_plane.shape} (Expected: (10, 10, 1))")
print(f"G plane shape: {g_plane.shape} (Expected: (10, 10, 1))")
print(f"B plane shape: {b_plane.shape} (Expected: (10, 10, 1))")
```
- **Edge Cases, Pitfalls & Nuances**: Notice that `r_plane` retains shape `(10, 10, 1)` rather than `(10, 10)`. To drop the singleton depth dimension, apply `.squeeze(axis=2)`.

#### Q9: What is the computational time and space complexity of `np.split` and `np.array_split`?
- **Definition & Theoretical Intuition**: The time complexity of splitting an array into $K$ sections is strictly $O(K)$, completely independent of the total element count $N$ in the array. The space complexity is $O(K)$ for the list of $K$ lightweight Python view objects.
- **Technical & Memory Mechanics**: Because splitting creates strided slice views, no numeric data is copied or moved in RAM. The function simply allocates $K$ small `PyArrayObject` C-structures (~96 bytes each) pointing into offsets of the existing buffer.
- **Self-Contained Code Snippet**:
```python
import numpy as np
import time

# Giant 1 GB array (125 million float64s)
giant = np.ones((10000, 12500), dtype=np.float64)

t0 = time.perf_counter()
chunks = np.split(giant, 10, axis=0)
elapsed = time.perf_counter() - t0

print(f"Time to split 1 GB array into 10 chunks: {elapsed * 1e6:.2f} microseconds")
print(f"Chunks are views: {all(c.base is giant for c in chunks)}")
```
- **Edge Cases, Pitfalls & Nuances**: Even for multi-gigabyte tensors, splitting is practically instantaneous ($< 10$ microseconds).

#### Q10: How does `np.split` handle negative axis indices?
- **Definition & Theoretical Intuition**: Negative integers count backward from `-1` (the trailing axis) to `-ndim` (the leading axis).
- **Technical & Memory Mechanics**: NumPy normalizes negative axis arguments using $axis = axis + ndim$. An axis of `-1` on a 2D array splits along columns (axis 1); on a 3D tensor, it splits along depth (axis 2).
- **Self-Contained Code Snippet**:
```python
import numpy as np

mat = np.arange(12).reshape(3, 4)

# Split along trailing axis (-1 == axis 1):
c1, c2 = np.split(mat, 2, axis=-1)

print(f"c1 shape: {c1.shape} (Expected: (3, 2))")
print(f"c2 shape: {c2.shape} (Expected: (3, 2))")
```
- **Edge Cases, Pitfalls & Nuances**: Passing `axis < -ndim` or `axis >= ndim` raises `np.exceptions.AxisError`.

#### Q11: What happens when splitting an array with 0 elements or empty dimensions?
- **Definition & Theoretical Intuition**: Splitting an empty array (e.g. shape `(0, 4)`) along axis 0 into $N$ sections is valid ONLY if $0 \pmod N == 0$, which evaluates to $N$ empty sub-arrays of shape `(0, 4)`.
- **Technical & Memory Mechanics**: In `np.split(np.empty((0, 4)), 2, axis=0)`, dimension length 0 is divisible by 2 ($0 / 2 = 0$). NumPy returns 2 sub-arrays of shape `(0, 4)`.
- **Self-Contained Code Snippet**:
```python
import numpy as np

empty_arr = np.empty((0, 4))
splits = np.split(empty_arr, 2, axis=0)

print(f"Number of splits: {len(splits)}")
print(f"Split shapes: {[s.shape for s in splits]}")
assert all(s.size == 0 for s in splits)
```
- **Edge Cases, Pitfalls & Nuances**: In `array_split`, splitting `np.empty((0, 4))` into 3 sections yields 3 sub-arrays of shape `(0, 4)` without error.

#### Q12: Can you split a 0-dimensional scalar array?
- **Definition & Theoretical Intuition**: No. A 0D scalar array has 0 axes ($ndim == 0$). Attempting to split a scalar raises `ValueError: zero-dimensional array cannot be split`.
- **Technical & Memory Mechanics**: Splitting requires an axis along which to partition. Since shape is `()`, no valid axis index exists.
- **Self-Contained Code Snippet**:
```python
import numpy as np

scalar = np.array(42)
try:
    np.split(scalar, 2)
except ValueError as e:
    print(f"Caught expected ValueError: {e}")
```
- **Edge Cases, Pitfalls & Nuances**: To partition a scalar, expand its dimensions first to a 1D vector `np.array([42])`.

#### Q13: What happens when passing an empty list of split indices (`indices_or_sections = []`)?
- **Definition & Theoretical Intuition**: Passing an empty list `[]` as boundary indices specifies zero split points. NumPy returns a single sub-array containing the entire original array: `[arr[:]]`.
- **Technical & Memory Mechanics**: With no boundary points, the slice interval is from beginning to end ($arr[:]$).
- **Self-Contained Code Snippet**:
```python
import numpy as np

data = np.arange(5)
res = np.split(data, [])

print(f"Number of returned sub-arrays: {len(res)}")
print(f"Returned content: {res[0]}")
assert len(res) == 1
assert res[0].base is data
```
- **Edge Cases, Pitfalls & Nuances**: This acts as an identity operation that returns a 1-element list containing a view of the original array.

#### Q14: How does `np.split` behave with non-contiguous (strided) input arrays?
- **Definition & Theoretical Intuition**: Splitting operates purely on strided descriptors. Non-contiguous arrays (e.g. transposed matrices or strided slices) can be split just as easily as contiguous arrays.
- **Technical & Memory Mechanics**: The sub-arrays inherit the input\'s strides and non-contiguous flags. Each sub-array\'s base pointer is calculated using the input\'s strided offsets.
- **Self-Contained Code Snippet**:
```python
import numpy as np

# Non-contiguous transposed matrix
mat = np.arange(20).reshape(4, 5).T # Shape (5, 4), F-contiguous
assert not mat.flags.c_contiguous

s1, s2 = np.split(mat, [2], axis=0)
print(f"s1 shape: {s1.shape}, strides: {s1.strides}")
print(f"s2 shape: {s2.shape}, strides: {s2.strides}")
print(f"s1 is view: {s1.base is mat.base}")
```
- **Edge Cases, Pitfalls & Nuances**: Sub-arrays created from non-contiguous parents remain non-contiguous.

#### Q15: How do you split a 2D array into a 2D grid of sub-matrices (quadrants/tiles)?
- **Definition & Theoretical Intuition**: A 2D grid split (e.g. splitting a $4 \times 4$ matrix into four $2 \times 2$ quadrants) is achieved by chaining `vsplit` and `hsplit`.
- **Technical & Memory Mechanics**: First, `vsplit(mat, 2)` cuts the matrix into top and bottom halves (shape $2 \times 4$ each). Then, applying `hsplit(half, 2)` to each half cuts columns, producing four $2 \times 2$ quadrant views.
- **Self-Contained Code Snippet**:
```python
import numpy as np

grid = np.arange(16).reshape(4, 4)

# Step 1: Vertical split into top and bottom
top, bottom = np.vsplit(grid, 2)

# Step 2: Horizontal split on each half
q1, q2 = np.hsplit(top, 2)
q3, q4 = np.hsplit(bottom, 2)

print(f"Quadrant 1 (Top-Left):\n{q1}")
print(f"Quadrant 2 (Top-Right):\n{q2}")
print(f"Quadrant 3 (Bottom-Left):\n{q3}")
print(f"Quadrant 4 (Bottom-Right):\n{q4}")
```
- **Edge Cases, Pitfalls & Nuances**: All four quadrant arrays are views sharing memory with the original $4 \times 4$ matrix.

#### Q16: What happens when boundary indices in `indices_or_sections` are unsorted?
- **Definition & Theoretical Intuition**: If indices are not in ascending order (e.g. `[5, 2]`), NumPy executes slices according to the given numbers: `arr[:5]`, `arr[5:2]`, `arr[2:]`.
- **Technical & Memory Mechanics**: In Python slicing, a forward slice with $start > stop$ and positive step (like `arr[5:2]`) produces an empty array of length 0.
- **Self-Contained Code Snippet**:
```python
import numpy as np

arr = np.arange(10)
sub_arrays = np.split(arr, [5, 2])

print(f"Sub-array 0 (arr[:5]): {sub_arrays[0]}")
print(f"Sub-array 1 (arr[5:2]): {sub_arrays[1]} (EMPTY!)")
print(f"Sub-array 2 (arr[2:]): {sub_arrays[2]}")
assert sub_arrays[1].size == 0
```
- **Edge Cases, Pitfalls & Nuances**: Always sort boundary index lists with `sorted(indices)` prior to splitting unless empty slices are intentionally desired.

#### Q17: What is the behavior of passing negative indices in `indices_or_sections`?
- **Definition & Theoretical Intuition**: Negative integers in an index sequence count backward from the end of the array, exactly following Python slice conventions.
- **Technical & Memory Mechanics**: For length $N$, passing `[-2]` evaluates to slice `arr[:-2]` and `arr[-2:]`.
- **Self-Contained Code Snippet**:
```python
import numpy as np

data = np.arange(10)
# Split at 2 elements from the end:
head, tail = np.split(data, [-2])

print(f"Head: {head} (length {len(head)})")
print(f"Tail: {tail} (length {len(tail)})")
assert np.array_equal(tail, [8, 9])
```
- **Edge Cases, Pitfalls & Nuances**: Splitting at `[-1]` is the standard idiom for separating feature columns $X$ from label column $y$ in tabular matrices: `X, y = np.split(dataset, [-1], axis=1)`.

#### Q18: How does `np.array_split` partition remainder elements across chunks?
- **Definition & Theoretical Intuition**: `array_split` implements a balanced partition algorithm that guarantees no chunk differs in size by more than 1 element from any other chunk ($|size_i - size_j| \le 1$).
- **Technical & Memory Mechanics**: Given length $L$ and sections $N$, let $q = L // N$ and $r = L \% N$. The first $r$ chunks get length $q + 1$; the remaining $N - r$ chunks get length $q$.
- **Self-Contained Code Snippet**:
```python
import numpy as np

# Length 14 into 4 chunks: 14 // 4 = 3, remainder = 2
# Expected chunk sizes: 4, 4, 3, 3 (4 + 4 + 3 + 3 = 14)
arr = np.arange(14)
chunks = np.array_split(arr, 4)

lengths = [len(c) for c in chunks]
print(f"Chunk lengths: {lengths}")
assert lengths == [4, 4, 3, 3]
```
- **Edge Cases, Pitfalls & Nuances**: The remainder elements are always placed in the *leading* sub-arrays, never the trailing ones.

#### Q19: What happens if `indices_or_sections` specifies more sections than the array length?
- **Definition & Theoretical Intuition**: In `np.array_split`, asking for $N > L$ sections produces $L$ sub-arrays of length 1, followed by $N - L$ empty sub-arrays of length 0.
- **Technical & Memory Mechanics**: The quotient $q = 0$ and remainder $r = L$. The first $L$ sub-arrays get $0 + 1 = 1$ element, and the remaining $N - L$ sub-arrays get $0$ elements.
- **Self-Contained Code Snippet**:
```python
import numpy as np

arr = np.arange(3) # Length 3
chunks = np.array_split(arr, 5) # 5 sections requested

print(f"Number of chunks returned: {len(chunks)}")
print(f"Chunk shapes: {[c.shape for c in chunks]}")
print(f"Chunks: {chunks}")
assert chunks[3].size == 0 and chunks[4].size == 0
```
- **Edge Cases, Pitfalls & Nuances**: In contrast, `np.split(arr, 5)` would immediately raise `ValueError: array split does not result in an equal division`.

#### Q20: Can masked arrays (`np.ma.MaskedArray`) be split with `np.split`?
- **Definition & Theoretical Intuition**: Yes. When a masked array is split, each sub-array in the returned list is also a `MaskedArray` view that correctly references slices of both the data buffer and the mask buffer.
- **Technical & Memory Mechanics**: The mask buffer is sliced with the exact same stride offsets as the data buffer, preserving masked value states across all partitions.
- **Self-Contained Code Snippet**:
```python
import numpy as np

ma = np.ma.masked_array([1, 2, 3, 4, 5, 6], mask=[0, 1, 0, 0, 1, 0])
s1, s2 = np.split(ma, 2)

print(f"s1 mask: {s1.mask}")
print(f"s2 mask: {s2.mask}")
assert isinstance(s1, np.ma.MaskedArray)
assert s1.mask[1] == True
assert s2.mask[1] == True
```

#### Q35: How do you split an array along multiple axes simultaneously?

- **Self-Contained Code Snippet**:

```python
            next_blocks.extend(np.split(block, num, axis=axis))
        current_blocks = next_blocks
    return current_blocks
```

### 3.D Memory Footprint, Strides, and Cache Locality (Q51–Q55)

#### Q51: How does the memory pinning hazard cause silent memory leaks in long-running applications?
- **Definition & Theoretical Intuition**: In Python, an object cannot be garbage collected as long as any active reference points to it. An ndarray view references its parent array through `view.base`. If an application loads a massive array, splits it, and retains only a tiny sub-array, the parent array remains pinned in memory forever.
- **Technical & Memory Mechanics**: The CPython garbage collector checks the reference count of the parent `PyArrayObject`. Because `sub_array->base` points to `parent`, `parent->ob_refcnt >= 1`. The OS heap buffer cannot be freed.
- **Self-Contained Code Snippet**:
```python
import numpy as np

# Allocate 100 MB parent
huge_dataset = np.ones((10000, 1250), dtype=np.float64) # 100 MB

# Keep only 1 row (10 KB)
sample = np.split(huge_dataset, 10000)[0]

# Delete reference to parent
del huge_dataset

print(f"sample size:        {sample.nbytes} bytes (10 KB)")
print(f"Pinned buffer size: {sample.base.nbytes / 1e6:.1f} MB (STILL RESIDENT IN RAM!)")
assert sample.base is not None
```
- **Edge Cases, Pitfalls & Nuances**: Always break view dependencies by calling `.copy()` when retaining small subsets of large datasets: `sample = np.split(huge_dataset, 10000)[0].copy()`.

#### Q53: How do strides propagate when splitting along axis 0 vs axis 1 in C-contiguous arrays?
- **Definition & Theoretical Intuition**: In a C-contiguous 2D array, splitting along axis 0 produces sub-arrays that are strictly C-contiguous. Splitting along axis 1 produces sub-arrays that are still C-contiguous if viewed row-by-row, but share the parent row stride.
- **Technical & Memory Mechanics**: For shape `(H, W)` with strides `(W * 8, 8)`:
  - Row split (`axis=0`): Sub-arrays have shape `(H / 2, W)` and identical strides `(W * 8, 8)`. They are fully C-contiguous.
  - Column split (`axis=1`): Sub-arrays have shape `(H, W / 2)` and identical strides `(W * 8, 8)`. They are NOT C-contiguous because jumping from the end of row $i$ to start of row $i+1$ skips over the remaining columns of the parent array!
- **Self-Contained Code Snippet**:
```python
import numpy as np

mat = np.ones((10, 10), dtype=np.float64) # strides: (80, 8)

row_sub1, row_sub2 = np.split(mat, 2, axis=0) # shape (5, 10)
col_sub1, col_sub2 = np.split(mat, 2, axis=1) # shape (10, 5)

print(f"Row split C-contiguous:    {row_sub1.flags.c_contiguous}")
print(f"Column split C-contiguous: {col_sub1.flags.c_contiguous} (NOT C-CONTIGUOUS!)")
print(f"Column split strides:      {col_sub1.strides} (Row stride still 80 bytes!)")
```
- **Edge Cases, Pitfalls & Nuances**: Flattening `col_sub1.reshape(-1)` forces a memory copy because it is not C-contiguous.

#### Q54: How does column-splitting impact CPU cache line performance in downstream reductions?
- **Definition & Theoretical Intuition**: Because column sub-arrays are non-contiguous across rows (separated by the parent\'s full width stride), iterating sequentially down rows skips memory addresses, reducing L1 cache line reusability.
- **Technical & Memory Mechanics**: Each row of `col_sub1` occupies only half of a row\'s bytes; the remaining half of the cache line belongs to `col_sub2`. If multiple threads process columns in parallel, this causes "false sharing" and cache eviction thrashing.

```python

row1, row2 = np.split(mat, 2, axis=0)

t0 = time.perf_counter()
_ = row1.sum()
t_row = time.perf_counter() - t0

t0 = time.perf_counter()
_ = col1.sum()
t_col = time.perf_counter() - t0

print(f"Row split sum time:    {t_row*1000:.2f} ms")
print(f"Column split sum time: {t_col*1000:.2f} ms")
print(f"Cache miss penalty:    {t_col / t_row:.2f}x")
```
- **Edge Cases, Pitfalls & Nuances**: If performing intensive computation on a column sub-array, make it contiguous with `np.ascontiguousarray(col1)` beforehand.

```python
    shuffled_idx = rng.permutation(N)

    y_shuffled = y[shuffled_idx]

    y_train, y_val, y_test = np.split(y_shuffled, [cut1, cut2], axis=0)
    
    return (X_train, y_train), (X_val, y_val), (X_test, y_test)
```

#### Q69: How do Numba `@njit` and Cython compile array splitting operations?
- **Definition & Theoretical Intuition**: Numba does not implement `np.split` natively under `@njit(nogil=True)`. Instead, Numba requires idiomatic slice indexing `arr[start:end]`.
- **Technical & Memory Mechanics**: Direct slice indexing compiles to raw C pointer arithmetic inside Numba kernels, yielding zero Python overhead and maximum hardware speed.
- **Self-Contained Code Snippet**:
```python
import numpy as np

# Idiomatic Numba-friendly splitting pattern:
def numba_friendly_split(arr, num_chunks):
    n = len(arr)
    chunk_size = n // num_chunks
    # Use direct slicing instead of np.split:
    return [arr[i * chunk_size : (i + 1) * chunk_size] for i in range(num_chunks)]

arr = np.arange(12)
res = numba_friendly_split(arr, 3)
assert len(res) == 3
print(f"Numba-compatible split outputs: {res}")
```
- **Edge Cases, Pitfalls & Nuances**: When writing compiled high-performance extensions, always replace `np.split` with explicit slice ranges.

#### Q70: What is the false sharing hazard when multiple threads write to column-split sub-arrays?
- **Definition & Theoretical Intuition**: False sharing occurs when two threads running on different CPU cores modify different variables that reside on the same 64-byte hardware cache line.
- **Technical & Memory Mechanics**: In column-split sub-arrays (`np.hsplit(mat, 2)`), elements in row $i$ of `col1` and `col2` are adjacent in physical memory. When Thread 0 writes to `col1[i, -1]` and Thread 1 writes to `col2[i, 0]`, both cores fight over the same cache line, triggering cache invalidation bus storms (coherence misses) that can degrade performance by 10x–50x.
- **Self-Contained Code Snippet**:
```python
import numpy as np

mat = np.zeros((1000, 8), dtype=np.float64) # 8 floats = 64 bytes = exactly 1 cache line!
col_left, col_right = np.split(mat, 2, axis=1) # 4 floats each

print(f"Row 0 left address:  {col_left.__array_interface__['data'][0]}")
print(f"Row 0 right address: {col_right.__array_interface__['data'][0]}")
print(f"Address difference:  {col_right.__array_interface__['data'][0] - col_left.__array_interface__['data'][0]} bytes (SAME CACHE LINE!)")
```
- **Edge Cases, Pitfalls & Nuances**: To prevent false sharing in parallel write loops, always partition arrays along the leading contiguous axis (`axis=0`).

## 4. What-If Question Bank (13 Scenarios)

### 4.1 What if you pass an integer $N$ that does not evenly divide the dimension in `np.split`?
NumPy raises `ValueError: array split does not result in an equal division`. Use `np.array_split` to allow uneven division.

### 4.2 What if you mutate an element in a sub-array returned by `np.split`?
The modification immediately mutates the original parent array, because `np.split` returns zero-copy views.

### 4.3 What if you delete the original parent array (`del parent`) after splitting?
The parent memory buffer is NOT freed. The sub-array\'s `.base` attribute holds a reference to the parent, keeping the entire memory buffer pinned in RAM.

### 4.4 What if you call `np.vsplit` on a 1-dimensional array?
NumPy raises `ValueError: vsplit only works on arrays of 2 or more dimensions`.

### 4.5 What if you call `np.dsplit` on a 2-dimensional array?
NumPy raises `ValueError: dsplit only works on arrays of 3 or more dimensions`.

### 4.6 What if `indices_or_sections` contains an index that exceeds the array length?
NumPy returns an empty sub-array of length 0 for that slice range without raising an error.

### 4.7 What if `indices_or_sections` is an empty list `[]`?
NumPy returns a 1-element list containing a view of the complete original array: `[arr[:]]`.

### 4.8 What if you pass unsorted indices to `indices_or_sections` (e.g. `[5, 2]`)?
NumPy executes the slice ranges as given (`[:5]`, `[5:2]`, `[2:]`). Slices where $start > stop$ produce empty arrays of length 0.

### 4.9 What if you call `np.array_split` with $N$ greater than the array length?
It produces $L$ sub-arrays of length 1, followed by $N - L$ empty sub-arrays of length 0.

### 4.10 What if you pass floating-point numbers in `indices_or_sections`?
NumPy raises a `TypeError`. Split boundary indices must strictly be integers.

### 4.11 What if you call `np.split` on a 0-dimensional scalar array?
NumPy raises `ValueError: zero-dimensional array cannot be split`.

### 4.12 What if you split an array along a negative axis (e.g. `axis=-1`)?
NumPy normalizes the axis using $axis = axis + ndim$ and splits along the trailing dimension.

### 4.13 What if you want to prevent a sub-array from keeping the parent array alive in RAM?
Call `.copy()` on the sub-array immediately after splitting. This allocates an independent buffer and severs the `.base` link to the parent.

## 5. Top 10 Mistakes & Anti-Patterns (with Bad vs Good Code)

### 5.1 Mistake: Using `np.split` when section count does not divide length evenly
- **Why it occurs**: Assuming `np.split` handles uneven splits automatically.
- **Catastrophic consequence**: Throws runtime `ValueError` when dataset sample count varies.
- **Bad Code**:
```python
# Fails when len(dataset) is odd or prime!
train, test = np.split(dataset, 2) # CRASH if len is odd!
```
- **Good Code**:
```python
# Tolerates any sample count gracefully:
train, test = np.array_split(dataset, 2)
```

### 5.2 Mistake: Memory pinning leaks when storing small slices of giant arrays
- **Why it occurs**: Forgetting that sub-arrays are views that hold references to the parent.
- **Catastrophic consequence**: Multi-gigabyte parent arrays remain pinned in RAM indefinitely.
- **Bad Code**:
```python
def get_first_sample(filepath):
    huge_data = np.load(filepath) # 10 GB
    return np.split(huge_data, 1000)[0] # Pinned 10 GB in RAM!
```
- **Good Code**:
```python
def get_first_sample(filepath):
    huge_data = np.load(filepath)
    return np.split(huge_data, 1000)[0].copy() # Decoupled! 10 GB freed!
```

### 5.3 Mistake: Calling `np.vsplit` on 1D arrays
- **Why it occurs**: Assuming "vertical split" splits a 1D column vector.
- **Catastrophic consequence**: Throws `ValueError: vsplit only works on arrays of 2 or more dimensions`.
- **Bad Code**:
```python
vec = np.arange(10)
top, bot = np.vsplit(vec, 2) # CRASH!
```
- **Good Code**:
```python
vec = np.arange(10)
top, bot = np.split(vec, 2)
# Or:
top, bot = np.hsplit(vec, 2)
```

### 5.4 Mistake: Forgetting that mutating a sub-array mutates the parent array
- **Why it occurs**: Assuming `np.split` creates independent sub-arrays.
- **Catastrophic consequence**: Modifying validation data silently corrupts the training dataset.
- **Bad Code**:
```python
train, val = np.split(dataset, [800])
val[:] = (val - val.mean()) / val.std() # Corrupts dataset!
```
- **Good Code**:
```python
train, val = np.split(dataset, [800])
val_clean = val.copy() # Safe independent buffer
val_clean = (val_clean - val_clean.mean()) / val_clean.std()
```

### 5.5 Mistake: Passing unsorted boundary indices
- **Why it occurs**: Calculating split points dynamically without sorting.
- **Catastrophic consequence**: Produces empty sub-arrays and scrambled slice boundaries.
- **Bad Code**:
```python
boundaries = [80, 20] # Unsorted!
s1, s2, s3 = np.split(data, boundaries) # s2 is EMPTY!
```
- **Good Code**:
```python
boundaries = sorted([80, 20])
s1, s2, s3 = np.split(data, boundaries)
```

### 5.6 Mistake: Assuming `hsplit` on 2D arrays splits rows
- **Why it occurs**: Confusing horizontal cut (cutting across columns) with row partitioning.
- **Catastrophic consequence**: Splits columns instead of rows, partitioning features rather than samples.
- **Bad Code**:
```python
# Trying to split samples:
train, test = np.hsplit(feature_matrix, 2) # Splitting columns!
```
- **Good Code**:
```python
train, test = np.vsplit(feature_matrix, 2) # Splits rows (samples)
```

### 5.7 Mistake: Passing floats as split boundary percentages
- **Why it occurs**: Expecting `np.split` to accept fractional percentages directly.
- **Catastrophic consequence**: Throws `TypeError: Cannot cast array data from dtype('float64') to dtype('int64')`.
- **Bad Code**:
```python
train, val, test = np.split(data, [0.7, 0.85]) # TypeError!
```
- **Good Code**:
```python
N = len(data)
train, val, test = np.split(data, [int(0.7 * N), int(0.85 * N)])
```

### 5.8 Mistake: False sharing in multi-threaded processing of column splits
- **Why it occurs**: Assigning column sub-arrays to different threads in high-concurrency loops.
- **Catastrophic consequence**: Massive cache line invalidation and multi-core performance collapse.
- **Bad Code**:
```python
# Threads write to adjacent column slices on same cache lines
col1, col2 = np.hsplit(mat, 2)
# Thread 0 writes col1, Thread 1 writes col2 -> False sharing!
```
- **Good Code**:
```python
# Partition along rows (axis 0) so each thread has dedicated cache lines:
row1, row2 = np.vsplit(mat, 2)
```

### 5.9 Mistake: Trying to split along multiple axes in a single function call
- **Why it occurs**: Passing a tuple of axes `axis=(0, 1)`.
- **Catastrophic consequence**: Throws `TypeError: an integer is required`.
- **Bad Code**:
```python
quadrants = np.split(matrix, 2, axis=(0, 1)) # TypeError!
```
- **Good Code**:
```python
# Chain splits sequentially:
quadrants = [q for half in np.vsplit(matrix, 2) for q in np.hsplit(half, 2)]
```

### 5.10 Mistake: Expecting `np.split` on a 0-dimensional scalar array
- **Why it occurs**: Passing scalar metrics to general partitioning utilities.
- **Catastrophic consequence**: Throws `ValueError: zero-dimensional array cannot be split`.
- **Bad Code**:
```python
loss = np.array(0.45)
s = np.split(loss, 1) # CRASH!
```
- **Good Code**:
```python
loss = np.atleast_1d(loss)
s = np.split(loss, 1)
```

## 6. Top 5 Conceptual Confusions (Side-by-Side Comparison)

### 6.1 `np.split` vs `np.array_split`

| Feature | `np.split` | `np.array_split` |
|---|---|---|
| **Equal Divisibility** | **Mandatory**: Raises `ValueError` if $L \% N \neq 0$ | **Optional**: Tolerates uneven splits |
| **Remainder Distribution**| N/A (Equal only) | First $L \% N$ chunks get $+1$ element |
| **Boundary Index Sequence**| Supported (`[i0, i1, ...]`) | Supported (`[i0, i1, ...]`) |
| **View Guarantee** | Returns list of views | Returns list of views |
| **Primary Use Case** | Symmetry-enforced tensors (QKV, color planes) | Machine learning batches, $K$-Fold folds |

### 6.2 `np.vsplit` vs `np.hsplit` vs `np.dsplit`

| Feature | `np.vsplit` | `np.hsplit` | `np.dsplit` |
|---|---|---|---|
| **Target Direction** | Vertical (Rows) | Horizontal (Columns) | Depth (Channels) |
| **Target Axis** | Always `axis=0` | `axis=1` (2D+) or `axis=0` (1D) | Always `axis=2` |
| **Minimum Dimensionality**| Requires $ndim \ge 2$ | Requires $ndim \ge 1$ | Requires $ndim \ge 3$ |
| **Common Application** | Partitioning dataset samples | Decoupling features / stereo audio | Separating RGB image channels |

### 6.3 `np.split` vs Slicing in Python Lists

| Feature | `np.split(arr, N)` | `[arr[i:j] for ...]` |
|---|---|---|
| **Flexibility** | High (handles remainder math automatically) | Requires manual index math |
| **Safety** | Enforces divisibility checks | Silent out-of-bounds clipping |
| **Overhead** | Microsecond validation checks | Raw C speed (slightly faster) |
| **Readability** | High (intent-revealing) | Verbose index math |

### 6.4 Zero-Copy Views vs Memory Pinning

| Aspect | Zero-Copy Views | Memory Pinning |
|---|---|---|
| **Benefit** | Instant execution ($O(1)$), zero RAM allocated | No copy overhead |
| **Hazard** | Mutating slice corrupts parent array | Parent buffer cannot be garbage collected |
| **Remedy** | Call `.copy()` if mutation isolation needed | Call `.copy()` if retaining small slice |

### 6.5 Equal Splits vs Balanced Remainder Splits

| Partition Strategy | Array Length 10 into 3 Sections | Array Length 12 into 4 Sections |
|---|---|---|
| **`np.split`** | Fails with `ValueError` | Sub-array sizes: $[3, 3, 3, 3]$ |
| **`np.array_split`** | Sub-array sizes: $[4, 3, 3]$ | Sub-array sizes: $[3, 3, 3, 3]$ |

## 7. 10 Traps, Gotchas, and Silent Bugs

### 7.1 Trap 1: The Uneven Dataset `np.split` Production Crash
Code works during unit testing on toy datasets with 100 samples, but crashes in production when real datasets with odd sample counts (e.g. 10,001 samples) trigger `ValueError: array split does not result in an equal division`.

### 7.2 Trap 2: The Silent 10 GB Memory Pinning Leak
Extracting a single sample from a 10 GB dataset keeps the entire 10 GB memory allocation pinned in RAM because `sample.base` references the parent array.

### 7.3 Trap 3: The 1D `vsplit` Dimension Crash
Calling `vsplit` on a 1D vector of shape `(N,)` raises `ValueError: vsplit only works on arrays of 2 or more dimensions`.

### 7.4 Trap 4: Sub-Array Mutation Corrupting Validation Folds
Modifying or normalizing validation sub-arrays in-place alters the shared underlying memory buffer, contaminating training data.

### 7.5 Trap 5: The Unsorted Boundary Index Empty Slice Trap
Passing unsorted split indices like `[50, 20]` silently creates an empty array for slice `[50:20]`, corrupting downstream processing loops.

### 7.6 Trap 6: Multi-Threaded False Sharing on Column Splits
Multiple threads writing to adjacent column sub-arrays fight over the same 64-byte L1 cache lines, causing severe CPU performance degradation.

### 7.7 Trap 7: Float Split Percentage TypeError
Passing floating-point numbers like `[0.7, 0.85]` to `indices_or_sections` raises a `TypeError` rather than computing percentage cutoffs.

### 7.8 Trap 8: Non-Contiguity of Column Sub-Arrays
Column sub-arrays returned by `hsplit` or `split(..., axis=1)` are non-contiguous. Attempting `.reshape(-1)` forces an unexpected memory copy.

### 7.9 Trap 9: Boundary Clamping beyond Array Length
Passing split indices larger than array length silently appends empty arrays of length 0 to the returned list.

### 7.10 Trap 10: 0-Stride Propagation on Broadcasted Array Splits
Splitting broadcasted arrays produces sub-arrays that retain 0-strides and read-only flags, failing unexpectedly when passed to functions that perform in-place mutations.

#### Task 1: Balanced Uneven Partitioning Algorithm (`custom_array_split`)
- **Description**: Implement `custom_array_split(arr, num_sections, axis=0)` from scratch without using `np.array_split`, calculating exact slice offsets manually.
- **Solution Code**:
```python
import numpy as np

def custom_array_split(arr, num_sections, axis=0):
    L = arr.shape[axis]
    q = L // num_sections
    r = L % num_sections
    
    sub_arrays = []
    cursor = 0
    for i in range(num_sections):
        chunk_len = q + 1 if i < r else q
        # Construct slice tuple dynamically for target axis
        idx = [slice(None)] * arr.ndim
        idx[axis] = slice(cursor, cursor + chunk_len)
        sub_arrays.append(arr[tuple(idx)])
        cursor += chunk_len
    return sub_arrays

# Verification

    assert c.base is x
print(f"custom_array_split matches np.array_split: {[len(c) for c in custom_splits]}")
```
- **Explanation**: Explicitly calculates quotient and remainder to allocate extra elements to the leading $r$ chunks, using dynamic slice tuples to support arbitrary axes.

## 15. Architecture & Design Patterns (4 Patterns)

### 15.1 Pattern 1: Memory-Safe View Decoupler
- **Problem**: Long-lived services retaining small slices of large arrays suffer from memory pinning leaks.
- **Design Solution**: Wrap array splitting in a defensive copy boundary that severs `.base` dependencies when sub-array size is significantly smaller than parent size.
```python
import numpy as np

def safe_extract_slice(parent_array, slice_spec, copy_threshold=0.2):
    """Returns a view if slice retains most of array; copies if small to free parent."""
    sub = parent_array[slice_spec]
    if sub.nbytes < copy_threshold * parent_array.nbytes:
        return sub.copy()
    return sub
```

### 15.2 Pattern 2: Fault-Tolerant Distributed Batcher
- **Problem**: Uneven batch counts crash distributed worker nodes during inference.
- **Design Solution**: Use `np.array_split` inside a distributed batching adapter to guarantee balanced work distribution across arbitrary cluster worker counts.
```python
import numpy as np

def distribute_work_units(batch, num_workers):
    """Partitions arbitrary batch sizes across workers without dimension exceptions."""
    return np.array_split(batch, num_workers, axis=0)
```

### 15.3 Pattern 3: Multi-Head Projection Decoupler
- **Problem**: Decoupling fused transformer linear projections with readable, zero-allocation syntax.
- **Design Solution**: Encapsulate projection splitting with assertion guards that verify head and feature divisibility.
```python
import numpy as np

def split_qkv_projections(fused_qkv, num_projections=3):
```

### 15.4 Pattern 4: Cache-Aligned Parallel Partitioning Adapter
- **Problem**: Multi-threaded processing suffers severe performance collapse due to false sharing on column splits.
- **Design Solution**: Force parallel workloads to partition strictly along row dimensions (axis 0), ensuring each thread operates on independent CPU cache lines.

### 16.1 Variation 1: `np.split` vs `np.array_split` for Integer Sections

### 16.5 Variation 5: Zero-Copy View vs Decoupled `.copy()`

## 17. Alternative Implementations (Q76–Q80)

### Q76: How can array splitting be implemented in pure Python without NumPy?
- **Definition & Theoretical Intuition**: In standard Python, lists are partitioned using native slice syntax `[start:stop]`.
- **Technical & Memory Mechanics**: For a 2D list (list of lists), row splitting slices outer list indices `matrix[i:j]`. Column splitting requires list comprehensions slicing each inner row `[row[i:j] for row in matrix]`.
- **Self-Contained Code Snippet**:
```python
def pure_python_split(lst, num_sections):
    L = len(lst)
    q = L // num_sections
    r = L % num_sections
    
    sub_lists = []
    cursor = 0
    for i in range(num_sections):
        chunk_len = q + 1 if i < r else q
        sub_lists.append(lst[cursor : cursor + chunk_len])
        cursor += chunk_len
    return sub_lists

py_list = list(range(10))
splits = pure_python_split(py_list, 3)
print(f"Pure Python split: {splits}")
assert [len(s) for s in splits] == [4, 3, 3]
```
- **Edge Cases, Pitfalls & Nuances**: Python list slicing creates shallow copies of object references rather than zero-copy memory views.

### Q77: How can array splitting be implemented using `np.lib.stride_tricks.as_strided`?
- **Definition & Theoretical Intuition**: As demonstrated by NumPy\'s C core, splitting an array along an axis simply creates sub-array views with offset data pointers.
- **Technical & Memory Mechanics**: Calling `as_strided` with updated shape and calculated byte pointer offsets reproduces sub-array views directly.
- **Self-Contained Code Snippet**:

```python
import numpy as np
from numpy.lib.stride_tricks import as_strided

def stride_split_2d(matrix, num_row_sections):
    H, W = matrix.shape
    assert H % num_row_sections == 0
    sub_H = H // num_row_sections
    row_stride = matrix.strides[0]
    
    sub_arrays = []
    for i in range(num_row_sections):
        # Calculate byte offset for row start:
        byte_offset = i * sub_H * row_stride
        sub_view = as_strided(
            matrix[i * sub_H : (i + 1) * sub_H], # Use slice to set base pointer safely
            shape=(sub_H, W),
            strides=matrix.strides
        )
        sub_arrays.append(sub_view)
    return sub_arrays
```

## 18. System & Hardware-Level Realities (Q81–Q85)

### Q81: What happens to the CPython reference count and heap memory during array splitting?
- **Definition & Theoretical Intuition**: In CPython, every `ndarray` is backed by a `PyArrayObject` structure. Creating a view increments the reference count of the parent array via `Py_INCREF(parent)`.
- **Technical & Memory Mechanics**: The sub-array\'s internal C struct contains `base = (PyObject*)parent`. When the user calls `del parent`, the parent\'s reference count decreases by 1, but remains $> 0$ because `sub_array->base` points to it. The underlying C `malloc` buffer cannot be returned to the OS heap until all sub-arrays are deleted.
- **Self-Contained Code Snippet**:
```python
import numpy as np
import sys

parent = np.ones(1000)
ref_before = sys.getrefcount(parent)

# Create 3 sub-array views:
s1, s2, s3 = np.split(parent, [300, 700])
ref_after = sys.getrefcount(parent)

print(f"Parent refcount before splitting: {ref_before}")
print(f"Parent refcount after splitting:  {ref_after} (Incremented by 3!)")
assert ref_after == ref_before + 3
```
- **Edge Cases, Pitfalls & Nuances**: This reference tracking mechanism is what causes memory pinning leaks when small slices are retained.

### Q82: How does CPU cache false sharing degrade multi-threaded performance on column splits?
- **Definition & Theoretical Intuition**: Modern multi-core CPUs maintain cache coherence across cores using protocols like MESI/MOESI. When two cores write to different variables that reside on the same 64-byte L1 cache line, the line is repeatedly invalidated and re-fetched across cores.
- **Technical & Memory Mechanics**: In column sub-arrays, adjacent columns in row $i$ share the same 64-byte physical line. Concurrent writes trigger continuous bus transactions (coherence storm), stalling execution units while waiting for cache line ownership.
- **Self-Contained Code Snippet**:
```python
import numpy as np

# 2D matrix where row is 64 bytes (8 float64s)
matrix = np.zeros((1000, 8), dtype=np.float64)
# Column split divides the 64-byte line in half!
col_left, col_right = np.split(matrix, 2, axis=1)

print(f"Row size in bytes: {matrix.strides[0]} bytes (Exact L1 cache line!)")
print(f"Column 0 addr:     {col_left.__array_interface__['data'][0]}")
print(f"Column 1 addr:     {col_right.__array_interface__['data'][0]}")
```
- **Edge Cases, Pitfalls & Nuances**: Partitioning arrays along row boundaries (axis 0) guarantees complete cache line isolation between threads.

- **Technical & Memory Mechanics**: When a CUDA kernel launches on a sliced tensor, threads compute memory addresses relative to `devPtr`. If the slice is non-contiguous (e.g. column slice), thread memory access becomes non-coalesced, reducing effective VRAM bandwidth.

### Q84: How do OS virtual memory page tables track sliced array views?
- **Definition & Theoretical Intuition**: The operating system kernel manages memory in 4 KB virtual pages. Sliced array views simply reference virtual memory address ranges within the pages already allocated by the parent array.
- **Technical & Memory Mechanics**: No new page table entries (PTEs) are created by the OS kernel when `np.split` executes. The CPU Memory Management Unit (MMU) translates view addresses using the exact same page table entries established for the parent array.

### Q85: What are the NUMA (Non-Uniform Memory Access) implications of splitting arrays across sockets?
- **Definition & Theoretical Intuition**: On multi-socket servers, an array allocated on Socket 0 resides in Socket 0\'s local DRAM. Splitting the array and passing sub-arrays to threads running on Socket 1 forces all memory accesses to cross the inter-socket bus (UPI / Infinity Fabric).
- **Technical & Memory Mechanics**: Remote NUMA reads incur 2x higher latency. If worker threads on Socket 1 frequently access their split view, the interconnect becomes a severe communication bottleneck.
- **Self-Contained Code Snippet**:

```python
import numpy as np
import time

def run_splitting_verification_suite():
    print("=" * 70)
    print("RUNNING COMPLETE NUMPY SPLITTING ARRAYS VERIFICATION PIPELINE (8.4)")
    print("=" * 70)

    # 1. Equal Split vs Unequal Array_Split Remainder Balancing
    arr10 = np.arange(10)
    
    # np.split equal division
    equal_splits = np.split(arr10, 2)
    assert len(equal_splits) == 2
    assert len(equal_splits[0]) == 5 and len(equal_splits[1]) == 5
    
    # np.array_split unequal division: 10 into 3 chunks -> [4, 3, 3]
    unequal_splits = np.array_split(arr10, 3)
    assert len(unequal_splits) == 3
    assert [len(s) for s in unequal_splits] == [4, 3, 3]
    print("[OK] Test 1: Equal split and array_split balanced remainder partitioning verified.")

    # 2. Zero-Copy View Invariants and Memory Mutation Sharing
    base_data = np.array([10, 20, 30, 40])
    s1, s2 = np.split(base_data, 2)
    
    assert s1.base is base_data
    assert s2.base is base_data
    assert np.shares_memory(base_data, s1)
    
    # Mutating view reflects in parent
    s1[0] = 999
    assert base_data[0] == 999
    print("[OK] Test 2: Zero-copy view guarantee and shared memory mutation verified.")

    # 3. Memory Pinning Decoupling via .copy()
    huge_parent = np.ones((100, 100))
    pinned_sub = np.split(huge_parent, 2)[0]
    decoupled_sub = pinned_sub.copy()

    assert pinned_sub.base is huge_parent
    assert decoupled_sub.base is None
    assert not np.shares_memory(huge_parent, decoupled_sub)
    print("[OK] Test 3: Memory pinning decoupling via .copy() verified.")

    # 4. Vertical Split (vsplit) Mechanics
    mat_2d = np.zeros((4, 3))
    top, bot = np.vsplit(mat_2d, 2)
    assert top.shape == (2, 3)
    assert bot.shape == (2, 3)
    assert top.base is mat_2d
    assert np.shares_memory(mat_2d, top)
    print("[OK] Test 4: Vertical split (vsplit) row partitioning verified.")

    # 5. Horizontal Split (hsplit) on 1D vs 2D Arrays
    vec_1d = np.arange(6)
    h_1d = np.hsplit(vec_1d, 2)
    assert h_1d[0].shape == (3,)

    h_2d = np.hsplit(mat_2d, [1]) # Split at column index 1
    assert h_2d[0].shape == (4, 1)
    assert h_2d[1].shape == (4, 2)
    print("[OK] Test 5: Horizontal split (hsplit) 1D and 2D polymorphism verified.")

    # 6. Depth Split (dsplit) on 3D RGB Tensor
    rgb_tensor = np.zeros((10, 10, 3), dtype=np.uint8)
    r_plane, g_plane, b_plane = np.dsplit(rgb_tensor, 3)
    assert r_plane.shape == (10, 10, 1)
    assert g_plane.shape == (10, 10, 1)
    assert b_plane.shape == (10, 10, 1)
    assert r_plane.base is rgb_tensor
    print("[OK] Test 6: Depth split (dsplit) 3D channel decoupling verified.")

    # 7. Tabular Feature-Label Separation (X, y)
    tabular = np.arange(30).reshape(6, 5) # 5 columns
    X, y_col = np.split(tabular, [-1], axis=1)
    y = y_col.ravel()
    assert X.shape == (6, 4)
    assert y.shape == (6,)
    assert np.array_equal(y, tabular[:, -1])
    print("[OK] Test 7: Feature-label separation (X, y) via negative boundary index verified.")

    # 8. Transformer Fused QKV Projection Splitting
    B, S, D = 2, 8, 32
    fused_qkv = np.random.randn(B, S, 3 * D)
    Q, K, V = np.split(fused_qkv, 3, axis=-1)
    assert Q.shape == (B, S, D)
    assert K.shape == (B, S, D)
    assert V.shape == (B, S, D)
    assert Q.base is fused_qkv
    print("[OK] Test 8: Transformer QKV projection zero-copy splitting verified.")

    # 9. Vision Transformer (ViT) Patch Dicing
    img = np.random.randn(32, 32, 3)
    patches = []
    for strip in np.vsplit(img, 2):
        for p in np.hsplit(strip, 2):
            patches.append(p)
    assert len(patches) == 4
    assert patches[0].shape == (16, 16, 3)
    assert patches[0].base is img
    print(f"[OK] Test 9: Vision Transformer grid tile dicing verified: {len(patches)} tiles of shape {patches[0].shape}")

    # 10. Masked Array Split Preservation
    ma = np.ma.masked_array([1, 2, 3, 4], mask=[0, 1, 0, 1])
    m_splits = np.split(ma, 2)
    assert isinstance(m_splits[0], np.ma.MaskedArray)
    assert m_splits[0].mask[1] == True
    assert m_splits[1].mask[1] == True
    print("[OK] Test 10: Masked array split mask preservation verified.")

    # 11. Edge Cases: Empty Slices and Boundary Clamping
    data = np.arange(5)
    edge_splits = np.split(data, [0, 5, 10])
    assert edge_splits[0].size == 0 # [:0]
    assert edge_splits[1].size == 5 # [0:5]
    assert edge_splits[2].size == 0 # [5:10]
    assert edge_splits[3].size == 0 # [10:]
    print("[OK] Test 11: Edge cases (empty slices, out-of-bounds boundary clamping) verified.")

    # 12. Microsecond Execution Scaling Verification
    giant_arr = np.ones((5000, 5000)) # ~200 MB
    t0 = time.perf_counter()
    _ = np.split(giant_arr, 10)
    split_time = (time.perf_counter() - t0) * 1e6
    print(f"[OK] Test 12: Microsecond scaling verified: 200 MB array split in {split_time:.2f} microseconds.")

    print("=" * 70)
    print("[OK] All 8.4 Production Verification Tests Passed Successfully!")
    print("=" * 70)

if __name__ == "__main__":
    run_splitting_verification_suite()
```
