# Section: 8.1 Reshaping Arrays

## 1. Section Overview
In high-performance numerical computing, machine learning, and computer vision, array shape manipulation is one of the most fundamental daily operations. Transforming multidimensional tensors between batch representations (e.g., flattening 2D/3D convolutional activations into 1D feature vectors for fully connected layers, restructuring image buffers between NCHW and NHWC formats, or inferring unknown dimensions via `-1`) requires a deep understanding of how NumPy manages memory buffers, strides, and contiguous flags.

NumPy provides three primary primitives for reshaping and dimensionality reduction: `reshape()`, `flatten()`, and `ravel()`. While they may appear interchangeable at first glance, they have profoundly different memory allocation mechanics, computational costs, and mutation side effects. `reshape()` and `ravel()` strive to return zero-allocation memory **views** by simply altering array metadata (shape and strides), falling back to copies only when non-contiguous striding prevents a view. Conversely, `flatten()` strictly returns a newly allocated **copy** on the heap, ensuring memory isolation at the cost of allocation overhead.

This section delivers an exhaustive, production-grade guide to reshaping mechanics, the internal C-level stride recalculation engine, memory order parameters (`'C'`, `'F'`, `'A'`, `'K'`), dimension inference via `-1`, and the critical differences between `ravel()` and `flatten()`.

## 3. Fresher Interview Questions

### 3.A Core Concepts (Q1–Q20)

### Q1: What is `reshape()` in NumPy, and what is the fundamental requirement for reshaping an array?
- **Definition / Core Explanation**: `reshape()` gives a new shape to an array without changing its underlying data. The fundamental, non-negotiable requirement is that the total number of elements must remain identical: $\prod \text{new\_shape} = \prod \text{orig\_shape} = N$. If the product of the new dimensions does not match the total element count, NumPy raises a `ValueError: cannot reshape array of size X into shape Y`.
- **Technical & Memory Mechanics**: Reshaping primarily modifies the metadata in the `PyArrayObject` header—specifically the `shape` tuple and the `strides` tuple—while pointing to the exact same continuous data buffer (creating a **view**). No elements are copied or moved in memory if the existing memory strides can represent the new layout.
- **Production-Grade Code Example**:
```python
import numpy as np

arr = np.arange(12)  # 1D array of 12 elements
reshaped_2d = arr.reshape(3, 4)

print("Original shape:", arr.shape)
print("Reshaped shape:", reshaped_2d.shape)
print("Reshaped 3x4:\n", reshaped_2d)

# Modifying view modifies original buffer
reshaped_2d[0, 0] = 999
print("Original element after view mutation:", arr[0])
assert arr[0] == 999
```
- **Interview Traps & Edge-Case Nuances**: Assuming `reshape()` always returns a view. If an array has undergone slicing, transposing, or striding such that its memory is non-contiguous, `reshape()` cannot represent the new shape with valid strides and will silently allocate a **copy** instead of a view.

### Q2: What does passing `-1` as a dimension in `reshape()` do, and can you pass multiple `-1` values?
- **Definition / Core Explanation**: Passing `-1` instructs NumPy to automatically deduce the length of that dimension based on the total number of elements and the other specified dimensions. You can pass **at most one** `-1` in a reshape tuple. Passing more than one `-1` raises a `ValueError: can only specify one unknown dimension`.
- **Technical & Memory Mechanics**: NumPy calculates the unknown dimension as:
  $$\text{dim}_{-1} = \frac{\text{total\_elements}}{\prod_{d \ne -1} \text{dim}_d}$$
  If $\text{total\_elements}$ is not evenly divisible by the product of known dimensions, NumPy raises a `ValueError`.
- **Production-Grade Code Example**:
```python
import numpy as np

# Batch of image activations: 32 images, each 28x28 grayscale
batch_images = np.zeros((32, 28, 28))

# Flatten each image into a 1D feature vector while preserving batch size
flat_batch = batch_images.reshape(32, -1)
print("Flattened batch shape:", flat_batch.shape)  # (32, 784)
assert flat_batch.shape == (32, 784)

# Infer batch size from total elements
inferred_batch = flat_batch.reshape(-1, 28, 28)
assert inferred_batch.shape == (32, 28, 28)
```
- **Interview Traps & Edge-Case Nuances**: Trying to call `arr.reshape(-1, -1)`. Even if the array is a perfect square ($4 \times 4 = 16$), NumPy strictly disallows multiple `-1` arguments.

### Q3: What is `flatten()`, and how does its memory allocation behavior differ from `reshape()`?
- **Definition / Core Explanation**: `flatten()` is an ndarray method that returns a collapsed 1D copy of the array. It **always allocates new heap memory** and copies the elements into a brand-new contiguous buffer.
- **Technical & Memory Mechanics**: The output of `flatten()` has its `base` attribute set to `None`, and its memory address is guaranteed to be distinct from the original array. Modifying the array returned by `flatten()` never impacts the original array, guaranteeing memory safety at the cost of allocation and copy latency.
- **Production-Grade Code Example**:
```python
import numpy as np

orig = np.array([[1, 2, 3], [4, 5, 6]])
flat = orig.flatten()

# Verify memory independence
assert flat.base is None
assert flat.__array_interface__['data'][0] != orig.__array_interface__['data'][0]

flat[0] = 999
print("Original [0, 0]:", orig[0, 0])  # Remains 1!
assert orig[0, 0] == 1
```
- **Interview Traps & Edge-Case Nuances**: Using `flatten()` inside high-frequency loops (e.g. streaming inference or real-time simulation) causes severe heap allocation and garbage collection overhead. In performance-critical code, `ravel()` should be preferred.

### Q4: What is `ravel()`, and how does it differ from both `reshape(-1)` and `flatten()`?
- **Definition / Core Explanation**: `ravel()` returns a contiguous 1D flattened array. Unlike `flatten()`, `ravel()` returns a **view** whenever possible (i.e., whenever the input array is contiguous in memory). It falls back to allocating a copy only when the input array is non-contiguous.
- **Technical & Memory Mechanics**: When called on a contiguous array, `ravel()` performs an $O(1)$ metadata update by setting `shape = (N,)` and `strides = (itemsize,)`, sharing the underlying memory buffer (`out.base is orig`). In contrast, `flatten()` always performs an $O(N)$ memory allocation and data copy. `reshape(-1)` behaves almost identically to `ravel()`, but `ravel()` is available as both a top-level NumPy function (`np.ravel`) and an ndarray method, and supports memory order `'K'`.
- **Production-Grade Code Example**:
```python
import numpy as np

orig = np.array([[10, 20], [30, 40]])
rav = orig.ravel()

# Check that ravel returns a view
assert rav.base is orig
rav[0] = 777
print("Original after rav[0] mutation:", orig[0, 0])
assert orig[0, 0] == 777
```
- **Interview Traps & Edge-Case Nuances**: Modifying a raveled array expecting it to be independent. If you modify `rav[i]`, you mutate the original data! If isolation is needed, either use `flatten()` or call `ravel().copy()`.

### Q5: What is the difference between C-order (`order='C'`) and Fortran-order (`order='F'`) in reshaping?
- **Definition / Core Explanation**:
  - **C-order (`'C'`)**: Row-major order. The last index varies the fastest when iterating through memory (elements along rows are stored contiguously). Default in C, C++, Python, and NumPy.
  - **Fortran-order (`'F'`)**: Column-major order. The first index varies the fastest when iterating through memory (elements along columns are stored contiguously). Default in Fortran, MATLAB, and R.
- **Technical & Memory Mechanics**: Reshaping with `order='C'` reads elements row-by-row and packs them into the new shape row-by-row. Reshaping with `order='F'` reads elements column-by-column and packs them column-by-column.
- **Production-Grade Code Example**:
```python
import numpy as np

arr = np.array([[1, 2, 3], [4, 5, 6]])

# Flatten with C-order (row-major)
flat_c = arr.ravel(order='C')
# Flatten with Fortran-order (column-major)
flat_f = arr.ravel(order='F')

print("C-order ravel: ", flat_c)  # [1, 2, 3, 4, 5, 6]
print("F-order ravel: ", flat_f)  # [1, 4, 2, 5, 3, 6]
assert np.array_equal(flat_c, [1, 2, 3, 4, 5, 6])
assert np.array_equal(flat_f, [1, 4, 2, 5, 3, 6])
```
- **Interview Traps & Edge-Case Nuances**: Mixing orders when reshaping data received from external libraries (e.g. Scipy sparse matrices or MATLAB `.mat` files). If an array is Fortran-ordered and you reshape it using default C-order, elements are scrambled.

### Q6: How does NumPy determine whether `reshape()` returns a VIEW or a COPY?
- **Definition / Core Explanation**: `reshape()` returns a view if and only if the requested shape can be achieved by calculating a new set of strides over the existing memory buffer without rearranging physical bytes. If the array's memory is non-contiguous (e.g. after transposition or non-unit step slicing), NumPy cannot represent the new shape with linear strides and must allocate a copy.
- **Technical & Memory Mechanics**: NumPy inspects `arr.flags.c_contiguous` and `arr.flags.f_contiguous`. If contiguous, calculating new strides is an exact mathematical division: $\text{stride}_i = \prod_{j > i} \text{shape}_j \times \text{itemsize}$. If the memory buffer has gaps or reversed axes, this relation fails, triggering `PyArray_NewCopy()`.
- **Production-Grade Code Example**:
```python
import numpy as np

# Case 1: Contiguous array -> VIEW
a = np.arange(6)
b = a.reshape(2, 3)
print("Case 1 - b shares memory with a:", np.shares_memory(a, b))  # True
assert b.base is a

# Case 2: Non-contiguous transposed array -> COPY
orig = np.arange(6).reshape(2, 3)
transposed = orig.T  # Non-contiguous view! Shape (3, 2), strides (8, 24)
assert not transposed.flags.c_contiguous

reshaped_from_t = transposed.reshape(6)
print("Case 2 - reshaped_from_t shares memory with orig:", np.shares_memory(orig, reshaped_from_t))  # False!
assert reshaped_from_t.base is not orig
```
- **Interview Traps & Edge-Case Nuances**: Believing `reshape()` is always $O(1)$. When operating on non-contiguous arrays, `reshape()` is $O(N)$ in both time and memory because it must allocate and copy all elements.

### Q7: What is the `base` attribute in NumPy, and how does it verify view vs copy?
- **Definition / Core Explanation**: The `base` attribute of an ndarray points to the original object that owns the memory buffer. If an array owns its memory, `base` is `None`. If an array is a view over another array, `base` points to that parent array (or another view in a reference chain).
- **Technical & Memory Mechanics**: When NumPy creates a view, `PyArray_SetBaseObject` is called in C, incrementing the reference count of the owner object. This prevents Python's garbage collector from deallocating the underlying data buffer as long as any view remains alive.
- **Production-Grade Code Example**:
```python
import numpy as np

root = np.arange(10)
view1 = root.reshape(2, 5)
view2 = view1.ravel()
copy1 = root.flatten()

print("view1.base is root: ", view1.base is root)   # True
print("view2.base is root: ", view2.base is root)   # True
print("copy1.base is None: ", copy1.base is None)   # True

assert view1.base is root
assert copy1.base is None
```
- **Interview Traps & Edge-Case Nuances**: Checking `view2.base is view1`. When views are chained, NumPy's C implementation typically sets `base` directly to the root owner rather than creating an intermediate reference chain.

### Q8: What does setting the `shape` attribute directly (`arr.shape = (M, N)`) do?
- **Definition / Core Explanation**: Modifying `arr.shape` directly in-place attempts to reshape the array **in-place** without creating a new wrapper object.
- **Technical & Memory Mechanics**: If the array is contiguous and the new shape has the same total element count, NumPy updates the internal `shape` and `strides` fields of the existing `PyArrayObject` in-place. However, if the array is non-contiguous, or if resizing would require a memory copy, NumPy **raises an `AttributeError`** (`AttributeError: Incompatible shape for in-place modify`).
- **Production-Grade Code Example**:
```python
import numpy as np

arr = np.arange(12)
addr_before = arr.__array_interface__['data'][0]

# Modify shape in-place
arr.shape = (3, 4)
addr_after = arr.__array_interface__['data'][0]

print("Shape after in-place mutation:", arr.shape)
assert arr.shape == (3, 4)
assert addr_before == addr_after  # Zero allocation, same object

# Non-contiguous array fails
trans = arr.T
try:
    trans.shape = (12,)
except AttributeError as e:
    print("Caught expected AttributeError on non-contiguous array:", e)
```
- **Interview Traps & Edge-Case Nuances**: Assuming `arr.shape = new_shape` will fall back to a copy like `arr.reshape()`. It will **never** allocate a copy; it raises an `AttributeError` if a view cannot be formed.

### Q9: What is `np.resize()` versus `ndarray.resize()`, and how do they differ from `reshape()`?
- **Definition / Core Explanation**:
  - `reshape()`: Never changes the total number of elements. Product of dimensions must match.
  - `np.resize(a, new_shape)`: Top-level function that returns a new array with the specified shape. If the new shape is larger than the original, data is **repeated/cycled** to fill the space. If smaller, data is truncated.
  - `ndarray.resize(new_shape)`: In-place method that resizes the array buffer. If larger, new elements are initialized to zero. However, it requires that the array owns its memory and has no other references, otherwise it raises `ValueError`.
- **Technical & Memory Mechanics**: `np.resize` always allocates a new copy. `ndarray.resize` calls C `realloc()` to grow or shrink the physical buffer.
- **Production-Grade Code Example**:
```python
import numpy as np

a = np.array([1, 2, 3])

# np.resize repeats elements to fill new shape
b = np.resize(a, (2, 4))
print("np.resize repeated output:\n", b)
assert b.shape == (2, 4)
assert np.array_equal(b[1], [2, 3, 1, 2])

# ndarray.resize in-place zero-pads
c = np.array([1, 2, 3])
c.resize((5,), refcheck=False)
print("ndarray.resize zero-padded:", c)
assert np.array_equal(c, [1, 2, 3, 0, 0])
```
- **Interview Traps & Edge-Case Nuances**: Expecting `np.resize` to raise an error when shapes don't match like `reshape`. It silently repeats or truncates data, which can introduce silent data corruption in ML pipelines.

### Q10: What does `np.squeeze()` do, and what does the `axis` parameter control?
- **Definition / Core Explanation**: `np.squeeze()` removes single-dimensional entries (dimensions of length 1) from the shape of an array.
- **Technical & Memory Mechanics**: `squeeze()` returns a view of the input array with length-1 axes eliminated from the `shape` and `strides` tuples. The `axis` parameter specifies exactly which length-1 axes to drop; if a specified axis has a length greater than 1, a `ValueError` is raised.
- **Production-Grade Code Example**:
```python
import numpy as np

# Common CNN prediction output: (batch_size=1, num_classes=10, 1, 1)
preds = np.zeros((1, 10, 1, 1))

squeezed = np.squeeze(preds)
print("Squeezed all 1s:", squeezed.shape)  # (10,)
assert squeezed.shape == (10,)

# Selective squeeze along specific axis
squeezed_axis = np.squeeze(preds, axis=(2, 3))
print("Squeezed axes 2 and 3:", squeezed_axis.shape)  # (1, 10)
assert squeezed_axis.shape == (1, 10)
assert squeezed.base is preds  # Confirms it is a view
```
- **Interview Traps & Edge-Case Nuances**: If batch size is 1 (`preds.shape == (1, 10)`), calling `np.squeeze(preds)` without `axis` will drop the batch dimension too, turning `(1, 10)` into `(10,)`. In production pipelines, always pass `axis=...` explicitly to prevent dropping batch dimensions.

### Q11: How do `np.expand_dims()` and `np.newaxis` work, and are they identical?
- **Definition / Core Explanation**: Both `np.expand_dims()` and `np.newaxis` insert a new axis of length 1 into an array's shape at a designated position, enabling broadcasting.
- **Technical & Memory Mechanics**: In NumPy, `np.newaxis` is an exact alias for Python's `None`. When used in slicing syntax (`arr[:, np.newaxis]`), it instructs NumPy to insert a length-1 axis with a stride of 0 (or stride equal to the next dimension's stride). `np.expand_dims(a, axis)` is a functional wrapper around slicing with `None`. Both operations return zero-allocation **views**.
- **Production-Grade Code Example**:
```python
import numpy as np

x = np.array([1, 2, 3])  # Shape (3,)

# Using np.newaxis (or None)
x_col1 = x[:, np.newaxis]
x_col2 = x[:, None]

# Using np.expand_dims
x_col3 = np.expand_dims(x, axis=1)

assert x_col1.shape == x_col2.shape == x_col3.shape == (3, 1)
assert x_col1.base is x
assert np.newaxis is None  # True: exact alias!
print("Column vector shape:", x_col1.shape)
```
- **Interview Traps & Edge-Case Nuances**: Candidates often think `np.newaxis` creates a copy. It creates an $O(1)$ view.

### Q12: What does `order='K'` mean in `ravel()` and `reshape()`?
- **Definition / Core Explanation**: `order='K'` stands for "Keep" or "Known" memory order. It directs NumPy to flatten or reshape the array by reading elements in the exact order they occur in physical RAM, regardless of whether the array is C-contiguous, Fortran-contiguous, or has custom strides.
- **Technical & Memory Mechanics**: When an array has been transposed or strided, its memory layout is neither pure C nor pure Fortran. `ravel(order='K')` traverses memory along increasing physical addresses, avoiding memory copies and guaranteeing a view whenever possible.
- **Production-Grade Code Example**:
```python
import numpy as np

a = np.arange(6).reshape(2, 3)
a_trans = a.T  # Transposed array: non-contiguous in C-order

# C-order forces a copy because bytes are not row-contiguous in memory
rav_c = a_trans.ravel(order='C')
assert rav_c.base is not a_trans

# K-order returns a view by following physical memory layout!
rav_k = a_trans.ravel(order='K')
print("rav_k base is a_trans:", rav_k.base is a_trans or rav_k.base is a)
print("rav_k elements:", rav_k)  # [0, 1, 2, 3, 4, 5]
```
- **Interview Traps & Edge-Case Nuances**: Notice that `rav_k` visits elements in physical memory order (`[0, 1, 2, 3, 4, 5]`), which might differ from mathematical index order (`[0, 3, 1, 4, 2, 5]`).

### Q13: What does `order='A'` mean in array reshaping?
- **Definition / Core Explanation**: `order='A'` stands for "Any". It instructs NumPy to reshape or flatten the array in Fortran order (`'F'`) if and only if the input array is strictly Fortran-contiguous; otherwise, it defaults to C order (`'C'`).
- **Technical & Memory Mechanics**: Allows automated performance preservation when dealing with mixed pipelines where some matrices originate from Fortran/MATLAB routines and others from C/Python routines.
- **Production-Grade Code Example**:
```python
import numpy as np

c_arr = np.ones((2, 3), order='C')
f_arr = np.ones((2, 3), order='F')

flat_c = c_arr.ravel(order='A')
flat_f = f_arr.ravel(order='A')

print("flat_c is C-contiguous:", flat_c.flags.c_contiguous)
print("flat_f is F-contiguous:", flat_f.flags.f_contiguous)
assert flat_c.flags.c_contiguous
assert flat_f.flags.f_contiguous
```
- **Interview Traps & Edge-Case Nuances**: Assuming `'A'` preserves arbitrary custom striding like `'K'`. `'A'` checks only `flags.f_contiguous`.

### Q14: How does memory striding change when an array of shape $(2, 3, 4)$ is reshaped to $(6, 4)$?
- **Definition / Core Explanation**: For a C-contiguous array with itemsize 8 (float64), an array of shape $(2, 3, 4)$ has strides $(3 \times 4 \times 8, 4 \times 8, 8) = (96, 32, 8)$. When reshaped to $(6, 4)$, the new strides become $(4 \times 8, 8) = (32, 8)$.
- **Technical & Memory Mechanics**: The total memory footprint and byte sequence remain completely unaltered. NumPy merely replaces the 3-element shape and stride tuples in the C struct with 2-element tuples.
- **Production-Grade Code Example**:
```python
import numpy as np

arr = np.zeros((2, 3, 4), dtype=np.float64)
print("Original shape:  ", arr.shape)
print("Original strides:", arr.strides)

reshaped = arr.reshape(6, 4)
print("Reshaped shape:  ", reshaped.shape)
print("Reshaped strides:", reshaped.strides)

assert reshaped.strides == (32, 8)
assert reshaped.base is arr
```
- **Interview Traps & Edge-Case Nuances**: Interviewers often ask candidates to calculate strides by hand. The formula for dimension $i$ in a C-contiguous array is $\text{stride}_i = \text{itemsize} \times \prod_{j=i+1}^{D-1} \text{shape}_j$.

### Q15: Why can't a transposed array of shape $(3, 2)$ be reshaped to $(6,)$ as a VIEW?
- **Definition / Core Explanation**: When a $2 \times 3$ array is transposed to $3 \times 2$, its strides are swapped (e.g., from $(24, 8)$ to $(8, 24)$). To read the transposed array row-by-row into a 1D vector of length 6, the memory pointer must jump: $+8, +8$ (row 0), then back $-16 + 24 = +8$, etc.
- **Technical & Memory Mechanics**: A 1D view requires a single constant stride $S$ between consecutive elements ($P_k = P_0 + k \times S$). Because consecutive elements of the transposed matrix do not have a uniform step in physical memory, no single stride can represent the 1D sequence. Hence, NumPy **must allocate a new contiguous array and copy the data**.
- **Production-Grade Code Example**:
```python
import numpy as np

a = np.arange(6).reshape(2, 3)
t = a.T  # Transposed shape (3, 2)

print("Original strides:  ", a.strides)  # (24, 8)
print("Transposed strides:", t.strides)  # (8, 24)

# Reshaping transposed array forces a copy
flat_t = t.reshape(6)
print("flat_t shares memory with a:", np.shares_memory(flat_t, a))  # False!
assert not np.shares_memory(flat_t, a)
```
- **Interview Traps & Edge-Case Nuances**: Candidates often assume that transposing and reshaping always stays zero-copy. This is the single most tested view vs copy question in senior Python interviews.

### Q16: How do you verify programmatically whether two arrays share the exact same underlying memory buffer?
- **Definition / Core Explanation**: Use `np.shares_memory(a, b)` for a rigorous memory overlap check, or `np.may_share_memory(a, b)` for a fast heuristic check.
- **Technical & Memory Mechanics**: `a.base is b` checks only if `a` directly references `b`. It fails if both `a` and `b` are separate views pointing to a common root ancestor array! `np.shares_memory()` inspects the memory intervals and stride lattices of both arrays to determine if any byte overlap exists.
- **Production-Grade Code Example**:
```python
import numpy as np

root = np.arange(10)
view1 = root[:5]
view2 = root[2:8]

# base comparison fails to show relationship between siblings
print("view1.base is view2:", view1.base is view2)  # False!

# np.shares_memory correctly identifies common buffer
print("np.shares_memory(view1, view2):", np.shares_memory(view1, view2))  # True
assert np.shares_memory(view1, view2)
```
- **Interview Traps & Edge-Case Nuances**: Using `a is b` to check memory sharing. `a is b` checks Python object identity (whether they are the same variable), NOT whether they share underlying buffer memory.

### Q17: What is the performance difference between `arr.flatten()` and `arr.ravel()`?
- **Definition / Core Explanation**: For a contiguous array, `arr.ravel()` is $O(1)$ in time and $O(1)$ in memory because it creates a metadata view. `arr.flatten()` is $O(N)$ in time and $O(N)$ in memory because it allocates a new buffer and copies every element.
- **Technical & Memory Mechanics**: For a $10^7$ float64 array (~80 MB), `ravel()` takes nanoseconds (metadata update), while `flatten()` takes ~15–30 milliseconds (heap allocation + memory bandwidth copy).
- **Production-Grade Code Example**:
```python
import numpy as np
import time

arr = np.zeros((1000, 10000), dtype=np.float64)  # 80 MB

# Benchmark ravel()
t0 = time.perf_counter()
rav = arr.ravel()
t_ravel = time.perf_counter() - t0

# Benchmark flatten()
t0 = time.perf_counter()
flat = arr.flatten()
t_flatten = time.perf_counter() - t0

print(f"ravel() time:   {t_ravel * 1e6:.2f} microseconds")
print(f"flatten() time: {t_flatten * 1e3:.2f} milliseconds")
print(f"Speedup:        {t_flatten / t_ravel:.1f}x")
```

### 3.C Theoretical Nuances (Q41–Q50)

### Q41: What are the exact mathematical conditions under which an $N$-dimensional array can be reshaped as a VIEW without memory copying?
- **Definition / Core Explanation**: An array can be reshaped into a new shape $(d'_0, d'_1, \dots, d'_{M-1})$ as a zero-allocation view if and only if the original data layout can be partitioned into contiguous chunks that align with the new dimension boundaries.
- **Technical & Memory Mechanics**: In NumPy's C implementation (`array_assign_array`), the runtime checks whether adjacent dimensions are "compatible" by verifying the stride relation: $\text{stride}_i = \text{shape}_{i+1} \times \text{stride}_{i+1}$. If all dimensions to be collapsed satisfy this relation, a single combined stride can represent the collapsed axis. If any collapsed dimension has custom slicing or transposition gaps, the stride relation fails, making view creation mathematically impossible and forcing a heap copy.
- **Production-Grade Code Example**:
```python
import numpy as np

# Compatible strides: contiguous 2x3x4 array
arr = np.arange(24).reshape(2, 3, 4)
print("Original strides:", arr.strides)  # (96, 32, 8)

# Merging first two dimensions (2, 3) -> 6:
# Since stride[0] (96) == shape[1] (3) * stride[1] (32), this can be a VIEW
res = arr.reshape(6, 4)
print("Reshaped strides:", res.strides)  # (32, 8)
assert res.base is arr  # Confirms VIEW!
```
- **Interview Traps & Edge-Case Nuances**: Many candidates assume that any contiguous array can be reshaped as a view. While true for contiguous arrays, if an array is non-contiguous, only dimensions whose sub-blocks are internally contiguous can be reshaped without copying.

### Q42: Why does `a.T.reshape(-1)` require a copy, whereas `a.T.ravel(order='K')` returns a view?
- **Definition / Core Explanation**: `a.T.reshape(-1)` defaults to C-order (`order='C'`), which requires reading elements in row-major order of the transposed matrix. Because the transposed matrix has swapped strides, row-major elements are not consecutive in memory, forcing a copy. In contrast, `order='K'` instructs NumPy to visit elements in their **existing physical memory order**, which matches the contiguous order of the underlying buffer, allowing an $O(1)$ view.
- **Technical & Memory Mechanics**: `a.T` has strides $(8, 24)$ instead of $(24, 8)$. Reading row-major means stepping by $8$, then jumping by $-16 + 24$. No single stride can represent this sequence. But physical memory order simply traverses the original buffer with stride $8$, exactly matching the underlying root array!
- **Production-Grade Code Example**:
```python
import numpy as np

a = np.arange(6).reshape(2, 3)
t = a.T

# Default C-order reshape forces a copy
flat_c = t.reshape(-1)
assert not np.shares_memory(flat_c, a)

# K-order ravel returns a VIEW!
flat_k = t.ravel(order='K')
assert np.shares_memory(flat_k, a)

print("C-order copy elements: ", flat_c)  # [0, 3, 1, 4, 2, 5]
print("K-order view elements: ", flat_k)  # [0, 1, 2, 3, 4, 5]
```
- **Interview Traps & Edge-Case Nuances**: Notice that the element order differs! `flat_c` reflects the transposed index order, whereas `flat_k` reflects the physical storage order.

### Q43: How do C-order and Fortran-order memory layouts impact multi-dimensional tensor contraction and BLAS operations?
- **Definition / Core Explanation**: BLAS and LAPACK routines (like `dgemm` for matrix multiplication) are historically implemented in Fortran, expecting Fortran-contiguous (column-major) arrays. Modern BLAS libraries (Intel MKL, OpenBLAS) support C-contiguous matrices by either transposing operations internally or utilizing row-major wrappers.
- **Technical & Memory Mechanics**: When computing $C = A @ B$ where $A$ is C-contiguous and $B$ is C-contiguous, the inner loop computes a dot product between row $i$ of $A$ and column $j$ of $B$. In C-order, rows of $A$ are contiguous in cache, but columns of $B$ are strided! Transposing $B$ to Fortran order beforehand makes columns of $B$ contiguous, yielding optimal L1/L2 cache prefetching.
- **Production-Grade Code Example**:
```python
import numpy as np
import time

N = 2000
A = np.random.randn(N, N)
B_c = np.random.randn(N, N)  # C-order
B_f = np.asfortranarray(B_c) # F-order

# Warm up
_ = A @ B_c

t0 = time.perf_counter()
res_c = A @ B_c
t_c = time.perf_counter() - t0

t0 = time.perf_counter()
res_f = A @ B_f
t_f = time.perf_counter() - t0

print(f"Multiply with C-order B: {t_c * 1000:.2f} ms")
print(f"Multiply with F-order B: {t_f * 1000:.2f} ms")
```
- **Interview Traps & Edge-Case Nuances**: Believing that memory order is purely cosmetic; in large-scale linear algebra, stride alignment with cache lines accounts for up to 30% performance differences.

### Q44: What are the memory reference cycle and garbage collection implications of chaining views (`view.base.base...`)?
- **Definition / Core Explanation**: When an array view is created, its `base` attribute references the parent array. As long as any view remains referenced, the entire original data buffer cannot be garbage collected, even if the parent variable is deleted.
- **Technical & Memory Mechanics**: If you load a 10 GB dataset into memory, take a small 1 MB slice, reshape it into a view, and delete the 10 GB variable (`del large_arr`), **all 10 GB remains pinned in physical RAM** because `view.base` holds an active reference to the entire buffer! To free the memory, you must explicitly call `.copy()` on the slice or reshaped view.
- **Production-Grade Code Example**:
```python
import numpy as np
import sys

# Create large 10-million float buffer (~80 MB)

# Take small reshaped view of 5 elements
small_view = large_arr[:5].reshape(5, 1)

# Delete original array variable
del large_arr

# The 80 MB buffer is still pinned in RAM by small_view.base!
print("small_view.base is alive:", small_view.base is not None)
print("Pinned memory size:", small_view.base.nbytes / (1024 * 1024), "MB")
assert small_view.base.nbytes > 70_000_000

# Fix: Create isolated copy and delete view
isolated_copy = small_view.copy()
del small_view
print("Isolated copy base is None:", isolated_copy.base is None)
```
- **Interview Traps & Edge-Case Nuances**: Silent memory leaks in production servers where tiny reshaped views extracted from large requests prevent the operating system from reclaiming gigabytes of memory.

### Q50: How does NumPy's internal C implementation `PyArray_Newshape` validate shape compatibility?
- **Definition / Core Explanation**: `PyArray_Newshape` in `arrayobject.c` performs dimension validation. It calculates the product of positive dimensions. If a `-1` is present, it divides the array's total element count by this product.

```python
    print("Caught non-divisible error:", e)

    arr.reshape(-1, -1)
except ValueError as e:
    print("Caught multiple -1 error:", e)
```
- **Interview Traps & Edge-Case Nuances**: Understanding this 4-step C pipeline allows candidates to answer any edge case question regarding reshape validation instantly.

## 7. Interview Traps (10 Traps)
1. **The Transpose-Reshape Trap**: "Does `arr.T.reshape(-1)` create a view?" (Answer: No, it forces a copy because transposed strides are non-contiguous in C-order).
2. **The K-Order Bypass Trap**: "How can you flatten a transposed array as a VIEW?" (Answer: Use `arr.T.ravel(order='K')`).
3. **The Channel Swap Trap**: "Can I convert an image from $(3, 32, 32)$ to $(32, 32, 3)$ using `reshape(32, 32, 3)`?" (Answer: No, it scrambles spatial pixel values; you must use `transpose(1, 2, 0)`).
4. **The Squeeze Batch Trap**: "Why did my ML model fail in production when test batch size was 1?" (Answer: `np.squeeze()` dropped the batch axis too; must specify `axis=(...)`).
5. **The Memory Pinning Trap**: "Why is my process consuming 5 GB of RAM after `del large_dataset`?" (Answer: A tiny reshaped view still holds a reference to the buffer in `view.base`).
6. **The Double -1 Trap**: "Can you do `arr.reshape(-1, -1)` if `arr.size == 16`?" (Answer: No, raises `ValueError: can only specify one unknown dimension`).
7. **The Resize Zero-Padding Trap**: "Does `np.resize` pad with zeros?" (Answer: No, `np.resize` repeats elements; `ndarray.resize` pads with zeros).
8. **The Reshape In-Place Trap**: "Does `arr.shape = (M, N)` create a copy if the array is non-contiguous?" (Answer: No, it raises an `AttributeError`).
9. **The Writable Clone Trap**: "How can you make a mutable copy of a read-only array in one call?" (Answer: `read_only_arr.flatten()`).
10. **The Base Inheritance Trap**: "If `b = a.reshape(...)` and `c = b.reshape(...)`, is `c.base is b`?" (Answer: Usually `c.base is a`; NumPy links directly to the root owner).

### Q74: How do you reshape embedding tensors for Multi-Head Attention in Transformer architectures?
- **Definition / Core Explanation**: In Transformer Self-Attention, input token representations of shape $(B, S, D)$ (Batch, Sequence Length, Embedding Dimension) must be projected into $H$ heads of dimension $D_k = D / H$:
  $$(B, S, D) \longrightarrow (B, S, H, D_k) \longrightarrow (B, H, S, D_k)$$
- **Technical & Memory Mechanics**: Reshaping $(B, S, D) \to (B, S, H, D_k)$ splits the embedding channels. Then `transpose(0, 2, 1, 3)` swaps the sequence length and head axes so that subsequent matrix multiplications operate in parallel across heads.
- **Production-Grade Code Example**:
```python

S = 4   # Sequence length (tokens)
D = 16  # Model embedding dimension
H = 4   # Number of attention heads
D_k = D // H  # Head dimension = 4

Q = np.random.randn(B, S, D)

# Step 1: Reshape to split heads
Q_split = Q.reshape(B, S, H, D_k)
assert Q_split.base is Q

# Step 2: Transpose to (B, H, S, D_k)
Q_heads = Q_split.transpose(0, 2, 1, 3)

print("Original shape: ", Q.shape)
print("Multi-head shape:", Q_heads.shape)
assert Q_heads.shape == (2, 4, 4, 4)
```
- **Interview Traps & Edge-Case Nuances**: Attempting to go directly from $(B, S, D)$ to $(B, H, S, D_k)$ via `reshape(B, H, S, D_k)` corrupts token representations! Reshape splits elements within tokens; `transpose` is mandatory to move the head axis forward.

### Q75: How do you reshape and de-interleave multi-channel stereo audio buffers?

```python
right_channel = deinterleaved[1]
```

## 13. Flashcards (15 Flashcards)

#### Flashcard 1
- **Front**: Under what conditions does `np.reshape()` return a view?
- **Back**: When the memory buffer is contiguous and compatible strides can be recalculated without rearranging bytes. If non-contiguous, it silently returns a copy.
- **Key Insight**: Never assume `reshape()` is always $O(1)$ zero-copy.

#### Flashcard 2
- **Front**: What is the fundamental difference between `flatten()` and `ravel()`?
- **Back**: `flatten()` ALWAYS returns a new copy in heap memory. `ravel()` returns a VIEW if the array is contiguous, falling back to a copy only when non-contiguous.
- **Key Insight**: Use `ravel()` for performance; use `flatten()` for mutation isolation.

#### Flashcard 3
- **Front**: How does the `-1` dimension inference work in `reshape()`?
- **Back**: Inferred as $\text{total\_elements} / \prod \text{known\_dimensions}$. At most one `-1` is allowed; otherwise raises `ValueError`.
- **Key Insight**: Total elements must be evenly divisible by known dimensions.

#### Flashcard 4
- **Front**: Why does `arr.reshape(H, W, C)` fail to convert a Channel-First image to Channel-Last?
- **Back**: `reshape()` preserves sequential C-order memory bytes; it does not permute axes. Converting $(C, H, W) \to (H, W, C)$ requires `np.transpose(1, 2, 0)`.
- **Key Insight**: Reshape restructures dimensions; transpose permutes axes.

#### Flashcard 5
- **Front**: Why does `a.T.reshape(-1)` force a memory copy?
- **Back**: Transposing swaps strides, making row-major traversal non-contiguous. No single stride can represent row-major traversal of transposed data, forcing a copy.
- **Key Insight**: `a.T.ravel(order='K')` avoids the copy by following physical memory order.

#### Flashcard 6
- **Front**: What happens when you assign directly to `arr.shape = (M, N)`?
- **Back**: Modifies shape in-place without creating a new wrapper object. If the array is non-contiguous, it raises `AttributeError`.
- **Key Insight**: Unlike `reshape()`, in-place assignment never falls back to a copy.

#### Flashcard 7
- **Front**: What do `'C'`, `'F'`, `'A'`, and `'K'` memory orders mean?
- **Back**: `'C'`: Row-major (C-style). `'F'`: Column-major (Fortran-style). `'A'`: Fortran if input is F-contiguous, else C. `'K'`: Keep physical memory order.
- **Key Insight**: `'K'` enables zero-copy views on transposed or strided arrays.

#### Flashcard 8
- **Front**: Why can a small reshaped view cause a memory leak?
- **Back**: A view holds a reference to the entire parent array buffer via its `base` attribute, preventing garbage collection of the entire buffer.
- **Key Insight**: Call `.copy()` on the small view to allow the parent buffer to be freed.

#### Flashcard 9
- **Front**: Why is `np.squeeze()` dangerous without the `axis` parameter?
- **Back**: It drops ALL length-1 axes. In single-sample test inference (batch size 1), it drops the batch axis, corrupting downstream layer shapes.
- **Key Insight**: Always pass explicit axes: `np.squeeze(arr, axis=(2, 3))`.

#### Flashcard 10
- **Front**: What is the difference between `np.expand_dims()` and `np.newaxis`?
- **Back**: `np.newaxis` is an alias for Python's `None` used in slicing syntax. `np.expand_dims()` is a functional wrapper. Both return zero-copy views.
- **Key Insight**: `x[:, None]` is identical to `np.expand_dims(x, 1)`.

#### Flashcard 11
- **Front**: How does `np.resize()` differ from `reshape()`?
- **Back**: `reshape()` preserves total element count. `np.resize()` creates a new array, repeating elements cyclically if larger, or truncating if smaller.
- **Key Insight**: `ndarray.resize()` zero-pads instead of repeating.

#### Flashcard 12
- **Front**: How do you check if two sibling views share memory?
- **Back**: Use `np.shares_memory(a, b)`. `a.base is b` fails because sibling views both point to a common parent root, not each other.
- **Key Insight**: `shares_memory` inspects the underlying memory buffer bounds.

#### Flashcard 13
- **Front**: What happens if you call `flatten()` on a read-only array?
- **Back**: Returns a brand-new writable copy (`flags.writeable == True`).
- **Key Insight**: `flatten()` breaks out of read-only locks into a fresh mutable buffer.

#### Flashcard 14
- **Front**: What are the new strides when reshaping $(2, 3, 4)$ to $(6, 4)$ for float64?
- **Back**: Original strides were $(96, 32, 8)$. New strides are $(32, 8)$.
- **Key Insight**: Stride formula: $\text{stride}_i = \text{itemsize} \times \prod_{j>i} \text{shape}_j$.

#### Flashcard 15
- **Front**: Can an array be reshaped into an empty shape?
- **Back**: Yes, if its size is 0, it can be reshaped to any shape with product 0 (e.g., `(0, 5)`).
- **Key Insight**: `(0, -1)` raises `ValueError` because $0/0$ is undefined.

## 14. NumPy Interview Cheat Sheet
```
====================================================================================================
NUMPY ARRAY RESHAPING CHEAT SHEET
====================================================================================================
Core Reshaping Functions:
  arr.reshape(*shape, order='C') : Returns a VIEW if contiguous; falls back to COPY if needed.
  arr.ravel(order='C')          : Returns a 1D VIEW if contiguous; falls back to COPY if needed.
  arr.flatten(order='C')        : ALWAYS returns a newly allocated 1D COPY. Guaranteed safe mutation.
  arr.shape = (M, N)            : In-place metadata mutation. Raises AttributeError if copy needed.

Memory Orders:
  order='C'                     : Row-major (last axis varies fastest). Default.
  order='F'                     : Column-major (first axis varies fastest).
  order='A'                     : Fortran if array is F-contiguous, else C.
  order='K'                     : Keep physical memory layout (zero-copy for transposed views).

Dimensionality Helpers:
  np.expand_dims(arr, axis)     : Inserts length-1 dimension. Zero-copy VIEW.
  arr[:, np.newaxis] / [None]   : Inserts length-1 dimension via slicing. Zero-copy VIEW.
  np.squeeze(arr, axis=...)     : Removes length-1 dimensions. Zero-copy VIEW.
  np.resize(arr, new_shape)     : Returns a COPY. Repeats or truncates elements.

Verification & Inspection:
  arr.base                      : Points to owner array (None if owns memory).
  np.shares_memory(a, b)        : Rigorous check for overlapping memory buffers.
  np.ascontiguousarray(arr)     : Returns C-contiguous array (view if already contiguous, else copy).
====================================================================================================
```

## 15. Fresher Answer Patterns (4 Patterns)

### Pattern 1: Answering "What is the difference between `flatten()` and `ravel()`?"
- **Structure**:
  1. **Memory Allocation**: State clearly that `flatten()` **always** allocates new heap memory and copies data, while `ravel()` returns a **view** whenever possible.
  2. **Mutation Safety**: Explain that modifying `flatten()` is safe (isolated copy), while modifying `ravel()` mutates the original parent array.
  3. **Performance**: Highlight that `ravel()` is $O(1)$ in time and memory for contiguous arrays, whereas `flatten()` is $O(N)$.
  4. **Recommendation**: Recommend `ravel()` for read-only operations and performance, and `flatten()` when mutation isolation is mandatory.

### Pattern 2: Answering "How does `-1` work in `reshape()`?"
- **Structure**:
  1. **Automatic Inference**: Explain that `-1` tells NumPy to calculate that dimension automatically from total element count and known dimensions.
  2. **Strict Limit**: Emphasize that **at most one** `-1` can be specified; multiple `-1`s raise `ValueError`.
  3. **Divisibility Requirement**: Note that total elements must be evenly divisible by the product of known dimensions.

### Pattern 3: Answering "Why does `a.T.reshape(-1)` create a copy?"
- **Structure**:
  1. **Stride Inversion**: Explain that transposing swaps the strides, making rows non-contiguous in physical memory.
  2. **Single Stride Constraint**: Explain that a 1D view requires a constant single stride between consecutive elements.
  3. **Fallback to Copy**: Note that because consecutive row elements in the transposed array cannot be represented by a single stride, NumPy must allocate a copy.
  4. **The `order='K'` Solution**: Mention that `a.T.ravel(order='K')` creates a view by traversing physical memory order.

### Pattern 4: Answering "Why can't I convert $(C, H, W)$ to $(H, W, C)$ using `reshape`?"
- **Structure**:
  1. **Memory Sequence vs Axis Permutation**: Explain that `reshape` reads and writes in sequential C-order without reordering axes.
  2. **Feature Smearing**: Point out that reshaping across channels interleaves spatial coordinates, destroying pixel geometry.
  3. **Correct Primitive**: State that axis permutation requires `np.transpose(arr, (1, 2, 0))`.

- **Definition / Core Explanation**: In image processing and generative models (GANs, Diffusion), a batch of $B = K \times K$ generated images of shape $(B, H, W, C)$ is often arranged into a single large grid image of shape $(K \times H, K \times W, C)$ for visualization.

- **Production-Grade Code Example**:
```python
import numpy as np

def make_image_grid(batch_images: np.ndarray, grid_rows: int, grid_cols: int) -> np.ndarray:
    """Arranges a batch of (B, H, W, C) images into a (grid_rows*H, grid_cols*W, C) mosaic."""
    B, H, W, C = batch_images.shape
    assert B == grid_rows * grid_cols, "Batch size must equal rows * cols!"

    grid = batch_images.reshape(grid_rows, grid_cols, H, W, C)
    # 2. Transpose to interleave grid rows with pixel height, grid cols with pixel width
    grid = grid.transpose(0, 2, 1, 3, 4)
```

### Q78: Natural Language Processing — Reshaping Skip-Gram Word2Vec Training Batches
- **Definition / Core Explanation**: In Word2Vec skip-gram models, a sliding context window generates pairs of `(center_word, context_word)`. Reshaping transforms flat sequence windows into 2D batch matrices of shape $(N_{\text{pairs}}, 2)$.

- **Production-Grade Code Example**:
```python
import numpy as np
from numpy.lib.stride_tricks import sliding_window_view

def generate_skipgram_pairs(token_ids: np.ndarray, window_radius: int = 2) -> np.ndarray:
    """Extracts (center, context) token pairs using sliding windows and reshaping."""
    window_len = 2 * window_radius + 1
    # Extract all context windows: shape (num_windows, window_len)
    windows = sliding_window_view(token_ids, window_shape=window_len)
    
    center_tokens = windows[:, window_radius]
    
    # Build pairs
    pairs = []
    for offset in range(-window_radius, window_radius + 1):
        if offset != 0:
            context = windows[:, window_radius + offset]
            pairs.append(np.column_stack((center_tokens, context)))
            
    return np.vstack(pairs)

skipgram_pairs = generate_skipgram_pairs(tokens, window_radius=1)
print("Skip-gram pairs shape:", skipgram_pairs.shape)
```

### Q82: Reshape + Slicing — Why Strided Slicing Forces Reshape Copies

- **Theoretical Assessment**: Demonstrates deep understanding of memory contiguity in stride calculations.
- **Production-Grade Code Example**:
```python
import numpy as np

arr = np.arange(20)

contiguous_slice = arr[:10]
strided_slice = arr[::2]

res_view = contiguous_slice.reshape(2, 5)
res_copy = strided_slice.reshape(2, 5)

print("Contiguous slice reshape shares memory:", np.shares_memory(res_view, arr))  # True
print("Strided slice reshape shares memory:   ", np.shares_memory(res_copy, arr))  # False
```

```
====================================================================================================
NUMPY ARRAY RESHAPING MEMORIZATION SPECIFICATION
====================================================================================================
1. Reshape Core Law       : prod(new_shape) == prod(orig_shape) == arr.size. Raises ValueError if false.
2. View vs Copy           :
     - reshape()          : VIEW if contiguous; falls back to COPY if non-contiguous.
     - ravel()            : 1D VIEW if contiguous; falls back to COPY if non-contiguous.
     - flatten()          : ALWAYS a COPY on the heap. Guaranteed memory isolation.
3. Unknown Dimension      : At most ONE dimension can be specified as -1.
4. Channel Reordering     : Converting (C, H, W) -> (H, W, C) REQUIRES np.transpose(1, 2, 0).
5. Transposed Flatten     : a.T.reshape(-1) is a COPY; a.T.ravel(order='K') is a VIEW.
6. Memory Orders          :
     - 'C'                : Row-major (C-style). Last index changes fastest.
     - 'F'                : Column-major (Fortran-style). First index changes fastest.
     - 'K'                : Keep physical memory layout order (avoids copies).
7. In-Place Shape         : arr.shape = (M, N) raises AttributeError if non-contiguous (never copies).
8. Singleton Axes         :
     - Expand             : arr[:, np.newaxis] or arr[None, ...] or np.expand_dims(arr, axis).
     - Squeeze            : np.squeeze(arr, axis=...) removes length-1 dimensions.
9. Memory Leak Protection : Sub-array views hold entire parent buffer in .base. Call .copy() to isolate.
10. Memory Overlap Check  : Use np.shares_memory(a, b). Never use 'a is b' or 'a.base is b'.
====================================================================================================
```

1. **Interviewer**: "What is the primary difference between `flatten()` and `ravel()`?"

   **Candidate**: "When the array's memory layout is non-contiguous (e.g. after transposing or non-unit slicing) such that the requested shape cannot be represented by a valid set of linear strides over the existing buffer."

   **Candidate**: "No! `reshape` preserves sequential C-order memory bytes; it does not permute axes. Doing so interleaves pixels across channels, destroying image features. You must use `np.transpose(arr, (1, 2, 0))`."
5. **Interviewer**: "Why does `a.T.reshape(-1)` create a copy?"  
   **Candidate**: "Because transposing swaps strides, making row-major access non-contiguous. A 1D view requires a single constant stride between consecutive elements, which is impossible across transposed rows."
6. **Interviewer**: "How can you flatten a transposed matrix without allocating a copy?"  
   **Candidate**: "Use `a.T.ravel(order='K')`. The `'K'` order visits elements in physical memory order, matching the contiguous underlying buffer."

11. **Interviewer**: "How can a small reshaped view cause a memory leak?"

```python
5. In-place shape mutation verification.
6. Memory sharing audit via np.shares_memory.

import numpy as np

def verify_reshaping_production_pipeline():
    print("=== Production Reshaping Pipeline Demonstration ===")
    
    # 1. Zero-copy reshape and -1 dimension inference
    arr = np.arange(24)
    reshaped_3d = arr.reshape(2, 3, -1)
    assert reshaped_3d.shape == (2, 3, 4)
    assert reshaped_3d.base is arr
    print("[OK] Reshape view creation and -1 inference verified.")
    
    # 2. Flatten (isolated copy) vs Ravel (shared view)
    orig = np.array([[10, 20], [30, 40]])
    flat_copy = orig.flatten()
    rav_view = orig.ravel()
    
    # Mutating view updates original
    rav_view[0] = 999
    assert orig[0, 0] == 999
    
    # Mutating copy does not update original
    flat_copy[1] = 888
    assert orig[0, 1] == 20
    print("[OK] Flatten (isolated copy) vs Ravel (shared view) verified.")
    
    # 3. Transposed matrix flattening view via order='K'
    a = np.arange(6).reshape(2, 3)
    t = a.T
    flat_c = t.reshape(-1)        # Copy
    flat_k = t.ravel(order='K')   # View
    assert not np.shares_memory(flat_c, a)
    assert np.shares_memory(flat_k, a)
    print("[OK] Transposed flattening view via order='K' verified.")
    
    # 4. Safe dimension expansion and selective squeezing
    feat = np.zeros((1, 64, 1, 1))
    # Squeeze only spatial dimensions, strictly preserving batch dim at axis 0
    safe_sq = np.squeeze(feat, axis=(2, 3))
    assert safe_sq.shape == (1, 64)
    
    # Expand dims via newaxis
    re_expanded = safe_sq[:, :, np.newaxis, np.newaxis]
    assert re_expanded.shape == (1, 64, 1, 1)
    assert re_expanded.base is feat
    print("[OK] Selective squeezing and expansion verified.")
    
    # 5. In-place shape assignment
    m = np.arange(12)
    addr_before = m.__array_interface__['data'][0]
    m.shape = (3, 4)
    addr_after = m.__array_interface__['data'][0]
    assert addr_before == addr_after
    assert m.shape == (3, 4)
    print("[OK] In-place shape mutation verified.")
    
    # 6. Sibling view memory overlap audit
    root = np.arange(20)
    v1 = root[:10].reshape(2, 5)
    v2 = root[5:15].reshape(2, 5)
    assert np.shares_memory(v1, v2)
    print("[OK] Sibling view memory overlap audit verified.")
    
    print("\nAll production reshaping pipelines executed successfully!")

if __name__ == "__main__":
```
