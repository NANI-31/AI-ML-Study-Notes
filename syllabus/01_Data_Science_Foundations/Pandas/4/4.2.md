# 4. Data Selection and Indexing

## 4.2 Selecting Rows

---

## 1. Section Overview

Row selection forms the core operational mechanic for filtering, sampling, partitioning, and inspecting individual records in Pandas. While column selection isolates features, row selection controls the observation space across time, entity cohorts, experimental splits (train/validation/test), and boundary states. In technical data engineering and data science interviews, row selection is intensely tested because indexing ambiguity—particularly confusing label-based indexing (`loc`) with integer position-based indexing (`iloc`)—is the number one source of production logic errors, off-by-one boundary bugs, and runtime performance regressions in tabular data workflows.

### Core Practical Themes
- **Label vs Position Duality**: Navigating the critical distinction between label identity (`loc[]`, where endpoints are fully inclusive) and physical integer coordinates (`iloc[]`, where slices follow standard Python half-open conventions `[start:stop)`).
- **Index Architecture**: Understanding how `RangeIndex`, custom string indices, and timestamp indices alter row lookup mechanics, hash collisions, and slice ordering.
- **Boundary Extraction**: Idiomatic selection of edge records (first, last, extremes) using `head()`, `tail()`, `iloc[0]`, `iloc[-1]`, and tensor dimension preservation (`iloc[[0]]` vs `iloc[0]`).
- **Memory & Slicing Semantics**: Analyzing zero-copy shallow views versus deep defensive copies under modern Pandas Copy-on-Write (CoW).

### Production & Interview Relevance
Hiring managers expect candidates to know not only the syntactic differences between `.loc` and `.iloc`, but also the underlying computational mechanics: why integer labels cause silent bugs when indices are shuffled, how `.iloc` behaves under negative indices, why `.loc` includes the stop endpoint, and how to write deterministic row slicing code that never triggers `SettingWithCopyWarning` or unexpected `IndexError` / `KeyError` exceptions.

## 2. Topic-Wise Interview Concepts

### Topic 1: Selecting Rows by Index
- **1. What it is**: Accessing records based on the index labels assigned to the DataFrame's vertical axis (axis 0).
- **2. Why it exists**: Real-world tabular records possess natural business identifiers (user IDs, timestamps, product SKUs, transaction hashes). The index provides an associative lookup mechanism to retrieve observations directly by identity.
- **3. How Pandas handles it under the hood**:
  - `df.index` maintains an internal hash table engine (`_engine.mapping`).
  - When querying by index label, Pandas hashes the search key and looks up its integer location in $O(1)$ amortized time.
  - If the index contains duplicate labels, the hash table maps to a slice or boolean mask, returning a DataFrame instead of a Series.
- **4. Key methods, parameters, variations**:
  - `df.loc[label]`: Explicit label lookup (returns Series for unique label, DataFrame for duplicate labels).
  - Single-bracket slice `df['label_start':'label_stop']`: Evaluates across row index labels (inclusive).
  - Boolean index alignment: Selecting rows where index matches a set or condition.
- **5. Common interview questions**:
  - *"What happens if an index contains duplicate labels and you query `df.loc['dup_label']`?"*
  - *"Why is single-bracket row slicing like `df[0:5]` discouraged in production code?"*
  - *"How does a default `RangeIndex` differ from an explicit `Int64Index`?"*
- **6. Edge cases & pitfalls**:
  - Shuffled integer indices: If a DataFrame has index `[3, 1, 0, 2]`, calling `df.loc[1]` returns the record with label `1`, NOT the second row.
  - Non-monotonic indices: Slicing non-sorted string indices with `.loc['a':'c']` can raise `KeyError` in older Pandas versions or produce unintuitive results.
- **7. Code example**:
  ```python
  import pandas as pd

  df = pd.DataFrame(
      {"user": ["Alice", "Bob", "Charlie"]},
      index=["u101", "u102", "u103"]
  )

  # Exact label lookup
  row_series = df.loc["u102"]
  print(type(row_series))  # <class 'pandas.core.series.Series'>
  print(row_series["user"])  # 'Bob'

  # Label slicing (inclusive of stop!)
  row_slice = df.loc["u101":"u102"]
  print(row_slice.index.tolist())  # ['u101', 'u102']
  ```
- **8. Rule of thumb for interviews**: Always clarify whether an operation relies on label identity or positional order. If an index has integer labels, never use single brackets for row access.

### Topic 2: Selecting Rows Using `loc[]`
- **1. What it is**: The primary, label-based indexer for selecting rows (and optionally columns) by their explicit names, labels, or boolean conditions.
- **2. Why it exists**: Provides an unambiguous, explicit syntax for 2D coordinate referencing that avoids the dual-interpretation ambiguities of standard Python brackets.
- **3. How Pandas handles it under the hood**:
  - `df.loc` is an instance of the `_LocIndexer` class.
  - Slices passed to `loc` are **inclusive of both start and stop boundaries** (`[start, stop]`). This is because in non-numeric label sequences (e.g., `'Jan':'Dec'`), there is no natural "next" element to represent an exclusive endpoint.
  - Accepts single labels, lists of labels, label slices, boolean arrays, and callables.
- **4. Key methods, parameters, variations**:
  - `df.loc[row_label]`: Single row Series extraction.
  - `df.loc[[row_label]]`: Single row DataFrame extraction (preserves 2D tensor shape).
  - `df.loc[row_list]`: Multi-row projection by label list.
  - `df.loc[start_label:stop_label]`: Inclusive range slice.
  - `df.loc[boolean_condition]`: Boolean row filtering.
- **5. Common interview questions**:
  - *"Why is `loc` endpoint-inclusive while standard Python slicing is endpoint-exclusive?"*
  - *"What does `df.loc[0]` do if the index is a string index containing `'0'` vs integer `0`?"*
  - *"What happens if you pass a list of labels to `loc` where some labels do not exist?"*
- **6. Edge cases & pitfalls**:
  - Missing labels: In modern Pandas, passing non-existent labels in a list raises `KeyError`.
  - Type sensitivity: If the index is string `'0'`, querying integer `df.loc[0]` raises `KeyError`.
  - Modifying slices: Chained indexing `df.loc[rows]['col'] = val` causes `SettingWithCopyWarning`. Always use atomic 2D coordinates: `df.loc[rows, 'col'] = val`.
- **7. Code example**:
  ```python
  import pandas as pd

  df = pd.DataFrame(
      {"revenue": [100, 200, 300, 400]},
      index=["q1", "q2", "q3", "q4"]
  )

  # Inclusive slice: BOTH q1 and q3 appear!
  print(df.loc["q1":"q3"].index.tolist())  # ['q1', 'q2', 'q3']

  # Boolean masking via loc
  high_rev = df.loc[df["revenue"] > 250]
  print(high_rev.index.tolist())  # ['q3', 'q4']
  ```
- **8. Rule of thumb for interviews**: `loc` is strictly label-based. Its slices are **always closed/inclusive** of both endpoints.

### Topic 3: Selecting Rows Using `iloc[]`
- **1. What it is**: The pure integer position-based indexer for selecting rows by their 0-indexed physical location within the DataFrame.
- **2. Why it exists**: Datasets often lack clean business keys or have arbitrary indices. Positional indexing allows algorithmic operations: fetching the top $k$ rows, sampling alternating rows, or extracting matrix boundaries invariant to index labels.
- **3. How Pandas handles it under the hood**:
  - `df.iloc` is an instance of `_iLocIndexer`.
  - Slices passed to `iloc` adhere strictly to standard Python / NumPy half-open interval conventions: `[start:stop)` where `start` is included and `stop` is **excluded**.
  - Negative integers count backward from the end (`-1` is the last row), identical to Python list indexing.
  - Maps directly to C-level array offsets within the internal NumPy/Arrow buffers.
- **4. Key methods, parameters, variations**:
  - `df.iloc[i]`: 1D Series of the row at physical offset $i$.
  - `df.iloc[[i]]`: 2D DataFrame of the row at physical offset $i$.
  - `df.iloc[start:stop:step]`: Positional slicing with optional stride.
  - `df.iloc[[0, 3, 5]]`: Positional list extraction.
  - `df.iloc[-1]`: Last row extraction.
- **5. Common interview questions**:
  - *"Contrast the slicing endpoint behavior of `loc` and `iloc`."*
  - *"What error is raised if you supply an out-of-bounds integer to `iloc[100]` vs `iloc[10:100]`?"*
  - *"Can you pass boolean arrays to `iloc`?"*
- **6. Edge cases & pitfalls**:
  - Scalar out-of-bounds: `df.iloc[100]` on a 10-row table raises `IndexError: single positional indexer is out-of-bounds`.
  - Slice out-of-bounds: `df.iloc[5:100]` on a 10-row table does NOT raise an error; it gracefully returns rows 5 to 9 (Python slice parity).
  - Boolean index alignment: Boolean series passed to `iloc` must have identical integer length or be converted to a NumPy boolean array/list; passing an unaligned boolean Series can raise `IndexError`.
- **7. Code example**:
  ```python
  import pandas as pd

  df = pd.DataFrame(
      {"val": [10, 20, 30, 40, 50]},
      index=[100, 200, 300, 400, 500]  # Non-0-based index
  )

  # iloc targets physical 0-based position:
  print(df.iloc[0]["val"])  # 10 (at offset 0, index 100)
  print(df.loc[100]["val"]) # 10 (at label 100)

  # Half-open slice: stop position 3 is EXCLUDED (offsets 0, 1, 2)
  print(df.iloc[0:3].index.tolist())  # [100, 200, 300]
  ```
- **8. Rule of thumb for interviews**: `iloc` is strictly position-based (0 to $N-1$). Its slices are **half-open** (stop is excluded). Negative integers count from the back.

### Topic 4: Selecting First and Last Rows
- **1. What it is**: Extracting boundary records at the top and bottom of a tabular dataset.
- **2. Why it exists**: Vital for pipeline sanity verification, time-series boundary detection (earliest vs latest timestamp), queue simulation (FIFO/LIFO), and previewing data transformations during debugging.
- **3. How Pandas handles it under the hood**:
  - `df.head(n)`: Internally evaluates `df.iloc[:n]`, returning a shallow view of the first $n$ rows.
  - `df.tail(n)`: Internally evaluates `df.iloc[-n:]` (or `df.iloc[len(df)-n:]`), returning a shallow view of the last $n$ rows.
  - `df.iloc[0]` / `df.iloc[-1]`: Extracts the boundary row as a 1D Series.
  - `df.iloc[[0]]` / `df.iloc[[-1]]`: Extracts the boundary row as a 2D DataFrame.
- **4. Key methods, parameters, variations**:
  - `df.head(n=5)`: Default 5 rows from start.
  - `df.tail(n=5)`: Default 5 rows from end.
  - `df.iloc[0]`: First row scalar access (Series).
  - `df.iloc[-1]`: Final row scalar access (Series).
  - `df.iloc[:1]` / `df.iloc[-1:]`: First/last row preserving 2D DataFrame shape.
- **5. Common interview questions**:
  - *"What is the difference in return type between `df.iloc[0]` and `df.iloc[:1]`?"*
  - *"How does `df.head(-2)` behave?"*
  - *"Does calling `df.head(5)` copy the data into a new memory buffer?"*
- **6. Edge cases & pitfalls**:
  - Calling `iloc[0]` or `iloc[-1]` on an empty DataFrame (`len(df) == 0`) raises `IndexError`.
  - Calling `head(5)` or `tail(5)` on an empty DataFrame returns an empty DataFrame gracefully without raising an exception.
  - In time series datasets, `df.iloc[0]` is only the "earliest" row if the index is strictly sorted chronologically.
- **7. Code example**:
  ```python
  import pandas as pd

  df = pd.DataFrame({"metric": [10, 20, 30, 40, 50]})

  # First row as Series vs DataFrame
  s_first = df.iloc[0]
  df_first = df.iloc[:1]
  print(type(s_first))   # <class 'pandas.core.series.Series'>
  print(type(df_first))  # <class 'pandas.core.frame.DataFrame'>

  # Last row
  last_val = df.iloc[-1]["metric"]
  print(last_val)  # 50

  # Negative head
  print(df.head(-2).shape)  # (3, 1) -> all except last 2 rows
  ```
- **8. Rule of thumb for interviews**: Use `head()` and `tail()` for quick inspection and pipeline sanity checks. Use `iloc[0]` / `iloc[-1]` for programmatic access to first/last boundary records.

## 3. Fresher Interview Questions

### Part A: Basic Questions (20 Questions)

#### Q1: What is the primary difference between `loc[]` and `iloc[]`?
- **Direct Answer**: `.loc[]` is strictly **label-based** (indexing by index/column names with inclusive slices), whereas `.iloc[]` is strictly **integer position-based** (indexing by 0-based physical offsets with half-open, exclusive slices).
- **Under the Hood**: `loc` queries the index hash map engine to match keys. `iloc` translates integer coordinates directly into array pointer offsets in underlying memory.
- **Code Example**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"val": [10, 20]}, index=["a", "b"])
  print(df.loc["a", "val"])   # 10 (label 'a')
  print(df.iloc[0, 0])        # 10 (offset 0)
  ```
- **Interview Follow-up**: *"What if the index labels are integers like `10, 20`?"* `df.loc[10]` searches for the label `10`, while `df.iloc[10]` attempts to access the 11th row at offset 10.

#### Q2: Are slice endpoints inclusive or exclusive in `loc[]` versus `iloc[]`?
- **Direct Answer**: Slices in `.loc[]` are **inclusive of both start and stop** (`[start, stop]`). Slices in `.iloc[]` are **exclusive of the stop endpoint** (`[start:stop)`), following standard Python slicing conventions.
- **Under the Hood**: Label sequences lack an inherent successor function (e.g., what comes right after `'March'`?), requiring `loc` to include the stop label. Integer positions have clear succession, allowing `iloc` to follow Python's zero-based half-open standard.
- **Code Example**:
  ```python
  df = pd.DataFrame({"x": range(5)}, index=["a", "b", "c", "d", "e"])
  print(df.loc["a":"c"].index.tolist())   # ['a', 'b', 'c'] -> INCLUSIVE
  print(df.iloc[0:2].index.tolist())      # ['a', 'b']      -> EXCLUSIVE
  ```
- **Interview Follow-up**: *"What happens if the stop label in `loc['a':'c']` is not in the index?"* If the index is sorted, it returns all labels up to where `'c'` would fall; if unsorted, it raises a `KeyError`.

#### Q3: How do you select the first row of a DataFrame as a Series?
- **Direct Answer**: Using `df.iloc[0]`.
- **Under the Hood**: Accesses row offset 0, returning a 1D `pd.Series` where the original DataFrame columns become the Series index.
- **Code Example**:
  ```python
  df = pd.DataFrame({"name": ["Alice", "Bob"], "age": [25, 30]})
  row = df.iloc[0]
  print(type(row))  # <class 'pandas.core.series.Series'>
  print(row["name"])  # 'Alice'
  ```
- **Interview Follow-up**: *"How do you select the first row as a 1-row DataFrame instead of a Series?"* Use list indexing: `df.iloc[[0]]` or slicing `df.iloc[:1]`.

#### Q4: How do you select the last row of a DataFrame?
- **Direct Answer**: Using negative positional indexing: `df.iloc[-1]`.
- **Under the Hood**: Python negative index translation evaluates `-1` as `len(df) - 1`, fetching the final row buffer.
- **Code Example**:
  ```python
  df = pd.DataFrame({"score": [88, 92, 95]})
  last_row = df.iloc[-1]
  print(last_row["score"])  # 95
  ```
- **Interview Follow-up**: *"Does `df.loc[-1]` work to get the last row?"* No, unless the literal integer `-1` exists as an index label; otherwise it raises `KeyError: -1`.

#### Q5: What is the return type of `df.loc['label']` when the label is unique versus duplicated?
- **Direct Answer**: If `'label'` is unique, it returns a 1D `pd.Series`. If `'label'` appears multiple times in the index, it returns a 2D `pd.DataFrame`.
- **Under the Hood**: The index engine's `get_loc()` returns an integer scalar for unique matches, prompting Series extraction. For duplicates, it returns a boolean mask or slice, prompting DataFrame extraction.
- **Code Example**:
  ```python
  df_unique = pd.DataFrame({"a": [1, 2]}, index=["x", "y"])
  df_dup = pd.DataFrame({"a": [1, 2]}, index=["x", "x"])

  print(type(df_unique.loc["x"]))  # <class 'pandas.core.series.Series'>
  print(type(df_dup.loc["x"]))     # <class 'pandas.core.frame.DataFrame'>
  ```
- **Interview Follow-up**: *"Why is this dangerous in production?"* Code expecting a scalar Series attribute like `res['a']` will return a Series instead of a scalar if duplicate labels enter the dataset, triggering unexpected type errors.

#### Q6: How do you select multiple non-consecutive rows by position?
- **Direct Answer**: Pass a list of integer offsets to `iloc`: `df.iloc[[0, 2, 4]]`.
- **Under the Hood**: Invokes internal `take()` routine to gather specific row indices into a new DataFrame.
- **Code Example**:
  ```python
  df = pd.DataFrame({"val": range(10)})
  sample = df.iloc[[0, 3, 7]]
  print(sample["val"].tolist())  # [0, 3, 7]
  ```
- **Interview Follow-up**: *"Can you pass negative integers in the list?"* Yes, e.g., `df.iloc[[0, -1]]` selects the first and last rows.

#### Q7: What error is raised when `iloc` receives an integer indexer that is out of bounds?
- **Direct Answer**: `IndexError: single positional indexer is out-of-bounds`.
- **Under the Hood**: Bounds checking verifies `0 <= pos < len(df)`. Failing the check raises `IndexError`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [1, 2]})
  try:
      df.iloc[10]
  except IndexError as e:
      print("Caught:", e)  # Caught: single positional indexer is out-of-bounds
  ```
- **Interview Follow-up**: *"Does `df.iloc[5:10]` raise an `IndexError` on that same 2-row table?"* No! Slices tolerate out-of-bounds endpoints in Python, returning an empty DataFrame with 0 rows.

#### Q8: What error is raised when `loc` receives a label that does not exist?
- **Direct Answer**: A `KeyError`.
- **Under the Hood**: The hash map lookup on `df.index` fails to locate the requested label.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [1]}, index=["row1"])
  try:
      df.loc["missing_row"]
  except KeyError as e:
      print("Caught:", repr(e))  # Caught: KeyError('missing_row')
  ```
- **Interview Follow-up**: *"How do you safely query row labels that might be missing?"* Check membership with `if label in df.index:` or use `df.reindex([label])`.

#### Q9: How does `df.head(n)` select rows, and what is its default value?
- **Direct Answer**: It selects the first $n$ rows of the DataFrame. The default argument is `n=5`.
- **Under the Hood**: Evaluates `df.iloc[:n]`, producing a shallow slice view of the top rows.
- **Code Example**:
  ```python
  df = pd.DataFrame({"x": range(10)})
  print(len(df.head()))   # 5 (default)
  print(len(df.head(3)))  # 3
  ```
- **Interview Follow-up**: *"What if $n$ is greater than the total number of rows?"* It gracefully returns all rows without error.

#### Q10: How does `df.tail(n)` select rows, and what is its default value?
- **Direct Answer**: It selects the final $n$ rows of the DataFrame. The default argument is `n=5`.
- **Under the Hood**: Evaluates `df.iloc[-n:]` (or `df.iloc[max(0, len(df)-n):]`).
- **Code Example**:
  ```python
  df = pd.DataFrame({"x": range(10)})
  print(df.tail(2)["x"].tolist())  # [8, 9]
  ```
- **Interview Follow-up**: *"What does `df.tail(-2)` return?"* It returns all rows starting from index offset 2 to the end (skipping the first 2 rows).

#### Q11: What does passing a negative integer to `df.head(-n)` do?
- **Direct Answer**: It returns all rows except the final $n$ rows.
- **Under the Hood**: Maps directly to Python slice `df.iloc[:-n]`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"x": range(10)})
  # Drop last 3 rows:
  print(len(df.head(-3)))  # 7 (rows 0 through 6)
  ```
- **Interview Follow-up**: *"What if `-n` has an absolute value larger than `len(df)`?"* It returns an empty DataFrame with 0 rows.

#### Q12: Can you select rows using a boolean mask with `loc`?
- **Direct Answer**: Yes: `df.loc[boolean_condition]`.
- **Under the Hood**: Evaluates the boolean Series against index labels, aligning and filtering rows where the condition evaluates to `True`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"age": [15, 25, 35]})
  adults = df.loc[df["age"] >= 18]
  print(len(adults))  # 2
  ```
- **Interview Follow-up**: *"How does `df.loc[mask]` differ from `df[mask]`?"* `df.loc[mask, 'col']` allows specifying columns simultaneously in a single atomic 2D indexing call, preventing chained assignment bugs.

#### Q13: Can you pass a boolean Series to `iloc`?
- **Direct Answer**: In modern Pandas, you can only pass a boolean Series to `iloc` if its index is default integer-aligned; if custom indexed, it raises an `IndexError`. To be safe, pass a boolean NumPy array or Python list: `df.iloc[(df['col'] > 0).to_numpy()]`.
- **Under the Hood**: `iloc` operates strictly on positional offsets and cannot perform index label alignment. Passing an unaligned boolean Series with non-integer labels causes an alignment violation.
- **Code Example**:
  ```python
  df = pd.DataFrame({"val": [1, 2, 3]}, index=["a", "b", "c"])
  mask = df["val"] > 1
  # df.iloc[mask] -> IndexError: Cannot mask with non-boolean array containing NA / unaligned
  # Correct positional masking:
  res = df.iloc[mask.to_numpy()]
  print(res.index.tolist())  # ['b', 'c']
  ```
- **Interview Follow-up**: *"Why not just use `loc` for boolean masking?"* `loc` is indeed the idiomatic, standard choice for boolean filtering.

#### Q14: How do you select rows using a callable function in `loc` or `iloc`?
- **Direct Answer**: Pass a lambda or function taking the DataFrame as input and returning a valid indexer: `df.loc[lambda d: d['salary'] > 50000]`.
- **Under the Hood**: During evaluation, Pandas invokes the callable passing the caller DataFrame, then uses the returned boolean mask or label list to index rows.
- **Code Example**:
  ```python
  df = pd.DataFrame({"score": [45, 85, 95]})
  high_scorers = df.loc[lambda d: d["score"] > 80]
  print(high_scorers["score"].tolist())  # [85, 95]
  ```
- **Interview Follow-up**: *"Why is this essential in method chaining?"* It allows filtering on dynamically calculated columns created earlier in the chain without assigning intermediate variables.

#### Q15: What is the difference between `df.iloc[0]` and `df.iloc[[0]]`?
- **Direct Answer**: `df.iloc[0]` returns a 1D `pd.Series` (shape `(M,)`). `df.iloc[[0]]` returns a 2D `pd.DataFrame` with a single row (shape `(1, M)`).
- **Under the Hood**: Passing an integer scalar extracts a 1D vector. Passing a list of integers preserves 2D tabular structure.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [10], "b": [20]})
  print(df.iloc[0].shape)    # (2,) -> Series
  print(df.iloc[[0]].shape)  # (1, 2) -> DataFrame
  ```
- **Interview Follow-up**: *"When is `df.iloc[[0]]` preferred?"* When appending or concatenating the row to another DataFrame, which requires matching 2D dimensions.

#### Q16: How do you select alternating (even or odd) rows from a DataFrame?
- **Direct Answer**: Using step slicing in `iloc`: `df.iloc[::2]` for even rows, `df.iloc[1::2]` for odd rows.
- **Under the Hood**: Leverages Python slice stride parameter `[start:stop:step]` on underlying block buffers.
- **Code Example**:
  ```python
  df = pd.DataFrame({"id": range(6)})
  even_rows = df.iloc[::2]
  print(even_rows["id"].tolist())  # [0, 2, 4]
  ```
- **Interview Follow-up**: *"Does `df.iloc[::-1]` reverse all rows?"* Yes, it reverses the entire row ordering in $O(1)$ time by creating a strided view.

#### Q17: What happens when an index is shuffled and you query `df.loc[0:2]`?
- **Direct Answer**: `loc` searches for the physical boundaries of label `0` and label `2` and returns all records occurring between them in the current ordering, regardless of numerical order.
- **Under the Hood**: `loc` treats `0` and `2` as labels, not positions. If the index is non-monotonic, slicing can raise an error or return an unpredictable subset.
- **Code Example**:
  ```python
  df = pd.DataFrame({"val": ["A", "B", "C", "D"]}, index=[3, 0, 1, 2])
  # loc slices from label 0 to label 2:
  sub = df.loc[0:2]
  print(sub.index.tolist())  # [0, 1, 2] -> records at physical positions 1, 2, 3!
  ```
- **Interview Follow-up**: *"What if label 0 appears AFTER label 2 in the index?"* It returns an empty DataFrame unless the index is sorted.

#### Q18: How do you select rows where the index label is in a specific list?
- **Direct Answer**: `df.loc[df.index.isin(target_list)]` or `df.loc[target_list]`.
- **Under the Hood**: `df.index.isin()` creates an exact boolean mask in $O(N)$ time. `df.loc[target_list]` performs direct list indexing (raising `KeyError` if any label is absent).
- **Code Example**:
  ```python
  df = pd.DataFrame({"val": [10, 20, 30]}, index=["r1", "r2", "r3"])
  selected = df.loc[df.index.isin(["r1", "r3", "r99"])]
  print(selected.index.tolist())  # ['r1', 'r3']
  ```
- **Interview Follow-up**: *"Why is `df.index.isin()` safer than `df.loc[target_list]`?"* Because `isin()` gracefully ignores missing labels (like `'r99'`), whereas direct list indexing raises `KeyError`.

#### Q19: What is the performance complexity of `df.loc[label]` vs `df.iloc[pos]`?
- **Direct Answer**: Both execute in $O(1)$ amortized time. `iloc` is slightly faster because it skips hash table lookups and directly performs pointer arithmetic.
- **Under the Hood**: `loc` hashes the label key and inspects the index hash map ($O(1)$). `iloc` calculates memory offset `base_address + pos * stride` ($O(1)$).
- **Code Example**:
  ```python
  # iloc is pure integer offset arithmetic:
  val1 = df.iloc[100]
  # loc requires hash computation on the label:
  val2 = df.loc['user_100']
  ```
- **Interview Follow-up**: *"When does `loc` degrade from $O(1)$?"* When duplicate labels exist, requiring linear scans across duplicate buckets.

#### Q20: Can you select rows using both row condition and column names in one `loc` statement?

#### Q21: What is the underlying memory mechanics of `iloc` row slicing under Copy-on-Write?
- **Direct Answer**: Slicing rows via `df.iloc[start:stop]` produces a shallow view referencing the parent DataFrame's existing memory blocks. The internal block pointers are offset, but no array data is copied until a mutation is attempted.

- **Code Example**:
  ```python

  pd.options.mode.copy_on_write = True

  ```

#### Q66: Time-Series Out-Of-Sample Data Splitter
- **Scenario**: In an algorithmic trading firm, backtesting models on financial time series requires strict temporal splitting into Training (60%), Validation (20%), and Out-of-Sample Test (20%) sets. Random sampling (like `train_test_split`) causes lookahead bias. You must build a strictly positional sequential splitter that guarantees zero record leakage or index overlaps.
- **Candidate Solution**:
  ```python
  import pandas as pd

  def split_time_series(df: pd.DataFrame) -> tuple[pd.DataFrame, pd.DataFrame, pd.DataFrame]:
      n = len(df)
      train_end = int(n * 0.60)
      val_end = int(n * 0.80)
      
      # Use iloc for half-open, non-overlapping intervals:
      train = df.iloc[0:train_end]
      val = df.iloc[train_end:val_end]
      test = df.iloc[val_end:n]
      
      # Assert zero index overlap
      assert len(train) + len(val) + len(test) == n
      assert len(set(train.index).intersection(set(test.index))) == 0
      
      return train, val, test

  # Verification
  dates = pd.date_range("2024-01-01", periods=100, freq="D")

  tr, va, te = split_time_series(stock_df)

  ```
- **Technical Rationale**: Utilizing `iloc[start:stop]` provides exact, half-open integer intervals `[0, 60)`, `[60, 80)`, `[80, 100)`. This mathematically eliminates index overlap and data leakage, which would occur if inclusive `.loc` slicing was accidentally used.

#### Q67: Sliding Window Telemetry Batch Processor
- **Scenario**: An edge microservice receives continuous sensor streams. Every 10 seconds, it must evaluate anomalies across a rolling window of the most recent 100 observations. If the edge buffer exceeds 10,000 records, older records must be pruned to avoid memory exhaustion while retaining the newest 1,000 observations.
- **Candidate Solution**:
  ```python
  import pandas as pd

  class StreamBufferManager:
      def __init__(self, max_capacity: int = 10000, prune_target: int = 1000):
          self.max_capacity = max_capacity
          self.prune_target = prune_target
          self.buffer = pd.DataFrame()
          
      def ingest_batch(self, new_data: pd.DataFrame) -> None:
          self.buffer = pd.concat([self.buffer, new_data])
          if len(self.buffer) > self.max_capacity:
              # Retain only the most recent rows using negative iloc
              self.buffer = self.buffer.iloc[-self.prune_target:].copy()
              
      def get_latest_window(self, window_size: int = 100) -> pd.DataFrame:
          # Safe extraction of boundary records
          return self.buffer.tail(window_size)

  manager = StreamBufferManager(max_capacity=5, prune_target=3)
  manager.ingest_batch(pd.DataFrame({"temp": [1, 2, 3, 4, 5, 6]}))
  print(len(manager.buffer))  # 3 (pruned to 3 newest)
  print(manager.buffer["temp"].tolist())  # [4, 5, 6]
  ```
- **Technical Rationale**: Slicing with `iloc[-target:]` or `.tail()` provides $O(1)$ shallow slice extraction of trailing stream records without requiring complex index sorting or timestamp recalculation.

## 4. Top Questions to Definitely Prepare

### Must Know Top 5
1. **What is the fundamental operational difference between `.loc[]` and `.iloc[]`?**
   - *Key Distinction*: `.loc[]` is strictly label-based (queries index names and labels; slices are closed/inclusive of both endpoints). `.iloc[]` is strictly integer position-based (queries 0-indexed physical array offsets; slices are half-open `[start:stop)` exclusive of the stop boundary).
2. **Why does slicing `df.loc[0:5]` return 6 rows while `df.iloc[0:5]` returns 5 rows on a default integer index?**
   - *Key Distinction*: `loc` treats `0` and `5` as index labels and includes both boundaries (`0, 1, 2, 3, 4, 5` $\rightarrow 6$ rows). `iloc` treats `0` and `5` as positional offsets and excludes offset `5` (`offsets 0, 1, 2, 3, 4` $\rightarrow 5$ rows).
3. **What error occurs when passing an out-of-bounds indexer to `iloc[100]` versus `iloc[10:100]` on a 10-row DataFrame?**
   - *Key Distinction*: Scalar indexing `iloc[100]` raises `IndexError: single positional indexer is out-of-bounds`. Slice indexing `iloc[10:100]` adheres to Python slice tolerance, returning an empty DataFrame with 0 rows without raising an exception.
4. **How does `df.iloc[-1]` behave, and why does `df.loc[-1]` fail on standard default DataFrames?**
   - *Key Distinction*: `iloc[-1]` evaluates negative positions relative to table length (`len(df) - 1`), fetching the last row. `loc[-1]` searches for the literal integer `-1` among index labels; if absent, it raises `KeyError: -1`.
5. **What is the difference in return type between `df.iloc[0]` and `df.iloc[[0]]`?**
   - *Key Distinction*: `df.iloc[0]` extracts a 1D `pd.Series` (shape `(M,)`). `df.iloc[[0]]` preserves 2D tabular structure, returning a 1-row `pd.DataFrame` (shape `(1, M)`).

### Good to Know Top 5
6. **Why does passing an unaligned boolean Series into `iloc` raise an `IndexError`?**
   - *Key Distinction*: `iloc` operates on raw positional offsets and lacks index label alignment logic. If a boolean Series has custom index labels that do not match default integer positions, `iloc` cannot align them. Converting to a NumPy boolean array (`mask.to_numpy()`) or using `loc` avoids this error.
7. **What happens if you slice `loc['a':'c']` on an unsorted index where `'c'` physically precedes `'a'`?**
   - *Key Distinction*: Slices evaluate in physical sequence order. If the stop label appears before the start label in an unsorted index, Pandas returns an empty DataFrame (or raises a `KeyError` in older versions). Sorting via `df.sort_index()` is required for predictable range slicing.
8. **Why does chained assignment `df[df['col'] > 0]['status'] = 'active'` fail to update the DataFrame?**
   - *Key Distinction*: The first bracket `df[...]` returns an intermediate slice view or copy. Modifying `'status'` on that intermediate object does not propagate to the parent DataFrame and triggers `SettingWithCopyWarning`. The atomic fix is `df.loc[df['col'] > 0, 'status'] = 'active'`.
9. **How do `df.head(n)` and `df.tail(n)` behave when passed a negative integer?**
   - *Key Distinction*: `head(-n)` drops the last $n$ rows (`df.iloc[:-n]`). `tail(-n)` skips the first $n$ rows (`df.iloc[n:]`).
10. **What is the computational complexity of querying rows by index label vs positional offset?**
    - *Key Distinction*: Both are $O(1)$ amortized operations. `iloc` is marginally faster as it performs direct pointer arithmetic, whereas `loc` hashes the label key and inspects the index hash map.

### Bonus Top 5
11. **What does `df.loc['dup']` return when the label `'dup'` appears multiple times in the index?**
    - *Key Distinction*: It returns a 2D `pd.DataFrame` containing all matching records rather than a 1D `pd.Series`, frequently triggering downstream scalar type mismatch errors.
12. **How does `DatetimeIndex` partial string slicing work in `loc`?**
    - *Key Distinction*: Querying `df.loc['2024-01']` parses the string into a closed timestamp window `[2024-01-01 00:00:00, 2024-01-31 23:59:59.999999999]`, returning all records occurring in January.
13. **Why does `df.iloc[::-1]` reverse all rows with zero memory copy overhead?**
    - *Key Distinction*: It constructs a strided array view with a negative step offset ($-1$), swapping pointer order without duplicating the underlying data blocks.
14. **How can you safely select rows using a list of labels that might contain missing keys?**
    - *Key Distinction*: Use `df.loc[df.index.intersection(query_list)]` (returns existing matches) or `df.reindex(query_list)` (returns all keys, padding missing ones with `NaN`). Direct `df.loc[query_list]` raises `KeyError`.
15. **What is the difference between `df.truncate(before=..., after=...)` and `.loc` slicing?**
    - *Key Distinction*: `truncate()` is designed specifically for sorted time series; it raises a `ValueError` if the index is not monotonic, whereas `.loc` attempts best-effort label matching.

## 5. Common Beginner Mistakes

### 1. Assuming `loc[0:5]` Returns 5 Rows on Integer Indices
- **Wrong**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"val": range(10)})
  # Developer expects first 5 rows
  sub = df.loc[0:5]
  print(len(sub))  # Returns 6 rows! (0, 1, 2, 3, 4, 5)
  ```
- **Right**:
  ```python
  sub = df.iloc[0:5]  # Half-open positional slice returns exactly 5 rows (0, 1, 2, 3, 4)
  # Or:
  sub = df.loc[0:4]
  ```
- **Why**: `loc` slicing is inclusive of both endpoints. On a 0-indexed DataFrame, `0:5` includes label `5`, producing 6 records.

### 2. Using `df.loc[-1]` to Retrieve the Last Row
- **Wrong**:
  ```python
  df = pd.DataFrame({"a": [10, 20, 30]})
  # last_row = df.loc[-1]  # KeyError: -1
  ```
- **Right**:
  ```python
  last_row = df.iloc[-1]  # Correct positional access
  ```
- **Why**: `loc` interprets `-1` as a literal label match. If `-1` is not in `df.index`, it raises `KeyError`. Negative offset indexing is exclusive to `iloc`.

### 3. Chained Indexing for Row Filtering and Assignment
- **Wrong**:
  ```python
  df = pd.DataFrame({"age": [15, 25], "role": ["student", "student"]})
  df[df["age"] >= 18]["role"] = "adult"  # SettingWithCopyWarning! Value NOT updated!
  print(df["role"].tolist())  # Still ['student', 'student']
  ```
- **Right**:
  ```python
  df.loc[df["age"] >= 18, "role"] = "adult"  # Atomic 2D coordinate update
  print(df["role"].tolist())  # ['student', 'adult']
  ```
- **Why**: `df[mask]` returns an intermediate temporary DataFrame. Modifying `['role']` on the temporary object does not update the parent DataFrame.

### 4. Querying String Indices with Integer Numbers in `loc`
- **Wrong**:
  ```python
  df = pd.DataFrame({"name": ["Alice", "Bob"]}, index=["101", "102"])
  # row = df.loc[101]  # KeyError: 101
  ```
- **Right**:
  ```python
  row = df.loc["101"]  # Pass exact string type
  # Or positionally:
  row = df.iloc[0]
  ```
- **Why**: Index lookups in `loc` are strictly type-sensitive; integer `101` does not match string `'101'`.

### 5. Passing Python Logical `and` / `or` for Row Filtering
- **Wrong**:
  ```python
  df = pd.DataFrame({"x": [1, 5, 10]})
  # res = df.loc[df['x'] > 2 and df['x'] < 8]  # ValueError: The truth value of a Series is ambiguous
  ```
- **Right**:
  ```python
  res = df.loc[(df["x"] > 2) & (df["x"] < 8)]  # Bitwise & with mandatory parentheses
  ```
- **Why**: Python's `and` evaluates scalar truthiness of the entire Series object. Bitwise `&` evaluates element-wise boolean arrays.

### 6. Passing an Unaligned Boolean Series into `iloc`
- **Wrong**:
  ```python
  df = pd.DataFrame({"val": [10, 20]}, index=["a", "b"])
  mask = df["val"] > 15
  # sub = df.iloc[mask]  # IndexError: Cannot mask with non-boolean array containing NA / unaligned
  ```
- **Right**:
  ```python
  sub = df.loc[mask]  # loc natively supports index-aligned boolean Series
  # Or:
  sub = df.iloc[mask.to_numpy()]  # Cast to raw NumPy boolean array
  ```
- **Why**: `iloc` only accepts unlabelled integer offsets or unlabelled boolean NumPy arrays; it cannot resolve custom index labels on a boolean Series.

### 7. Calling `iloc[0]` on an Empty Filtered DataFrame
- **Wrong**:
  ```python
  df = pd.DataFrame({"score": [10, 20]})
  filtered = df.loc[df["score"] > 100]
  # top = filtered.iloc[0]  # IndexError: single positional indexer is out-of-bounds
  ```
- **Right**:
  ```python
  top = filtered.iloc[0] if not filtered.empty else None
  # Or safely as a 0-row DataFrame:
  top_df = filtered.head(1)
  ```
- **Why**: Positional scalar extraction `iloc[0]` requires `len(df) > 0`. Slicing or checking `.empty` prevents fatal crashes.

### 8. Slicing Unsorted String Indices with `loc`
- **Wrong**:
  ```python
  df = pd.DataFrame({"val": [1, 2, 3]}, index=["z", "a", "m"])
  # Developer expects all rows between 'a' and 'z'
  res = df.loc["a":"z"]
  print(res.index.tolist())  # Returns ['a', 'm'] because 'z' was at index 0!
  ```
- **Right**:
  ```python
  df_sorted = df.sort_index()
  res = df_sorted.loc["a":"z"]
  print(res.index.tolist())  # ['a', 'm', 'z']
  ```
- **Why**: `loc` slices evaluate physical sequence order. If the index is unsorted, the slice terminates at the first encounter of the stop boundary or returns truncated sequences.

### 9. Confusing `head(-n)` with `tail(n)`
- **Wrong**:
  ```python
  df = pd.DataFrame({"id": range(10)})
  # Developer wants the last 3 rows
  last3 = df.head(-3)  # Returns the FIRST 7 rows!
  ```
- **Right**:
  ```python
  last3 = df.tail(3)
  # Or:
  last3 = df.iloc[-3:]
  ```
- **Why**: In Python slice syntax, `[:-n]` drops the final $n$ rows. To select the trailing $n$ rows, use `tail(n)` or `iloc[-n:]`.

### 10. Assuming Duplicate Index Labels Return a Series from `loc`
- **Wrong**:

  # Check if result is Series or DataFrame
  user_data = df.loc["user_1"]

  else:

## 6. Section-Adaptive Pandas API Confusions

### 1. `df.loc[]` vs `df.iloc[]`
- **Conceptual Difference**: `loc` is strictly label-based (references index names/keys; slices are fully inclusive `[start, stop]`). `iloc` is strictly integer position-based (references 0-indexed physical array offsets; slices are half-open `[start:stop)`).
- **Memory/Performance**: Both execute in $O(1)$ amortized time. `iloc` is slightly faster because it translates directly to array pointer offsets without hashing string labels.
- **Code Comparison**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"val": [10, 20, 30]}, index=["x", "y", "z"])
  
  # Label query:
  print(df.loc["x", "val"])  # 10
  
  # Positional query:
  print(df.iloc[0, 0])       # 10
  ```
- **Interview Rule of Thumb**: Use `loc` when business logic references identifiers, dates, or boolean conditions. Use `iloc` for numerical algorithms, batch splitting, or sampling top/bottom bounds.

### 2. `df.iloc[0]` vs `df.iloc[[0]]`
- **Conceptual Difference**: `df.iloc[0]` extracts a single observation as a 1D `pd.Series`. `df.iloc[[0]]` extracts a single observation as a 2D `pd.DataFrame` of shape `(1, M)`.
- **Memory/Performance**: `iloc[0]` returns a Series wrapping a 1D slice. `iloc[[0]]` constructs a full DataFrame wrapper with two axes.
- **Code Comparison**:
  ```python
  df = pd.DataFrame({"a": [1, 2], "b": [3, 4]})
  s = df.iloc[0]
  d = df.iloc[[0]]
  print(s.ndim, s.shape)  # 1 (2,)
  print(d.ndim, d.shape)  # 2 (1, 2)
  ```
- **Interview Rule of Thumb**: Use `iloc[0]` for feature inspection, scalar extraction, or series math. Use `iloc[[0]]` when appending, concatenating, or passing to Scikit-Learn transformers.

### 3. `df.loc[start:stop]` vs `df.iloc[start:stop]`
- **Conceptual Difference**: `loc[start:stop]` is closed/inclusive (both `start` and `stop` labels appear in the output). `iloc[start:stop]` is half-open (offset `stop` is excluded, matching Python `range()` and list slices).
- **Memory/Performance**: Identical zero-copy view creation under Copy-on-Write.
- **Code Comparison**:
  ```python
  df = pd.DataFrame({"val": range(5)})
  print(df.loc[1:3].index.tolist())   # [1, 2, 3] -> 3 records!
  print(df.iloc[1:3].index.tolist())  # [1, 2]    -> 2 records!
  ```
- **Interview Rule of Thumb**: Never slice sequential train/test splits with `loc[0:80]` and `loc[80:100]` because record `80` will leak into both sets. Always use `iloc[0:80]` and `iloc[80:100]`.

### 4. `df.head(n)` vs `df.iloc[:n]`
- **Conceptual Difference**: Functionally identical. `df.head(n)` is an expressive high-level convenience wrapper that delegates directly to `df.iloc[:n]`.
- **Memory/Performance**: Identical execution paths; both produce shallow slice views without copying data blocks.
- **Code Comparison**:
  ```python
  df = pd.DataFrame({"id": range(10)})
  assert df.head(3).equals(df.iloc[:3])
  ```
- **Interview Rule of Thumb**: Use `df.head(n)` in exploratory data analysis and logging for readability. Use `df.iloc[:n]` inside low-level indexing algorithms where slicing parameters are calculated mathematically.

### 5. `df[mask]` vs `df.loc[mask]`
- **Conceptual Difference**: `df[mask]` is limited to filtering rows across all columns. `df.loc[mask, cols]` allows filtering rows AND projecting target columns simultaneously in an atomic 2D operation.
- **Memory/Performance**: `df[mask]` often requires a second chained bracket `df[mask][['col']]` to project columns, creating intermediate copies and triggering `SettingWithCopyWarning`. `df.loc[mask, cols]` executes in a single optimized pass.
- **Code Comparison**:
  ```python
  df = pd.DataFrame({"age": [20, 30], "salary": [50000, 60000]})
  # Chained indexing (suboptimal):
  res1 = df[df["age"] > 25]["salary"]
  # Atomic 2D indexing (idiomatic production standard):
  res2 = df.loc[df["age"] > 25, "salary"]
  assert res1.equals(res2)
  ```
- **Interview Rule of Thumb**: Always prefer `df.loc[mask, cols]` over chained brackets `df[mask][cols]` in production code.

## 7. Interview Traps

### Trap 1: The Shuffled Integer Index Trap
- **The Trap**: The interviewer asks: *"I have a DataFrame with index `[3, 1, 0, 2]`. What is the result of `df.loc[1]` versus `df.iloc[1]`?"*
- **Naive Fresher Answer**: *"They both return the second row because 1 represents index 1."*
- **What the Interviewer is Testing**: Understanding that `loc` targets label names while `iloc` targets 0-based physical positions.
- **The Reality / Under the Hood**: `df.loc[1]` searches for the record whose index label is literally `1` (which is physically at offset 1, row 2). `df.iloc[1]` retrieves the record at physical offset 1 (which has label 1). However, if queried with `0`, `df.loc[0]` returns row 3 (label 0), whereas `df.iloc[0]` returns row 1 (physical offset 0, label 3).
- **Winning Response**: *"`df.loc[1]` looks up the row with index label `1`, whereas `df.iloc[1]` extracts the record at physical offset 1 (the second row). On shuffled integer indices, label identity and positional offset diverge completely. For example, `df.loc[0]` targets the third row (label 0), but `df.iloc[0]` targets the first row (label 3)."*

### Trap 2: The Train/Test Data Leakage Slicing Trap
- **The Trap**: *"A junior ML engineer wrote `train = df.loc[0:80]` and `test = df.loc[80:100]` on a 100-row dataset. Why did the model evaluate with artificially high test accuracy?"*
- **Naive Fresher Answer**: *"The dataset was too small, causing overfitting."*
- **What the Interviewer is Testing**: Knowledge of inclusive slice endpoints in `loc`.
- **The Reality / Under the Hood**: `loc` slicing is closed/inclusive of both endpoints. Row index `80` is included in `train` (rows 0 through 80 = 81 rows) AND in `test` (rows 80 through 100 = 21 rows). Row `80` was evaluated during training, creating pure data leakage during testing.
- **Winning Response**: *"Because `loc` slice endpoints are inclusive, row label `80` was included in both the training set and the test set. The model was trained on row 80 and tested on row 80, creating classic data leakage. The engineer must use half-open positional slicing: `train = df.iloc[0:80]` and `test = df.iloc[80:100]`."*

### Trap 3: The Missing Key List Crash
- **The Trap**: *"I executed `df.loc[['user_1', 'user_99']]`. In older code this returned `user_99` filled with `NaN`, but on our new server it crashes with `KeyError`. Why?"*
- **Naive Fresher Answer**: *"The new server must be running a corrupted Python installation."*
- **What the Interviewer is Testing**: Awareness of breaking API changes across Pandas versions regarding `loc` list validation.
- **The Reality / Under the Hood**: In historical Pandas (<0.21), passing non-existent keys in a list to `loc` was deprecated with a warning and padded with `NaN`. Modern Pandas strictly raises `KeyError` if any key in the list is absent.
- **Winning Response**: *"Modern Pandas strictly enforces `KeyError` when any requested label in a list is missing from `df.index`. To achieve the legacy behavior of padding missing keys with `NaN` without crashing, the engineer should use `df.reindex(['user_1', 'user_99'])`. To select only existing keys, use `df.loc[df.index.intersection(['user_1', 'user_99'])]`."*

### Trap 4: The Silent `head(0)` Dimension Mirage
- **The Trap**: *"What happens when you call `df.head(0)` versus `df.iloc[0]` on an empty DataFrame?"*
- **Naive Fresher Answer**: *"They both crash with an `IndexError` because the DataFrame is empty."*
- **What the Interviewer is Testing**: Understanding error handling in scalar indexers vs slice/convenience indexers.
- **The Reality / Under the Hood**: `df.iloc[0]` is a scalar lookup; on an empty table it raises `IndexError: single positional indexer is out-of-bounds`. `df.head(0)` is a slice operation (`df.iloc[:0]`); in Python, slicing empty sequences does not raise exceptions, returning a clean empty DataFrame of shape `(0, M)` preserving column schema.
- **Winning Response**: *"`df.iloc[0]` crashes with `IndexError` because scalar positional indexing validates bounds strictly. `df.head(0)` evaluates a slice (`df.iloc[:0]`), which gracefully returns an empty 2D DataFrame with 0 rows, preserving all column headers and dtypes."*

### Trap 5: The Duplicate Label Type Inversion Trap
- **The Trap**: *"I wrote a microservice that calls `row = df.loc[customer_id]`. It worked in QA for months, but in production `row['email']` suddenly threw `AttributeError: 'Series' object has no attribute 'email'`. How is this possible?"*
- **Naive Fresher Answer**: *"The customer's email must have been missing or stored as a float."*
- **What the Interviewer is Testing**: Understanding that `loc` dynamically changes return type from `Series` to `DataFrame` when an index label is duplicated.
- **The Reality / Under the Hood**: In QA, all customer IDs were unique, so `df.loc[customer_id]` returned a 1D `pd.Series` (where `'email'` was a scalar accessed via `row['email']`). In production, a customer registered twice, creating duplicate index labels. `df.loc[customer_id]` returned a 2D `pd.DataFrame`. In a DataFrame, `row['email']` returns a Series, breaking code that expected a scalar string.
- **Winning Response**: *"A duplicate index label entered the dataset. When an index label is unique, `loc` returns a 1D Series. When an index label is duplicated, `loc` returns a 2D DataFrame. Calling `row['email']` on a DataFrame returns a Series rather than a scalar string. The service should enforce index uniqueness with `assert df.index.is_unique` or deduplicate with `df[~df.index.duplicated(keep='first')]`."*

### Trap 6: The Unsorted Label Slice Trap
- **The Trap**: *"I called `df.loc['2023-01-01':'2023-01-05']` on a daily sales table, and it returned 0 rows even though sales data exists for every day in January. Why?"*
- **Naive Fresher Answer**: *"The date strings were formatted incorrectly; you must use forward slashes."*
- **What the Interviewer is Testing**: Knowledge of monotonic index requirements for range slicing.
- **The Reality / Under the Hood**: If the `DatetimeIndex` (or string index) is unsorted—for example, if rows were appended out of order—Pandas cannot determine the boundaries of the slice and returns an empty DataFrame or raises a `KeyError`.
- **Winning Response**: *"The index is not monotonically sorted. Label-based range slicing in `loc` requires a sorted index to resolve intermediate bounds. Calling `df = df.sort_index()` before slicing guarantees that `df.loc['2023-01-01':'2023-01-05']` returns all matching rows."*

### Trap 7: The Chained Indexing Memory Trap
- **The Trap**: *"Why does `df.iloc[0:10]['val'] = 0` sometimes produce a `SettingWithCopyWarning` and fail to modify `df`, whereas `df.iloc[0:10, df.columns.get_loc('val')] = 0` always works?"*
- **Naive Fresher Answer**: *"The first one uses square brackets twice, which Python does not support."*
- **What the Interviewer is Testing**: Deep knowledge of chained indexing vs 2-dimensional coordinate assignment in the `BlockManager`.
- **The Reality / Under the Hood**: The first expression calls `__getitem__` to create an intermediate row slice DataFrame, then attempts to set `'val'` on that temporary object. In modern Pandas, modifying temporary slices raises `SettingWithCopyWarning` and does not write back to the parent. The second expression passes both row and column coordinates in a single `__setitem__` call, updating the underlying array block in-place.
- **Winning Response**: *"The first expression performs chained indexing, generating a temporary intermediate DataFrame slice. Writing to the slice fails to update the parent DataFrame. The second expression performs atomic 2D coordinate indexing directly on the parent DataFrame in a single call, updating the underlying memory buffer reliably."*

### Trap 8: The Out-Of-Bounds Slice vs Scalar Illusion
- **The Trap**: *"If `len(df) == 5`, why does `df.iloc[10]` raise an `IndexError`, but `df.iloc[10:20]` executes cleanly?"*
- **Naive Fresher Answer**: *"It's a bug in Pandas `iloc` bounds checking."*
- **What the Interviewer is Testing**: Understanding Python slice protocol parity.
- **The Reality / Under the Hood**: In Python (both native lists and NumPy/Pandas), scalar access requires an exact valid index offset (`0 <= i < len`). Slices represent half-open intervals and gracefully clamp out-of-bounds start and stop values to the sequence boundaries (e.g., `[][10:20]` returns `[]`).
- **Winning Response**: *"`iloc` mirrors Python slicing semantics. Scalar access `iloc[10]` enforces strict boundary validation and raises `IndexError` when the offset is out of bounds. Slice access `iloc[10:20]` adheres to Python's slice protocol, clamping out-of-bounds offsets to return an empty DataFrame with 0 rows without raising an error."*

### Trap 9: The Negative Index Boolean Mask Trap
- **The Trap**: *"Can I filter rows using negative indexing inside a boolean condition, like `df.loc[df.index != -1]`?"*
- **Naive Fresher Answer**: *"Yes, that excludes the last row of the DataFrame."*
- **What the Interviewer is Testing**: Understanding that `loc` compares values against index labels, not positions.
- **The Reality / Under the Hood**: `df.index != -1` evaluates whether each index label is not equal to the literal integer `-1`. Unless the index contains a row explicitly labeled `-1`, this condition evaluates to `True` for all rows, dropping nothing.
- **Winning Response**: *"No. `df.index != -1` performs an equality check against the literal label `-1`. It does not refer to the final row position. To exclude the final row positionally, you must use `df.iloc[:-1]` or `df.head(-1)`."*

### Trap 10: The Inverted Step Slicing Reversal Trap
- **The Trap**: *"If I run `df_rev = df.iloc[::-1]`, what happens to `df_rev.iloc[0]` versus `df_rev.loc[0]`?"*
- **Naive Fresher Answer**: *"They both return the original first row of `df`."*
- **What the Interviewer is Testing**: Understanding how index labels travel with records during positional reversal.
- **The Reality / Under the Hood**: Positional reversal reverses physical rows. `df_rev.iloc[0]` extracts the row at physical offset 0 of the reversed DataFrame (which was originally the last row). However, `df_rev.loc[0]` searches for index label `0` (which was originally the first row and is now located at the bottom).
- **Winning Response**: *"`df_rev.iloc[0]` returns the record at the new first physical position (the original last row). `df_rev.loc[0]` searches for the label `0`, which traveled with its original record to the bottom of the DataFrame. Positional offsets are reassigned, but index labels remain bound to their records."*

### Q1: High-Performance Sequential Train/Validation/Test Partitioning
- **Scenario**: In an automated algorithmic trading pipeline, daily price feeds containing 5,000,000 rows must be split into training (70%), validation (15%), and test (15%) sets. The split must execute in sub-millisecond time without duplicating RAM, and index overlap between splits must be mathematically impossible.
- **Engineering Solution**:
  ```python
  import pandas as pd

  def split_market_data(df: pd.DataFrame) -> tuple[pd.DataFrame, pd.DataFrame, pd.DataFrame]:
      n = len(df)
      train_cutoff = int(n * 0.70)
      val_cutoff = int(n * 0.85)
      
      # Use iloc half-open intervals for zero-copy views under CoW:
      train_df = df.iloc[:train_cutoff]
      val_df = df.iloc[train_cutoff:val_cutoff]
      test_df = df.iloc[val_cutoff:]
      
      return train_df, val_df, test_df
  ```
- **Trade-off Analysis**: `iloc` integer slicing uses $O(1)$ pointer arithmetic. Under Copy-on-Write, zero data blocks are duplicated. The half-open intervals `[:train_cutoff]`, `[train_cutoff:val_cutoff]`, `[val_cutoff:]` guarantee zero record leakage.

### Q2: Circular Buffer Stream Ingestion with Memory Clamping
- **Scenario**: An IoT gateway processes telemetry from hundreds of factory machines. Memory is strictly capped at 256 MB. The gateway must ingest continuous batches and retain only the most recent 100,000 observations, pruning older records without memory fragmentation.
- **Engineering Solution**:
  ```python
  import pandas as pd

  class GatewayBuffer:
      def __init__(self, max_records: int = 100000):
          self.max_records = max_records
          self.buffer = pd.DataFrame()
          
      def append_stream(self, batch: pd.DataFrame) -> None:
          # Concatenate incoming batch
          self.buffer = pd.concat([self.buffer, batch], copy=False)
          
          # Clamp to max records using negative iloc slicing
          if len(self.buffer) > self.max_records:
              self.buffer = self.buffer.iloc[-self.max_records:].copy()
  ```
- **Trade-off Analysis**: Slicing with `iloc[-self.max_records:].copy()` drops older array references, allowing the Python garbage collector to reclaim expired memory blocks and preventing container OOM kills.

### Q3: Resilient Multi-Entity Lookup Under Incomplete Data
- **Scenario**: A fraud detection microservice receives webhook alerts containing lists of up to 500 suspect account IDs. The service must retrieve all matching account profiles from a master DataFrame. If any queried ID does not exist, the query must not crash, and the missing IDs must be logged for investigation.
- **Engineering Solution**:
  ```python
  import pandas as pd

  def lookup_suspect_accounts(master_df: pd.DataFrame, suspect_ids: list[str]) -> tuple[pd.DataFrame, list[str]]:
      # Step 1: Compute intersection against master index
      valid_ids = master_df.index.intersection(suspect_ids)
      missing_ids = list(set(suspect_ids) - set(valid_ids))
      
      # Step 2: Extract verified records using loc
      verified_profiles = master_df.loc[valid_ids]
      
      return verified_profiles, missing_ids
  ```
- **Trade-off Analysis**: Querying `master_df.loc[suspect_ids]` directly raises `KeyError` if a single ID is missing. Intersecting with `master_df.index` filters the query list in $O(K)$ time, ensuring robust 100% uptime.

### Q4: Dynamic Date-Window Slicing with Timestamp Drift Tolerance
- **Scenario**: An ETL billing pipeline aggregates monthly energy consumption. Billing cycles end at midnight on the last day of each month, but sensor readings suffer intermittent latency drift (readings arrive between 23:59:50 and 00:00:10). The pipeline must extract exact monthly billing windows without boundary dropouts.
- **Engineering Solution**:

  def extract_billing_cycle(df: pd.DataFrame, year: int, month: int) -> pd.DataFrame:

          df = df.sort_index()

      # loc partial string indexing captures entire calendar month

      return cycle_df

## 10. "Explain This Code"

### Snippet 1
```python
sub = df.iloc[0:5]
```
- **Line-by-Line Breakdown**:
  - `df.iloc`: Accesses the pure integer positional indexer.
  - `0:5`: Slices from physical offset 0 up to, but not including, offset 5.
  - Returns a DataFrame containing rows at offsets 0, 1, 2, 3, 4 (exactly 5 rows).
- **Hidden Edge Cases**: If `len(df) < 5`, it returns all available rows without raising an `IndexError`.
- **Interviewer Follow-up**: *"How does this differ from `df.loc[0:5]`?"*
  - **Answer**: *"`df.loc[0:5]` queries index labels 0 through 5 inclusively, producing 6 rows on a default integer index."*

### Snippet 2
```python
last_row = df.iloc[-1]
```
- **Line-by-Line Breakdown**:
  - `df.iloc`: Positional indexer.
  - `-1`: Python negative indexing evaluating to `len(df) - 1`.
  - Extracts the final row as a 1D `pd.Series`.
- **Hidden Edge Cases**: If `df` is empty (`len(df) == 0`), calling `df.iloc[-1]` raises `IndexError: single positional indexer is out-of-bounds`.
- **Interviewer Follow-up**: *"How do you make this return a 1-row DataFrame instead of a Series?"*
  - **Answer**: `df.iloc[[-1]]` or `df.tail(1)`.

### Snippet 3
```python
df.loc[df["score"] > 80, "grade"] = "A"
```
- **Line-by-Line Breakdown**:
  - `df["score"] > 80`: Generates a boolean Series aligned with the DataFrame index.
  - `df.loc[..., "grade"]`: Coordinates 2D assignment targeting rows where condition is `True` and the `'grade'` column.
  - `="A"`: Assigns scalar string `'A'` in-place to those targeted cells.
- **Hidden Edge Cases**: If the column `'grade'` does not exist, Pandas automatically creates and inserts it into the `BlockManager`.
- **Interviewer Follow-up**: *"Why does this not trigger a `SettingWithCopyWarning`?"*
  - **Answer**: *"Because it performs atomic 2D indexing in a single `__setitem__` call directly on the parent DataFrame, avoiding intermediate slice copies."*

### Snippet 4
```python
reversed_df = df.iloc[::-1]
```
- **Line-by-Line Breakdown**:
  - `df.iloc`: Positional indexer.
  - `[::-1]`: Python slice with `step=-1`, starting from the end and stepping backward to index 0.
  - Reverses the order of all rows in the DataFrame.
- **Hidden Edge Cases**: The index labels travel with the rows; physical offsets are reversed, but original index labels are preserved.
- **Interviewer Follow-up**: *"Does this operation allocate a duplicate copy of the dataset?"*
  - **Answer**: *"No. It creates a shallow strided array view in $O(1)$ time."*

## 13. Flashcard Section

### Flashcard 1
- **Front**: What is the core difference between `loc` and `iloc` slicing endpoints?
- **Back**: `loc[start:stop]` is closed and inclusive (both start and stop labels appear in the output). `iloc[start:stop]` is half-open and exclusive of the stop boundary (`[start, stop)`), matching standard Python slice protocol.

### Flashcard 2
- **Front**: Why does `df.loc[0:80]` and `df.loc[80:100]` cause data leakage in ML splits?
- **Back**: `loc` includes both boundaries, so record `80` is included in both the training set and the test set. Half-open `iloc[0:80]` and `iloc[80:100]` must be used instead.

### Flashcard 3
- **Front**: What happens when an index label is duplicated and queried with `df.loc[label]`?
- **Back**: If unique, `loc` returns a 1D `pd.Series`. If duplicated, `loc` dynamically returns a 2D `pd.DataFrame` containing all matching rows.

### Flashcard 4
- **Front**: Why does `df.loc[-1]` raise a `KeyError` on a standard 0-indexed DataFrame?
- **Back**: `loc` searches for the literal key `-1` in the index labels. It does not interpret negative integers as relative offsets from the end; use `iloc[-1]` for positional access.

### Flashcard 5
- **Front**: What is the structural difference between `df.iloc[0]` and `df.iloc[[0]]`?
- **Back**: `df.iloc[0]` produces a 1D `pd.Series` (shape `(M,)`). `df.iloc[[0]]` produces a 2D `pd.DataFrame` (shape `(1, M)`), preserving column headers and matrix dimensionality.

### Flashcard 6
- **Front**: Why does `df.iloc[100]` crash on a 5-row table while `df.iloc[10:20]` does not?
- **Back**: Scalar indexers enforce strict boundary checks and raise `IndexError`. Slice indexers adhere to Python slice semantics and clamp out-of-bounds offsets, returning an empty DataFrame.

### Flashcard 7
- **Front**: Why does chained indexing `df[mask]['col'] = val` fail to update the DataFrame?
- **Back**: `df[mask]` returns an intermediate temporary DataFrame slice. Mutating the slice triggers `SettingWithCopyWarning` and does not write back to the parent. Use atomic `df.loc[mask, 'col'] = val`.

### Flashcard 8
- **Front**: How do you safely query multiple row labels when some might be missing?
- **Back**: Use `df.loc[df.index.intersection(query_list)]` (returns existing rows) or `df.reindex(query_list)` (returns all keys, padding missing ones with `NaN`). Direct `df.loc[query_list]` raises `KeyError`.

### Flashcard 9
- **Front**: What causes `ValueError: The truth value of a Series is ambiguous` during row filtering?
- **Back**: Using Python logical operators `and` / `or` / `not` instead of Pandas vectorized bitwise operators `&` / `|` / `~` with mandatory parentheses.

### Flashcard 10
- **Front**: Why does `df.iloc[df['col'] > 0]` raise an `IndexError` on non-integer indices?
- **Back**: `iloc` cannot align boolean Series with custom index labels. Convert the condition to a raw NumPy array: `df.iloc[(df['col'] > 0).to_numpy()]` or use `df.loc[...]`.

### Flashcard 11
- **Front**: What does `df.head(-n)` do versus `df.tail(-n)`?
- **Back**: `df.head(-n)` drops the last $n$ rows (`df.iloc[:-n]`). `df.tail(-n)` skips the first $n$ rows and returns the rest (`df.iloc[n:]`).

### Flashcard 12
- **Front**: How does `DatetimeIndex` partial string slicing work in `loc`?
- **Back**: Querying `df.loc['2024-01']` automatically parses the string into a closed timestamp window covering the entire month, returning all matching records.

### Flashcard 13
- **Front**: Does row slicing via `df.iloc[start:stop]` duplicate memory under Copy-on-Write?
- **Back**: No. It returns a shallow view referencing existing array buffers in $O(1)$ time. Memory is copied only if either DataFrame is mutated.

### Flashcard 14
- **Front**: Why is `df.sort_index()` mandatory before label range slicing on string indices?
- **Back**: Slices evaluate physical index order. If the index is unsorted, range boundaries cannot be resolved deterministically, returning empty or truncated slices.

### Flashcard 15
- **Front**: How does `df.sample(n=k, random_state=42)` select rows?
- **Back**: It uses NumPy's pseudorandom number generator to sample $k$ unique positional offsets, returning a reproducible random row subset.

### Flashcard 16
- **Front**: How do you reverse all rows in a DataFrame with zero copy overhead?
- **Back**: Call `df.iloc[::-1]`. It constructs a strided array view with step $-1$ in $O(1)$ time.

## 15. Fresher Answer Evolution Patterns

### Question 1: "What is the difference between `loc` and `iloc`?"
- **Weak Fresher Answer**: *"They are both used to select data in Pandas. `loc` uses names and `iloc` uses numbers."*
- **Experienced Fresher Answer**: *"`loc` is strictly label-based, indexing by row and column names where range slices are closed and inclusive of both endpoints. `iloc` is strictly integer position-based, indexing by 0-based physical array offsets where range slices are half-open `[start:stop)`, strictly excluding the stop endpoint. For example, `df.loc[0:5]` returns 6 records on default integer indices, while `df.iloc[0:5]` returns exactly 5 records."*
- **What Changed & Why**: Replaced vague lay terms with exact technical terminology: label identity vs physical offset, inclusive vs half-open slice intervals, and concrete output counts.

### Question 2: "How do you get the last row of a DataFrame?"
- **Weak Fresher Answer**: *"You can do `df.loc[-1]` or `df.tail(1)`."*
- **Experienced Fresher Answer**: *"`df.loc[-1]` will fail with a `KeyError: -1` on a standard default index because `loc` searches for the literal label `-1`. The idiomatic ways are `df.iloc[-1]` to extract the row as a 1D Series, `df.iloc[[-1]]` or `df.tail(1)` to extract it as a 1-row DataFrame, or `df.iloc[-1:]` for zero-copy slicing."*
- **What Changed & Why**: Corrected the severe misconception about `loc[-1]`, explaining why it fails and contrasting Series vs DataFrame return types.

### Question 3: "Why did my conditional assignment trigger a `SettingWithCopyWarning`?"
- **Weak Fresher Answer**: *"Because Pandas didn't know if it was a view or a copy, so you should use `.copy()`."*
- **Experienced Fresher Answer**: *"You used chained indexing like `df[mask]['col'] = val`. The first bracket `df[mask]` returns an intermediate slice. Modifying `'col'` on that temporary slice does not reliably propagate back to the parent DataFrame. To fix this, you must use atomic 2D indexing: `df.loc[mask, 'col'] = val`. This executes a single `__setitem__` call directly on the parent DataFrame's `BlockManager`."*
- **What Changed & Why**: Diagnosed the root cause of chained indexing, explained the intermediate slice lifecycle, and provided the atomic `.loc` solution.

### Question 4: "What happens if an index has duplicate labels and you call `loc`?"
- **Weak Fresher Answer**: *"It returns the first one it finds."*
- **Experienced Fresher Answer**: *"Unlike Python dictionaries which reject duplicate keys, Pandas indices permit duplicate labels. When you query a duplicated label with `df.loc[label]`, Pandas returns a 2-dimensional `pd.DataFrame` containing all matching rows, NOT a 1D `pd.Series`. This frequently breaks downstream code expecting a scalar attribute."*
- **What Changed & Why**: Clarified that Pandas does not drop duplicates, identified the dynamic type switch from Series to DataFrame, and noted the production risk.

- **Base Question**: What does `df.iloc[::-1]` do?
- **Variant 1 (What if...)**: What does `df.iloc[::-2]` do?

## 19. What a Fresher Should Memorize

1. **Exact Slicing Rules**:
   - `loc[start:stop]` is **inclusive** (`[start, stop]`).
   - `iloc[start:stop]` is **exclusive** of stop (`[start, stop)`).
2. **Error Types**:
   - `iloc[out_of_bounds_scalar]` $\rightarrow$ `IndexError`.
   - `loc['missing_label']` $\rightarrow$ `KeyError`.
   - `loc[-1]` on default integer index $\rightarrow$ `KeyError`.
3. **Boundary Return Types**:
   - `df.iloc[0]` $\rightarrow$ `pd.Series` (shape `(M,)`).
   - `df.iloc[[0]]` $\rightarrow$ `pd.DataFrame` (shape `(1, M)`).
   - `df.head(n)` $\rightarrow$ `pd.DataFrame`.
   - `df.tail(n)` $\rightarrow$ `pd.DataFrame`.
4. **Boolean Indexing Syntax**:
   - Always use bitwise operators `&`, `|`, `~` with parentheses: `(cond1) & (cond2)`.
   - Never use Python logical operators `and`, `or`, `not`.

## 20. What a Fresher Should Understand

1. **Label vs Positional Indexing Mental Model**:
   - Labels are associative keys (like dictionary keys).
   - Positions are physical array offsets (like C array indices `0` to `N-1`).
   - When indices are integers, `loc` and `iloc` diverge whenever the index is shuffled, filtered, or non-consecutive.
2. **The Atomic 2D Assignment Rule**:
   - Chained assignment `df[rows]['col'] = val` fails because `df[rows]` produces an intermediate temporary object.
   - Atomic 2D coordinate assignment `df.loc[rows, 'col'] = val` modifies the parent array directly without warnings or memory bugs.
3. **Copy-on-Write (CoW) Mechanics**:
   - Row slicing creates shallow array views sharing buffer references.
   - Modifying a slice triggers an automatic, transparent memory copy at mutation time.
4. **Monotonic Index Requirements**:
   - Range slicing with `.loc` on string or timestamp indices requires the index to be monotonic (`df.index.is_monotonic_increasing`). Sorting via `sort_index()` guarantees predictable range boundaries.

### Answer Key & Scoring Rubric

#### Answer 1 (4 Marks)
- **Model Answer**:
  - **Indexing Basis**: `loc` is label-based (references index names/keys); `iloc` is integer position-based (references 0-indexed physical array offsets).
  - **Slice Endpoints**: `loc[start:stop]` is closed and inclusive of both endpoints. `iloc[start:stop]` is half-open `[start, stop)` exclusive of the stop boundary.
  - **Negative Integers**: `iloc[-1]` evaluates relative to table length (`len(df) - 1`), fetching the last row. `loc[-1]` searches for the literal label `-1`, raising `KeyError` if absent.
- **Marking**: 1.5 marks for basis contrast; 1.5 marks for endpoint inclusivity; 1 mark for negative index handling.

#### Answer 2 (4 Marks)
- **Model Answer**: Chained assignment calls `__getitem__` first (`df[df['a'] > 10]`), returning an intermediate temporary slice. Modifying `['b']` on that temporary object does not update the parent DataFrame and triggers `SettingWithCopyWarning`. The fix is atomic 2D indexing: `df.loc[df['a'] > 10, 'b'] = 0`.
- **Marking**: 2 marks for explaining intermediate temporary slice creation; 2 marks for atomic `df.loc[rows, cols]` syntax.

#### Answer 3 (4 Marks)

## 24. Final 2-Minute Revision Summary

- **`loc[]` vs `iloc[]`**:
  - `loc` is **label-based**; slices are **inclusive** of both endpoints `[start, stop]`.
  - `iloc` is **integer position-based** (0 to $N-1$); slices are **half-open** `[start, stop)`.
- **Boundary Record Access**:
  - `df.iloc[0]`: First row as a 1D `pd.Series`.
  - `df.iloc[-1]`: Last row as a 1D `pd.Series` (never use `df.loc[-1]`).
  - `df.iloc[[0]]` / `df.iloc[[-1]]`: First / last row as a 2D `pd.DataFrame`.
  - `df.head(n)` / `df.tail(n)`: First / last $n$ rows as a DataFrame.
  - Negative arguments: `head(-n)` drops last $n$ rows; `tail(-n)` skips first $n$ rows.
- **Slice Tolerance & Bounds Checking**:
  - Scalar `iloc[100]` on 5 rows raises `IndexError`.
  - Slice `iloc[10:100]` clamps gracefully and returns an empty DataFrame.
- **Atomic 2D Assignment Rule**:
  - Never write chained assignments like `df[mask]['col'] = val`.
  - Always use atomic 2D indexing: `df.loc[mask, 'col'] = val`.
- **Duplicate Label Mechanics**:
  - If an index label is unique, `df.loc[label]` returns a `pd.Series`.
  - If an index label is duplicated, `df.loc[label]` returns a 2D `pd.DataFrame`.
- **Missing Keys in Lists**:
  - `df.loc[key_list]` raises `KeyError` if any key is missing.
  - Use `df.loc[df.index.intersection(key_list)]` to select only existing keys.
  - Use `df.reindex(key_list)` to conform the DataFrame, populating missing rows with `NaN`.
