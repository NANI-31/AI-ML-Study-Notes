# 4. Data Selection and Indexing

## 4.3 Indexing Techniques

---

### Section 1: Architecture Blueprint & Mental Model

Pandas provides a unified, two-dimensional coordinate system for data access through two explicit indexing accessors: `.loc` (label-based) and `.iloc` (integer-position-based), complemented by specialized scalar accessors `.at` and `.iat`. Mastering indexing requires understanding how Pandas maps user-supplied coordinates (labels, positions, slices, boolean masks, callables) against its internal 1D array managers (`Index` objects) and 2D block managers (`BlockManager` / `ArrayManager`).

```
                              DataFrame Access Pipeline
                                         │
                   ┌─────────────────────┴─────────────────────┐
                   ▼                                           ▼
          Label-Based (`.loc`)                       Position-Based (`.iloc`)
                   │                                           │
       Index.get_loc() / slice_locs()              Direct 0-based C-array offset
                   │                                           │
      Endpoint: INCLUSIVE [start, stop]           Endpoint: EXCLUSIVE [start, stop)
                   │                                           │
       Labels: Strings, Dates, Ints                Integers only: 0 <= i < N
                   │                                           │
                   └─────────────────────┬─────────────────────┘
                                         ▼
                             Dimensionality Resolver
                                         │
                   ┌─────────────────────┼─────────────────────┐
                   ▼                     ▼                     ▼
             Scalar Access          1D Slice / List       2D Slice / Matrix
             (`.at` / `.iat`)        (Returns Series)     (Returns DataFrame)
                   │                     │                     │
               O(1) Fast             O(K) Copy/View        O(R*C) Copy/View
```

#### The Coordinate Access Matrix

| Feature / Dimension | `.loc[row, col]` | `.iloc[row, col]` | `.at[row, col]` | `.iat[row, col]` |
| :--- | :--- | :--- | :--- | :--- |
| **Addressing Mode** | Index & Column Labels | 0-based Integer Offsets | Single Index & Col Label | Single Integer Offsets |
| **Slice Inclusivity** | **Both endpoints closed**: `[start, stop]` | **Half-open**: `[start, stop)` | Slicing Not Allowed | Slicing Not Allowed |
| **Negative Integers** | Interpreted as actual label `-1` | Negative offset from end (`-1` = last) | Interpreted as actual label | Negative offset from end |
| **Return Dimensionality** | Scalar, Series, or DataFrame | Scalar, Series, or DataFrame | **Strictly Scalar** | **Strictly Scalar** |
| **Engine Overhead** | High (validates labels, alignments) | Moderate (boundary checks) | **Ultra Low** (direct lookup) | **Ultra Low** (direct pointer) |
| **Boolean Masking** | Supported (aligns on labels) | Supported (boolean array / list) | Not Supported | Not Supported |
| **Callable Support** | `lambda df: ...` supported | `lambda df: ...` supported | Not Supported | Not Supported |
| **Out-of-Bounds Handling** | `KeyError` if label missing | `IndexError` on scalar/list | `KeyError` if label missing | `IndexError` |

#### Core Architectural Trade-offs
1. **Expressiveness vs. Execution Speed**: `.loc` and `.iloc` parse complex multi-axis indexers (tuples, lists, slices, booleans, callables) and construct new Pandas objects, introducing noticeable microseconds of python dispatch overhead. For high-frequency tight loops requiring single-cell reads/writes, `.at` and `.iat` bypass DataFrame wrapper logic to operate in nanoseconds.
2. **Label Semantics vs. Sequential Semantics**: Label-based slicing (`loc['A':'C']`) includes `'C'` because in business, dates, and domain taxonomies, users naturally expect interval endpoints to be inclusive. In contrast, positional slicing (`iloc[0:3]`) honors standard Python / NumPy conventions where the right endpoint is excluded.
3. **View vs. Copy Hazards**: Slicing coordinates along homogeneous data blocks can yield zero-copy views, whereas list-based fancy indexing (`df.loc[['r1', 'r2']]`) or mixed-type selections force memory allocation and deep copies.

### Section 2: Deep Dive per Syllabus Topic

#### Topic 1: Label-Based Indexing (`.loc`)

##### 1. Formal Engineering Definition & Internal Mechanics
`.loc` is Pandas' primary label-based accessor. It routes requests through `df.index` (for axis 0) and `df.columns` (for axis 1). Internally, when an exact label is queried, `.loc` calls `Index.get_loc(key)`, which queries an internal hash map mapping labels to integer array offsets. If the index is monotonic, binary search may be used. Slices invoke `Index.slice_locs(start, end)` to resolve the inclusive start and end integer positions.

##### 2. Concrete, Runnable Code Example
```python
import pandas as pd
import numpy as np

# Create DataFrame with custom string labels
df = pd.DataFrame(
    data={"revenue": [100, 150, 200], "margin": [0.2, 0.25, 0.3]},
    index=["Q1", "Q2", "Q3"]
)

# Label-based scalar, row, and slice access
scalar_val = df.loc["Q2", "revenue"]
row_series = df.loc["Q2"]
slice_df = df.loc["Q1":"Q2", ["revenue"]]

print("Scalar Value:", scalar_val)
print("\nRow Series:\n", row_series)
print("\nSlice DataFrame (Both Inclusive):\n", slice_df)
```

##### 3. Complexity Guarantees
- **Exact Hash Lookup (`Unique Index`)**: $O(1)$ amortized average time complexity via internal hash table.
- **Exact Hash Lookup (`Non-Unique Index`)**: $O(K)$ where $K$ is the number of matching duplicate labels.
- **Sorted / Monotonic Slice (`start:end`)**: $O(\log N + M)$ where $M$ is the slice length, resolved via binary search.
- **Unsorted Slice (`start:end`)**: $O(N)$ full scan, or raises `KeyError`/`UnsortedIndexError` if duplicate boundaries exist.

##### 4. Memory & Performance Implications
`.loc` validates labels on every call, checking both index and columns. If multiple columns of different dtypes are returned for a row, a new `Series` with `object` dtype is created, generating memory allocation and cache misses.

##### 5. Edge Cases & Boundary Conditions
- If the DataFrame index consists of integers (`[10, 20, 30]`), `df.loc[10]` searches for the *label* `10`, not the 10th row.
- Missing labels raise `KeyError`.
- Slicing with labels missing from an unsorted index raises `KeyError`.

##### 6. Failure Modes & Anti-Patterns
- **Anti-Pattern**: Using `.loc` in a tight loop across thousands of rows.
- **Failure Mode**: Assuming `df.loc[0]` always gets the first row. If index is `[101, 102, 103]`, `df.loc[0]` raises `KeyError`.

##### 7. Best Practices & Idiomatic Python
- Use `.loc` when coordinate names carry business semantics (e.g., date strings, country codes, customer IDs).
- When selecting both rows and columns, pass both explicit dimensions: `df.loc[row_indexer, col_indexer]`.

##### 8. Interactive Exploration Experiment
```python
# Experiment: Compare integer-labeled DataFrame behavior
df_int = pd.DataFrame({"val": [10, 20, 30]}, index=[2, 1, 0])
print("df_int.loc[0]:\n", df_int.loc[0])    # Searches for label 0 (the 3rd physical row!)
print("df_int.iloc[0]:\n", df_int.iloc[0])  # Searches for 0-th offset (the 1st physical row!)
```

#### Topic 2: Position-Based Indexing (`.iloc`)

##### 1. Formal Engineering Definition & Internal Mechanics
`.iloc` provides purely positional, integer-based indexing along both axes, adhering strictly to Python's 0-based sequence protocol. `.iloc` maps integers directly to memory block offsets using NumPy array indexing semantics without consulting the label hash tables of `df.index` or `df.columns`.

##### 2. Concrete, Runnable Code Example
```python
import pandas as pd
import numpy as np

df = pd.DataFrame(
    [[10, 20, 30], [40, 50, 60], [70, 80, 90]],
    index=["alpha", "beta", "gamma"],
    columns=["c1", "c2", "c3"]
)

# Position-based access
first_row = df.iloc[0]
sub_matrix = df.iloc[0:2, 1:3]  # Half-open: rows 0,1; cols 1,2

print("First Row:\n", first_row)
print("\nSub Matrix (Half-Open Slices):\n", sub_matrix)
```

##### 3. Complexity Guarantees
- **Integer Scalar Access**: $O(1)$ direct array index.
- **Positional Slice (`start:stop:step`)**: $O(1)$ metadata view creation (for single-block 2D arrays).
- **Fancy Positional List (`[0, 2, 4]`)**: $O(K)$ array copy allocation where $K$ is the number of elements requested.

##### 4. Memory & Performance Implications
`.iloc` bypasses label lookup, making it significantly faster than `.loc`. Positional slices across a single homogeneous float/int block return views where possible, minimizing memory footprint.

##### 5. Edge Cases & Boundary Conditions
- Passing floating-point numbers (`df.iloc[1.5]`) raises `TypeError: cannot do positional indexing with float type`.
- Slicing past the end (`df.iloc[0:100]` on a 5-row DataFrame) gracefully returns all available rows (Python standard slice behavior).
- Scalar out-of-bounds (`df.iloc[100]`) raises `IndexError: single positional indexer is out-of-bounds`.

##### 6. Failure Modes & Anti-Patterns
- **Anti-Pattern**: Using `.iloc` when column order is dynamic or subject to ETL drift. If upstream columns are reordered, `df.iloc[:, 2]` silently pulls the wrong business attribute.
- **Failure Mode**: Expecting inclusive upper bounds. `df.iloc[0:3]` returns rows 0, 1, and 2, omitting row 3.

##### 7. Best Practices & Idiomatic Python
- Use `.iloc` when algorithms require geometric or ordinal row partitions (e.g., train/test splits, top-k ranking offsets, matrix math).
- Always verify sequence lengths before positional scalar calls to avoid runtime `IndexError`.

##### 8. Interactive Exploration Experiment
```python

    _ = df_test.iloc[99]
except IndexError as e:
    print("Scalar beyond bounds (Fails):", type(e).__name__)
```

#### Topic 3: Selecting Specific Rows and Columns (`loc[rows, cols]`, `iloc[rows, cols]`)

##### 1. Formal Engineering Definition & Internal Mechanics
Pandas supports 2D coordinate indexing using two-element comma-separated indexers: `df.loc[row_indexer, col_indexer]` and `df.iloc[row_indexer, col_indexer]`. The dimensionality of the resulting object is governed by the Cartesian product of the indexer types:
- `(scalar, scalar)` $\rightarrow$ scalar value (or Series if duplicates exist).
- `(scalar, list)` or `(list, scalar)` $\rightarrow$ `pd.Series`.
- `(list, list)` or `(slice, slice)` $\rightarrow$ `pd.DataFrame`.

##### 2. Concrete, Runnable Code Example
```python
import pandas as pd

df = pd.DataFrame(
    data=[[1, 2, 3], [4, 5, 6], [7, 8, 9]],
    index=["r1", "r2", "r3"],
    columns=["cA", "cB", "cC"]
)

# 1. 2D Selection returning DataFrame
df_subset = df.loc[["r1", "r3"], ["cA", "cC"]]

# 2. 2D Selection returning Series (scalar row, list of cols)
series_row = df.loc["r2", ["cA", "cC"]]

# 3. 2D Selection with iloc returning scalar
val = df.iloc[1, 2]

print("Subset DataFrame:\n", df_subset)
print("\nSubset Series:\n", series_row)
print("\nScalar Val:", val)
```

##### 3. Complexity Guarantees
- 2D coordinate access runs in $O(R_{lookup} + C_{lookup} + R \times C_{alloc})$ where $R$ and $C$ represent selected row and column counts.
- For list indexers, memory allocation is always triggered to construct the output container.

##### 4. Memory & Performance Implications
Chained indexing (`df.loc[rows][cols]`) creates an intermediate temporary DataFrame, wasting memory and risking `SettingWithCopyWarning`. Simultaneous 2D indexing (`df.loc[rows, cols]`) performs coordinate resolution in a single pass directly on the underlying manager.

##### 5. Edge Cases & Boundary Conditions
- Passing a colon `:` for rows (`df.loc[:, ["cA"]]`) selects all rows while preserving 2D DataFrame shape.
- If list indexers contain labels not in the DataFrame, Pandas raises `KeyError`.

##### 6. Failure Modes & Anti-Patterns
- **Anti-Pattern**: Chaining `df.loc[r][c] = val`. This modifies a copy or triggers runtime warnings.
- **Correct**: Always use atomic 2D indexing: `df.loc[r, c] = val`.

##### 7. Best Practices & Idiomatic Python
- Use `.at[r, c]` or `.iat[r, c]` when both coordinates are single scalars and maximum speed is paramount.
- Maintain readable column lists: `TARGET_COLS = ["cA", "cB"]; df.loc[mask, TARGET_COLS]`.

##### 8. Interactive Exploration Experiment
```python
# Experiment: Verify Dimensionality collapse
df_dim = pd.DataFrame({"x": [10, 20], "y": [30, 40]}, index=["a", "b"])
print("Scalar row, scalar col ->", type(df_dim.loc["a", "x"]).__name__)
print("List row, scalar col   ->", type(df_dim.loc[["a"], "x"]).__name__)
print("List row, list col     ->", type(df_dim.loc[["a"], ["x"]]).__name__)
```

#### Topic 4: Selecting Ranges (Slicing Mechanics)

##### 1. Formal Engineering Definition & Internal Mechanics
Range selection allows contiguous or stepped window extraction along either axis using the slice syntax `start:stop:step`.
- **In `.loc`**: Slicing operates over labels. The range is **closed** (both `start` and `stop` are included).
- **In `.iloc`**: Slicing operates over 0-based integer positions. The range is **half-open** (`start` is included, `stop` is excluded), mirroring Python sequence slicing.

##### 2. Concrete, Runnable Code Example
```python
import pandas as pd
import numpy as np

df = pd.DataFrame(
    data=np.arange(25).reshape(5, 5),
    index=["2026-01", "2026-02", "2026-03", "2026-04", "2026-05"],
    columns=["A", "B", "C", "D", "E"]
)

# loc range: inclusive of "2026-03" and "C"
loc_slice = df.loc["2026-01":"2026-03", "A":"C"]

# iloc range: rows 0, 1, 2; cols 0, 1, 2 (excludes row 3 and col 3)
iloc_slice = df.iloc[0:3, 0:3]

print("loc slice shape:", loc_slice.shape)    # (3, 3)
print("iloc slice shape:", iloc_slice.shape)  # (3, 3)
assert loc_slice.equals(iloc_slice)
print("Slices are numerically identical!")
```

##### 3. Complexity Guarantees
- Positional slicing on single-block data is $O(1)$ in time and space because it generates a slice view over the existing NumPy array without data copying.
- Label-based slicing on a monotonic index requires $O(\log N)$ to find boundary offsets via `searchsorted`, followed by $O(1)$ slice view instantiation.

##### 4. Memory & Performance Implications
Modifying a slice view directly alters the original DataFrame if it is a view. When mixed dtypes or consolidated blocks are involved, Pandas may generate copies.

##### 5. Edge Cases & Boundary Conditions
- **Unsorted Index in `.loc`**: Slicing an unsorted index with labels that do not exist raises `KeyError`. If labels exist, it extracts all rows physically between them.
- **Stepping**: Negative steps (`df.iloc[::-1]`) invert the row axis.
- **Omitted endpoints**: `df.loc[:"2026-03"]` slices from the beginning up to and including `"2026-03"`.

##### 6. Failure Modes & Anti-Patterns
- Confusing `.loc` slice inclusivity with `.iloc` exclusivity, leading to off-by-one bugs in production data extraction.
- Slicing on string-formatted dates that are not zero-padded (e.g. `'2026-1'` vs `'2026-10'`).

##### 7. Best Practices & Idiomatic Python
- Ensure indices are sorted using `df.sort_index()` prior to executing high-throughput label range slicing.
- Use explicit slice steps rather than manual loop indexing.

##### 8. Interactive Exploration Experiment
```python

print("Physical slice between 'd' and 'c' in unsorted index:")
print(df_unsorted.loc["d":"c"])
```

#### Topic 5: Negative Indexing

##### 1. Formal Engineering Definition & Internal Mechanics
Python's sequence protocol interprets negative indices as relative offsets from the end of the collection (where $-1$ refers to the last element, $-2$ the penultimate, etc.).
- **In `.iloc`**: Negative integers are universally supported across rows and columns. Pandas converts $-k$ to $N - k$.
- **In `.loc`**: Negative integers are treated strictly as **literal label values**. If an index has integer labels `[-2, -1, 0, 1]`, `df.loc[-1]` retrieves the row whose index label is mathematically `-1`. If the index has string or positive labels, `df.loc[-1]` fails with `KeyError`.

##### 2. Concrete, Runnable Code Example
```python
import pandas as pd

df = pd.DataFrame({
    "product": ["Widget", "Gadget", "Doodad"],
    "cost": [10.5, 20.0, 35.2]
}, index=["p1", "p2", "p3"])

# iloc negative indexing
last_row = df.iloc[-1]
last_two_cols_last_row = df.iloc[-1, -2:]
tail_slice = df.iloc[-2:, :]

print("Last row via iloc[-1]:\n", last_row)
print("\nNegative 2D slice:\n", last_two_cols_last_row)

# loc with literal negative index
df_neg_labels = pd.DataFrame({"score": [88, 92, 95]}, index=[-2, -1, 0])
print("\nloc with literal negative label -1:\n", df_neg_labels.loc[-1])
```

##### 3. Complexity Guarantees
- `df.iloc[-k]` computes `N - k` in $O(1)$ arithmetic time and executes offset indexing in $O(1)$ time.
- `df.loc[-k]` computes hash lookup of key `-k` in $O(1)$ average time.

##### 4. Memory & Performance Implications
Positional negative indexing has zero performance penalty compared to positive indexing; it is evaluated in C-level array logic.

##### 5. Edge Cases & Boundary Conditions
- `df.iloc[-N]` retrieves the very first row.
- `df.iloc[-(N+1)]` raises `IndexError: single positional indexer is out-of-bounds`.
- Slices with negative bounds: `df.iloc[:-1]` drops the last row cleanly.

##### 6. Failure Modes & Anti-Patterns
- Writing `df.loc[-1]` expecting the last row of a DataFrame. This is the #1 cause of `KeyError` among developers transitioning from standard Python lists.
- Using `df.iloc[-1:]` (returns DataFrame) when a scalar value or Series is desired, or vice versa.

##### 7. Best Practices & Idiomatic Python
- For accessing the last row as a Series, use `df.iloc[-1]`.
- For getting the last $k$ rows as a DataFrame, use `df.iloc[-k:]` or `df.tail(k)`.

##### 8. Interactive Exploration Experiment

#### Topic 6: Conditional Indexing (Boolean Masking)

##### 1. Formal Engineering Definition & Internal Mechanics
Conditional indexing uses boolean vectors, expressions, or callables to filter rows or columns.
When evaluating `df.loc[mask, cols]`:
1. `mask` must be a boolean Series, NumPy boolean array, or callable returning a boolean array.
2. If `mask` is a Pandas Series, **index alignment** occurs: Pandas aligns the boolean mask against `df.index`. Any unaligned rows become `False` or raise `IndexingError` if lengths mismatch on non-Series arrays.
3. Multiple conditions require bitwise operators (`&` for AND, `|` for OR, `~` for NOT) because Python's logical operators (`and`, `or`, `not`) cannot be overloaded for vector truth values.
4. Python's operator precedence evaluates bitwise operators before comparison operators (`>`, `<`), making parentheses mandatory around each condition: `(df["a"] > 1) & (df["b"] < 5)`.

##### 2. Concrete, Runnable Code Example
```python
import pandas as pd

df = pd.DataFrame({
    "department": ["Eng", "Sales", "Eng", "HR", "Sales"],
    "salary": [110000, 85000, 125000, 70000, 95000],
    "experience": [3, 5, 8, 2, 6]
})

# Compound conditional indexing with .loc
mask = (df["department"] == "Eng") & (df["salary"] > 115000)
high_eng = df.loc[mask, ["salary", "experience"]]

# Using isin() and negation ~
non_exec = df.loc[~df["department"].isin(["HR"]), :]

# Callable conditional indexing
bonus_pool = df.loc[lambda d: d["salary"] * 0.10 > 9000, ["department", "salary"]]

print("High Eng Engineers:\n", high_eng)
print("\nNon-HR Staff:\n", non_exec)
print("\nBonus Pool (>9000):\n", bonus_pool)
```

##### 3. Complexity Guarantees
- Vectorized boolean mask generation: $O(N)$ across columns.
- Bitwise combination (`&`, `|`): $O(N)$ SIMD-accelerated bit operations.
- Index alignment: $O(N)$ linear pass.
- Filtered subset extraction: $O(M \times C)$ where $M$ is the number of matching `True` rows.

##### 4. Memory & Performance Implications
Generating intermediate boolean Series creates small temporary allocations. To avoid memory bloat in massive DataFrames, use `.loc[condition, specific_columns]` instead of filtering all columns and then subsetting.

##### 5. Edge Cases & Boundary Conditions
- **Missing Data in Mask**: If a comparison yields `NaN` (e.g. from missing values), Pandas treats it as `False` in indexing, but explicit `.fillna(False)` is recommended for safety.
- **Unaligned Index Mask**: If `mask` has a different index than `df`, Pandas aligns them by label, potentially dropping rows that do not match index labels.

##### 6. Failure Modes & Anti-Patterns
- Forgetting parentheses: `df[df["salary"] > 80000 & df["experience"] > 3]` raises `TypeError: cannot compare a dtyped [int64] array with a scalar of type [bool]`.
- Using `and` / `or`: `df[df["a"] > 1 and df["b"] < 2]` raises `ValueError: The truth value of a Series is ambiguous`.

##### 7. Best Practices & Idiomatic Python
- Use `.isin()` for membership testing instead of chaining multiple `|` conditions.
- Always filter and project simultaneously: `df.loc[mask, ["col_a", "col_b"]]`.
- Use callable indexing (`lambda x: ...`) when method-chaining data transformations.

##### 8. Interactive Exploration Experiment

### Section 3: Questions & Answers (68 Questions)

#### 3.1 Basic Q&A (20 Questions: Q1 to Q20)

##### Q1: What is the fundamental difference between `.loc` and `.iloc`?
1. **Core Concept & Syntax**:
   `.loc` is label-based, indexing by explicit row/column names and including both endpoints in slices (`[start, stop]`). `.iloc` is integer-position-based, indexing by 0-based physical offsets and excluding the right endpoint in slices (`[start, stop)`).
2. **Complete, Runnable Code Demonstration**:
   ```python
   import pandas as pd
   df = pd.DataFrame({"A": [10, 20, 30]}, index=["x", "y", "z"])
   loc_val = df.loc["y", "A"]
   iloc_val = df.iloc[1, 0]
   ```
3. **Output**:
   ```python
   print(loc_val, iloc_val)
   # Output: 20 20
   ```
4. **Detailed Code Walkthrough**:
   `df.loc["y", "A"]` searches the index for string label `"y"` and column label `"A"`. `df.iloc[1, 0]` accesses physical row offset 1 and column offset 0 directly. Both point to the exact same cell in memory.

---

##### Q2: How does slice endpoint inclusivity differ between `.loc` and `.iloc`?
1. **Core Concept & Syntax**:
   `.loc[start:stop]` includes `stop` (closed interval). `.iloc[start:stop]` excludes `stop` (half-open interval `[start, stop)`).
2. **Complete, Runnable Code Demonstration**:
   ```python
   import pandas as pd
   df = pd.DataFrame({"score": [10, 20, 30, 40]}, index=["a", "b", "c", "d"])
   loc_res = df.loc["a":"c"]
   iloc_res = df.iloc[0:2]
   ```
3. **Output**:
   ```python
   print("loc length:", len(loc_res))   # 3 ('a', 'b', 'c')
   print("iloc length:", len(iloc_res)) # 2 (offsets 0, 1)
   ```
4. **Detailed Code Walkthrough**:
   `df.loc["a":"c"]` extracts labels `"a"`, `"b"`, and `"c"`. `df.iloc[0:2]` extracts row offsets 0 and 1, stopping before offset 2.

---

##### Q3: How do you select a single scalar value using `.loc`?
1. **Core Concept & Syntax**:
   Pass a single row label and column label: `df.loc[row_label, col_label]`.
2. **Complete, Runnable Code Demonstration**:
   ```python
   import pandas as pd
   df = pd.DataFrame({"price": [100, 200]}, index=["item1", "item2"])
   p = df.loc["item1", "price"]
   ```
3. **Output**:
   ```python
   print("Price:", p)
   # Output: Price: 100
   ```
4. **Detailed Code Walkthrough**:
   The coordinates `"item1"` and `"price"` locate the unique cell. If the index contains duplicate labels, a Series containing all matching values would be returned instead.

---

##### Q4: How do you select a single scalar value using `.iloc`?
1. **Core Concept & Syntax**:
   Pass integer offsets for row and column: `df.iloc[row_idx, col_idx]`.
2. **Complete, Runnable Code Demonstration**:
   ```python
   import pandas as pd
   df = pd.DataFrame({"price": [100, 200]}, index=["item1", "item2"])
   p = df.iloc[0, 0]
   ```
3. **Output**:
   ```python
   print("Position 0,0:", p)
   # Output: Position 0,0: 100
   ```
4. **Detailed Code Walkthrough**:
   `df.iloc[0, 0]` accesses the 0th row and 0th column in internal memory without inspecting row/column string names.

---

##### Q5: What are `.at` and `.iat`, and when should you use them instead of `.loc` and `.iloc`?
1. **Core Concept & Syntax**:
   `.at` (label-based) and `.iat` (integer-position-based) are specialized fast scalar accessors. They cannot handle lists or slices, but have microsecond latency advantages for single-cell lookups.
2. **Complete, Runnable Code Demonstration**:
   ```python
   import pandas as pd
   df = pd.DataFrame({"A": [1, 2]}, index=["r1", "r2"])
   val1 = df.at["r1", "A"]
   val2 = df.iat[0, 0]
   ```
3. **Output**:
   ```python
   print(val1, val2)
   # Output: 1 1
   ```

##### Q66: High-Frequency Sensor Reading Ingestion & Outlier Masking
1. **Business/Engineering Problem Statement**:
   An IoT monitoring node processes streams of 500,000 sensor readings per batch with columns `["device_id", "voltage", "temperature"]`. Readings with negative voltage or temperatures $> 120.0$ are physical anomalies. The system must flag anomalies, clamp invalid voltages to $0.0$, and return the clean subset with columns `["device_id", "voltage"]`.
2. **Naive/Suboptimal Solution**:
   ```python
   # Naive: Iterating over rows or using chained indexing
   # for idx, row in df.iterrows(): ... (Extremely slow)
   # Or chained indexing:
   clean_df = df[df["voltage"] >= 0]
   clean_df = clean_df[clean_df["temperature"] <= 120]
   # Chained assignment triggers warnings:
   # df[df["voltage"] < 0]["voltage"] = 0
   ```
3. **Production-Ready Idiomatic Solution**:
   ```python
   import pandas as pd
   import numpy as np

   def clean_sensor_batch(df: pd.DataFrame) -> pd.DataFrame:
       # Atomic in-place clamping
       neg_voltage_mask = df["voltage"] < 0
       df.loc[neg_voltage_mask, "voltage"] = 0.0

       # Compound boolean filter with simultaneous column projection
       valid_mask = (df["voltage"] >= 0) & (df["temperature"] <= 120.0)
       return df.loc[valid_mask, ["device_id", "voltage"]].copy()
   ```
4. **Architectural Trade-offs & Benchmarks**:

##### Q67: Sliding Financial Window Feature Generation

   A quantitative trading backtest receives market order book snapshots indexed by sorted nanosecond timestamps. The strategy needs to evaluate rolling 3-row historical windows to compute spread momentum without relying on external time-series libraries.

   ```python
   # Naive: Querying df.loc with timestamp calculations inside a loop
   # for t in timestamps: df.loc[t - delta : t] -> Repeated binary searches
   ```

   ```python
   import pandas as pd
   import numpy as np

   def extract_rolling_windows(df: pd.DataFrame, window_size: int = 3):

       return features
   ```

##### Q68: Multi-Tenant Data Masking & Role-Based Projection
1. **Business/Engineering Problem Statement**:

   ```python
   # Multiple copies, filtering tenant first, then deleting column, then looping to mask
   tenant_df = df[df["tenant_id"] == "t123"].copy()
   ```

#### Must-Know Concepts (Tier 1: Production Fundamentals)

##### 1. Label-Based Inclusive Slicing (`df.loc[start:stop]`)
- **Why It Matters**: Unlike standard Python sequences, `.loc` includes the right endpoint. Business users requesting `"2026-01":"2026-03"` expect March to be included.
- **When to Use**: Whenever filtering or partitioning DataFrames by meaningful domain labels (dates, ticker symbols, categorical codes).
- **Production Trap**: Forgetting that `.loc` slice inclusion will return an extra row if you treat it like a 0-based Python sequence index.

##### 2. Position-Based Half-Open Slicing (`df.iloc[start:stop]`)
- **Why It Matters**: Standardizes with NumPy array indexing semantics (`[start, stop)`), ensuring seamless integration with machine learning feature matrices and batch samplers.
- **When to Use**: When splitting data into train/test folds, grabbing fixed geometric batches, or operating on ordered numerical offsets.
- **Production Trap**: Assuming `df.iloc[0:5]` returns 6 rows. It strictly returns 5 rows (indices 0, 1, 2, 3, 4).

##### 3. Simultaneous Two-Dimensional Coordinate Access (`df.loc[rows, cols]`)
- **Why It Matters**: Eliminates chained indexing (`df[rows][cols]`), ensuring single-pass lookup, avoiding temporary copies, and preventing `SettingWithCopyWarning`.
- **When to Use**: On every multi-axis extraction or mutation in production code.
- **Production Trap**: Writing `df.loc[rows][cols] = val` which modifies a disconnected intermediate slice.

##### 4. Bitwise Vector Logical Operators (`&`, `|`, `~`)
- **Why It Matters**: Python's `and`, `or`, and `not` cannot evaluate truth vectors. Bitwise operators evaluate element-wise SIMD boolean arrays.
- **When to Use**: On any compound conditional filter across DataFrame columns.
- **Production Trap**: Omitting parentheses `(cond1) & (cond2)`. Bitwise operators have higher precedence than comparison operators, causing runtime `TypeError`.

##### 5. High-Frequency Scalar Accessors (`.at` and `.iat`)
- **Why It Matters**: `.loc` and `.iloc` have 5–15x overhead due to dynamic return typing and argument parsing. `.at` and `.iat` operate at nanosecond latency for single-cell reads/writes.
- **When to Use**: Inside simulations, event loops, or cell-by-cell validation routines.
- **Production Trap**: Passing slices or lists to `.at` or `.iat`. They strictly accept individual scalar coordinates.

#### Good-to-Know Concepts (Tier 2: Engineering Efficiency)

##### 6. Categorical Set Filtering via `.isin()`
- **Why It Matters**: Replaces long, unreadable chains of `(df[c] == v1) | (df[c] == v2)` with an efficient, hash-based vectorized search.
- **When to Use**: When filtering against lists of IDs, whitelist domains, or multi-state enums.
- **Production Trap**: Passing a single scalar instead of an iterable collection (list, set, tuple) to `.isin()`.

##### 7. Negative Positional Indexing (`df.iloc[-k:]`)
- **Why It Matters**: Provides clean access to the tail end of ordered series without calculating `len(df) - k`.
- **When to Use**: Fetching the most recent $k$ records or dropping trailing summary rows.
- **Production Trap**: Attempting to use `df.loc[-1]` on an integer-indexed DataFrame expecting the last row.

##### 8. Vectorized In-Place Value Updates (`df.loc[mask, col] = new_val`)
- **Why It Matters**: Updates column values in-place based on arbitrary predicate logic without looping or creating full DataFrame replicas.
- **When to Use**: Data cleansing, clipping outliers, imputation, and status flag transitions.
- **Production Trap**: Supplying a right-hand-side array that doesn't match the number of `True` rows in `mask` or the DataFrame index.

##### 9. Closed Interval Filtering with `.between()`
- **Why It Matters**: Evaluates `left <= x <= right` in a single vectorized method, eliminating redundant references to column names and complex boolean logic.
- **When to Use**: Bounding telemetry, sensor tolerances, and financial price bands.
- **Production Trap**: Default parameter is `inclusive='both'`. If half-open intervals are needed, specify `inclusive='left'` or `inclusive='right'`.

##### 10. Automatic Label Alignment in Boolean Masks
- **Why It Matters**: When filtering a DataFrame using a boolean `Series`, Pandas aligns by index labels, not physical array offsets.
- **When to Use**: Re-applying masks generated from transformed or reordered sub-tables back to the parent DataFrame.
- **Production Trap**: Using a mask from a DataFrame whose index has diverged, causing unaligned rows to silently evaluate to `False`.

#### Bonus Concepts (Tier 3: Expert Edge Cases)

##### 11. MultiIndex Coordinate Tuples in `.loc`
- **Why It Matters**: Allows coordinate navigation across hierarchical index levels without flattening or unstacking tables.
- **When to Use**: OLAP cube extraction, financial panels with `(Ticker, Date)` indexes.
- **Production Trap**: Forgetting that inner levels cannot be omitted unless slicing with `pd.IndexSlice`.

- **Why It Matters**: Enables dynamic row and column filtering inside long method-chaining pipelines without intermediate variable assignments.
- **When to Use**: Data transformation pipelines using `.pipe()` and fluent syntax.
- **Production Trap**: Writing expensive, non-vectorized lambda bodies that trigger row-by-row Python iteration.

##### 13. Index Difference for Inverted Projections (`df.index.difference()`)
- **Why It Matters**: Mathematically computes the set complement of index keys in $O(N)$ hash-table time without boolean masking.
- **When to Use**: Removing blacklisted keys, holdout validation sets, or outlier IDs.
- **Production Trap**: Does not preserve original index order; returns a sorted Index by default.

##### 14. Data Type Reflection Indexing (`df.loc[:, df.dtypes == ...]`)
- **Why It Matters**: Programmatically selects all columns matching specific physical storage types without hardcoded column lists.
- **When to Use**: Automated pre-processing pipelines feeding numeric features to scikit-learn models.
- **Production Trap**: Assuming `df.dtypes == 'float'` catches nullable `Float64Dtype` or custom extension arrays.

- **When to Use**: Parsing log entries, URL routes, or semi-structured SKU indices.
- **Production Trap**: Null values in string indexes produce `NaN` booleans, causing `ValueError` unless `na=False` is passed.

#### 1. Chained Indexing Assignment (`df[mask]['col'] = val`)
- **Wrong**:
  ```python
  df[df["status"] == "active"]["points"] = 100
  ```
- **Why It Fails**: `df[df["status"] == "active"]` returns an intermediate slice. Setting `['points']` modifies the temporary slice, not `df`.
- **Correct**:
  ```python
  df.loc[df["status"] == "active", "points"] = 100
  ```
- **Performance Impact**: Eliminates redundant slice creation and guarantees in-place updates.

#### 2. Using `df.loc[-1]` for Last Row Access
- **Wrong**:
  ```python
  last_item = df.loc[-1]
  ```
- **Why It Fails**: `.loc` searches for the literal label `-1` in `df.index`. Unless a row is named `-1`, it raises `KeyError`.
- **Correct**:
  ```python
  last_item = df.iloc[-1]
  ```
- **Performance Impact**: Direct $O(1)$ offset lookup.

#### 3. Using Python Logical `and` / `or` in Vector Filters
- **Wrong**:
  ```python
  sub = df[df["age"] > 21 and df["salary"] > 50000]
  ```
- **Why It Fails**: `and` coerces the left operand to a single boolean, raising `ValueError: The truth value of a Series is ambiguous`.
- **Correct**:
  ```python
  sub = df.loc[(df["age"] > 21) & (df["salary"] > 50000)]
  ```
- **Performance Impact**: Vectorized SIMD bitwise evaluation across continuous memory.

#### 4. Omitting Parentheses Around Compound Conditions
- **Wrong**:
  ```python
  sub = df[df["a"] > 10 & df["b"] < 20]
  ```
- **Why It Fails**: In Python, `&` has higher precedence than `>` or `<`. Python parses this as `df["a"] > (10 & df["b"]) < 20`, triggering a `TypeError`.
- **Correct**:
  ```python
  sub = df.loc[(df["a"] > 10) & (df["b"] < 20)]
  ```
- **Performance Impact**: Prevents runtime failure and ensures correct logic execution.

#### 5. Confusing Integer Labels with Positional Offsets
- **Wrong**:
  ```python
  # DataFrame with index [10, 20, 30]
  first_row = df.loc[0] # Expecting row at offset 0
  ```
- **Why It Fails**: `.loc` searches for the integer label `0`, which does not exist in `[10, 20, 30]`, raising `KeyError`.
- **Correct**:
  ```python
  first_row = df.iloc[0]
  ```
- **Performance Impact**: Prevents catastrophic production crashes when index labels are non-zero-based integers.

#### 6. Iterative Cell Updates Using `.loc` Inside Loops
- **Wrong**:
  ```python
  for i in range(len(df)):
      df.loc[i, "cumulative"] = df.loc[i, "val"] * 1.05
  ```
- **Why It Fails**: Each call to `.loc` creates Series wrappers, parses coordinates, and checks index hashes.
- **Correct**:
  ```python
  # Vectorized calculation
  df["cumulative"] = df["val"] * 1.05
  # Or if scalar loop is mandatory:
  # df.iat[i, col_idx] = ...
  ```
- **Performance Impact**: Vectorized assignment is 100x to 1,000x faster.

#### 7. Off-by-One Errors in Positional Slicing
- **Wrong**:
  ```python
  # Developer needs 10 rows
  ten_rows = df.iloc[0:9]
  ```
- **Why It Fails**: `.iloc` excludes the stop boundary. `0:9` returns 9 rows (indices 0 through 8).
- **Correct**:
  ```python
  ten_rows = df.iloc[0:10]
  ```
- **Performance Impact**: Prevents silent truncation of data pipelines and statistical models.

#### 8. Passing Unvalidated Column Lists to `.loc`
- **Wrong**:
  ```python
  cols = ["id", "price", "predicted_churn"]
  subset = df.loc[:, cols]
  ```
- **Why It Fails**: If `"predicted_churn"` has not yet been computed, Pandas raises `KeyError: "['predicted_churn'] not in index"`.
- **Correct**:
  ```python
  valid_cols = [c for c in cols if c in df.columns]
  subset = df.loc[:, valid_cols]
  ```
- **Performance Impact**: Clean execution without unhandled exception halts.

#### 9. Slicing Non-Existent Bounds on Unsorted Indices
- **Wrong**:
  ```python
  df_unsorted = pd.DataFrame({"v": [1, 2, 3]}, index=["c", "a", "b"])
  sub = df_unsorted.loc["a":"z"]
  ```
- **Why It Fails**: For unsorted indices, `.loc` requires explicit existence of both boundary keys. Since `"z"` is missing, it raises `KeyError: 'z'`.
- **Correct**:
  ```python
  sub = df_unsorted.sort_index().loc["a":"z"]
  ```
- **Performance Impact**: Sorted binary search completes in $O(\log N)$ time.

#### 10. Boolean Masking with Unhandled Missing Values
- **Wrong**:
  ```python
  mask = df["email"].str.contains("@company.com")
  internal = df.loc[mask]
  ```
- **Why It Fails**: If any `"email"` is `NaN`, `.str.contains` produces `NaN`, causing `ValueError: Cannot mask with non-boolean array containing NA / NaN values`.
- **Correct**:
  ```python
  mask = df["email"].str.contains("@company.com", na=False)
  internal = df.loc[mask]
  ```
- **Performance Impact**: Avoids runtime crashes on real-world dirty data.

### Section 6: Top 5 Confusing Concepts & Distinctions

```
┌────────────────────────────────────────────────────────────────────────┐

├─────────────────────────┬──────────────────────────┬───────────────────┤
│ Concept A               │ Concept B                │ Core Distinction  │
├─────────────────────────┼──────────────────────────┼───────────────────┤
│ 1. .loc                 │ .iloc                    │ Label vs Position │
│ 2. .loc / .iloc         │ .at / .iat               │ General vs Scalar │

│ 4. Boolean Series Mask  │ NumPy Boolean Array Mask │ Label Align vs Pos│

└─────────────────────────┴──────────────────────────┴───────────────────┘
```

#### 1. `.loc` vs. `.iloc`
- **Key Conceptual Difference**: `.loc` queries the index hash tables using coordinate names and includes both slice endpoints. `.iloc` queries physical memory offsets using 0-based integers and excludes the slice end.
- **Memory & Storage Model**: `.loc` accesses `Index.get_loc()` to resolve offsets. `.iloc` accesses underlying C-array strides directly.
- **Code Example**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"A": [10, 20, 30]}, index=[2, 1, 0])
  print("loc[0]:", df.loc[0, "A"])   # Label 0 -> 3rd physical row (value 30)
  print("iloc[0]:", df.iloc[0, 0])   # Position 0 -> 1st physical row (value 10)
  ```
- **Best Practice**: Use `.loc` for domain queries (dates, IDs). Use `.iloc` for structural row/column array slicing.

#### 2. General Accessors (`.loc`/`.iloc`) vs. Fast Scalar Accessors (`.at`/`.iat`)
- **Key Conceptual Difference**: `.loc` and `.iloc` handle slices, lists, booleans, and callables, dynamically boxing return values into Series or DataFrames. `.at` and `.iat` accept only single scalars and return raw Python/NumPy values.
- **Memory & Storage Model**: General accessors initialize internal parser pipelines. Fast accessors perform direct array cell fetches with minimal Python dispatch.
- **Code Example**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"A": [100]}, index=["r1"])
  scalar_loc = df.loc["r1", "A"] # High overhead
  scalar_at = df.at["r1", "A"]   # Fast path
  assert scalar_loc == scalar_at
  ```
- **Best Practice**: Use `.at` / `.iat` strictly inside high-frequency loops or latency-sensitive code paths.

#### 3. Single Column Indexing: `df.loc[:, 'A']` vs. `df.loc[:, ['A']]`
- **Key Conceptual Difference**: Passing a scalar string collapses dimensionality by one, producing a 1D `pd.Series`. Passing a list preserving dimensionality produces a 2D `pd.DataFrame`.
- **Memory & Storage Model**: `Series` has a single 1D array buffer and an index. `DataFrame` wraps a 2D block manager or multiple 1D arrays with index and columns.
- **Code Example**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"A": [1, 2]})
  print(type(df.loc[:, "A"]).__name__)   # Series (shape: (2,))
  print(type(df.loc[:, ["A"]]).__name__) # DataFrame (shape: (2, 1))
  ```
- **Best Practice**: Pass list `['A']` when downstream functions require a 2D DataFrame (e.g., scikit-learn transformers).

#### 4. Boolean Series Masking vs. NumPy Boolean Array Masking
- **Key Conceptual Difference**: A boolean `Series` aligns to the DataFrame index by label before filtering. A NumPy boolean array ignores labels and filters purely by physical positional offset.
- **Memory & Storage Model**: Series masking triggers index alignment (hash comparison). NumPy array masking executes direct contiguous boolean array indexing in C.
- **Code Example**:
  ```python
  import pandas as pd
  import numpy as np
  df = pd.DataFrame({"val": [10, 20]}, index=["b", "a"])
  s_mask = pd.Series([True, False], index=["a", "b"]) # 'a' is True, 'b' is False
  np_mask = np.array([True, False])                   # Offset 0 is True, Offset 1 is False

  print("Series mask aligns on labels:\n", df.loc[s_mask])
  print("NumPy mask aligns on position:\n", df.loc[np_mask])
  ```
- **Best Practice**: Ensure boolean masks share the exact index of the target DataFrame, or convert via `.values` if positional masking is explicitly intended.

#### 5. Range Interval Boundaries: `df.loc['a':'c']` vs. `df.iloc[0:2]`
- **Key Conceptual Difference**: Slicing with labels in `.loc` is closed (`[start, stop]`). Slicing with integer positions in `.iloc` is half-open (`[start, stop)`).
- **Memory & Storage Model**: Both create views where possible over contiguous memory blocks, but `.loc` resolves stop position using `slice_locs` to include the boundary key.
- **Code Example**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"v": [1, 2, 3, 4]}, index=["a", "b", "c", "d"])
  print("loc length:", len(df.loc["a":"c"]))   # 3 rows: a, b, c
  print("iloc length:", len(df.iloc[0:2]))     # 2 rows: offsets 0, 1
  ```
- **Best Practice**: Always double-check boundary logic when porting code between `.loc` and `.iloc`.

### Section 7: Top 10 Gotchas & Production Traps

- **The Trap**: Calling `df.loc[0]` on a DataFrame whose index is `[1, 2, 3]`.

### Section 13: Flashcards / Key Terms

| Term | Engineering Definition | Code Anchor | Interview Trap |
| :--- | :--- | :--- | :--- |
| **`.loc`** | Label-based coordinate accessor supporting strings, dates, slices, and boolean masks. | `df.loc['row_a', 'col_b']` | Inclusive stop boundary; integer keys match labels, not positions. |
| **`.iloc`** | 0-based integer positional accessor mapping directly to internal array strides. | `df.iloc[0:5, [0, 2]]` | Exclusive stop boundary; negative integers count from end. |
| **`.at`** | Ultra-fast label-based scalar accessor for single-cell coordinate lookup and mutation. | `df.at['r1', 'c1']` | Cannot accept lists or slices; raises `TypeError: unhashable slice`. |
| **`.iat`** | Ultra-fast positional scalar accessor bypassing Pandas dispatch logic. | `df.iat[0, 0]` | Single integers only; out-of-bounds raises `IndexError`. |
| **Chained Indexing** | Two sequential indexing operations (`df[a][b]`) producing intermediate copies. | `df[mask]['col'] = 1` | Triggers `SettingWithCopyWarning`; fails to update root DataFrame. |
| **Atomic 2D Indexing** | Passing row and column coordinates in a single call to `.loc` or `.iloc`. | `df.loc[mask, 'col'] = 1` | Correct production idiom for all updates and projections. |
| **Boolean Mask** | Vector of boolean flags indicating row/column inclusion. | `mask = df['a'] > 10` | Series masks align by label; NumPy masks align by position. |
| **Vector Bitwise AND (`&`)** | Element-wise logical conjunction across boolean Series. | `(s1 > 0) & (s2 < 5)` | Precedence higher than comparison; requires parentheses. |
| **Vector Bitwise NOT (`~`)** | Element-wise boolean inversion. | `df.loc[~df['flag']]` | Inverts booleans; unparenthesized `~s > 0` inverts integer bits. |
| **`.isin()`** | Vectorized set-membership check returning a boolean mask. | `df['cat'].isin(list_v)` | Passing a bare string checks substring membership across characters. |
| **`.between()`** | Vectorized closed-interval numeric range filter. | `df['v'].between(10, 20)` | Defaults to inclusive of both endpoints (`inclusive='both'`). |
| **Monotonic Index** | Strictly increasing or decreasing index allowing $O(\log N)$ binary search. | `df.index.is_monotonic_increasing` | Required for label range slicing with non-existent boundary keys. |
| **Callable Indexer** | Function or lambda passed to `.loc`/`.iloc` accepting the DataFrame. | `df.loc[lambda d: d.x > 0]` | Must return valid coordinate indexer (boolean, list, slice). |
| **Index Alignment** | Automatic matching of operand index labels during vector operations. | `df.loc[mask_series]` | Mismatched labels evaluate to `False`, silently dropping data. |
| **Fancy Indexing** | Selecting arbitrary non-contiguous subsets via lists of labels or offsets. | `df.iloc[[0, 3, 5]]` | Always allocates new memory; never returns a zero-copy view. |
| **Dimension Collapse** | Reduction from DataFrame to Series (or Series to scalar) via scalar indexing. | `df.loc[:, 'A']` (Series) | Wrap keys in lists (`['A']`) to preserve 2D DataFrame dimensionality. |

### Section 14: Practical Cheat Sheet & Syntax Reference

#### Core Coordinate Access Patterns

```python
# 1. Label-based (.loc)
df.loc["r1", "c1"]              # Scalar
df.loc[["r1", "r2"], "c1"]      # Series (1D)
df.loc[["r1", "r2"], ["c1"]]    # DataFrame (2D)
df.loc["r1":"r3", "c1":"c4"]    # DataFrame slice (BOTH ENDPOINTS INCLUDED)

# 2. Position-based (.iloc)
df.iloc[0, 0]                   # Scalar
df.iloc[[0, 1], 0]              # Series (1D)
df.iloc[[0, 1], [0]]            # DataFrame (2D)
df.iloc[0:3, 1:4]               # DataFrame slice (STOP EXCLUDED: rows 0..2, cols 1..3)
df.iloc[-1]                     # Last row as Series
df.iloc[-3:, -2:]               # Bottom-right corner (last 3 rows, last 2 cols)

# 3. High-Speed Scalars (.at / .iat)
df.at["r1", "c1"]               # Fast label scalar read
df.at["r1", "c1"] = 100         # Fast label scalar write
df.iat[0, 0]                    # Fast position scalar read
df.iat[0, 0] = 100              # Fast position scalar write

# 4. Conditional Boolean Filters (.loc)
df.loc[df["age"] > 21]          # Simple condition
df.loc[(df["a"] > 0) & (df["b"] < 5)] # Compound AND with mandatory parentheses
df.loc[(df["a"] > 0) | (df["b"] < 5)] # Compound OR
df.loc[~df["is_deleted"]]       # Negation (NOT)
df.loc[df["dept"].isin(["IT", "HR"])] # Set membership
df.loc[df["score"].between(80, 90)]   # Range check [80, 90]
df.loc[mask, ["col_a", "col_b"]]      # Atomic filter + projection
df.loc[mask, "status"] = "PROCESSED"  # Atomic in-place update
```

#### Complexity Guarantees Table

| Operation | Index Structure | Time Complexity | Memory / Allocation |
| :--- | :--- | :--- | :--- |
| `df.loc[scalar_label]` | Unique Hash Index | $O(1)$ amortized | Scalar / Series creation |
| `df.loc[scalar_label]` | Non-Unique Index | $O(K)$ matching rows | Series / DataFrame copy |
| `df.loc[start:stop]` | Monotonic / Sorted | $O(\log N + M)$ | Zero-copy view (single block) |
| `df.loc[start:stop]` | Unsorted Index | $O(N)$ or `KeyError` | Copy / View dependent |
| `df.iloc[pos]` | Any | $O(1)$ | Series creation |
| `df.iloc[start:stop]` | Any | $O(1)$ | Zero-copy view (single block) |
| `df.iloc[[p1, p2, ...]]`| Any | $O(K)$ | Always creates copy |
| `df.at[r, c] / df.iat[r, c]` | Any | $O(1)$ Ultra-fast | Zero allocation |
| `df.loc[bool_mask]` | Unique Index | $O(N + M \times C)$ | Filtered DataFrame copy |

### Section 16: Code Perturbation & "What-If" Analysis

#### Perturbation 1: Changing Scalar String to List in Column Indexer
- **Base Working Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"rev": [10, 20]})
  res = df.loc[:, "rev"]
  ```
- **Perturbation**:
  ```python
  res = df.loc[:, ["rev"]]
  ```
- **Exact Behavior / Output Change**:
  Base code returns a `pd.Series` of shape `(2,)`. Perturbed code returns a `pd.DataFrame` of shape `(2, 1)`.
- **Mechanical Explanation**:
  Pandas inspects the collection type of the coordinate argument. Scalars trigger dimension collapse; list structures preserve the 2D tabular container.

#### Perturbation 2: Removing Parentheses in Compound Boolean Mask
- **Base Working Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"a": [1, 5, 10], "b": [20, 15, 5]})
  res = df.loc[(df["a"] > 2) & (df["b"] > 10)]
  ```
- **Perturbation**:
  ```python
  res = df.loc[df["a"] > 2 & df["b"] > 10]
  ```
- **Exact Behavior / Output Change**:
  Base code returns row index 1. Perturbed code raises `TypeError: cannot compare a dtyped [int64] array with a scalar of type [bool]`.
- **Mechanical Explanation**:
  Python operator precedence executes `2 & df["b"]` before evaluating the comparison operators `>` on either side.

#### Perturbation 3: Changing `.loc` Slice to `.iloc` Slice
- **Base Working Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"val": [10, 20, 30, 40]}, index=[0, 1, 2, 3])
  res = df.loc[0:2]
  ```
- **Perturbation**:
  ```python
  res = df.iloc[0:2]
  ```
- **Exact Behavior / Output Change**:
  Base code returns 3 rows (indices 0, 1, 2). Perturbed code returns 2 rows (indices 0, 1).
- **Mechanical Explanation**:
  `.loc` includes the stop endpoint (`2`). `.iloc` excludes the stop endpoint (`2`), extracting only indices `0` and `1`.

#### Perturbation 4: Querying Integer Label with Negative Value
- **Base Working Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"score": [80, 90, 95]})
  res = df.iloc[-1]
  ```
- **Perturbation**:
  ```python
  res = df.loc[-1]
  ```
- **Exact Behavior / Output Change**:
  Base code returns the last row (`score: 95`). Perturbed code raises `KeyError: -1`.
- **Mechanical Explanation**:
  `.iloc` supports negative sequence offsets from the end of the array. `.loc` performs a hash lookup for literal label `-1`, which does not exist in `RangeIndex(0, 3)`.

#### Perturbation 5: Using `Series` Mask with Misaligned Index
- **Base Working Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"v": [10, 20, 30]}, index=["a", "b", "c"])
  mask = pd.Series([True, False, True], index=["a", "b", "c"])
  res = df.loc[mask]
  ```
- **Perturbation**:
  ```python
  mask_misaligned = pd.Series([True, False, True], index=["x", "y", "z"])
  res = df.loc[mask_misaligned]
  ```
- **Exact Behavior / Output Change**:
  Base code returns rows `'a'` and `'c'`. Perturbed code returns an empty DataFrame (0 rows).
- **Mechanical Explanation**:
  When a `Series` is passed as a mask to `.loc`, Pandas aligns by index labels. None of `['x', 'y', 'z']` match `['a', 'b', 'c']`, so all rows default to `False`.

### Section 22: The 2-Minute Elevator Pitch / Executive Summary

- **Coordinate System Duality**: Pandas separates data navigation into `.loc` (label-driven, closed intervals including stop, domain-oriented) and `.iloc` (0-based integer position-driven, half-open intervals excluding stop, matrix/ML-oriented).
- **Atomic 2D Access**: Production code must always use two-dimensional indexing (`df.loc[rows, cols]`) rather than chained brackets (`df[rows][cols]`) to guarantee in-place updates, avoid intermediate memory copies, and eliminate `SettingWithCopyWarning`.
- **Vector Boolean Discipline**: Multi-condition filters strictly require bitwise operators (`&`, `|`, `~`) enclosed in parentheses `(c1) & (c2)` due to Python operator precedence rules, supplemented by `.isin()` and `.between()` for clean expression design.
- **Latency Optimization**: For high-frequency single-cell reads and writes inside event loops or simulations, `.at` and `.iat` bypass Series wrapping and argument validation to deliver nanosecond execution speed.
- **Index Alignment Mechanics**: Boolean Series align to DataFrames by index labels rather than array positions; ensure indices are sorted using `df.sort_index()` to enable $O(\log N)$ label range slicing across arbitrary intervals.
