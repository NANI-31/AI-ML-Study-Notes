# 4. Data Selection and Indexing

## 4.1 Selecting Columns

---

## 1. Section Overview

Column selection is the fundamental gateway to tabular data processing in Pandas. In modern machine learning pipelines, exploratory data analysis (EDA), and production ETL systems, feature extraction and column filtering represent the very first operations applied after data ingestion. Engineering interviews relentlessly scrutinize column selection because small syntactic choices dictate whether Pandas returns an isolated 1-dimensional Series or a 2-dimensional DataFrame, whether operations execute via zero-copy metadata views or trigger deep memory allocations, and whether downstream mutations raise catastrophic `SettingWithCopyWarning` errors.

### Core Practical Themes
- **Dimensionality Control**: Differentiating between single-bracket indexing `df['col']` (extracting a 1D Series) and double-bracket indexing `df[['col']]` (retaining a 2D DataFrame).
- **Access Patterns**: Contrasting dictionary-like bracket notation `df['col']` with dot-attribute notation `df.col`, exposing the edge cases where dot notation catastrophically fails.
- **Dynamic Programmatic Selection**: Querying and pruning feature spaces using programmatic lists, list comprehensions, predicate filtering (`df.filter()`), and dtype-based dispatching (`df.select_dtypes()`).
- **Memory & Computational Mechanics**: Understanding how single-column selection slices directly into underlying continuous array blocks versus how multiple-column projection constructs new `BlockManager` layouts.

### Production & Interview Relevance
Hiring managers evaluate column selection to distinguish candidates who memorize syntax from engineers who understand Pandas internals. Candidates must demonstrate fluency in dynamic schemas (handling shifting API columns, high-cardinality feature spaces, and programmatic downcasting) while writing defensive code that prevents silent data mutation bugs and unnecessary memory duplication.

## 2. Topic-Wise Interview Concepts

### Topic 1: Selecting a Single Column (`df['col']` vs `df.col`)
- **1. What it is**: The extraction of one vertical series of observations corresponding to a specific feature key within a DataFrame.
- **2. Why it exists**: To isolate features for statistical transformations, mathematical modeling, conditional evaluations, or series-level operations.
- **3. How Pandas handles it under the hood**:
  - `df['col']`: Pandas hashes the column name and queries the DataFrame's column index (`df.columns`). Upon locating the integer position of the column within the internal `BlockManager`, Pandas retrieves a 1D slice of the underlying 2D NumPy array (or Arrow chunk) and wraps it inside a `pd.Series` object pointing to the parent DataFrame's index.
  - `df.col`: Python intercept attribute access via `__getattr__`. If `'col'` matches an existing column label and does not collide with a built-in DataFrame attribute or method (e.g., `shape`, `count`, `values`, `head`), it delegates directly to `__getitem__`.
- **4. Key methods, parameters, variations**:
  - `df['feature']`: Standard bracket access. Returns `pd.Series`.
  - `df[['feature']]`: Single column inside a list. Returns `pd.DataFrame`.
  - `df.feature`: Dot-attribute access. Returns `pd.Series`.
- **5. Common interview questions**:
  - *"Why is `df.column_name` considered bad practice in production code?"*
  - *"What is the memory and structural difference between `df['col']` and `df[['col']]`?"*
  - *"Can you create a new column using dot notation like `df.new_col = [1, 2, 3]`?"*
- **6. Edge cases & pitfalls**:
  - Column names containing spaces, hyphens, periods, or leading numbers (e.g., `df.2023_sales`, `df.first name`) cause syntax errors under dot notation.
  - Collisions with built-in DataFrame methods: `df.count` returns the bound method `<bound method DataFrame.count...>`, not the column named `'count'`.
  - Creating new columns via `df.new_col = value` attaches a dynamic attribute to the Python DataFrame instance rather than inserting a new column into the `BlockManager`, leaving the DataFrame unchanged.
- **7. Code example**:
  ```python
  import pandas as pd

  df = pd.DataFrame({
      "user_id": [101, 102, 103],
      "user age": [25, 30, 35],
      "count": [1, 5, 2]
  })

  # Standard bracket extraction -> Series
  s_age = df["user age"]
  print(type(s_age))  # <class 'pandas.core.series.Series'>

  # Double bracket extraction -> DataFrame
  df_age = df[["user age"]]
  print(type(df_age))  # <class 'pandas.core.frame.DataFrame'>

  # Dot notation collision pitfall
  print(callable(df.count))  # True -> refers to method, not column!
  print(df["count"].tolist())  # [1, 5, 2] -> refers to column
  ```
- **8. Rule of thumb for interviews**: Always default to bracket notation `df['col']` in production code. Never use dot notation for mutating data or accessing columns with arbitrary user-defined names.

### Topic 2: Selecting Multiple Columns (`df[['col1', 'col2']]`)
- **1. What it is**: Projecting a subset of columns from a DataFrame to construct a narrower 2-dimensional DataFrame containing only the requested features.
- **2. Why it exists**: Real-world datasets often arrive with dozens or hundreds of raw attributes (identifiers, audit logs, metadata); modeling and aggregation routines require isolating only relevant feature matrices.
- **3. How Pandas handles it under the hood**:
  - When passed an iterable (Python list) of keys, `df.__getitem__` invokes the internal `BlockManager.reindex()` or `take_nd()` routine.
  - If the requested columns span multiple internal blocks of different data types (e.g., one `int64` block and one `float64` block), Pandas constructs a new `BlockManager` referencing those existing blocks or shallowly slicing them.
  - Slicing multiple columns always produces a 2D `pd.DataFrame`.
- **4. Key methods, parameters, variations**:
  - `df[['a', 'b']]`: Explicit inline list projection.
  - `df[['a']]`: Single-item list projection yielding a 1-column DataFrame.
  - Reordering: `df[['b', 'a']]` reorders columns in the returned DataFrame.
  - Duplication: `df[['a', 'a']]` constructs a DataFrame containing duplicated columns sharing underlying data.
- **5. Common interview questions**:
  - *"What happens if one of the column names in the list does not exist in the DataFrame?"*
  - *"How does the internal BlockManager handle multiple column projection?"*
  - *"Does `df[['a', 'b']]` return a view or a copy in modern Pandas 2.0+ / 3.0?"*
- **6. Edge cases & pitfalls**:
  - Passing column names as separate comma-delimited arguments instead of a list: `df['a', 'b']` triggers a `KeyError: ('a', 'b')` because Pandas interprets `('a', 'b')` as a single MultiIndex tuple key.
  - Key errors: If any requested column in the list is absent, Pandas raises `KeyError` with the list of missing keys.
- **7. Code example**:
  ```python
  import pandas as pd

  df = pd.DataFrame({
      "id": [1, 2],
      "name": ["Alice", "Bob"],
      "score": [95.5, 88.0]
  })

  # Correct projection
  subset = df[["name", "score"]]
  print(subset.shape)  # (2, 2)

  # Reordering features
  reordered = df[["score", "id", "name"]]
  print(reordered.columns.tolist())  # ['score', 'id', 'name']
  ```
- **8. Rule of thumb for interviews**: Emphasize that multiple column selection *always* requires a nested list (`[[ ... ]]`). Passing unbracketed comma-separated keys attempts tuple MultiIndex lookup and fails with a `KeyError`.

### Topic 3: Selecting Columns Using Lists
- **1. What it is**: Decoupling the list of target column names into an external Python variable or configuration object prior to indexing the DataFrame.
- **2. Why it exists**: Enables modular, clean architecture in production pipelines. Column lists can be imported from configuration files (YAML, JSON), derived dynamically from schema registries, or separated into numeric versus categorical feature groups for Scikit-Learn pipelines.
- **3. How Pandas handles it under the hood**:
  - The variable holds a standard Python `list`, `pd.Index`, or `np.ndarray` of string objects.
  - When passed into `df[target_columns]`, Pandas validates that all strings in the list exist within `df.columns`. It checks membership against `df.columns._engine` (a hashtable) in $O(K)$ time where $K$ is the number of target columns.
- **4. Key methods, parameters, variations**:
  - `cols = ['feature1', 'feature2']; df[cols]`: Standard list passing.
  - `df.reindex(columns=cols)`: Safe selection that does NOT raise `KeyError` if columns are missing, instead inserting `NaN` columns.
  - `df.loc[:, cols]`: Explicit 2D coordinate indexing using an external list.
- **5. Common interview questions**:
  - *"How do you select columns using a list when some columns might be missing, without crashing your script with a `KeyError`?"*
  - *"What is the difference between `df[cols]` and `df.reindex(columns=cols)`?"*
  - *"Can you pass a set or tuple instead of a list?"*
- **6. Edge cases & pitfalls**:
  - Passing a Python `set` like `df[{'a', 'b'}]`: Deprecated or raises `KeyError` because sets are unordered; Pandas requires an ordered sequence to preserve column alignment.
  - Passing a `tuple` like `df[('a', 'b')]`: Interpreted as a single hierarchical MultiIndex key rather than a list of two columns.
- **7. Code example**:
  ```python
  import pandas as pd

  df = pd.DataFrame({
      "age": [20, 30],
      "salary": [50000, 60000],
      "city": ["NY", "SF"]
  })

  target_features = ["salary", "age"]
  # Strict selection (raises KeyError if missing)
  feature_matrix = df[target_features]

  # Defensive selection (pads missing columns with NaN)
  requested_cols = ["salary", "age", "bonus"]
  safe_features = df.reindex(columns=requested_cols)
  print(safe_features.columns.tolist())  # ['salary', 'age', 'bonus']
  print(safe_features["bonus"].isna().all())  # True
  ```
- **8. Rule of thumb for interviews**: Use `df[cols]` when missing features indicate data corruption that must halt the pipeline. Use `df.reindex(columns=cols)` or list intersections `[c for c in cols if c in df.columns]` when handling optional schema features.

### Topic 4: Selecting Columns Dynamically
- **1. What it is**: Selecting columns programmatically based on naming patterns, data types, prefixes/suffixes, or statistical properties rather than hardcoded string lists.
- **2. Why it exists**: Enterprise datasets frequently contain hundreds of columns (e.g., sensor telemetry `sensor_01`, `sensor_02`, one-hot encoded flags `cat_NY`, `cat_CA`, or time series lags `lag_1`, `lag_2`). Manually hardcoding column lists is error-prone and unmaintainable.
- **3. How Pandas handles it under the hood**:
  - `df.select_dtypes(include=..., exclude=...)`: Iterates over the internal `BlockManager` blocks, filtering blocks whose NumPy/Arrow dtypes match the requested type hierarchy. Runs in $O(M)$ time where $M$ is total column count.
  - `df.filter(items=..., like=..., regex=...)`: Evaluates string predicates or compiled regular expressions against the strings in `df.columns`.
  - List comprehensions: `[c for c in df.columns if ...]` executes native Python iteration over the string labels of `df.columns`.
- **4. Key methods, parameters, variations**:
  - `df.select_dtypes(include=['number'])`: Extracts all integer and floating-point columns.
  - `df.select_dtypes(include=['object', 'category'])`: Extracts all categorical/text features.
  - `df.filter(like='date')`: Substring search across column names.
  - `df.filter(regex=r'^sensor_\d+$')`: Full regex matching on column labels.
  - List comprehension with string methods: `df[[c for c in df.columns if c.startswith('target_')]]`.
- **5. Common interview questions**:
  - *"How do you separate numeric columns from categorical columns in an automated ML preprocessing pipeline?"*
  - *"What is the difference between `df.filter(like='val')` and `df[[c for c in df.columns if 'val' in c]]`?"*
  - *"Can `select_dtypes` distinguish between float32 and float64?"*
- **6. Edge cases & pitfalls**:
  - `df.filter()` operates strictly on labels; it does *not* filter rows by column values. Freshers frequently confuse `df.filter()` with row-filtering Boolean masks.
  - In `select_dtypes(include='number')`, boolean columns (`bool`) are treated as numeric in older versions, but distinct in newer versions; explicitly test with `include=['int64', 'float64']` if booleans must be excluded.
  - Regex failures in `df.filter(regex=...)` silently return an empty DataFrame rather than raising an error if no patterns match.
- **7. Code example**:
  ```python
  import pandas as pd

  df = pd.DataFrame({
      "sensor_temp_1": [21.5, 22.0],
      "sensor_temp_2": [23.1, 22.8],
      "sensor_pressure": [1013, 1015],
      "status": ["OK", "WARN"],
      "target_flag": [0, 1]
  })

  # 1. Select numeric features dynamically
  num_cols = df.select_dtypes(include="number")
  print(num_cols.columns.tolist())  # ['sensor_temp_1', 'sensor_temp_2', 'sensor_pressure', 'target_flag']

  # 2. Select using prefix matching via filter()
  temp_cols = df.filter(like="temp")
  print(temp_cols.columns.tolist())  # ['sensor_temp_1', 'sensor_temp_2']

  # 3. Regex selection
  sensor_cols = df.filter(regex=r"^sensor_")
  print(sensor_cols.columns.tolist())  # ['sensor_temp_1', 'sensor_temp_2', 'sensor_pressure']

  # 4. List comprehension with condition
  high_cardinality = [c for c in df.columns if df[c].dtype == "object"]
  print(high_cardinality)  # ['status']
  ```
- **8. Rule of thumb for interviews**: In production ML pipelines, always isolate numeric and categorical features using `df.select_dtypes(include='number')` and `df.select_dtypes(include=['object', 'category'])`. For naming conventions, use `df.filter(like=...)` for simple tokens and `df.filter(regex=...)` for structured naming schemas.

## 3. Fresher Interview Questions

### Part A: Basic Questions (20 Questions)

#### Q1: What is the primary syntax for selecting a single column in Pandas?
- **Direct Answer**: The standard, production-grade syntax is bracket notation passing a single column label: `df['column_name']`.
- **Under the Hood**: Pandas looks up the column label in the `df.columns` hash map, retrieves the corresponding 1D array slice from the internal `BlockManager`, and wraps it into a `pd.Series` sharing the DataFrame's index.
- **Code Example**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"age": [25, 30, 35]})
  s = df["age"]
  print(type(s))  # <class 'pandas.core.series.Series'>
  ```
- **Interview Follow-up**: *"What happens if the column name doesn't exist?"* It raises a `KeyError: 'column_name'`.

#### Q2: What is the fundamental difference in return type between `df['col']` and `df[['col']]`?
- **Direct Answer**: `df['col']` returns a 1-dimensional `pd.Series`. `df[['col']]` returns a 2-dimensional `pd.DataFrame` with one column.
- **Under the Hood**: A single string key commands `__getitem__` to extract the individual Series vector. A list of strings commands `__getitem__` to invoke projection logic in `BlockManager`, maintaining 2D tabular structure.
- **Code Example**:
  ```python
  df = pd.DataFrame({"score": [90, 80]})
  print(type(df["score"]))    # <class 'pandas.core.series.Series'>
  print(type(df[["score"]]))  # <class 'pandas.core.frame.DataFrame'>
  print(df["score"].shape)    # (2,)
  print(df[["score"]].shape)  # (2, 1)
  ```
- **Interview Follow-up**: *"When would an ML library require `df[['col']]` instead of `df['col']`?"* Scikit-Learn transformers (like `StandardScaler` or `OneHotEncoder`) require 2D array inputs of shape `(n_samples, n_features)`; passing a 1D Series raises a `ValueError: Expected 2D array, got 1D array instead`.

#### Q3: How do you select multiple columns at once in Pandas?
- **Direct Answer**: By passing a Python list of column names inside square brackets: `df[['col1', 'col2', 'col3']]`.
- **Under the Hood**: Pandas extracts a block sub-table containing only the specified columns, preserving the order specified in the list.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [1, 2], "b": [3, 4], "c": [5, 6]})
  subset = df[["a", "c"]]
  print(subset.columns.tolist())  # ['a', 'c']
  ```
- **Interview Follow-up**: *"Can you pass a tuple of column names like `df[('a', 'c')]`?"* No, a tuple is treated as a single MultiIndex key, causing a `KeyError` unless the columns are a hierarchical MultiIndex.

#### Q4: What is dot-attribute notation for column access, and how does it work?
- **Direct Answer**: Dot notation accesses a column as if it were an object attribute: `df.col_name`.
- **Under the Hood**: Python's `__getattr__` intercepts the attribute lookup. If the name matches an existing column in `df.columns` and does not collide with class methods or properties, Pandas returns `df['col_name']`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"salary": [50000, 75000]})
  print(df.salary.mean())  # 62500.0
  ```
- **Interview Follow-up**: *"Why is this dangerous for columns named `'mean'` or `'min'`?"* It returns the DataFrame method rather than the column data.

#### Q5: Name three scenarios where dot-attribute column selection fails completely.
- **Direct Answer**:
  1. Column names containing spaces, symbols, or hyphens (e.g., `'first name'`, `'user-id'`).
  2. Column names that start with numbers (e.g., `'2024_sales'`).
  3. Column names that match existing Pandas DataFrame methods or attributes (e.g., `'count'`, `'size'`, `'shape'`, `'values'`).
- **Under the Hood**: Python's grammar parser rejects invalid identifiers (spaces, leading numbers) at compile time. For method names, instance attribute resolution takes precedence over `__getattr__`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"user id": [1], "2024": [2], "shape": [3]})
  # df.user id  -> SyntaxError
  # df.2024     -> SyntaxError
  print(df.shape)  # Returns tuple (1, 3), NOT the column [3]!
  ```
- **Interview Follow-up**: *"What is the third failure mode?"* Creating a new column via `df.new_col = [1, 2]` fails to add the column to the DataFrame.

#### Q6: Can you add a new column to a DataFrame using dot notation?
- **Direct Answer**: No. You must use bracket notation: `df['new_col'] = values`.
- **Under the Hood**: Assigning to `df.new_col = values` sets a standard Python instance attribute on the `DataFrame` object in memory. It does not update the `BlockManager` or `df.columns`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [1, 2]})
  df.b = [10, 20]  # Attaches attribute to df instance
  print("b" in df.columns)  # False!
  df["b"] = [10, 20]  # Properly inserts column
  print("b" in df.columns)  # True!
  ```
- **Interview Follow-up**: *"Why does Pandas allow setting attributes on DataFrames then?"* It inherits from standard Python class mechanics; developers sometimes attach metadata or flags to objects.

#### Q7: How does passing an external Python list variable into brackets work?
- **Direct Answer**: You define a list of strings `cols = ['col1', 'col2']` and pass it directly: `df[cols]`.
- **Under the Hood**: Pandas receives the list object and matches every element against `df.columns` using internal hashtables before returning the projected DataFrame.
- **Code Example**:
  ```python
  df = pd.DataFrame({"x": [1], "y": [2], "z": [3]})
  selected = ["x", "z"]
  print(df[selected])
  ```
- **Interview Follow-up**: *"What is the time complexity of validating the column list?"* $O(K)$ where $K$ is the length of the list, because `df.columns` lookup is backed by a hash table ($O(1)$ per key).

#### Q8: Does selecting multiple columns reorder them according to the list?
- **Direct Answer**: Yes. The returned DataFrame arranges columns in the exact sequential order specified in the list.
- **Under the Hood**: Pandas uses the list's order to reconstruct the column index and order the block slices in the new `BlockManager`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"c": [3], "b": [2], "a": [1]})
  ordered = df[["a", "b", "c"]]
  print(ordered.columns.tolist())  # ['a', 'b', 'c']
  ```
- **Interview Follow-up**: *"How can you sort all columns alphabetically?"* By calling `df[sorted(df.columns)]`.

#### Q9: What happens if you request the same column multiple times in a list?
- **Direct Answer**: Pandas returns a DataFrame containing duplicated columns with identical labels and data.
- **Under the Hood**: Pandas creates two column index entries referencing the same underlying data block.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [10, 20]})
  dup = df[["a", "a"]]
  print(dup.shape)  # (2, 2)
  print(dup.columns.tolist())  # ['a', 'a']
  ```
- **Interview Follow-up**: *"What problem arises when you later index `dup['a']`?"* It returns a DataFrame of both columns instead of a single Series, often breaking downstream functions.

#### Q10: What error is raised when you select a non-existent column using `df['unknown']`?
- **Direct Answer**: A `KeyError`.
- **Under the Hood**: The `df.columns` index lookup fails to find the key in its hash table, and `Index.get_loc()` raises `KeyError`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [1]})
  try:
      df["b"]
  except KeyError as e:
      print("Caught error:", repr(e))  # Caught error: KeyError('b')
  ```
- **Interview Follow-up**: *"How can you safely select a column with a default fallback if it doesn't exist?"* Use `df.get('b', default_series)`.

#### Q11: How does `df.get('col')` work for column selection?
- **Direct Answer**: It emulates Python dictionary `get()`. It returns the column if present; if missing, it returns `None` (or a user-specified default) without raising `KeyError`.
- **Under the Hood**: It checks `if key in df: return df[key] else: return default`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [1, 2]})
  val = df.get("missing_col", default=pd.Series([0, 0]))
  print(val.tolist())  # [0, 0]
  ```
- **Interview Follow-up**: *"Can `df.get()` select multiple columns?"* Yes, passing a list of columns returns a DataFrame or the default if any are missing.

#### Q12: How do you select all columns of a specific data type using `select_dtypes()`?
- **Direct Answer**: Use `df.select_dtypes(include=['data_type'])`.
- **Under the Hood**: Pandas iterates over the internal blocks of the `BlockManager`, checks block dtypes against NumPy's dtype hierarchy or Arrow dtypes, and returns a DataFrame containing only matching blocks.
- **Code Example**:
  ```python
  df = pd.DataFrame({"id": [1, 2], "score": [9.5, 8.2], "name": ["A", "B"]})
  numeric_df = df.select_dtypes(include="number")
  print(numeric_df.columns.tolist())  # ['id', 'score']
  ```
- **Interview Follow-up**: *"What string shortcut includes all integers and floats?"* `'number'`.

#### Q13: How do you exclude specific data types using `select_dtypes()`?
- **Direct Answer**: Pass the types to the `exclude` parameter: `df.select_dtypes(exclude=['object', 'category'])`.
- **Under the Hood**: Pandas tests block dtypes against the exclude tuple and retains blocks that do not inherit from or match those types.
- **Code Example**:
  ```python
  df = pd.DataFrame({"id": [1], "name": ["Alice"], "date": pd.to_datetime(["2024-01-01"])})
  non_text = df.select_dtypes(exclude="object")
  print(non_text.columns.tolist())  # ['id', 'date']
  ```
- **Interview Follow-up**: *"What happens if both `include` and `exclude` contain overlapping types?"* Pandas raises a `ValueError`.

#### Q14: How does `df.filter(like='...')` select columns?
- **Direct Answer**: It selects columns whose label contains the specified substring: `df.filter(like='substring')`.
- **Under the Hood**: Pandas iterates over `df.columns` and evaluates `'substring' in col_label` for each column, returning a projected DataFrame.
- **Code Example**:
  ```python
  df = pd.DataFrame({"user_id": [1], "user_name": ["Alice"], "total_amount": [100]})
  user_cols = df.filter(like="user")
  print(user_cols.columns.tolist())  # ['user_id', 'user_name']
  ```
- **Interview Follow-up**: *"Is `df.filter(like=...)` case-sensitive?"* Yes, exact string containment is checked.

#### Q15: How does `df.filter(regex='...')` select columns?
- **Direct Answer**: It matches column names against a regular expression pattern: `df.filter(regex=r'pattern')`.
- **Under the Hood**: It compiles the regex pattern using Python's `re.search()` and filters `df.columns` matching the pattern.
- **Code Example**:
  ```python
  df = pd.DataFrame({"feat_1": [1], "feat_2": [2], "meta_info": [3]})
  features = df.filter(regex=r"^feat_\d+$")
  print(features.columns.tolist())  # ['feat_1', 'feat_2']
  ```
- **Interview Follow-up**: *"Does `regex` match from the beginning or anywhere in the string?"* `re.search()` matches anywhere unless anchored with `^` or `$`.

#### Q16: How do you select columns ending with a specific suffix using list comprehension?
- **Direct Answer**: Sift column names using string methods: `df[[c for c in df.columns if c.endswith('_id')]]`.
- **Under the Hood**: Python iterates over the `df.columns` array, filters matching strings via `.endswith()`, and passes the resulting list to `df[...]`.
- **Code Example**:
  ```python
  df = pd.DataFrame({"customer_id": [1], "order_id": [101], "amount": [50.0]})
  id_cols = df[[c for c in df.columns if c.endswith("_id")]]
  print(id_cols.columns.tolist())  # ['customer_id', 'order_id']
  ```
- **Interview Follow-up**: *"What is the advantage of list comprehension over `df.filter()`?"* List comprehensions allow arbitrary Python logic (e.g., checking dtypes, nullness, or multiple complex conditions simultaneously).

#### Q17: What does `df.columns` return, and what is its underlying type?
- **Direct Answer**: It returns a `pd.Index` object containing the column labels.
- **Under the Hood**: `pd.Index` is an immutable, hashable 1D array-like structure backed by an internal hashtable mapping labels to integer positions.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [1], "b": [2]})
  print(type(df.columns))  # <class 'pandas.core.indexes.base.Index'>
  print(df.columns.tolist())  # ['a', 'b']
  ```
- **Interview Follow-up**: *"Can you modify a single column name in place via `df.columns[0] = 'new'`?"* No, `Index` objects are immutable; it raises `TypeError: Index does not support mutable operations`.

#### Q18: How do you safely select columns that may or may not exist without crashing?
- **Direct Answer**: Use `df.reindex(columns=wanted_cols)` or filter the target list with an intersection: `[c for c in wanted_cols if c in df.columns]`.
- **Under the Hood**: `reindex` checks missing labels and inserts new columns filled with `NaN`. List comprehension drops absent labels entirely.
- **Code Example**:
  ```python
  df = pd.DataFrame({"a": [1, 2], "b": [3, 4]})
  target = ["a", "z"]
  safe = df[[c for c in target if c in df.columns]]
  print(safe.columns.tolist())  # ['a']
  ```
- **Interview Follow-up**: *"What is the key difference between the two approaches?"* List intersection returns only existing columns (shape $2 \times 1$), while `reindex` guarantees the output shape contains all requested columns, padding missing ones with `NaN` (shape $2 \times 2$).

#### Q21: What is the internal architecture of Pandas `BlockManager` regarding column storage?
- **Direct Answer**: Pandas organizes DataFrame data into 2-dimensional homogeneous NumPy array "blocks" grouped by datatype (e.g., all `float64` columns in one block, all `int64` columns in another), managed by the `BlockManager`.
- **Under the Hood**: When you select a single column from a block, Pandas creates a 1D view of that block's row slice. When you select multiple columns spanning different types, Pandas creates a new `BlockManager` referencing the respective blocks.
- **Code Example**:
  ```python
  df = pd.DataFrame({
      "f1": [1.0, 2.0],
      "f2": [3.0, 4.0],
      "i1": [10, 20]
  })
  # f1 and f2 are stored in a single 2D float64 block of shape (2, 2)
  # i1 is stored in a separate 1D/2D int64 block of shape (1, 2)
  ```
- **Interview Follow-up**: *"How does the new PyArrow backend change this architecture?"* PyArrow stores data strictly column-by-column (1D Arrow arrays/chunked arrays) without heterogeneous block consolidation, eliminating `BlockManager` fragmentation.

#### Q22: Why does `df[['a']]` create an extra dimension compared to `df['a']`?

## 4. Top Questions to Definitely Prepare

### Must Know Top 5
1. **What is the exact dimensional and architectural difference between `df['col']` and `df[['col']]`?**
   - *Key Distinction*: `df['col']` extracts a 1D `pd.Series` (shape `(N,)`, single index). `df[['col']]` constructs a 2D `pd.DataFrame` (shape `(N, 1)`, row and column index). Scikit-Learn transformers require 2D DataFrames; passing a 1D Series triggers shape validation errors.
2. **Why is dot notation (`df.col_name`) hazardous in production data pipelines?**
   - *Key Distinction*: Fails on column names containing spaces, hyphens, or numbers; causes silent method collisions (e.g., `df.count` accesses `<bound method DataFrame.count...>` instead of the column); and cannot create new columns (`df.new_col = [...]` sets an instance attribute without inserting into the DataFrame).
3. **What happens if you execute `df['col1', 'col2']` without double brackets?**
   - *Key Distinction*: Python interprets `'col1', 'col2'` as a single 2-tuple `('col1', 'col2')`. Pandas treats it as a hierarchical MultiIndex key lookup, failing with `KeyError: ('col1', 'col2')`.
4. **How does `df.select_dtypes(include='number')` operate, and how does it handle boolean columns?**
   - *Key Distinction*: It inspects block-level metadata in the `BlockManager`, identifying subclasses of `np.number`. In modern Pandas, boolean columns (`bool`) are treated as distinct from numbers; explicitly passing `include=['int64', 'float64']` guarantees exclusion of boolean indicators.
5. **What is the difference between `df[cols_list]` and `df.reindex(columns=cols_list)` when columns are missing?**
   - *Key Distinction*: `df[cols_list]` requires 100% of keys to exist, raising `KeyError` if any column is absent. `df.reindex(columns=cols_list)` never raises `KeyError`; it gracefully returns a DataFrame containing all requested columns, populating missing features with `NaN`.

### Good to Know Top 5
6. **How does `df.filter(like='...')` differ from `df.filter(regex='...')`?**
   - *Key Distinction*: `like` performs exact case-sensitive substring matching (`'substring' in col`). `regex` compiles regular expression patterns via `re.search()`, allowing anchors (`^`, `$`), character classes (`\d+`), and alternation (`(temp|volt)`).
7. **Why does `df['a':'c']` NOT slice columns from 'a' to 'c'?**
   - *Key Distinction*: In standard bracket notation, slice syntax `df[slice]` evaluates strictly along **axis 0 (rows)**. To slice columns by label, you must explicitly use 2-axis coordinate indexing: `df.loc[:, 'a':'c']`.
8. **Does `df[['a', 'b']]` return a view or a copy under modern Pandas 2.0+ / 3.0?**
   - *Key Distinction*: Under Copy-on-Write (CoW), column selection returns a shallow view pointing to existing memory buffers. Memory is copied only if either the parent or subset is modified later.
9. **How do you programmatically select columns whose missing value ratio exceeds a given threshold?**
   - *Key Distinction*: `df.loc[:, df.isna().mean() > threshold]`. The boolean mask must be evaluated across axis 1 inside `.loc[:, mask]`; using `df[mask]` fails because single-bracket boolean indexing targets rows.
10. **What is the time complexity of selecting a single column vs selecting $K$ columns?**
    - *Key Distinction*: Single column lookup is $O(1)$ via hash map lookup on `df.columns`. Multiple column projection is $O(K)$ hash lookups plus $O(N \times K)$ block metadata assembly.

### Bonus Top 5
11. **How do you select columns using a callable in method chaining without assigning intermediate variables?**
    - *Key Distinction*: `df.loc[:, lambda d: d.columns.str.startswith('feat_')]` dynamically evaluates the callable on the intermediate DataFrame in the chain.
12. **What occurs when duplicate column labels exist and you select `df['col']`?**
    - *Key Distinction*: It returns a `pd.DataFrame` containing all matching columns rather than a `pd.Series`, often causing subtle downstream shape-mismatch bugs.
13. **How can you reorder DataFrame columns to place key ID features first without hardcoding all column names?**
    - *Key Distinction*: `priority = ['id', 'timestamp']; df[priority + [c for c in df.columns if c not in priority]]`.
14. **Why is converting column names via `df.columns = df.columns.astype(str)` a critical best practice after loading Excel or CSV data?**
    - *Key Distinction*: Raw ingestion engines frequently parse year headers (e.g., `2023`, `2024`) as Python `int` objects. Integer column labels break all string-based vector filters (`.str.startswith()`, regex filters) with `AttributeError`.
15. **How does `df.filter(items=...)` differ from `df.reindex(columns=...)`?**
    - *Key Distinction*: Both avoid `KeyError` on missing keys. However, `filter(items=...)` returns *only* the subset of existing columns (ignoring missing ones), whereas `reindex(columns=...)` forces the output to match the requested length, synthesizing `NaN` columns for missing keys.

## 5. Common Beginner Mistakes

### 1. Using Dot Notation to Create a New Column
- **Wrong**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"a": [1, 2]})
  df.b = [10, 20]  # Attaches instance attribute, NOT a column!
  print("b" in df.columns)  # False!
  ```
- **Right**:
  ```python
  df["b"] = [10, 20]  # Inserts into DataFrame
  print("b" in df.columns)  # True
  ```
- **Why**: Dot assignment sets an attribute on the Python object instance. Only bracket assignment registers a new column with the internal `BlockManager`.

### 2. Passing Multiple Columns Without an Outer List
- **Wrong**:
  ```python
  df = pd.DataFrame({"x": [1], "y": [2], "z": [3]})
  sub = df["x", "y"]  # KeyError: ('x', 'y')
  ```
- **Right**:
  ```python
  sub = df[["x", "y"]]  # Correct nested list
  ```
- **Why**: Comma-separated keys without outer brackets pass a tuple, which Pandas interprets as a single MultiIndex coordinate lookup.

### 3. Attempting Column Slicing Inside Single Brackets
- **Wrong**:
  ```python
  df = pd.DataFrame({"col_a": [1], "col_b": [2], "col_c": [3]})
  sub = df["col_a":"col_c"]  # Evaluates on ROWS, returns empty DataFrame!
  ```
- **Right**:
  ```python
  sub = df.loc[:, "col_a":"col_c"]  # Explicit 2D coordinate indexing
  ```
- **Why**: Single-bracket slicing `df[start:stop]` is reserved exclusively for row indexing.

### 4. Passing a 1D Series to a Scikit-Learn Transformer
- **Wrong**:
  ```python
  from sklearn.preprocessing import StandardScaler

  ```
- **Right**:
  ```python
  scaler.fit_transform(df[["feature"]])  # Passes 2D DataFrame of shape (N, 1)
  ```
- **Why**: `df['feature']` returns a 1D Series of shape `(N,)`. ML estimators mandate a 2D matrix of shape `(N, n_features)`.

### 5. Confusing `df.filter()` with Value-Based Row Filtering

## 6. Section-Adaptive Pandas API Confusions

### 1. `df['col']` vs `df[['col']]`
- **Conceptual Difference**: `df['col']` extracts a 1D `pd.Series`. `df[['col']]` extracts a 2D `pd.DataFrame` with one column.
- **Memory/Performance**: `df['col']` performs an instantaneous 1D slice. `df[['col']]` constructs a full DataFrame wrapper with two index axes (`index` and `columns`).
- **Code Comparison**:
  ```python
  import pandas as pd
  df = pd.DataFrame({"score": [95, 85]})
  s = df["score"]
  d = df[["score"]]
  print(s.shape)  # (2,)
  print(d.shape)  # (2, 1)
  ```
- **Interview Rule of Thumb**: Use `df['col']` when applying scalar operations, string methods, or series aggregations. Use `df[['col']]` when passing features to machine learning algorithms or concatenating tables horizontally.

### 2. `df.col` vs `df['col']`
- **Conceptual Difference**: `df.col` is Python syntactic sugar relying on `__getattr__`. `df['col']` is the standard dictionary lookup mapping to `__getitem__`.
- **Memory/Performance**: Identical execution speed once resolved, but dot notation has slight overhead during attribute resolution and fails completely on edge-case column names.
- **Code Comparison**:
  ```python
  df = pd.DataFrame({"user name": ["Alice"], "shape": [10]})
  # df.user name -> SyntaxError
  # df.shape     -> returns tuple (1, 2), NOT the column [10]!
  print(df["user name"].iloc[0])  # 'Alice'
  print(df["shape"].iloc[0])      # 10
  ```
- **Interview Rule of Thumb**: Never write dot notation in production code; reserve it strictly for quick exploratory probing in interactive notebooks.

### 3. `df[cols]` vs `df.reindex(columns=cols)`
- **Conceptual Difference**: `df[cols]` is a strict projection requiring all keys to exist. `df.reindex(columns=cols)` is a resilient projection that conforms the DataFrame to the target list, synthesizing `NaN` columns for missing keys.
- **Memory/Performance**: `df[cols]` is faster ($O(K)$ lookup). `df.reindex` creates new memory blocks for missing columns and reallocates memory to match the requested schema.
- **Code Comparison**:
  ```python
  df = pd.DataFrame({"a": [1, 2]})
  target = ["a", "missing_col"]
  
  # df[target] -> raises KeyError: "['missing_col'] not in index"
  safe = df.reindex(columns=target)
  print(safe)
  #    a  missing_col
  # 0  1          NaN
  # 1  2          NaN
  ```
- **Interview Rule of Thumb**: Use `df[cols]` when missing features represent critical data pipeline failures. Use `df.reindex(columns=cols)` when aligning unpredictable vendor inputs to a fixed production schema.

### 4. `df.filter()` vs Boolean Masking `df[...]`
- **Conceptual Difference**: `df.filter()` inspects and selects **labels** (column names or row index strings). Boolean masking `df[condition]` inspects and filters **data values** inside rows.
- **Memory/Performance**: `df.filter()` runs in $O(M)$ time proportional to column count. Boolean masking runs in $O(N)$ time scanning all rows.
- **Code Comparison**:
  ```python
  df = pd.DataFrame({"metric_a": [10, 50], "metric_b": [20, 60]})
  
  # Filter metadata labels (selects columns matching 'metric'):
  cols = df.filter(like="metric")
  
  # Filter data values (selects rows where metric_a > 15):
  rows = df[df["metric_a"] > 15]
  ```
- **Interview Rule of Thumb**: If you need to pick columns by their names, use `df.filter()`. If you need to select records by their contents, use boolean masking.

### 5. `df.select_dtypes()` vs List Comprehension on `df.columns`
- **Conceptual Difference**: `df.select_dtypes()` leverages Pandas and NumPy's internal dtype inheritance trees at the block level. List comprehensions evaluate arbitrary Python string conditions against column names.
- **Memory/Performance**: `select_dtypes` operates directly on internal blocks in $O(M)$ time. List comprehensions that inspect column contents (e.g., `df[c].nunique()`) force full column data scans ($O(N \times M)$).
- **Code Comparison**:
  ```python
  df = pd.DataFrame({"num": [1, 2], "str": ["a", "b"], "dt": pd.to_datetime(["2024-01-01", "2024-01-02"])})
  
  # Type-based block filtering (vectorized and clean):
  num_df = df.select_dtypes(include="number")
  
  # String-based naming filtering:
  str_cols = df[[c for c in df.columns if len(c) == 3]]
  ```
- **Interview Rule of Thumb**: Always use `df.select_dtypes()` for data type partitioning. Reserve list comprehensions for complex naming rules, prefix matching, or cardinality checks.

## 7. Interview Traps

### Trap 1: The Invisible Column Insertion Failure
- **The Trap**: The interviewer asks: *"I ran `df.new_feature = [10, 20, 30]` in my training script. On the next line, `X = df[['new_feature', 'age']]` raised `KeyError: 'new_feature'`. Why did this happen?"*
- **Naive Fresher Answer**: *"Maybe the length of the list didn't match the rows in the DataFrame, or there was a typo in the column name."*
- **What the Interviewer is Testing**: Understanding that dot assignment attaches standard Python attributes to the class instance rather than mutating the underlying `BlockManager`.
- **The Reality / Under the Hood**: `df.new_feature = ...` invokes Python's standard `__setattr__`. Pandas overrides `__setitem__` (bracket notation) for column insertion, but purposefully prevents `__setattr__` from inserting new columns to avoid colliding with internal DataFrame attributes.
- **Winning Response**: *"Dot notation cannot insert new columns into a DataFrame. It attaches `new_feature` as a standard Python object attribute on the DataFrame instance, leaving `df.columns` and the internal `BlockManager` completely untouched. To insert the column into the DataFrame, the developer must use bracket assignment: `df['new_feature'] = [10, 20, 30]`."*

### Trap 2: The Multi-Column Bracket Syntax Error
- **The Trap**: *"Why does `df['col1', 'col2']` raise a `KeyError` instead of returning the two columns?"*
- **Naive Fresher Answer**: *"Pandas requires a list of strings, so you just forgot square brackets."*
- **What the Interviewer is Testing**: Deep knowledge of Python tuple syntax and Pandas MultiIndex resolution mechanics.
- **The Reality / Under the Hood**: In Python, comma-separated arguments inside brackets evaluate to a tuple: `['col1', 'col2']` is syntax for `__getitem__(('col1', 'col2'))`. In Pandas, a tuple key represents a hierarchical MultiIndex lookup on a single column. Since the DataFrame has a standard flat index, the tuple is not found in the columns hash table, raising `KeyError: ('col1', 'col2')`.
- **Winning Response**: *"Passing unbracketed comma-separated strings generates a Python tuple. Pandas interprets a tuple as a single coordinate key for MultiIndex column hierarchies. To project multiple columns from a flat index, you must pass an explicit Python list: `df[['col1', 'col2']]`."*

### Trap 3: The Method Collision Trap
- **The Trap**: *"I loaded a customer dataset with an integer column named `'count'`. When I executed `df.count + 5`, Python raised `TypeError: unsupported operand type(s) for +: 'method' and 'int'`. What went wrong?"*
- **Naive Fresher Answer**: *"The data in the 'count' column must have been stored as strings or nulls instead of numbers."*
- **What the Interviewer is Testing**: Knowledge of namespace precedence in Pandas attribute resolution.
- **The Reality / Under the Hood**: DataFrames possess a built-in method named `count()` that returns non-null counts. When evaluating `df.count`, Python resolves existing instance methods on the class before invoking `__getattr__`. Consequently, `df.count` returns `<bound method DataFrame.count...>`, which cannot be added to an integer.
- **Winning Response**: *"The column name `'count'` collides with the built-in DataFrame method `DataFrame.count()`. Class methods take precedence over dynamic column attribute lookup. To access the column safely without collision, you must use bracket notation: `df['count'] + 5`."*

### Trap 4: The 1D vs 2D Scikit-Learn Model Crash
- **The Trap**: *"Why does `scaler.fit_transform(df['income'])` throw a `ValueError: Expected 2D array, got 1D array instead`, whereas `scaler.fit_transform(df[['income']])` executes without issue?"*
- **Naive Fresher Answer**: *"The first one passes a single column, but Scikit-Learn only works on datasets with multiple columns."*
- **What the Interviewer is Testing**: Understanding of tensor dimensionality in Pandas data structures (`Series.ndim == 1` vs `DataFrame.ndim == 2`).
- **The Reality / Under the Hood**: `df['income']` extracts a 1D `pd.Series` with shape `(N,)`. Scikit-Learn's API contract explicitly requires feature matrices to have shape `(n_samples, n_features)`. `df[['income']]` passes a list, returning a 2D `pd.DataFrame` with shape `(N, 1)`, satisfying the 2D matrix requirement.
- **Winning Response**: *"Single brackets extract a 1-dimensional Series of shape `(N,)`, whereas double brackets extract a 2-dimensional DataFrame of shape `(N, 1)`. Scikit-Learn estimators require 2-dimensional inputs for the feature space $X$. Using `df[['income']]` preserves the second dimension."*

### Trap 5: The Column Slicing Mirage
- **The Trap**: *"What happens when you run `df['col_a':'col_c']` on a DataFrame with columns `['col_a', 'col_b', 'col_c']`?"*
- **Naive Fresher Answer**: *"It returns a DataFrame containing columns 'col_a', 'col_b', and 'col_c'."*
- **What the Interviewer is Testing**: Understanding the dual nature of `__getitem__` in Pandas.
- **The Reality / Under the Hood**: Standard bracket slice syntax `df[start:stop]` operates strictly on **rows (axis 0)** based on index labels. Because the row index does not contain labels `'col_a'` through `'col_c'`, Pandas returns an empty DataFrame (or raises a `KeyError` if non-monotonic).
- **Winning Response**: *"Single-bracket slicing operates strictly on rows, not columns! Slicing columns by label requires explicit coordinate indexing using `.loc`: `df.loc[:, 'col_a':'col_c']`."*

### Trap 6: The Unanchored Regex Leak
- **The Trap**: *"I used `df.filter(regex='temp')` to select temperature sensors, but my resulting dataset contained an unexpected column named `'attempt_status'`. Why did this happen?"*
- **Naive Fresher Answer**: *"Pandas regex matching has a bug that matches similar-sounding words."*
- **What the Interviewer is Testing**: Regex compilation mechanics in `df.filter()`.
- **The Reality / Under the Hood**: `df.filter(regex=...)` uses Python's `re.search()`, which searches for the pattern anywhere in the target string. The substring `'temp'` is present inside `'at[temp]t_status'`.
- **Winning Response**: *"`df.filter(regex=...)` executes unanchored search. To restrict matching strictly to temperature sensors, anchor the pattern with word boundaries or start/end tokens, such as `regex=r'^temp'` or `regex=r'\btemp\b'`."*

### Trap 7: The Unordered Set Indexing Trap
- **The Trap**: *"Can I pass a Python set of column names into a DataFrame like `df[{'age', 'salary'}]` to avoid duplicate selections?"*
- **Naive Fresher Answer**: *"Yes, sets remove duplicates and work just like lists."*
- **What the Interviewer is Testing**: Understanding of hash-set ordering and Pandas indexing contracts.
- **The Reality / Under the Hood**: Sets are unordered. In modern Pandas, passing a set to `__getitem__` is either deprecated or raises an immediate `KeyError`. Tabular data requires deterministic column alignment.
- **Winning Response**: *"No. Passing sets to `__getitem__` is prohibited or deprecated because sets do not guarantee deterministic ordering. You should pass an ordered sequence, such as a list or `Index` object: `df[list({'age', 'salary'})]` or `df[sorted(list({'age', 'salary'}))]`."*

### Trap 8: The `filter()` Data-Value Fallacy
- **The Trap**: *"Why does `df.filter(like='100')` return zero rows when my dataset contains dozens of rows where values equal 100?"*
- **Naive Fresher Answer**: *"You need to convert the 100 to an integer instead of a string: `df.filter(like=100)`."*
- **What the Interviewer is Testing**: Distinction between metadata filtering and data filtering.
- **The Reality / Under the Hood**: `df.filter()` inspects *axis labels* (column names or row index strings), never data cell values. Passing `like='100'` searches for columns whose names contain the characters `'100'`.
- **Winning Response**: *"`df.filter()` filters metadata labels (column names or row index labels), not cell values. To filter rows based on numerical cell values, you must use boolean indexing: `df[df['col'] == 100]`."*

### Trap 9: The Integer Column Header Pitfall
- **The Trap**: *"After importing an Excel sheet, `[c for c in df.columns if c.startswith('202')]` crashed with `AttributeError: 'int' object has no attribute 'startswith'`. Why?"*
- **Naive Fresher Answer**: *"The file was corrupted during download."*
- **What the Interviewer is Testing**: Awareness that Pandas `Index` objects support arbitrary Python types, including integers.
- **The Reality / Under the Hood**: Excel sheets with yearly headers (e.g., `2021`, `2022`, `2023`) are parsed by `pd.read_excel()` as integer numbers, not strings. Calling string methods directly on integers raises `AttributeError`.
- **Winning Response**: *"The Excel parser imported the year headers as integer objects (`int64`). You must cast them before string operations: `[c for c in df.columns if str(c).startswith('202')]`, or normalize all headers at ingestion: `df.columns = df.columns.astype(str)`."*

### Trap 10: The Duplicate Column Series Mirage
- **The Trap**: *"If a DataFrame has two columns with the exact same name `'metric'`, what does `df['metric']` return?"*
- **Naive Fresher Answer**: *"It returns the first column as a Series and ignores the second."*
- **What the Interviewer is Testing**: Understanding duplicate column label behavior in Pandas.
- **The Reality / Under the Hood**: Pandas permits duplicate column labels. When you request a label shared by multiple columns, `__getitem__` returns a 2-dimensional `pd.DataFrame` containing all matching columns, NOT a `pd.Series`.
- **Winning Response**: *"It returns a 2-dimensional `pd.DataFrame` containing both columns. This frequently breaks downstream code expecting a 1D Series. Duplicate column labels should be audited and eliminated using `df.columns.duplicated()`."*

### Q1: Automated Feature Store Ingestion Under Schema Drift
- **Scenario**: A production ML pipeline reads customer profile data from third-party partners. Partners frequently add experimental telemetry columns or temporarily omit optional features. Downstream XGBoost models require exactly 45 pre-trained feature columns in strict sequential order.
- **Engineering Solution**:
  ```python
  import pandas as pd

  def enforce_feature_store_schema(incoming_df: pd.DataFrame, expected_features: list[str]) -> pd.DataFrame:
      # Step 1: Detect completely missing critical columns
      incoming_set = set(incoming_df.columns)
      missing_features = [f for f in expected_features if f not in incoming_set]
      
      if len(missing_features) > 10:
          raise ValueError(f"Fatal schema drift: {len(missing_features)} features missing from source!")
          
      # Step 2: Use reindex to strictly order features and populate missing ones with NaN
      model_ready_df = incoming_df.reindex(columns=expected_features)
      
      return model_ready_df
  ```
- **Trade-off Analysis**: `df.reindex(columns=...)` is an $O(K)$ operation that guarantees both column ordering and dimensionality alignment in a single step, preventing silent feature shift bugs in production models.

### Q2: High-Throughput Column Partitioning for Hybrid Preprocessing
- **Scenario**: In an automated ETL pipeline processing 50-column tables, numeric features must be imputed with medians and scaled, while categorical features must be encoded. Writing manual column lists creates maintenance bottlenecks whenever the schema updates.
- **Engineering Solution**:

  ```python
  def partition_features_by_dtype(df: pd.DataFrame) -> tuple[pd.DataFrame, pd.DataFrame, pd.DataFrame]:
      # Vectorized block isolation
      numeric_matrix = df.select_dtypes(include="number")
      categorical_matrix = df.select_dtypes(include=["object", "category"])
      temporal_matrix = df.select_dtypes(include=["datetime", "timedelta"])
      
      return numeric_matrix, categorical_matrix, temporal_matrix
  ```
- **Trade-off Analysis**: `select_dtypes` inspects the internal `BlockManager` metadata in microseconds ($O(M)$), avoiding full data scans and eliminating hardcoded column lists.

### Q3: Dynamic Feature Pruning by Variance and Missingness
- **Scenario**: A data science pipeline receives 1,000 raw features from an automated feature generation library (e.g., Featuretools). Features with zero variance (constants) or greater than 60% missingness must be dynamically pruned before training.
- **Engineering Solution**:
  ```python
  import pandas as pd

  def prune_uninformative_features(df: pd.DataFrame, max_null_ratio: float = 0.60) -> pd.DataFrame:
      # 1. Prune high-null features
      valid_null_cols = df.loc[:, df.isna().mean() <= max_null_ratio].columns
      df_pruned = df[valid_null_cols]
      
      # 2. Prune zero-variance numeric features
      num_cols = df_pruned.select_dtypes(include="number").columns
      non_zero_var_cols = [c for c in num_cols if df_pruned[c].nunique(dropna=False) > 1]
      non_num_cols = [c for c in df_pruned.columns if c not in num_cols]
      
      return df_pruned[non_num_cols + non_zero_var_cols]
  ```
- **Trade-off Analysis**: Using `.loc[:, mask]` combines vectorized null percentage computation with dynamic column pruning without copying unselected blocks.

### Q4: Sanitizing Unclean User Column Headers in Enterprise Data Lakes
- **Scenario**: Files uploaded by enterprise users contain malformed headers: leading/trailing whitespaces, punctuation marks, mixed casing, and spaces.
- **Engineering Solution**:
  ```python
  import re
  import pandas as pd

  def sanitize_dataframe_columns(df: pd.DataFrame) -> pd.DataFrame:
      clean_df = df.copy()
      clean_columns = []
      
      for col in clean_df.columns:
          # Convert to string, strip whitespace, lowercase
          c_str = str(col).strip().lower()
          # Replace whitespace and punctuation with single underscore
          c_clean = re.sub(r"[^\w]+", "_", c_str)
          # Strip leading/trailing underscores
          c_clean = c_clean.strip("_")
          clean_columns.append(c_clean)
          
      clean_df.columns = clean_columns
      return clean_df
  ```
- **Trade-off Analysis**: Sanitizing column headers at the ingestion boundary ensures that downstream pipelines can safely utilize regex filtering and programmatic list indexing without encountering silent formatting bugs.

## 13. Flashcard Section

### Flashcard 1
- **Front**: What is the structural and tensor difference between `df['col']` and `df[['col']]`?
- **Back**: `df['col']` extracts a 1D `pd.Series` of shape `(N,)`. `df[['col']]` extracts a 2D `pd.DataFrame` of shape `(N, 1)`. Scikit-Learn transformers require 2D arrays, making `df[['col']]` mandatory for single feature scaling.

### Flashcard 2
- **Front**: Why does `df.column_name = [...]` fail to add a column to a DataFrame?
- **Back**: `__setattr__` attaches standard Python instance attributes to the object in memory. To insert a column into the DataFrame's internal `BlockManager`, bracket assignment `df['column_name'] = [...]` is required.

### Flashcard 3
- **Front**: What causes `KeyError: ('col1', 'col2')` during multiple column selection?
- **Back**: Omitting outer brackets causes Python to interpret the comma-separated strings as a tuple. Pandas treats tuples as hierarchical MultiIndex coordinates rather than a list of independent columns.

### Flashcard 4
- **Front**: What is the difference between `df.filter(items=cols)` and `df.reindex(columns=cols)`?
- **Back**: `filter(items=cols)` returns only the columns that actually exist, dropping absent ones without error. `reindex(columns=cols)` forces the output DataFrame to match `cols` exactly, populating missing columns with `NaN`.

### Flashcard 5
- **Front**: Why does `df['col_a':'col_b']` fail to select columns between 'col_a' and 'col_b'?
- **Back**: Single-bracket slicing `df[start:stop]` operates strictly on rows (axis 0). To slice columns by label, you must use 2-axis coordinate indexing: `df.loc[:, 'col_a':'col_b']`.

### Flashcard 6
- **Front**: What happens when dot notation accesses a column named `'count'` or `'shape'`?
- **Back**: Built-in DataFrame class methods and attributes take precedence over `__getattr__`. `df.count` returns the bound method `<bound method DataFrame.count...>`, not the column's data.

### Flashcard 7
- **Front**: How does `df.select_dtypes(include='number')` operate under the hood?
- **Back**: It traverses the `BlockManager` blocks and checks their NumPy/Arrow dtypes against `np.number` using `issubclass()`. It runs in $O(M)$ time proportional to column count.

### Flashcard 8
- **Front**: How do you select columns based on data values (e.g., columns with < 30% nulls)?
- **Back**: Use `.loc[:, boolean_series]`: `df.loc[:, df.isna().mean() < 0.30]`. Single-bracket `df[bool_series]` evaluates along axis 0 and attempts to mask rows.

### Flashcard 9
- **Front**: Why does `[c for c in df.columns if c.startswith('202')]` crash on raw Excel datasets?
- **Back**: Excel imports numeric headers (like years `2023`, `2024`) as integers (`int64`), which lack string methods. Use `str(c).startswith('202')` or cast `df.columns = df.columns.astype(str)`.

### Flashcard 10
- **Front**: What does `df.filter(regex=r'temp')` do, and why might it select `'attempt_id'`?
- **Back**: It uses Python's unanchored `re.search()`, matching the pattern anywhere in the column label. To prevent matching `'attempt_id'`, anchor the regex with `^` or word boundaries: `r'^temp'`.

### Flashcard 11
- **Front**: How does `df.get('col', default)` behave differently from `df['col']`?
- **Back**: `df['col']` raises a fatal `KeyError` if missing. `df.get()` returns the specified `default` object (or `None`), preventing pipeline crashes on optional features.

### Flashcard 12
- **Front**: What is returned when you query a non-unique column label via `df['metric']`?
- **Back**: If multiple columns share the label `'metric'`, Pandas returns a 2-dimensional `pd.DataFrame` containing all instances, NOT a 1D `pd.Series`.

### Flashcard 13
- **Front**: How do you reorder DataFrame columns to place specific priority columns at the front?
- **Back**: Concatenate lists: `priority = ['id', 'name']; df[priority + [c for c in df.columns if c not in priority]]`.

### Flashcard 14
- **Front**: Why is passing a set `df[{'a', 'b'}]` bad practice?
- **Back**: Sets are unordered. Tabular data structures require deterministic column ordering; passing sets raises a `KeyError` or deprecation warning in modern Pandas.

### Flashcard 15
- **Front**: How does Copy-on-Write (CoW) affect column projections like `df[['a', 'b']]`?
- **Back**: CoW returns a shallow view of the underlying memory blocks. Memory is only copied if one of the structures is mutated, maximizing performance and RAM efficiency.

### Flashcard 16
- **Front**: How do you select columns dynamically in a method chain without assigning temporary variables?
- **Back**: Pass a lambda to `.loc`: `df.loc[:, lambda d: d.columns.str.endswith('_clean')]`.

   - `df['a':'c']` slices **rows**, NOT columns!
   - `df.loc[:, 'a':'c']` slices **columns**.

## 20. What a Fresher Should Understand

1. **`BlockManager` Architecture**:
   - Pandas stores tabular data internally as 2D NumPy blocks grouped by dtype.
   - Single-column selection from a block creates a 1D slice sharing the block's array buffer.
   - Multi-column selection spanning multiple types creates a new `BlockManager` referencing the respective blocks.
2. **Copy-on-Write (CoW)**:
   - Slicing columns creates shallow views with zero memory duplication.
   - Modifying a sliced DataFrame triggers an automatic, transparent copy at the moment of mutation, eliminating `SettingWithCopyWarning`.
3. **Tensor Dimensionality (1D vs 2D)**:
   - Machine learning algorithms strictly differentiate between 1D vectors (shape `(N,)` for target labels $y$) and 2D matrices (shape `(N, M)` for feature matrices $X$).
   - `df['col']` is a vector; `df[['col']]` is a matrix.
4. **Namespace Resolution Precedence**:
   - In dot notation (`df.attr`), Python checks built-in attributes and methods of the `DataFrame` class before calling `__getattr__` for columns. Column names colliding with methods (e.g., `'count'`, `'min'`) are permanently inaccessible via dot notation.

#### Answer 1 (4 Marks)
- **Model Answer**: `df['feature']` extracts a 1D `pd.Series` with shape `(N,)` and a single index. `df[['feature']]` constructs a 2D `pd.DataFrame` with shape `(N, 1)` containing both row and column index axes. Scikit-Learn estimators require 2-dimensional feature matrices of shape `(n_samples, n_features)`; passing a 1D Series raises `ValueError: Expected 2D array, got 1D array instead`.
- **Marking**: 1.5 marks for 1D vs 2D return types; 1.5 marks for exact shape representation; 1 mark for Scikit-Learn 2D requirement.

#### Answer 2 (4 Marks)
- **Model Answer**: Dot assignment `df.new_column = ...` invokes standard Python `__setattr__`. This attaches `new_column` as a regular instance attribute on the Python object in memory. It does not update the `BlockManager` or register with `df.columns`. Adding a column to a DataFrame requires bracket assignment: `df['new_column'] = ...`.
- **Marking**: 2 marks for explaining Python instance attribute attachment; 2 marks for contrasting with `BlockManager` bracket assignment.

#### Answer 3 (4 Marks)
- **Model Answer**: `df[cols_list]` enforces strict validation and raises a fatal `KeyError` if any column in the list is missing. `df.reindex(columns=cols_list)` provides resilient schema projection; it never raises `KeyError`, returning a DataFrame containing all requested columns and populating missing keys with `NaN`.
- **Marking**: 2 marks for `KeyError` on `df[cols_list]`; 2 marks for `reindex` creating `NaN` columns without crashing.

#### Answer 4 (4 Marks)
- **Model Answer**: Single-bracket slicing `df[start:stop]` evaluates strictly along **axis 0 (rows)** based on index labels. When passed string labels `'col_a':'col_c'`, Pandas attempts to find those labels in the row index. Since the row index contains numeric integers, no rows match, returning an empty DataFrame. Column slicing requires `.loc[:, 'col_a':'col_c']`.
- **Marking**: 2.5 marks for identifying axis 0 (row) evaluation; 1.5 marks for specifying `.loc[:, ...]` for column slicing.

#### Answer 5 (4 Marks)
- **Model Answer**: `df['col']` is an $O(1)$ constant-time operation relying on an internal hash map lookup in `df.columns._engine`. `df[['col1', 'col2', 'col3']]` takes $O(K)$ time where $K$ is the number of requested columns (3 hash lookups) plus $O(N \times K)$ memory overhead to construct the new `BlockManager` and DataFrame wrapper.

## 24. Final 2-Minute Revision Summary

- **Bracket vs Dot Notation**:
  - Always use bracket notation `df['col']` in production.
  - Dot notation `df.col` fails on spaces, hyphens, leading digits, and method name collisions (e.g., `count`, `shape`), and cannot create new columns.
- **Dimensionality Control**:
  - `df['col']` returns a 1D `pd.Series` (shape `(N,)`).
  - `df[['col']]` returns a 2D `pd.DataFrame` (shape `(N, 1)`), required by Scikit-Learn transformers.
  - `df[['a', 'b']]` projects multiple columns in the specified list order.
  - `df['a', 'b']` raises `KeyError: ('a', 'b')` because commas evaluate to tuples (MultiIndex lookup).
- **Dynamic Selection Utilities**:
  - `df.select_dtypes(include='number')`: Selects all numerical features (ints and floats) via block metadata in $O(M)$ time.
  - `df.select_dtypes(include=['object', 'category'])`: Selects all categorical/text features.
  - `df.filter(like='substring')`: Substring search across column headers.
  - `df.filter(regex=r'^feat_')`: Anchored regex pattern search across column headers.
- **Defensive Schema Patterns**:
  - `df[cols]` raises `KeyError` if any column is missing.
  - `df.filter(items=cols)` returns only existing columns without crashing.
  - `df.reindex(columns=cols)` forces the output to match `cols` exactly, populating missing features with `NaN`.
- **Column Slicing Rule**:
  - `df['col_a':'col_c']` slices **rows**, NOT columns!
  - Always use `.loc[:, 'col_a':'col_c']` for column slicing.
