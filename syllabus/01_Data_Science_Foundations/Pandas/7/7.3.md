### 1. Section Overview

- **What this section is about**: Section 7.3 covers the detection, remediation, and standardization of invalid, corrupt, infinite, and inconsistent data in Pandas. Unlike missing values (`NaN`/`None`), invalid data consists of values that are physically present in the table but violate domain constraints, schema definitions, or logical boundaries (e.g., negative ages, impossible percentages $> 100\%$, mixed casing like `'US'`, `'usa'`, `'U.S.'`, floating-point infinity `np.inf`, or obsolete/spurious categorical levels).
- **Why these Pandas concepts matter**: Real-world databases and user-facing forms constantly leak invalid data into downstream analytics. Hiring managers evaluate whether a candidate can detect non-null anomalies, perform surgical replacements via `replace()` and `.loc[]`, handle mathematical anomalies like division-by-zero infinities (`np.inf`), sanitize messy string variants using vectorized string accessors, and clean categorical schemas using `pd.Categorical` methods without mutating valid data.
- **Where they are used in real projects**: In customer master data management (MDM), financial transaction validation (flagging negative prices or impossible transaction timestamps), machine learning preprocessing (preventing gradient explosions caused by `np.inf` or category explosion from typographic errors), and data warehouse staging layers.
- **What a fresher should be able to do**:

  2. Perform scalar, dictionary, list, and regex-based replacements using `df.replace()`.
  3. Identify and remediate positive and negative infinite values (`np.inf`, `-np.inf`) using `np.isinf()` and explicit replacement to `np.nan`.
  4. Standardize text strings across casing (`.str.lower()`, `.str.title()`), whitespace (`.str.strip()`), and synonyms.
  5. Clean categorical columns: adding valid categories, merging rare categories, removing unused categories (`.cat.remove_unused_categories()`), and re-coding invalid labels.
  6. Apply conditional value transformations safely using 2D `.loc[mask, col] = val` and `np.where()`.

### 2. Topic-Wise Interview Concepts

#### Topic 1: Detecting Invalid Values

- **Concept**: Invalid values are data points that are present (non-null) but violate logical rules, business constraints, or expected schemas (e.g., `age < 0` or `age > 120`, `discount_pct > 1.0`, or unexpected data types). Detection relies on generating boolean validation masks.
- **Why it matters**: Machine learning models and SQL pipelines fail or produce corrupt insights when trained on invalid data. Finding invalid values before they corrupt models is a primary responsibility of junior data practitioners.
- **Technical / Algorithmic Intuition**: Pandas evaluates vectorized boolean predicates at the C/NumPy level (e.g., `(df['age'] < 0) | (df['age'] > 120)`). These comparisons create a 1D boolean array in $O(N)$ time with zero Python loop overhead.
- **Syntax / Pandas API**:
  - `invalid_mask = (df['col'] < min_val) | (df['col'] > max_val)`
  - `invalid_mask = ~df['col'].between(min_val, max_val)`
  - `invalid_rows = df[invalid_mask]`
  - `invalid_count = invalid_mask.sum()`
- **Minimal Working Example**:
  ```python
  import pandas as pd
  import numpy as np

  df = pd.DataFrame({
      'user_id': [101, 102, 103, 104],
      'age': [25, -5, 142, 38],
      'score': [88.0, 95.0, 105.0, 72.0]
  })

  # Business rules: 0 <= age <= 120, 0 <= score <= 100
  invalid_age = ~df['age'].between(0, 120)
  invalid_score = ~df['score'].between(0, 100)

  invalid_records = df[invalid_age | invalid_score]
  print("Invalid records:\n", invalid_records)
  ```
- **Output**:
  ```text
  Invalid records:
      user_id  age  score
  1      102   -5   95.0
  2      103  142  105.0
  ```
  - *Line-by-line explanation*: Row 1 has invalid negative age (`-5`). Row 2 has both invalid age (`142`) and score exceeding 100 (`105.0`). The disjunction `|` isolates both records.
- **Complexity & Performance**: Vectorized mask creation executes in $O(N)$ time and allocates 1 byte per row for the boolean mask.
- **Common Interview Gotcha**: Using `s.isna()` to find invalid data. `isna()` only detects missing values; it returns `False` for `-999`, `-5`, or `99999`.

#### Topic 2: Replacing Invalid Values

- **Concept**: Once invalid values are detected, they must be converted to valid defaults, imputed, or mapped to `np.nan` for systematic handling. Pandas provides `df.replace()`, 2D conditional indexing `.loc[]`, and `np.where()`.
- **Why it matters**: Clean data replacement must be atomic and type-safe. Interviewers look for candidates who use `.replace()` and `.loc[]` appropriately rather than error-prone iterative loops.
- **Technical / Algorithmic Intuition**: `df.replace()` checks values against a hash table or regex pattern and writes replacement values into the underlying array blocks. When conditional masks depend on thresholds, `.loc[mask, col] = new_val` performs direct block modification.
- **Syntax / Pandas API**:
  - `df['col'] = df['col'].replace(to_replace, value)`
  - `df = df.replace({-999: np.nan, 'Unknown': np.nan})` (dictionary mapping)
  - `df.replace(r'^\s*$', np.nan, regex=True)` (regex pattern replacement)
  - `df.loc[mask, 'col'] = new_val` (conditional in-place assignment)
  - `df['col'] = np.where(condition, valid_val, fallback_val)`
- **Minimal Working Example**:
  ```python
  import pandas as pd
  import numpy as np

  df = pd.DataFrame({
      'status_code': [200, 404, 999, -1],
      'score': [85, 92, -999, 78]
  })

  # Replace sentinel error codes with np.nan
  df_clean = df.replace({-999: np.nan, -1: np.nan})

  # Clamp out-of-range status codes using .loc
  df_clean.loc[df_clean['status_code'] > 500, 'status_code'] = 500
  print(df_clean)
  ```
- **Output**:
  ```text
     status_code  score
  0        200.0   85.0
  1        404.0   92.0
  2        500.0    NaN
  3          NaN   78.0
  ```
  - *Line-by-line explanation*: `replace({-999: np.nan, -1: np.nan})` maps `-999` in `'score'` and `-1` in `'status_code'` to `NaN`. `.loc` clamps `999` down to `500`.
- **Complexity & Performance**: Exact value lookup in `.replace()` is $O(N)$ using hash matching. Regex replacement compiles Python's `re` engine, taking $O(N \times L)$ where $L$ is string length.
- **Common Interview Gotcha**: Writing `df[df['col'] < 0]['col'] = 0`. This chained indexing triggers `SettingWithCopyWarning` and leaves `df` unmutated. Use `df.loc[df['col'] < 0, 'col'] = 0`.

#### Topic 3: Handling Infinite Values

- **Concept**: Infinite values (`np.inf`, `-np.inf`) arise from mathematical operations like division by zero (e.g., calculating price-to-earnings or profit margin when cost is zero) or floating-point overflow.
- **Why it matters**: In standard Pandas, `np.inf` is **NOT** recognized as a missing value by `isna()` (`pd.isna(np.inf)` returns `False`). However, scikit-learn models and statistical estimators crash with `ValueError: Input contains infinity`.
- **Technical / Algorithmic Intuition**: In IEEE 754 floating-point, infinity has a distinct bit pattern (all ones in the exponent and all zeros in the mantissa). It participates in calculations ($1.0 / 0.0 = \text{inf}$), but breaks machine learning algorithms. Pandas 2.1+ deprecated `mode.use_inf_as_na`; production code must explicitly replace infinities.
- **Syntax / Pandas API**:
  - `np.isinf(df['col'])` (detects positive and negative infinity)
  - `df.replace([np.inf, -np.inf], np.nan)` (canonical replacement)
  - `df[np.isinf(df).any(axis=1)]` (filter rows with infinity)
- **Minimal Working Example**:
  ```python
  import pandas as pd
  import numpy as np

  df = pd.DataFrame({
      'revenue': [100.0, 200.0, 300.0],
      'cost': [50.0, 0.0, 150.0]
  })

  # Calculate profit multiple (triggers division by zero at index 1)
  df['multiple'] = df['revenue'] / df['cost']

  print("Raw calculation:\n", df['multiple'])
  print("Does isna() catch inf?", df['multiple'].isna().iloc[1])

  # Canonical remediation: replace inf with np.nan
  df['multiple'] = df['multiple'].replace([np.inf, -np.inf], np.nan)
  print("\nAfter replacement:\n", df['multiple'])
  ```
- **Output**:
  ```text
  Raw calculation:
  0    2.0
  1    inf
  2    2.0
  Name: multiple, dtype: float64
  Does isna() catch inf? False

  After replacement:
  0    2.0
  1    NaN
  2    2.0
  Name: multiple, dtype: float64
  ```
  - *Line-by-line explanation*: Division by zero generates `inf` at index 1. `df['multiple'].isna()` returns `False`. Calling `.replace([np.inf, -np.inf], np.nan)` standardizes `inf` to `NaN`, allowing standard imputation methods to clean it.
- **Complexity & Performance**: `np.isinf()` and `.replace()` operate in $O(N)$ vectorized C-level time.
- **Common Interview Gotcha**: Relying on deprecated option `pd.set_option('mode.use_inf_as_na', True)`. In modern Pandas, this option raises a `FutureWarning` or error. Always use explicit `.replace([np.inf, -np.inf], np.nan)`.

#### Topic 4: Standardizing Inconsistent Values

- **Concept**: Inconsistent values occur when the same semantic entity is entered using different formatting, casing, whitespace, or synonyms (e.g., `'Male'`, `'male'`, `'M'`, `'m'`, `'MALE '`).
- **Why it matters**: Categorical grouping and aggregation treat `'NY'`, `'ny'`, and `'NY '` as three completely different categories, fragmenting analysis and artificially increasing cardinalities.
- **Technical / Algorithmic Intuition**: Vectorized string methods under the `.str` accessor operate element-wise on string arrays. Chaining `.str.strip()` and `.str.lower()` standardizes lexical representations before dictionary mapping.
- **Syntax / Pandas API**:
  - `s.str.strip()` (removes leading and trailing whitespace)
  - `s.str.lower()`, `s.str.upper()`, `s.str.title()` (casing standardization)
  - `s.map(mapping_dict)` or `s.replace(mapping_dict)` (synonym consolidation)
- **Minimal Working Example**:
  ```python
  import pandas as pd

  countries = pd.Series([' United States ', 'usa', 'U.S.', 'USA', 'united states', 'Canada '])

  # 1. Clean whitespace and casing
  standardized = countries.str.strip().str.upper()

  # 2. Map synonyms to canonical ISO-3 code
  synonym_map = {
      'USA': 'USA',
      'U.S.': 'USA',
      'UNITED STATES': 'USA',
      'CANADA': 'CAN'
  }
  canonical = standardized.map(synonym_map)
  print(canonical)
  ```
- **Output**:
  ```text
  0    USA
  1    USA
  2    USA
  3    USA
  4    USA
  5    CAN
  dtype: object
  ```
  - *Line-by-line explanation*: `.str.strip().str.upper()` normalizes whitespace and capitalization. `.map(synonym_map)` consolidates 5 variants into `'USA'`.
- **Complexity & Performance**: String methods run in $O(N \times L)$ time where $L$ is string length. In Pandas 2.0+ with PyArrow strings (`dtype='string[pyarrow]'`), performance is 5–10x faster than Python object arrays.
- **Common Interview Gotcha**: Using `.map()` without handling unmapped values. Unmapped keys in `.map(dict)` evaluate to `NaN`! If you want to keep unmapped values unchanged, use `.replace(dict)` instead of `.map(dict)`.

#### Topic 5: Cleaning Categorical Data

- **Concept**: Categorical columns (`pd.Categorical` or `dtype='category'`) maintain a fixed set of allowed categories. Cleaning involves removing obsolete categories, merging infrequent levels, re-coding misspelled categories, and handling invalid entries.
- **Why it matters**: Encoding categorical features with high cardinality or unused categories inflates one-hot encoded matrix dimensions and wastes RAM.
- **Technical / Algorithmic Intuition**: Categorical columns store data as small integer codes pointing to an array of categories (`s.cat.categories`). Modifying categories updates the small category lookup table without copying the full data buffer.
- **Syntax / Pandas API**:
  - `s.cat.categories` (view current allowed categories)
  - `s = s.cat.rename_categories(dict_mapping)` (rename existing categories)
  - `s = s.cat.remove_unused_categories()` (drop categories that have 0 occurrences)
  - `s = s.cat.add_categories(['NewCat'])` (register new allowed level)
  - Collapsing rare categories: `s = s.replace(rare_categories, 'Other')`
- **Minimal Working Example**:
  ```python
  import pandas as pd

  # Categorical column with typo and obsolete category
  s = pd.Series(['Bronze', 'Silver', 'Gold', 'Silvr'], dtype='category')

  # 1. Rename typo 'Silvr' -> 'Silver'
  s = s.cat.rename_categories({'Silvr': 'Silver'})

  # 2. Filter out 'Bronze'
  s_filtered = s[s != 'Bronze']
  print("Before removing unused:", s_filtered.cat.categories.tolist())

  # 3. Prune unused categories
  s_clean = s_filtered.cat.remove_unused_categories()
  print("After removing unused :", s_clean.cat.categories.tolist())
  ```
- **Output**:
  ```text
  Before removing unused: ['Bronze', 'Silver', 'Gold']
  After removing unused : ['Silver', 'Gold']
  ```
  - *Line-by-line explanation*: `.cat.rename_categories()` merges `'Silvr'` into `'Silver'`. Filtering out `'Bronze'` leaves it with 0 occurrences in the data, but it still lingers in metadata until `.cat.remove_unused_categories()` explicitly drops it.
- **Complexity & Performance**: $O(K)$ where $K$ is the number of unique categories ($K \ll N$), making categorical operations extremely fast and memory-efficient.
- **Common Interview Gotcha**: Forgetting that `.cat.remove_unused_categories()` returns a new Series; it does not mutate in-place.

#### A. Basic Questions (20 Questions)

##### Q1: What is the fundamental difference between missing data and invalid data in Pandas?
- **Direct Answer**: Missing data represents the absence of a value (`NaN`, `None`, `pd.NA`), whereas invalid data represents a value that is physically present in the cell but violates business logic, domain boundaries, or expected formats (e.g., `age = -5` or `zip_code = "9999999"`).
- **Detailed Explanation**: Missing data can be detected with `df.isna()`. Invalid data cannot be detected with `isna()` because it contains validly typed objects or numbers. Invalid data requires domain validation rules, range comparisons, or regex validation.
- **Python Code**:
  ```python
  import pandas as pd
  import numpy as np

  df = pd.DataFrame({'age': [25, np.nan, -5, 150]})
  print("Missing data (isna):\n", df[df['age'].isna()])
  print("\nInvalid data (domain check):\n", df[~df['age'].between(0, 120) & df['age'].notna()])
  ```
- **Follow-up Twist**: How should invalid data be treated during pre-modeling? It should usually be mapped to `np.nan` so standard imputation strategies can be applied.

##### Q2: Does `df.isna()` detect infinite values (`np.inf`)?
- **Direct Answer**: No, `df.isna()` evaluates `np.inf` and `-np.inf` as `False` (valid present values).
- **Detailed Explanation**: In IEEE 754 floating-point standards, infinity is a valid floating-point representation, not a missing value. To detect infinity, you must use `np.isinf()`.
- **Python Code**:
  ```python
  import pandas as pd
  import numpy as np

  s = pd.Series([1.0, np.nan, np.inf, -np.inf])
  print("isna():\n", s.isna().tolist())
  print("np.isinf():\n", np.isinf(s).tolist())
  ```
- **Output**:
  ```text
  isna():
   [False, True, False, False]
  np.isinf():
   [False, False, True, True]
  ```
- **Follow-up Twist**: How do you convert infinite values to `NaN`? `df.replace([np.inf, -np.inf], np.nan)`.

##### Q3: How do you replace exact values across an entire DataFrame using `df.replace()`?
- **Direct Answer**: `df.replace(to_replace, value)` or by passing a dictionary `df.replace({val_to_find: new_val})`.
- **Detailed Explanation**: `df.replace()` scans across all columns (or specified subsets), replacing exact matches without altering unmapped cells.
- **Python Code**:
  ```python
  import pandas as pd
  import numpy as np

  df = pd.DataFrame({'A': [-999, 10, 20], 'B': ['?', 'Yes', 'No']})
  df_clean = df.replace({-999: np.nan, '?': 'Missing'})
  print(df_clean)
  ```
- **Follow-up Twist**: Can you pass nested dictionaries to replace values in specific columns only? Yes: `df.replace({'A': {-999: np.nan}, 'B': {'?': 'Missing'}})`.

##### Q4: How do you clamp numerical values to stay within a valid range `[min_val, max_val]`?
- **Direct Answer**: Use `Series.clip(lower=min_val, upper=max_val)`.
- **Detailed Explanation**: `clip()` sets any value below `lower` to `min_val` and any value above `upper` to `max_val`, preserving values already inside the boundary.
- **Python Code**:
  ```python
  import pandas as pd

  s = pd.Series([-5, 10, 50, 120])
  s_clamped = s.clip(lower=0, upper=100)
  print(s_clamped.tolist())
  ```
- **Output**:
  ```text
  [0, 10, 50, 100]
  ```
- **Follow-up Twist**: How does `clip()` treat `NaN`s? `NaN` values are ignored and remain `NaN`.

##### Q5: How do you strip leading and trailing whitespace from string columns in Pandas?
- **Direct Answer**: Call `df['col'].str.strip()`.
- **Detailed Explanation**: The `.str.strip()` accessor applies Python's string `strip()` method element-wise across the column in compiled routines.
- **Python Code**:
  ```python
  import pandas as pd

  s = pd.Series(['  apple ', 'banana\t', ' cherry '])
  print(s.str.strip().tolist())
  ```
- **Follow-up Twist**: What about internal multiple spaces? Use `.str.replace(r'\s+', ' ', regex=True)`.

##### Q6: How do you standardize a column containing mixed case text to lowercase?
- **Direct Answer**: `df['col'] = df['col'].str.lower()`.
- **Detailed Explanation**: Vectorized `.str.lower()` converts all characters to lowercase, ensuring consistency across string labels.
- **Python Code**:
  ```python
  import pandas as pd

  s = pd.Series(['USA', 'Usa', 'usa'])
  print(s.str.lower().unique().tolist())  # ['usa']
  ```
- **Follow-up Twist**: How does `.str.lower()` handle missing values (`NaN`)? It leaves `NaN` untouched without raising an error.

##### Q7: What is the difference between `df['col'].map(dict)` and `df['col'].replace(dict)`?
- **Direct Answer**: `map(dict)` replaces values matching dictionary keys and converts any **unmatched** keys to `NaN`. `replace(dict)` replaces matching keys but leaves **unmatched** values unchanged.
- **Detailed Explanation**: This is a critical distinction. If you only want to standardize 2 synonyms out of 100 valid categories, `replace()` is safe; `map()` would accidentally wipe out the other 98 valid categories!
- **Python Code**:
  ```python
  import pandas as pd

  s = pd.Series(['A', 'B', 'C'])
  mapping = {'A': 'Alpha'}

  print("replace:\n", s.replace(mapping).tolist())  # ['Alpha', 'B', 'C']
  print("map:\n", s.map(mapping).tolist())          # ['Alpha', nan, nan]
  ```
- **Follow-up Twist**: When would you intentionally prefer `map()` over `replace()`? When you want a strict whitelist where any value not explicitly mapped should become `NaN`.

##### Q8: How do you detect rows containing `np.inf` or `-np.inf` across a DataFrame?
- **Direct Answer**: `df[np.isinf(df).any(axis=1)]`.
- **Detailed Explanation**: `np.isinf(df)` generates a 2D boolean DataFrame where infinite cells are `True`. Chaining `.any(axis=1)` finds rows with at least one infinite value.
- **Python Code**:
  ```python
  import pandas as pd
  import numpy as np

  df = pd.DataFrame({'a': [1.0, np.inf, 3.0], 'b': [4.0, 5.0, 6.0]})
  print(df[np.isinf(df).any(axis=1)])
  ```
- **Follow-up Twist**: How do you count total infinite cells in `df`? `int(np.isinf(df).to_numpy().sum())`.

##### Q9: How do you drop unused categories from a `pd.Categorical` column?
- **Direct Answer**: `df['cat_col'] = df['cat_col'].cat.remove_unused_categories()`.
- **Detailed Explanation**: When rows are filtered out, categories with zero remaining observations persist in `cat.categories`. Calling `.cat.remove_unused_categories()` cleans the categorical index metadata.
- **Python Code**:
  ```python
  import pandas as pd

  s = pd.Series(['A', 'B', 'C'], dtype='category')
  s_filtered = s[s != 'C']
  print("Before:", s_filtered.cat.categories.tolist())  # ['A', 'B', 'C']
  s_clean = s_filtered.cat.remove_unused_categories()
  print("After :", s_clean.cat.categories.tolist())     # ['A', 'B']
  ```
- **Follow-up Twist**: Why is this important before running Scikit-Learn `OneHotEncoder`? To prevent generating dummy columns that have zero variance (all zeros).

##### Q10: How do you conditionally replace negative numbers in column `'balance'` with `0`?
- **Direct Answer**: `df.loc[df['balance'] < 0, 'balance'] = 0`.
- **Detailed Explanation**: 2D `.loc` indexing isolates rows where `'balance' < 0` and mutates the `'balance'` column directly in-place.
- **Python Code**:
  ```python
  import pandas as pd

  df = pd.DataFrame({'balance': [100, -50, 200, -10]})
  df.loc[df['balance'] < 0, 'balance'] = 0
  print(df['balance'].tolist())
  ```
- **Follow-up Twist**: How do you achieve the same result using `np.where`? `df['balance'] = np.where(df['balance'] < 0, 0, df['balance'])`.

##### Q11: How do you replace regex patterns in string columns using `replace()`?
- **Direct Answer**: Pass `regex=True` to `df.replace()` or use `s.str.replace(pattern, repl, regex=True)`.
- **Detailed Explanation**: By default in modern Pandas, `s.str.replace()` treats patterns as regular expressions (`regex=True`). On DataFrames, `df.replace(to_replace, value, regex=True)` compiles regex searches across all cells.
- **Python Code**:
  ```python
  import pandas as pd

  s = pd.Series(['$100.50', '$25.00', 'Free'])
  s_clean = s.str.replace(r'[\$,]', '', regex=True)
  print(s_clean.tolist())  # ['100.50', '25.00', 'Free']
  ```
- **Follow-up Twist**: What warning occurs in Pandas 2.0+ if you don't explicitly specify `regex=True` or `regex=False` in `Series.str.replace()`? A `FutureWarning` reminding you that the default will remain `regex=True`.

##### Q12: How do you identify non-numeric values in a column that was supposed to be numeric?
- **Direct Answer**: Use `pd.to_numeric(s, errors='coerce')` and inspect which values became `NaN`.
- **Detailed Explanation**: `errors='coerce'` converts unparseable strings (e.g., `'N/A'`, `'invalid'`, `'?'`) to `np.nan`. Comparing with the original non-null values isolates corrupt non-numeric cells.
- **Python Code**:
  ```python
  import pandas as pd

  s = pd.Series(['100', '200', 'corrupt_data', '400'])
  numeric_s = pd.to_numeric(s, errors='coerce')
  invalid_mask = numeric_s.isna() & s.notna()
  print("Corrupt entries:\n", s[invalid_mask])
  ```
- **Follow-up Twist**: What does `errors='ignore'` do in `pd.to_numeric()`? In Pandas 2.0+, `errors='ignore'` is deprecated; previously it returned the Series completely unmodified if any parsing error occurred.

##### Q13: How do you rename categories in a categorical column?
- **Direct Answer**: `s = s.cat.rename_categories(dict_mapping)`.
- **Detailed Explanation**: Maps existing category names to new names. If multiple old categories are mapped to the same new name, Pandas merges them into a single unified category.
- **Python Code**:
  ```python
  import pandas as pd

  s = pd.Series(['m', 'f', 'male', 'female'], dtype='category')
  s = s.cat.rename_categories({'m': 'Male', 'male': 'Male', 'f': 'Female', 'female': 'Female'})
  print(s.tolist())
  print("Categories:", s.cat.categories.tolist())
  ```
- **Follow-up Twist**: What happens if you try to assign a value that is not in `s.cat.categories`? Pandas raises a `TypeError`.

##### Q14: How do you replace all occurrences of `-999` and `-9999` with `NaN` across an entire DataFrame?
- **Direct Answer**: `df = df.replace([-999, -9999], np.nan)`.

##### Q15: How do you detect duplicate category definitions caused by whitespace differences?
- **Direct Answer**: Strip whitespace from the categories index: `s.str.strip().unique()`.
- **Detailed Explanation**: If a categorical column contains `'Active'` and `'Active '`, they are treated as two distinct categories. Stripping whitespace standardizes them.

  ```python
  import pandas as pd
  ```

##### Q16: How do you detect rows where a percentage column has values outside `[0.0, 1.0]`?
- **Direct Answer**: `df[~df['pct_col'].between(0.0, 1.0)]`.
- **Detailed Explanation**: `Series.between(0.0, 1.0, inclusive='both')` generates a boolean mask for valid percentages. Inverting with `~` isolates invalid rows.
- **Python Code**:
  ```python
  import pandas as pd

  df = pd.DataFrame({'rate': [0.15, 1.05, -0.02, 0.88]})
  invalid_rates = df[~df['rate'].between(0.0, 1.0)]
  print(invalid_rates)
  ```
- **Follow-up Twist**: What if the column was recorded on a 0–100 scale? Check `.between(0.0, 100.0)`.

##### Q17: What is the risk of using `df.dropna()` before handling infinite values?

##### Q67: High-Frequency Ratio Calculation Sanitizer
- **Context**: In an algorithmic trading quantitative feature pipeline, hundreds of financial ratios (e.g., Price-to-Earnings, Debt-to-Equity, Turnover) are calculated dynamically. Zero denominators produce `np.inf`, zero-over-zero produces `np.nan`, and extreme outliers corrupt z-score normalizations. Clean the entire feature matrix by converting infinities to `NaN`, imputing with median, and capping at 3 standard deviations.
- **Pandas Solution Snippet**:
  ```python
  import pandas as pd
  import numpy as np

  def sanitize_quant_features(feature_df: pd.DataFrame) -> pd.DataFrame:
      df_clean = feature_df.copy()

      # 1. Replace infinities with NaN
      df_clean = df_clean.replace([np.inf, -np.inf], np.nan)

      # 2. Impute with median
      medians = df_clean.median()
      df_clean = df_clean.fillna(medians)

      # 3. Winsorize / clamp at 3 standard deviations
      for col in df_clean.columns:
          mean = df_clean[col].mean()
          std = df_clean[col].std()
          if std > 0:
              lower = mean - 3 * std
              upper = mean + 3 * std
              df_clean[col] = df_clean[col].clip(lower=lower, upper=upper)

      return df_clean
  ```
- **Explanation**: Systematically eliminates `inf` and `nan` before applying statistical 3-sigma clamping to protect downstream deep learning and linear models.

## 4. Top Questions to Definitely Prepare

### Must Know (Top 5)
1. **How do you detect, isolate, and count numerical values that fall outside physically possible domain bounds (e.g., negative ages, heart rates > 300)?**
   - *Key Points*: Use inverted boolean masking `~df['age'].between(0, 120)` or `df[(df['age'] < 0) | (df['age'] > 120)]`. Avoid row-by-row iteration or Python `eval()`. To count violations per column across a DataFrame, combine boolean conditions with `.sum(axis=0)`.
2. **What is the critical behavioral and functional difference between `df.replace()` and `s.map()` when standardizing dirty categories?**
   - *Key Points*: `df.replace(dict)` replaces only the keys present in the dictionary and leaves unmapped values untouched (pass-through). Conversely, `s.map(dict)` maps matching keys and turns **all unmatched elements into `NaN`**, which will unintentionally destroy valid unmapped data unless chained with `.fillna(s)`.
3. **How does Pandas represent infinite numbers resulting from division by zero, and how do you sanitize them for machine learning estimators?**
   - *Key Points*: Division by float zero generates `np.inf` or `-np.inf` (IEEE 754 float64). Standard Pandas functions like `df.isna()` return `False` for infinite values. To prepare features for Scikit-Learn (which raises `ValueError: Input contains infinity or a value too large for dtype('float64')`), explicitly run `df.replace([np.inf, -np.inf], np.nan)` followed by an appropriate imputation strategy (`.fillna()` or `SimpleImputer`).
4. **How do you perform vectorised string standardization on messy text columns with inconsistent case and extra whitespace?**
   - *Key Points*: Chain Pandas vectorized string accessors: `s.astype(str).str.strip().str.lower()`. Note that `.str.strip()` only strips leading and trailing whitespace; internal multiple spaces require regex substitution via `s.str.replace(r'\s+', ' ', regex=True)`.
5. **Why does filtering rows in a categorical column leave unused categories in the Series, and how do you eliminate them?**
   - *Key Points*: Categorical data types decouple the category code array from the category index. Dropping rows changes the data codes but does not modify `s.cat.categories`. To remove phantom categories that cause empty bins in `value_counts()` or bar plots, call `s.cat.remove_unused_categories()`.

### Good to Know (Top 5)
6. **When using `df.replace()` with regular expressions, why is `regex=True` mandatory, and how does full-string vs substring matching work?**
   - *Key Points*: By default, `df.replace({'pattern': 'repl'})` checks for exact full-string equality. Setting `regex=True` enables substring pattern compilation. To match entire strings in regex mode, use anchors `^` and `$`.
7. **How does `s.clip(lower=min_val, upper=max_val)` differ from boolean replacement `.loc[mask, col] = val`?**
   - *Key Points*: `s.clip(lower, upper)` squashes extreme outliers onto the threshold boundary values without creating `NaN`s, preserving sample size and monotonic order. Boolean replacement allows replacing invalid values with `np.nan` or a domain sentinel, which treats them as missing rather than extreme valid values.
8. **What happens if you try to assign a new string value to an existing `category` column without calling `.cat.add_categories()` first?**

9. **How do you collapse low-frequency long-tail categories into a single `'Other'` category efficiently without iterating?**
   - *Key Points*: Compute frequent categories using `freq = s.value_counts(normalize=True); top_cats = freq[freq >= threshold].index`. Then apply `s.where(s.isin(top_cats), other='Other')` or map via dictionary.
10. **Why was `pd.set_option('mode.use_inf_as_na', True)` deprecated and removed in modern Pandas 2.1+, and what is the modern standard?**
    - *Key Points*: The global option introduced side-effects across independent modules and violated NumPy/IEEE 754 semantic separation between missingness (NaN) and unbounded arithmetic (inf). The modern standard requires explicit, localized conversion using `df.replace([np.inf, -np.inf], np.nan)`.

### Bonus / Edge Cases (Top 3)
11. **How does `df.replace()` handle dictionary keys when replacing across multiple columns simultaneously?**
    - *Key Points*: Nested dictionaries `{col: {old_val: new_val}}` scope replacements strictly to specified columns, whereas flat dictionaries `{old_val: new_val}` apply uniformly across all columns, which may inadvertently corrupt IDs or columns where the value is valid.

## 5. Common Beginner Mistakes

### Mistake 1: Confusing `df.replace()` with `s.map()` for Categorical Cleaning
- **Wrong Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({'status': ['Active', 'Pending', 'Suspended', 'Unknown']})
  df['status'] = df['status'].map({'Active': 'A', 'Pending': 'P'})
  # Output: ['A', 'P', NaN, NaN] -> 'Suspended' and 'Unknown' turned into NaN!
  ```
- **Correct Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({'status': ['Active', 'Pending', 'Suspended', 'Unknown']})
  df['status'] = df['status'].replace({'Active': 'A', 'Pending': 'P'})
  # Output: ['A', 'P', 'Suspended', 'Unknown']
  ```

- **What Happens Silently**: Production data loses all unmapped categories without warning, turning valid records into missing values.
- **How to Fix**: Use `df['col'].replace(mapping_dict)` when modifying a subset of values, or use `df['col'].map(mapping_dict).fillna(df['col'])` if `map()` is required for performance.

## 6. Section-Adaptive Pandas API Confusions

### Confusion 1: `df.replace()` vs `s.map()`
| Feature | `df.replace(dict)` | `s.map(dict)` |
| :--- | :--- | :--- |
| **Scope** | Works on both Series and full DataFrame | Works strictly on a single Series |
| **Unmapped Values** | Preserves unmapped values unchanged (pass-through) | Replaces unmapped values with `NaN` |
| **Regex Support** | Yes, full native regex support (`regex=True`) | No regex support; direct exact hash lookup |
| **Primary Use Case** | Modifying specific target errors/sentinels without altering others | Complete re-coding or dictionary lookup where full coverage is expected |
| **Performance** | Moderately fast; checks regex/equality rules | Extremely fast C-hash table lookup |

```python
import pandas as pd
s = pd.Series(['apple', 'banana', 'cherry'])
# replace preserves unmapped 'cherry'
print(s.replace({'apple': 'fruit_a'}))
# Output: ['fruit_a', 'banana', 'cherry']

# map turns unmapped 'banana' and 'cherry' to NaN
print(s.map({'apple': 'fruit_a'}))
# Output: ['fruit_a', NaN, NaN]
```

---

### Confusion 2: `pd.isna()` vs `np.isinf()`
| Feature | `pd.isna(val)` / `df.isna()` | `np.isinf(val)` |
| :--- | :--- | :--- |
| **Target Values** | `np.nan`, `None`, `pd.NA`, `pd.NaT` | `np.inf`, `-np.inf`, `float('inf')` |
| **Behavior on `inf`** | Evaluates to `False` | Evaluates to `True` |
| **Behavior on `nan`** | Evaluates to `True` | Evaluates to `False` |
| **Return Type** | Boolean Series / DataFrame / scalar | Boolean NumPy array / scalar |
| **ML Implication** | Detected by imputer pipelines | Crashes standard scikit-learn models if unhandled |

```python
import numpy as np
import pandas as pd
val = np.inf
print(pd.isna(val))   # False
print(np.isinf(val))  # True
```

---

### Confusion 3: `s.str.strip()` vs `s.str.replace()`
| Feature | `s.str.strip()` | `s.str.replace()` |
| :--- | :--- | :--- |
| **Target Location** | Leading and trailing boundaries of the string | Anywhere throughout the entire string |
| **Pattern Support** | Accepts characters to trim from ends | Accepts regex patterns and fixed substring replacements |
| **Internal Spaces** | Cannot remove or modify internal whitespace | Modifies internal whitespace via `r'\s+'` |
| **Speed** | Extremely fast C-level pointer trimming | Pattern matching / regex engine overhead |

```python
import pandas as pd
s = pd.Series(['  Data   Science  '])
print(s.str.strip())                            # 'Data   Science' (internal multi-spaces preserved)
print(s.str.replace(r'\s+', ' ', regex=True))   # ' Data Science ' (boundary spaces collapsed but preserved)
print(s.str.strip().str.replace(r'\s+', ' ', regex=True)) # 'Data Science' (perfectly cleaned)
```

---

### Confusion 4: `s.clip()` vs Boolean Masking (`s.loc[mask] = val`)
| Feature | `s.clip(lower, upper)` | Boolean Masking (`s.loc[mask] = val`) |
| :--- | :--- | :--- |
| **Mechanism** | Squashes out-of-bounds values to the boundary threshold | Replaces out-of-bounds values with an arbitrary specified value (e.g., `NaN`) |
| **Sample Size** | Retains all original records without generating nulls | Can convert records to `NaN`, requiring subsequent imputation or dropping |
| **Monotonicity** | Preserves relative ordering at the tails | Can disrupt ordering depending on assigned sentinel |
| **Application** | Winsorization, sensor saturation bounding | Scrubbing physically impossible data points for imputation |

```python
import pandas as pd
s = pd.Series([10, 85, 120, -5, 50])
# Clip bounds values into [0, 100]
print(s.clip(lower=0, upper=100))
# Output: [10, 85, 100, 0, 50]

# Masking marks invalid data as NaN
s_clean = s.copy()
s_clean.loc[(s_clean < 0) | (s_clean > 100)] = np.nan
# Output: [10.0, 85.0, NaN, NaN, 50.0]
```

---

### Confusion 5: `s.cat.remove_unused_categories()` vs `s.dropna()`
| Feature | `s.cat.remove_unused_categories()` | `s.dropna()` |
| :--- | :--- | :--- |
| **Operation Target** | Metadata categories index (`s.cat.categories`) | Underlying row records / data buffer |
| **Row Count** | Row count remains 100% unchanged | Drops rows containing missing values |
| **Effect on NaN** | Leaves existing `NaN` records untouched | Discards `NaN` rows |
| **Purpose** | Clean unused labels after row filtering | Discard incomplete sample observations |

```python
import pandas as pd
s = pd.Series(['A', 'B', 'C', 'A'], dtype='category')
s_subset = s[s != 'C']
print(s_subset.cat.categories) # Index(['A', 'B', 'C']) -> 'C' is still present!
s_clean = s_subset.cat.remove_unused_categories()
print(s_clean.cat.categories)   # Index(['A', 'B']) -> 'C' eliminated
```

---

### Confusion 6: `df.replace(r'pattern', ...)` with `regex=True` vs `regex=False`
| Feature | `regex=False` (Default) | `regex=True` |
| :--- | :--- | :--- |
| **Match Rule** | Exact full-cell string equality match | Substring regular expression pattern search |
| **Pattern Syntax** | Treated as raw literal characters | Interpreted by Python's `re` engine |
| **Anchoring** | Automatically acts as if anchored `^pattern$` | Requires explicit `^` and `$` for full cell matching |
| **Use Case** | Replacing exact words like `'Unknown'` or `'-999'` | Stripping currency symbols, units, or extracting tokens |

```python
import pandas as pd
s = pd.Series(['$100', '100$', '$50$'])
print(s.replace('$', '', regex=False)) # Unchanged because no cell equals '$' exactly!
print(s.replace(r'\$', '', regex=True))  # Strips all dollar signs: ['100', '100', '50']
```

## 7. Interview Traps

### Trap 1: The "Cleaned String Still Has Trailing Whitespace" Trap
- **Trap Question**: "I ran `df['country'] = df['country'].str.strip()` on my column, but when I filter `df[df['country'] == 'USA']`, it still misses rows that clearly look like `'USA'`. What happened?"
- **What Interviewer Wants to Hear**: The candidate understands that `.str.strip()` by default only strips standard ASCII whitespace (`\t`, `\n`, `\r`, space). In web-scraped or dirty legacy data, strings frequently contain non-breaking spaces (`\u00A0` or `&nbsp;`), zero-width spaces (`\u200B`), or invisible trailing control characters that standard `.str.strip()` ignores.
- **Trap Answer**: "Pandas has a bug, or you forgot to reassign `df['country'] = ...`, or there are internal spaces."
- **Correct Model Answer**:
  ```python
  # Standard strip misses non-breaking space \u00a0
  df['country'] = df['country'].astype(str).str.replace(r'[\s\u00A0\u200B]+', ' ', regex=True).str.strip()
  ```
  "Standard `str.strip()` only strips ASCII whitespace characters by default. If the data originates from HTML scraping or Excel exports, trailing characters may be Unicode non-breaking spaces (`\u00A0`) or zero-width spaces (`\u200B`). You must inspect the string repr using `repr(df['country'].iloc[idx])` and clean it using regex unicode matching `df['col'].str.replace(r'[\s\u00A0]+', ' ', regex=True).str.strip()`."

### Trap 2: The "Map Turned My Valid Data into NaN" Trap
- **Trap Question**: "We have a column with 10 status codes. We only want to map 2 legacy codes (`'ACT'` -> `'Active'`, `'PND'` -> `'Pending'`). A junior engineer used `df['status'] = df['status'].map({'ACT': 'Active', 'PND': 'Pending'})`. What went wrong in production?"
- **What Interviewer Wants to Hear**: Recognition that `Series.map()` replaces every key that is not in the dictionary with `np.nan`. All other 8 valid status codes were irreversibly converted to missing values.
- **Trap Answer**: "Nothing is wrong, that is how dictionary mapping works in Pandas."
- **Correct Model Answer**:
  "`Series.map()` performs total key replacement; any existing value not present as a key in the mapping dictionary is silently replaced with `NaN`. For partial recoding, the engineer should use `df['status'] = df['status'].replace({'ACT': 'Active', 'PND': 'Pending'})`, which leaves all unmapped categories unchanged. Alternatively, chain `.map().fillna(df['status'])`."

### Trap 3: The "Division by Zero is Missing" Trap
- **Trap Question**: "Does `df.dropna()` remove rows where a column has an infinite value resulting from division by zero?"
- **What Interviewer Wants to Hear**: Firm grasp of IEEE 754 float specifications. `np.inf` is not `np.nan`. `dropna()` strictly checks for `NaN`/`None`/`pd.NA` and will completely ignore `inf`.
- **Trap Answer**: "Yes, `dropna()` drops all invalid and missing mathematical values including infinity."
- **Correct Model Answer**:
  "No, `dropna()` will not remove infinite rows. In Python/NumPy, `np.inf` and `-np.inf` evaluate to `False` under `.isna()`. Therefore, `dropna()` considers them valid floating-point numbers. To drop them, you must first convert infinities to `NaN` using `df.replace([np.inf, -np.inf], np.nan).dropna()`."

### Trap 4: The "Categorical Code Shift" Trap
- **Trap Question**: "If I have a categorical column with categories `['low', 'medium', 'high']` and I rename categories using a list: `s.cat.categories = ['high', 'medium', 'low']`, what happens to the underlying data?"

Direct assignment to `s.cat.categories = [...]` overwrites category labels in-place by ordinal position without re-mapping the integer codes. A row that was `'low'` (code 0) is now silently relabeled as `'high'`!
- **Trap Answer**: "Pandas reorders the data so that low becomes high and high becomes low."

### Trap 5: The "Clip vs Drop for Outliers" Trap
- **Trap Question**: "In data cleaning, when should you use `s.clip()` instead of filtering out or replacing invalid values with `NaN`?"
- **What Interviewer Wants to Hear**: Clear architectural understanding of the difference between physical measurement errors (invalid data) and genuine extreme tail events (valid outliers).
- **Trap Answer**: "`clip()` is always better because you don't lose any data rows."
- **Correct Model Answer**:
  "`clip()` is appropriate for bounding valid extreme values (Winsorization) or enforcing sensor saturation boundaries where a value beyond a threshold represents a valid measurement at or above that threshold. Conversely, if a value is **physically impossible or invalid** (e.g., negative patient age or 400°C room temperature), clipping it to 0 or 100 corrupts your distribution by concentrating corrupted records at the boundary. Invalid values must be marked as `np.nan` and either dropped or imputed using domain rules."

### Trap 6: The "Regex Metacharacter Literal Replacement" Trap
- **Trap Question**: "I want to remove literal question marks `?` and dollar signs `$` from my dataset using `df.replace(['?', '$'], '', regex=True)`. Why does this destroy my data?"
- **What Interviewer Wants to Hear**: In regular expressions, `?` means '0 or 1 occurrence of previous character' and `$` matches the end of a line. Passing unescaped `?` and `$` to regex mode triggers catastrophic pattern matching or syntax errors (`re.error: nothing to repeat at position 0`).
- **Trap Answer**: "You can't pass lists to `replace()`."
- **Correct Model Answer**:
  "Because `?` and `$` are reserved regex metacharacters. When `regex=True`, passing raw `'?'` causes an invalid regex compilation error, and raw `'$'` matches line endings, replacing nothing or creating corrupted string structures. You must escape metacharacters with `re.escape()` or write `df.replace([r'\?', r'\$'], '', regex=True)`."

### Trap 7: The "Chained Assignment on Invalid Value Replacement" Trap
- **Trap Question**: "Why does `df[df['age'] < 0]['age'] = 0` fail to clean invalid ages in a production DataFrame?"
- **What Interviewer Wants to Hear**: Deep knowledge of `SettingWithCopyWarning`. Chained indexing `df[mask]['col']` creates an intermediate slice copy. Modifying that copy modifies temporary memory that is immediately garbage collected, leaving `df` uncleaned.
- **Trap Answer**: "Because `age` is an immutable column."
- **Correct Model Answer**:
  "`df[df['age'] < 0]['age'] = 0` performs chained indexing. The first bracket `df[df['age'] < 0]` returns an internal temporary view or copy. The second bracket attempts assignment on that temporary object. In Pandas, this either triggers a `SettingWithCopyWarning` or silently fails, leaving the original `df` completely untouched. You must use single-indexer label-based access: `df.loc[df['age'] < 0, 'age'] = 0`."

## 8. Real-World Pandas Engineering Questions

### Question 1: Robust Multi-Stage Telemetry Sensor Sanitization Pipeline
- **Engineering Scenario**: You are ingesting real-time IoT sensor telemetry streamed from 50,000 industrial gas turbine sensors. Data arrives every minute with frequent hardware anomalies:
  - Voltage spikes reporting `99999` or `-99999` (sensor disconnected).
  - Floating-point divisions producing `inf` and `-inf` when differential pressure drops to zero.
  - Temperature readings occasionally recorded as negative Kelvin or exceeding 2000°C.
  - Firmware versions recorded as dirty strings (`' v1.0.2 '`, `'V1.0.2'`, `'v1.0.2_rc'`).
  Design a high-throughput, memory-efficient data cleaning function that sanitizes this DataFrame.
- **Architecture & Implementation**:
  ```python
  import numpy as np
  import pandas as pd
  from typing import List, Dict

  def sanitize_iot_telemetry(df: pd.DataFrame) -> pd.DataFrame:
      """
      Production-grade sanitization pipeline for high-frequency IoT telemetry.
      Eliminates hardware sentinels, IEEE 754 infinities, physical domain violations,
      and standardizes firmware metadata.
      """
      clean = df.copy()

      # 1. Clean hardware sentinels & infinities in numeric telemetry
      sensor_cols = [c for c in clean.columns if c.startswith('sensor_') or c in ('voltage', 'temp_c', 'pressure')]
      
      # Replace known hardware sentinels and infinities with NaN in a single vectorised call
      sentinels = [99999, -99999, 9999.0, -9999.0]
      clean[sensor_cols] = clean[sensor_cols].replace(sentinels + [np.inf, -np.inf], np.nan)

      # 2. Enforce Physical Domain Constraints (Thermodynamic bounds)
      if 'temp_c' in clean.columns:

              clean['firmware_version']
              .astype(str)
              .str.strip()
              .str.lower()
              .str.replace(r'^v\.?', 'v', regex=True)
  ```

  - Dates: `'0000-00-00'`, `'9999-12-31'`, `'1900-01-01'`.

- **Architecture & Implementation**:
  ```python
  import pandas as pd
  import numpy as np
  from typing import Dict, Any

  def migrate_legacy_mainframe_data(
      df: pd.DataFrame, 
      schema_contracts: Dict[str, Dict[str, Any]]
  ) -> pd.DataFrame:
      """
      Enterprise migration scrubber. Transforms multi-era mainframe sentinel values
      into clean ANSI/Snowflake compatible dtypes.
      """
      migrated = df.copy()

      for col, contract in schema_contracts.items():
          if col not in migrated.columns:
              continue

          target_type = contract['target_type']
          custom_nulls = contract.get('null_sentinels', [])

          # Step 1: Universal Sentinel Scrubbing
          if custom_nulls:
              migrated[col] = migrated[col].replace(custom_nulls, np.nan)

          # Step 2: Type-specific sanitization
          if target_type == 'numeric':
              migrated[col] = pd.to_numeric(migrated[col], errors='coerce')
              if 'min_val' in contract and 'max_val' in contract:
                  invalid_mask = ~migrated[col].between(contract['min_val'], contract['max_val'])
                  migrated.loc[invalid_mask, col] = np.nan

          elif target_type == 'datetime':
              migrated[col] = pd.to_datetime(migrated[col], errors='coerce')

          elif target_type == 'boolean':
              bool_map = {
                  'Y': True, 'y': True, '1': True, True: True, 'T': True, 'true': True,
                  'N': False, 'n': False, '0': False, False: False, 'F': False, 'false': False
              }
              migrated[col] = migrated[col].map(bool_map)
              # Leave unmapped values as np.nan (boolean nullable)
              migrated[col] = migrated[col].astype('boolean')

          elif target_type == 'categorical':
              migrated[col] = migrated[col].astype(str).str.strip().str.title()
              migrated[col] = migrated[col].replace({'Nan': np.nan, 'None': np.nan})
              migrated[col] = migrated[col].astype('category')

      return migrated
  ```

### Question 3: What is the difference between `df.replace()` and `s.map()`?
- **Weak Fresher Answer**: "They both replace values using a dictionary."
- **Why It's Weak**: Completely misses the critical difference regarding unmapped values, which is the #1 cause of silent data loss bugs in junior data cleaning scripts.
- **Senior / Winning Answer**:
  "While both accept dictionaries, their handling of unmapped keys is fundamentally different:
  1. `df.replace(dict)` replaces only matching keys and performs pass-through on all unmapped values, leaving them untouched. It also works across both Series and full DataFrames and supports regular expressions.

  ```python
  cond_adult_valid = (df['group'] == 'adult') & df['heart_rate'].between(40, 180)
  cond_infant_valid = (df['group'] == 'infant') & df['heart_rate'].between(80, 220)

  # Invalidate rows not meeting their group condition
  is_valid = cond_adult_valid | cond_infant_valid
  df.loc[~is_valid, 'heart_rate'] = np.nan

  assert pd.isna(df.loc[0, 'heart_rate'])  # Adult 35 -> NaN
  assert df.loc[1, 'heart_rate'] == 75.0   # Adult 75 -> Valid
  assert pd.isna(df.loc[2, 'heart_rate'])  # Infant 75 -> NaN
  assert df.loc[3, 'heart_rate'] == 120.0  # Infant 120 -> Valid
  ```

### Perturbation 4: Substring Regex Replacement vs Exact Full Cell Match
- **Base Question**: "How do you replace `'NA'` with `np.nan`?"

  ```python
  assert s_clean.iloc[1] == 'NAMIBIA'
  assert s_clean.iloc[2] == 'CHINA'
  assert pd.isna(s_clean.iloc[3])
  ```

### Scenario 5: Financial Fraud Transaction Amount Outlier Clipping
- **Scenario**: In credit card fraud detection, transaction amounts exhibit extreme power-law distributions ($0.01 to $5,000,000). While genuine fraud can be large, extreme outliers destabilize neural network gradient descent.
- **Cleaning Strategy**:
  1. Detect negative transaction amounts and set to `np.nan` (invalid).
  2. Apply 99.9th percentile upper bound clipping (Winsorization) to limit gradient explosion without dropping genuine fraud records.
- **Code Implementation**:
  ```python
  import numpy as np
  import pandas as pd

  def winsorize_transactions(df: pd.DataFrame, col: str = 'amount') -> pd.DataFrame:
      clean = df.copy()
      # Scrub impossible negative transactions
      clean.loc[clean[col] < 0, col] = np.nan
      # Winsorize at 99.9th percentile
      upper_limit = clean[col].quantile(0.999)
      clean[col] = clean[col].clip(lower=0.01, upper=upper_limit)
      return clean
  ```
- **Impact**: Stabilizes neural network training loss while preserving 100% of transaction row records for fraud evaluation.

## 18. Cross-Concept Bridges

### Bridge to NumPy
- **NumPy Representation of Infinities**:
  - NumPy provides `np.inf` and `-np.inf` (IEEE 754 floating-point constants).
  - Array functions: `np.isinf(arr)`, `np.isfinite(arr)`, `np.isnan(arr)`.
  - In NumPy: `np.isfinite(x) == (~np.isnan(x) & ~np.isinf(x))`.
- **Masking & Replacement**:
  - `np.where(condition, x, y)` is the underlying C-primitive powering `pd.Series.where()` and `pd.Series.mask()`.
  - Clipping: `np.clip(arr, a_min, a_max)` operates identically to `Series.clip()`.

---

### Bridge to SQL
- **Mapping Table**:
  | Pandas Operation | ANSI SQL Equivalent |
  | :--- | :--- |
  | `~df['age'].between(0, 120)` | `WHERE age NOT BETWEEN 0 AND 120` |
  | `df.replace({'Active': 'A', 'Pending': 'P'})` | `CASE WHEN status = 'Active' THEN 'A' WHEN status = 'Pending' THEN 'P' ELSE status END` |
  | `s.map({'Active': 'A', 'Pending': 'P'})` | `CASE WHEN status = 'Active' THEN 'A' WHEN status = 'Pending' THEN 'P' ELSE NULL END` |
  | `df.replace([np.inf, -np.inf], np.nan)` | `CASE WHEN status IN ('Infinity', '-Infinity') THEN NULL ELSE status END` |
  | `s.str.strip().str.lower()` | `LOWER(TRIM(col))` |
  | `s.clip(lower=0, upper=100)` | `LEAST(GREATEST(col, 0), 100)` |

---

### Bridge to Scikit-Learn
- **Crash Prevention**:
  - Scikit-Learn estimators (`LinearRegression`, `RandomForestClassifier`, `PCA`) execute `check_array(X, force_all_finite=True)`.
  - If `X` contains `np.inf`, Scikit-Learn immediately raises:
    `ValueError: Input contains infinity or a value too large for dtype('float64')`.
  - Converting infinities via `df.replace([np.inf, -np.inf], np.nan)` is a mandatory prerequisite before calling `SimpleImputer` or fitting estimators.
- **Categorical Encoders & Unused Levels**:
  - `OneHotEncoder(handle_unknown='ignore')` creates columns for every category level. Leaving unused categories in a categorical column creates phantom columns with zero variance, leading to singular covariance matrices in linear models.

---

### Bridge to Core Python
- **Strings**:
  - Python's `str.strip()` vs Pandas `.str.strip()`: Python operates on single strings; Pandas operates element-wise across millions of cells in C.
  - Python's `str.casefold()`: Used for aggressive Unicode case insensitivity; accessible in Pandas via `s.str.casefold()`.
- **Regular Expressions**:
  - Python's `re.sub(pattern, repl, string)` is the foundational engine behind `s.str.replace(pattern, repl, regex=True)`.
  - Metacharacters (`.`, `*`, `+`, `?`, `^`, `$`, `[`, `]`, `(`, `)`) must be escaped with `re.escape()` or `\` in both environments.

## 24. Final 2-Minute Revision Summary

1. **IEEE Infinities**: `pd.isna()` ignores `inf`. Always run `df.replace([np.inf, -np.inf], np.nan)` before passing features to Scikit-Learn.
2. **Replace vs Map**: `replace(dict)` keeps unmapped keys; `map(dict)` turns unmapped keys to `NaN`. Never use `map()` for partial updates.
3. **Outlier Bounding**: Use `s.clip(lower, upper)` for boundary squashing without data loss. Use `s.where(s.between(min, max), other=np.nan)` to invalidate corrupt values.
4. **String Sanitization**: Chain `.str.strip().str.replace(r'\s+', ' ', regex=True).str.lower()` for complete outer and internal whitespace cleanup.
5. **Regex Caution**: Escape metacharacters `r'[\$\?\*]'` or use `regex=False` for literal character matching.
6. **Categorical Integrity**: Adding an unregistered category throws `TypeError`. Register via `.cat.add_categories(['Label'])` first.
7. **Phantom Categories**: Slicing rows preserves categories in metadata. Run `s.cat.remove_unused_categories()` to avoid empty groups and dummy column explosion.
8. **Coercing Sentinels**: Use `pd.to_numeric(s, errors='coerce')` to parse mixed numeric columns with string errors into `float64`.
9. **Single Indexer Assignment**: Always use `df.loc[mask, 'col'] = val` to avoid silent failures and `SettingWithCopyWarning`.
10. **Type Discipline**: Never replace numbers with string flags like `'INVALID'`. It upcasts the column to `object`, destroying SIMD vectorization and increasing memory 4x–8x.
