### 1. Section Overview

- **What this section is about**: Section 6.1 covers the foundational mechanics of extracting subsets of tabular data using basic boolean predicates, label-based indexing, numerical boundaries, and vectorized string pattern evaluations. - **Why these Pandas concepts matter**: Filtering is the most frequent operation in data manipulation. Interviewers probe basic filtering to evaluate whether a candidate understands the difference between Python's scalar boolean evaluation (`if x:`) and Pandas' vectorized element-wise boolean arrays (`Series([True, False])`), whether they know how boolean indexing leverages NumPy memory buffers, and whether they can cleanly extract specific rows and columns without triggering intermediate memory copies or `SettingWithCopyWarning`.
- **Where they are used in real projects**: In exploratory data analysis (EDA), data cleaning pipelines, feature engineering, and reporting. Examples include segmenting transactional records by price thresholds, extracting customer records residing in specific cities using substring matching, isolating active sensor readings, and pruning invalid outlier records before model training.

  3. Filter rows using both standard square bracket indexing (`df[mask]`) and accessor-based indexing (`df.loc[mask]`).
  4. Perform simultaneous row filtering and column projection via `df.loc[row_mask, col_mask]` or `df.loc[row_mask, ['colA', 'colB']]`.
  5. Explain the underlying memory behavior of boolean selection, index alignment, and the differences between view and copy creation.

### 2. Topic-Wise Interview Concepts

#### Topic 1: Filtering Rows

- **Concept**: Row filtering in Pandas selects a subset of DataFrame observations matching a specified truth condition. When a boolean `Series` whose index matches the DataFrame's index is passed into `df[mask]` or `df.loc[mask]`, Pandas evaluates each row's index against the boolean array and retains only rows corresponding to `True`.
- **Why it matters**: Demonstrates fundamental data extraction skills. Interviewers verify if the candidate understands index alignment during filtering and knows why scalar Python `and`/`or` keywords cannot be used on Pandas Series objects.
- **Technical / Algorithmic Intuition**: A boolean mask is backed by a 1D NumPy array of `bool_` (or Apache Arrow boolean bitmask in modern Pandas). Under the hood, Pandas performs a fast C-level nonzero index lookup (`np.nonzero()` or `take`) to identify the integer offsets where the mask evaluates to `True`, extracting these rows into a new DataFrame structure.
- **Syntax / Pandas API**:
  - `df[boolean_series]`
  - `df.loc[boolean_series]`
  - `df.iloc[np.where(boolean_array)[0]]`
- **Minimal Working Example**:
  ```python
  import pandas as pd

  data = {
      'emp_id': [101, 102, 103, 104],
      'name': ['Alice', 'Bob', 'Charlie', 'Diana'],
      'salary': [75000, 48000, 92000, 61000]
  }
  df = pd.DataFrame(data)

  # Filter rows where salary > 60000
  mask = df['salary'] > 60000
  high_earners = df[mask]
  print(high_earners)
  ```
- **Expected Output / Interpretation**:
  ```text
     emp_id     name  salary
  0     101    Alice   75000
  2     103  Charlie   92000
  3     104    Diana   61000
  ```
  Rows 0, 2, and 3 are retained because their boolean evaluation is `True`. Note that the original index labels (`0`, `2`, `3`) are preserved intact.
- **Important Parameters & Options**:
  - `mask`: Must evaluate to a 1D boolean Series or array whose length or index strictly matches the DataFrame's row axis.
  - `.loc[row_indexer, col_indexer]`: Preferred in production over `df[mask]` because it allows simultaneous row filtering and column selection.
- **Common Interview Confusion**: Candidates often confuse `df[mask]` with `df.filter()`. `df[mask]` filters rows based on cell value conditions, whereas `df.filter()` filters rows or columns based on their label names (index or column names) using exact matching or regular expressions.

#### Topic 2: Filtering Columns

- **Concept**: Column filtering isolates a subset of DataFrame features based on data types, column names, or dynamically evaluated column-level boolean conditions. While selecting static columns is accomplished via `df[['colA', 'colB']]`, dynamic column filtering can be performed using boolean masks passed across the column axis in `df.loc[:, col_mask]`.
- **Why it matters**: Proves the candidate understands the 2D Cartesian indexing model of Pandas DataFrames (`df.loc[row_indexer, col_indexer]`). In production, datasets often contain hundreds of columns where only numeric columns or columns meeting variance criteria should be selected.
- **Technical / Algorithmic Intuition**: DataFrames store columns in internal block managers (or array managers in Pandas 2.0+). Filtering columns via a boolean array of length equal to `df.shape[1]` selects internal column pointers without deep-copying row data buffers when Copy-on-Write (CoW) is enabled.
- **Syntax / Pandas API**:
  - `df.loc[:, col_mask]`
  - `df[[col for col in df.columns if condition]]`
  - `df.select_dtypes(include=['number'])`
- **Minimal Working Example**:
  ```python
  import pandas as pd

  data = {
      'item_id': [1, 2, 3],
      'cost_usd': [12.50, 45.00, 8.20],
      'price_usd': [20.00, 65.00, 15.00],
      'vendor_code': ['V1', 'V2', 'V1']
  }
  df = pd.DataFrame(data)

  # Filter columns that contain the substring 'usd'
  col_mask = [col.endswith('_usd') for col in df.columns]
  usd_cols_df = df.loc[:, col_mask]
  print(usd_cols_df)
  ```
- **Expected Output / Interpretation**:
  ```text
     cost_usd  price_usd
  0      12.5       20.0
  1      45.0       65.0
  2       8.2       15.0
  ```
  Only the two numerical currency columns whose names satisfy `col.endswith('_usd')` are extracted across all rows.
- **Important Parameters & Options**:
  - `axis=1` or `, col_mask` inside `.loc`: Specifies column-level indexing.
  - Length of `col_mask`: Must strictly equal `df.shape[1]`.
- **Common Interview Confusion**: Passing a boolean list directly to `df[col_mask]` will attempt to filter **rows**, raising an `IndexError` or `ValueError` if the length of the list does not match the row count (`df.shape[0]`). Column-level boolean masking requires `.loc[:, col_mask]`.

#### Topic 3: Filtering Numerical Values

- **Concept**: Numerical filtering involves evaluating relational comparison operators (`<`, `<=`, `>`, `>=`, `==`, `!=`) against a numeric column or between two numeric columns. The operation broadcasts the comparison across every element in the column vector to produce a boolean Series.
- **Why it matters**: Numerical predicates form the core of data sanity checks, outlier isolation, and business rule segmentation. Interviewers look for proper handling of floating-point edge cases, `NaN` values in comparisons, and vectorization efficiency.
- **Technical / Algorithmic Intuition**: Vectorized comparisons run compiled C/SIMD instructions through NumPy's ufuncs (universal functions). When executing `df['salary'] > 50000`, Python does not loop over individual integers; instead, NumPy evaluates memory blocks contiguously. If missing values (`np.nan` or `pd.NA`) are present, standard IEEE 754 floating-point logic dictates that `NaN > x`, `NaN < x`, and `NaN == x` all evaluate to `False`.
- **Syntax / Pandas API**:
  - `df[df['col'] > threshold]`
  - `df[df['col_a'] <= df['col_b']]`
  - `df[df['col'].between(left, right)]`
- **Minimal Working Example**:
  ```python
  import pandas as pd
  import numpy as np

  data = {
      'sensor_id': ['S1', 'S2', 'S3', 'S4', 'S5'],
      'temperature': [22.4, np.nan, 38.9, 19.5, 42.1],
      'threshold': [30.0, 30.0, 30.0, 30.0, 30.0]
  }
  df = pd.DataFrame(data)

  # Numerical filter: temperatures exceeding the threshold column
  mask = df['temperature'] > df['threshold']
  alarm_df = df[mask]
  print(alarm_df)
  ```
- **Expected Output / Interpretation**:
  ```text
    sensor_id  temperature  threshold
  2        S3         38.9       30.0
  4        S5         42.1       30.0
  ```
  Only sensor records `S3` and `S5` are retained. Notice that sensor `S2` with `temperature = NaN` evaluated to `False` and was automatically excluded from the output.
- **Important Parameters & Options**:
  - Comparison operators return `bool` dtypes (`True`/`False`).
  - Column vs. Column comparisons require both columns to share an aligned index.
- **Common Interview Confusion**: Candidates often assume `NaN` values will raise an error during relational comparisons. In fact, `NaN` produces `False` silently for both `>` and `<=`, meaning neither condition includes the missing row.

#### Topic 4: Filtering String Values

- **Concept**: String filtering involves filtering DataFrame rows based on textual attributes using Pandas' vectorized `.str` accessor methods such as `.str.contains()`, `.str.startswith()`, `.str.endswith()`, and `.str.len()`.
- **Why it matters**: Real-world enterprise data is heavily populated with text attributes (customer names, email domains, error logs, SKU codes). Candidates must demonstrate mastery of vectorized string manipulation, case sensitivity control, regex toggles, and missing value propagation.
- **Technical / Algorithmic Intuition**: Standard Python string operations cannot be called directly on a Pandas Series object (`df['col'].startswith('A')` raises `AttributeError`). The `.str` accessor provides an interface that vectors string operations across all elements. When `na=False` is passed, missing values (`NaN` or `None`) are explicitly converted to `False` in the resulting boolean mask rather than propagating as `NaN`, preventing downstream indexing failures.
- **Syntax / Pandas API**:
  - `df['col'].str.contains(pat, case=True, regex=True, na=False)`
  - `df['col'].str.startswith(pat, na=False)`
  - `df['col'].str.endswith(pat, na=False)`
  - `df['col'].str.match(pat, na=False)`
- **Minimal Working Example**:
  ```python
  import pandas as pd

  data = {
      'user_id': [1001, 1002, 1003, 1004, 1005],
      'email': ['alice@corp.com', 'bob@gmail.com', None, 'charlie@CORP.COM', 'diana@corp.net']
  }
  df = pd.DataFrame(data)

  # Filter emails ending with 'corp.com', case-insensitive, handling missing values
  mask = df['email'].str.endswith('corp.com', na=False)
  filtered_df = df[mask]
  print(filtered_df)
  ```
- **Expected Output / Interpretation**:
  ```text
     user_id           email
  0     1001  alice@corp.com
  ```
  Notice that row 0 matches. Row 2 (`None`) is safely coerced to `False` due to `na=False`. Row 3 (`charlie@CORP.COM`) does not match because `.str.endswith()` is strictly case-sensitive.
- **Important Parameters & Options**:
  - `pat`: String or regex pattern to search for.
  - `case=False`: Toggles case-insensitive matching (available on `.str.contains()`).
  - `na=False`: Explicitly assigns `False` to `NaN`/`None` values. If omitted, `.str.contains()` returns a Series containing `NaN`, which causes `ValueError: Cannot mask with non-boolean array containing NA / NaN values` when passed to `df[...]`.
  - `regex=False`: Disables regex parsing to treat special characters (like `.`, `*`, `?`, `+`) as literal strings.
- **Common Interview Confusion**: Forgetting `na=False` is the single most common bug when filtering string columns containing missing data. Beginners write `df[df['email'].str.contains('corp')]` and encounter a runtime crash on production datasets containing `None`.

### 3. Fresher Interview Questions

#### A. Basic Questions (Exactly 20 Questions)

##### Q1: What is a boolean mask in Pandas?
- **Direct Answer & Definition**: A boolean mask in Pandas is a 1D Series or array of boolean values (`True` or `False`) that shares the same index or length as the target DataFrame.
- **Technical & Computational Reasoning**: When applied as an indexer, Pandas queries the underlying boolean memory buffer, locating all indices evaluating to `True` via C-level fast pointer lookups, and ignores entries evaluating to `False`.
- **Practical Application / Syntax**: A mask is created using vectorized comparisons, such as `mask = df['age'] >= 18`, and applied via `df[mask]` or `df.loc[mask]`.
- **Nuances, Defaults & Pitfalls**: If the mask contains `NaN` values rather than strict booleans, passing it into `df[mask]` raises a `ValueError: Cannot mask with non-boolean array containing NA / NaN values`.

##### Q2: What is the primary difference between `df[condition]` and `df.loc[condition]`?
- **Direct Answer & Definition**: `df[condition]` is a convenience shortcut for row filtering, whereas `df.loc[condition]` is the explicit, label-based indexing accessor capable of simultaneous row filtering and column projection.
- **Technical & Computational Reasoning**: `df[condition]` only accepts a single row indexer; attempting to select columns in the same call (like `df[condition, 'col']`) raises an exception. In contrast, `df.loc` implements the 2D Cartesian indexing protocol (`.loc[rows, cols]`), eliminating intermediate temporary object allocations.
- **Practical Application / Syntax**: In production code, prefer `df.loc[df['sales'] > 1000, ['customer_id', 'revenue']]` over chained indexing `df[df['sales'] > 1000][['customer_id', 'revenue']]`.
- **Nuances, Defaults & Pitfalls**: Chained indexing `df[condition]['col']` can trigger a `SettingWithCopyWarning` when assigning values, whereas `df.loc[condition, 'col'] = val` performs safe in-place assignment.

##### Q3: Why does `df[df['col'] = 5]` fail in Python?
- **Direct Answer & Definition**: It fails with a `SyntaxError: invalid syntax` because `=` is Python's variable assignment operator, whereas `==` is the equality comparison operator.
- **Technical & Computational Reasoning**: The Python grammar parser forbids assignment expressions inside function arguments or subscript slicing operations without the explicit walrus operator (`:=`). Relational testing requires `==`.
- **Practical Application / Syntax**: The correct syntax is `df[df['col'] == 5]`.
- **Nuances, Defaults & Pitfalls**: Even if validly written, remember that `==` on floating-point numbers can fail due to precision artifacts; for floating-point tolerance filtering, use `np.isclose()`.

##### Q4: What happens if you filter a DataFrame with a boolean Series that has a different index?
- **Direct Answer & Definition**: Pandas performs automatic index alignment before applying the filter.
- **Technical & Computational Reasoning**: Pandas aligns the index labels of the boolean Series with the DataFrame's index. Rows whose index labels exist in the mask and evaluate to `True` are kept; any DataFrame rows whose index labels are missing from the mask are treated as `NaN` (unmatched) and subsequently dropped.
- **Practical Application / Syntax**: If `df` has index `[0, 1, 2]` and `mask` has index `[1, 2, 3]`, filtering `df[mask]` aligns on labels `1` and `2`, ignoring label `3` and treating label `0` as `False`.
- **Nuances, Defaults & Pitfalls**: If the mask has identical length to the DataFrame but an unaligned custom index (e.g., reset index on mask vs non-reset on DataFrame), surprising empty or dropped outputs occur without error.

##### Q5: How do you filter rows where a numerical column is between two values inclusive?
- **Direct Answer & Definition**: You can filter numerical values within a closed interval using the `.between()` method or by combining relational operators.
- **Technical & Computational Reasoning**: The `.between(left, right, inclusive='both')` method compiles down to vectorized boundary comparisons `(x >= left) & (x <= right)`, returning a boolean Series without requiring manual parentheses or multiple Series allocations.
- **Practical Application / Syntax**: Use `df[df['price'].between(10, 50, inclusive='both')]`.
- **Nuances, Defaults & Pitfalls**: The `inclusive` parameter defaults to `'both'`, but can be set to `'neither'`, `'left'`, or `'right'`. Passing `inclusive=True` (boolean) is deprecated in modern Pandas in favor of string literals.

##### Q6: How do you filter a string column for exact matches?
- **Direct Answer & Definition**: Exact string matching is performed using the standard equality operator `==`.
- **Technical & Computational Reasoning**: The equality operator tests whether the string pointer or PyObject in each cell equals the target string literal, executing a vectorized C-level comparison across the column block.
- **Practical Application / Syntax**: Write `df[df['country'] == 'Canada']`.
- **Nuances, Defaults & Pitfalls**: Exact equality is strictly case-sensitive and sensitive to leading/trailing whitespace. If `'Canada '` has whitespace, `== 'Canada'` returns `False`. Use `.str.strip()` prior to matching if dirty strings exist.

##### Q7: How do you perform a case-insensitive substring search on a text column?
- **Direct Answer & Definition**: Use the `.str.contains()` accessor method with `case=False` and `na=False`.
- **Technical & Computational Reasoning**: `.str.contains()` compiles a regular expression search across each string element in the column. Specifying `case=False` applies the `re.IGNORECASE` flag internally.
- **Practical Application / Syntax**: `df[df['notes'].str.contains('urgent', case=False, na=False)]`.
- **Nuances, Defaults & Pitfalls**: If `na=False` is omitted and the column contains `np.nan` or `None`, `.str.contains()` outputs `NaN` for those rows, causing a runtime crash when used inside `df[...]`.

##### Q8: What does the `na=False` parameter do in `.str.contains()`?
- **Direct Answer & Definition**: It defines the fill value assigned to missing elements (`NaN`/`None`) in the resulting boolean Series.
- **Technical & Computational Reasoning**: When a string method evaluates a null cell, string operations cannot execute, producing `np.nan` by default. Setting `na=False` forces all missing values to boolean `False`.
- **Practical Application / Syntax**: `mask = df['description'].str.contains('error', na=False)`.
- **Nuances, Defaults & Pitfalls**: Setting `na=True` is useful when you want to retain rows with missing values alongside matching rows, but `na=False` is standard when you strictly want confirmed matches.

##### Q9: How do you select columns based on their data type?
- **Direct Answer & Definition**: Use the `.select_dtypes()` method to filter columns matching or excluding specific dtypes.
- **Technical & Computational Reasoning**: It inspects the `dtype` metadata attribute of each column block in the DataFrame schema and constructs a new DataFrame containing only blocks matching the specified types.
- **Practical Application / Syntax**: `df.select_dtypes(include=['number'])` or `df.select_dtypes(include=['object', 'string'])`.
- **Nuances, Defaults & Pitfalls**: Passing `'number'` selects both integers and floating-point columns. Passing `'object'` will include string columns unless they were explicitly cast to modern `string` or `category` dtypes.

##### Q10: How do you filter columns using a boolean list?
- **Direct Answer & Definition**: Pass the boolean list into `df.loc[:, boolean_list]`.
- **Technical & Computational Reasoning**: The `.loc` accessor takes a 2-tuple `(row_indexer, col_indexer)`. Placing a colon `:` in the first position retains all rows, while the boolean list in the second position filters column labels.
- **Practical Application / Syntax**: `df.loc[:, [True, False, True]]` selects the first and third columns of a 3-column DataFrame.
- **Nuances, Defaults & Pitfalls**: The length of the boolean list must exactly equal the number of columns (`df.shape[1]`), or an `IndexError: Length of logical indexers must match number of columns` is raised.

##### Q11: How do you filter rows where a numerical column is strictly not equal to a value?
- **Direct Answer & Definition**: Use the inequality operator `!=`.
- **Technical & Computational Reasoning**: The inequality operator evaluates element-wise whether the cell value is different from the scalar, returning a boolean Series of identical length.
- **Practical Application / Syntax**: `df[df['status_code'] != 200]`.
- **Nuances, Defaults & Pitfalls**: When applied to a column containing `np.nan`, `np.nan != 200` evaluates to `True` under IEEE 754 standards. If you wish to exclude `NaN` values as well, you must explicitly combine with `.notna()`.

##### Q12: How do you filter rows based on string prefix using Pandas?
- **Direct Answer & Definition**: Use the `.str.startswith()` accessor method.
- **Technical & Computational Reasoning**: It applies Python's string prefix checking vectorially across the Series elements, executing efficient prefix matching without regex overhead.
- **Practical Application / Syntax**: `df[df['sku'].str.startswith('PROD-', na=False)]`.
- **Nuances, Defaults & Pitfalls**: `.str.startswith()` does not support a `case` argument like `.str.contains()`. To perform case-insensitive prefix checks, you must call `.str.lower().str.startswith('prod-', na=False)`.

##### Q13: How do you filter rows based on string suffix using Pandas?
- **Direct Answer & Definition**: Use the `.str.endswith()` accessor method.
- **Technical & Computational Reasoning**: It evaluates whether the trailing characters of each string element match the specified pattern string.
- **Practical Application / Syntax**: `df[df['filename'].str.endswith('.csv', na=False)]`.
- **Nuances, Defaults & Pitfalls**: You can pass a tuple of strings (e.g., `('.csv', '.tsv')`) to match any suffix in the tuple, mirroring Python's native `str.endswith()`.

##### Q14: What is the return type of a comparison operation on a Pandas Series?
- **Direct Answer & Definition**: It returns a Pandas `Series` with a boolean data type (`dtype: bool` or `boolean`).
- **Technical & Computational Reasoning**: Relational operators trigger NumPy vector universal functions (`ufuncs`) that allocate a contiguous memory buffer of 1-byte booleans, preserving the index of the original Series.
- **Practical Application / Syntax**: Executing `type(df['price'] > 100)` yields `<class 'pandas.core.series.Series'>`, and `(df['price'] > 100).dtype` yields `dtype('bool')`.
- **Nuances, Defaults & Pitfalls**: If using Pandas nullable boolean dtypes (`pd.BooleanDtype()`), the dtype is `boolean` (capital B), which supports ternary logic (`True`, `False`, `<NA>`).

##### Q15: How can you count how many rows satisfy a filtering condition without creating a filtered DataFrame?
- **Direct Answer & Definition**: Call `.sum()` directly on the boolean mask Series.
- **Technical & Computational Reasoning**: In Python, boolean values evaluate numerically as `True == 1` and `False == 0`. Summing the boolean Series sums the ones, returning the count of matching rows in $O(N)$ time without allocating a new DataFrame.
- **Practical Application / Syntax**: `count = (df['score'] >= 90).sum()`.
- **Nuances, Defaults & Pitfalls**: Avoid writing `len(df[df['score'] >= 90])` in production, as that allocates an intermediate filtered DataFrame in memory just to inspect its length.

##### Q16: How do you calculate the proportion of rows that meet a condition?
- **Direct Answer & Definition**: Call `.mean()` directly on the boolean mask Series.
- **Technical & Computational Reasoning**: Because booleans cast to 1 and 0, the arithmetic mean is $\frac{\sum \text{matches}}{N}$, which calculates the proportion of `True` occurrences.
- **Practical Application / Syntax**: `pct_passed = (df['score'] >= 70).mean() * 100`.
- **Nuances, Defaults & Pitfalls**: If the boolean Series contains `<NA>` values (nullable boolean), `.mean()` skips them by default (`skipna=True`), which may bias the ratio if not accounted for.

##### Q17: Can you filter a DataFrame using a standard Python list of booleans?
- **Direct Answer & Definition**: Yes, a standard Python list of booleans can filter rows if its length exactly equals the DataFrame row count.
- **Technical & Computational Reasoning**: Pandas converts the list into a 1D NumPy boolean array and feeds it into the internal row-indexing engine.
- **Practical Application / Syntax**: `df[[True, False, True, False]]`.
- **Nuances, Defaults & Pitfalls**: Unlike a Pandas boolean Series, a Python list lacks index labels. Therefore, no index alignment occurs, and passing a list with even one extra or missing element immediately raises an `IndexError`.

##### Q18: What is the purpose of `regex=False` in `.str.contains()`?
- **Direct Answer & Definition**: `regex=False` disables regular expression parsing and performs literal string matching.
- **Technical & Computational Reasoning**: By default, `regex=True`, which interprets characters like `$`, `^`, `[`, `]`, `(`, `)`, `.`, and `*` as regex metacharacters. Setting `regex=False` searches for those literal characters directly.
- **Practical Application / Syntax**: `df[df['price_str'].str.contains('$10.00', regex=False, na=False)]`.
- **Nuances, Defaults & Pitfalls**: If `regex=False` is omitted when searching for `$10.00`, the `$` and `.` are parsed as end-of-line and wildcard anchors, yielding unexpected matches or regex compilation errors.

##### Q19: How do you filter rows by string length?
- **Direct Answer & Definition**: Use the `.str.len()` accessor method combined with a numerical comparison operator.
- **Technical & Computational Reasoning**: `.str.len()` calculates the character count of each string entry, producing an integer Series that can be compared against an integer scalar.
- **Practical Application / Syntax**: `df[df['password'].str.len() >= 8]`.
- **Nuances, Defaults & Pitfalls**: If a cell contains `np.nan`, `.str.len()` yields `NaN`. When compared against an integer (e.g. `>= 8`), `NaN >= 8` evaluates to `False`.

##### Q20: Why does `df.loc[df['col'] > 0]` preserve the original index labels?
- **Direct Answer & Definition**: Pandas indexing operations are label-preserving by design.
- **Technical & Computational Reasoning**: When Pandas filters rows, it retains the existing `Index` object references corresponding to the matching row positions, ensuring downstream joins, lookups, and time-series alignments remain consistent.
- **Practical Application / Syntax**: After filtering `df[df['col'] > 0]`, call `.reset_index(drop=True)` if you require a fresh `RangeIndex(0, N)`.
- **Nuances, Defaults & Pitfalls**: Failing to reset the index can cause subtle bugs when iterating or slicing with `.loc[]` using integer positional assumptions.

#### B. Intermediate Questions (Exactly 20 Questions)

##### Q21: What is the computational complexity of filtering rows on an unindexed column?
- **Direct Answer & Definition**: The computational complexity is $O(N)$, where $N$ is the number of rows in the DataFrame.
- **Technical & Computational Reasoning**: Because Pandas DataFrames do not maintain B-tree or hash-based indexes on arbitrary column values, evaluating `df['col'] > 10` requires a full linear scan across the memory block of that column.
- **Practical Application / Syntax**: For repeated queries on massive datasets, sorting or indexing on the column prior to querying optimizes retrieval time.
- **Nuances, Defaults & Pitfalls**: While the algorithmic complexity is $O(N)$, vectorized C loops execute dramatically faster than native Python `for` loops due to SIMD vectorization and CPU cache locality.

##### Q22: How does Copy-on-Write (CoW) in Pandas 2.0+ impact the memory behavior of basic filtering?
- **Direct Answer & Definition**: Under Copy-on-Write, filtering rows creates a new DataFrame that initially shares the underlying data memory buffers as a view rather than performing an immediate deep copy.
- **Technical & Computational Reasoning**: A filtered DataFrame references the parent array buffers. A physical copy of the data is deferred until a mutating write operation is performed on either the filtered subset or the parent DataFrame.
- **Practical Application / Syntax**: `pd.set_option('mode.copy_on_write', True)` ensures `filtered_df = df[df['val'] > 5]` incurs negligible memory allocation overhead upon creation.
- **Nuances, Defaults & Pitfalls**: Prior to CoW, filtering rows could unpredictably return either a view or a copy depending on block consolidation, leading to frequent `SettingWithCopyWarning` ambiguities.

##### Q23: Why does `df[mask]['col'] = 100` trigger `SettingWithCopyWarning`?
- **Direct Answer & Definition**: Because `df[mask]['col']` is a chained assignment that operates on an intermediate, temporary DataFrame object.
- **Technical & Computational Reasoning**: Python resolves `df[mask]['col'] = 100` as two distinct calls: `__getitem__(mask)` followed by `__setitem__('col', 100)`. If `__getitem__` returned a copy, the assignment modifies a temporary object that is immediately garbage collected, leaving `df` unchanged.
- **Practical Application / Syntax**: Always write `df.loc[mask, 'col'] = 100` to guarantee that mutation occurs directly on the parent DataFrame.
- **Nuances, Defaults & Pitfalls**: With Copy-on-Write enabled in Pandas 2.0+, chained assignment raises a hard `ChainedAssignmentError` instead of a warning, enforcing explicit code.

##### Q24: How can you filter a DataFrame by comparing values across two columns?
- **Direct Answer & Definition**: Compare the two column Series directly using relational operators.
- **Technical & Computational Reasoning**: Pandas aligns the index labels of both Series and performs element-wise comparison across the two aligned memory arrays.

## Phase 2: High-Yield Concepts, Pitfalls & Production Drills

### 4. Top Questions to Definitely Prepare

#### Must Know
1. **How do you filter a DataFrame by rows using a boolean condition?**
   - *Answer*: Generate a boolean Series by evaluating a relational condition on a column (e.g., `mask = df['price'] > 50`), then pass that mask into `df[mask]` or `df.loc[mask]`. This extracts all rows where the mask evaluates to `True` while preserving original row index labels.
2. **What is the difference between `df[mask]` and `df.loc[mask, 'col']`?**
   - *Answer*: `df[mask]` is shorthand for row filtering and only allows slicing rows across all columns. `df.loc[mask, 'col']` is the canonical label-based indexing syntax that allows simultaneous row filtering and column projection in a single operation, avoiding intermediate memory copies and `SettingWithCopyWarning`.
3. **How does `.str.contains()` behave when a column contains `NaN` or `None` values?**
   - *Answer*: By default, `.str.contains()` propagates nulls and outputs `NaN` for those elements. When this non-boolean Series is passed into `df[...]`, Pandas raises a `ValueError: Cannot mask with non-boolean array containing NA / NaN values`. To prevent this, always pass `na=False` (or `na=True`) to coerce missing entries to booleans.
4. **How do you filter columns dynamically using data types?**
   - *Answer*: Use `df.select_dtypes(include=[...], exclude=[...])`. For example, `df.select_dtypes(include=['number'])` dynamically returns a DataFrame subset containing all integer and floating-point columns, regardless of their column names.
5. **Why can't you use Python's built-in `if x:` or `and`/`or` keywords when filtering Pandas DataFrames?**
   - *Answer*: Python's `if`, `and`, and `or` keywords evaluate the truth value of an entire object as a single scalar boolean via `__bool__()`. When called on a Pandas Series with more than one element, Pandas raises `ValueError: The truth value of a Series is ambiguous. Use a.empty, a.bool(), a.item(), a.any() or a.all()`. Pandas requires vectorized bitwise operators (`&`, `|`, `~`).

#### Good to Know
6. **How do you filter columns by name using a substring or pattern?**
   - *Answer*: Use list comprehensions or generator expressions over `df.columns` combined with `.loc[:, col_mask]`. For example, `df.loc[:, [col.startswith('sales_') for col in df.columns]]` filters columns whose labels start with `'sales_'`.
7. **What is the difference between `.str.startswith()` and `.str.contains()`?**
   - *Answer*: `.str.startswith()` checks whether a string begins with a specified prefix pattern without invoking the regex engine. `.str.contains()` searches for a pattern anywhere within the string and defaults to regex matching (`regex=True`).
8. **How do you filter rows based on a numerical interval?**
   - *Answer*: Use `.between(left, right, inclusive='both')`. For example, `df[df['age'].between(21, 65)]` returns rows where age is between 21 and 65 inclusive, compiling to vectorized C-level boundary comparisons without requiring manual compound operator syntax.
9. **How does filtering interact with Pandas 2.0+ Copy-on-Write (CoW)?**
   - *Answer*: Under CoW, filtering creates a shallow reference (view) that shares underlying data arrays. A physical memory allocation (copy) is lazily deferred until a mutating operation modifies either the parent or the filtered child slice, eliminating defensive copies.
10. **How do you filter rows by exact string length?**
    - *Answer*: Call `.str.len()` on the text Series and apply an equality comparison, e.g., `df[df['zip_code'].str.len() == 5]`. Missing values evaluate to `NaN` and are excluded automatically.

#### Bonus
11. **How do you filter rows using a callable inside `.loc[]` and why is it useful in production pipelines?**
    - *Answer*: `.loc[]` accepts a single-argument lambda or function (e.g., `.loc[lambda d: d['rev'] > d['cost']]`). This is invaluable in method chaining pipelines because the callable dynamically receives the intermediate DataFrame state after prior transformations without needing intermediate variable assignments.
12. **What occurs under the hood when a boolean mask has unaligned index labels compared to the DataFrame?**
    - *Answer*: Pandas reindexes the mask against the DataFrame's index. Unaligned labels produce `NaN` booleans in the mask, which Pandas coerces to `False` in strict boolean indexing, potentially resulting in zero matching rows if indices are completely disjoint.
13. **How does `regex=False` in `.str.contains()` improve query execution speed?**
    - *Answer*: When `regex=False`, Pandas bypasses Python's `re` module and executes direct C-level Boyer-Moore-Horspool or substring search algorithms, executing substantially faster and avoiding regex compilation overhead.

### 5. Common Beginner Mistakes (10 Mistakes)

#### Mistake 1: Forgetting `na=False` in String Filtering Methods
- **Why It Happens**: Beginners test `.str.contains()` on clean toy datasets without missing values. When deployed on production data containing `NaN` or `None`, it generates `NaN` entries in the boolean mask.
- **Correct Approach**: Always supply `na=False` or `na=True` to `.str.contains()`, `.str.startswith()`, and `.str.endswith()`.
- **Example**:
  ```python
  # WRONG - Crashes with ValueError if 'comment' has NaN
  bad = df[df['comment'].str.contains('urgent')]

  # RIGHT - Safely treats NaNs as False
  good = df[df['comment'].str.contains('urgent', na=False)]
  ```

#### Mistake 2: Chained Indexing Assignment (`df[mask]['col'] = val`)
- **Why It Happens**: New users think `df[mask]` selects the rows and `['col'] = val` assigns the value, not realizing they are modifying an intermediate temporary object.
- **Correct Approach**: Use `.loc[mask, 'col'] = val` for single-step, safe in-place assignment.
- **Example**:
  ```python
  # WRONG - Triggers SettingWithCopyWarning, may fail silently
  df[df['status'] == 'pending']['flag'] = 1

  # RIGHT - Mutates df in-place reliably
  df.loc[df['status'] == 'pending', 'flag'] = 1
  ```

#### Mistake 3: Passing a Column Boolean Mask Directly to `df[col_mask]`
- **Why It Happens**: Users expect `df[...]` to intelligently detect whether the boolean mask applies to rows or columns based on length.
- **Correct Approach**: Square brackets `df[...]` default to row indexing. To filter columns with booleans, you must use `.loc[:, col_mask]`.
- **Example**:
  ```python
  # WRONG - Raises IndexError or ValueError (length mismatch with rows)
  col_mask = [col.startswith('num_') for col in df.columns]
  bad = df[col_mask]

  # RIGHT - Explicitly targets column axis
  good = df.loc[:, col_mask]
  ```

#### Mistake 4: Using Single Equals `=` Instead of Double Equals `==`
- **Why It Happens**: Typographical confusion between variable assignment and equality comparison.
- **Correct Approach**: Use `==` for element-wise comparison.
- **Example**:
  ```python
  # WRONG - SyntaxError: invalid syntax
  bad = df[df['tier'] = 'Gold']

  # RIGHT - Evaluates vectorized equality
  good = df[df['tier'] == 'Gold']
  ```

#### Mistake 5: Assuming `NaN == NaN` Returns True in Filtering
- **Why It Happens**: In standard Python equality `None == None` is `True`. In floating-point IEEE 754 arithmetic, `np.nan == np.nan` is always `False`.
- **Correct Approach**: Use `.isna()` or `.notna()` to filter for missing values.
- **Example**:
  ```python
  # WRONG - Always returns an empty DataFrame (0 rows)
  bad = df[df['missing_col'] == np.nan]

  # RIGHT - Uses dedicated missing value predicate
  good = df[df['missing_col'].isna()]
  ```

#### Mistake 6: Unparenthesized Bitwise NOT Inversion (`~df['col'] > 0`)
- **Why It Happens**: In mathematics, negation binds to the expression. In Python, `~` has higher operator precedence than `>`.
- **Correct Approach**: Wrap the entire relational comparison in parentheses before applying `~`.
- **Example**:
  ```python
  # WRONG - Inverts column integers first, causing TypeError or inverted math
  bad = df[~df['score'] >= 50]

  # RIGHT - Evaluates comparison first, then inverts boolean mask
  good = df[~(df['score'] >= 50)]
  ```

#### Mistake 7: Using `len(df[mask])` to Count Matching Records
- **Why It Happens**: Beginners filter the DataFrame first and then compute the length of the result.
- **Correct Approach**: Call `.sum()` directly on the boolean mask to count matches without allocating an intermediate DataFrame.
- **Example**:
  ```python
  # WRONG - High memory overhead on large DataFrames
  count = len(df[df['age'] > 30])

  # RIGHT - O(1) memory overhead, fast vectorized sum
  count = (df['age'] > 30).sum()
  ```

#### Mistake 8: Attempting String Methods Directly Without `.str` Accessor
- **Why It Happens**: Users forget that a Pandas Series is an array container, not a native Python string.
- **Correct Approach**: Access string methods via the `.str` accessor.
- **Example**:
  ```python
  # WRONG - AttributeError: 'Series' object has no attribute 'startswith'
  bad = df[df['sku'].startswith('A')]

  # RIGHT - Uses vectorized .str accessor
  good = df[df['sku'].str.startswith('A', na=False)]
  ```

#### Mistake 9: Filtering on Unstripped Strings
- **Why It Happens**: Data extracted from CSVs or SQL databases often contains trailing spaces or newline characters (`'Active '` vs `'Active'`).
- **Correct Approach**: Call `.str.strip()` on text columns before performing exact equality checks.
- **Example**:
  ```python
  # WRONG - Silently misses rows with trailing spaces
  bad = df[df['status'] == 'Active']

  # RIGHT - Strips whitespace prior to equality matching
  good = df[df['status'].str.strip() == 'Active']
  ```

#### Mistake 10: Filtering Numerical Columns Ingested as Strings
- **Why It Happens**: When CSV columns contain currency symbols (`$`) or commas, Pandas infers `object` (string) dtype. Comparing strings to numbers (`'100' > 50`) raises `TypeError`.
- **Correct Approach**: Clean and cast the column with `pd.to_numeric()` before relational filtering.
- **Example**:
  ```python
  # WRONG - TypeError: '>' not supported between instances of 'str' and 'int'
  bad = df[df['price_str'] > 100]

  # RIGHT - Cast to numeric first
  clean_price = pd.to_numeric(df['price_str'].str.replace('$', '', regex=False))
  good = df[clean_price > 100]
  ```

### 6. Pandas API Confusions (Section-Adaptive)

#### Confusion 1: `df[mask]` vs. `df.loc[mask]`
| Feature | `df[mask]` | `df.loc[mask]` |
| :--- | :--- | :--- |
| **Primary Scope** | 1D row filtering shortcut. | 2D label-based indexing (`[rows, cols]`). |
| **Column Selection** | Cannot specify columns in the same call (`df[mask, 'col']` fails). | Allows simultaneous column projection (`df.loc[mask, ['colA', 'colB']]`). |
| **In-Place Mutation** | Chained mutation triggers `SettingWithCopyWarning`. | Safe, direct in-place assignment on target DataFrame. |
| **Code Style** | Good for exploratory ad-hoc queries. | Standard production best practice. |
| **Side-by-Side Code Comparison**:
```python
# df[mask] - two-step indexing (creates intermediate object)
subset = df[df['salary'] > 50000][['name', 'salary']]

# df.loc[mask] - single-step 2D indexing (optimal)
subset = df.loc[df['salary'] > 50000, ['name', 'salary']]
```

#### Confusion 2: `df[col_mask]` vs. `df.loc[:, col_mask]`
| Feature | `df[col_mask]` | `df.loc[:, col_mask]` |
| :--- | :--- | :--- |
| **Axis Targeted** | Axis 0 (Rows) — raises error if length != rows. | Axis 1 (Columns) — correctly matches column count. |
| **Indexer Type** | Interpreted as row boolean slice. | Explicit 2D slice (`:` for all rows, `col_mask` for cols). |
| **Failure Mode** | `IndexError: Length of logical indexers must match...` | Evaluates cleanly across column labels. |
| **Side-by-Side Code Comparison**:
```python
col_mask = [True, False, True] # for a 3-column, 5-row DataFrame

# WRONG: expects 5 booleans for rows
# df[col_mask] -> IndexError

# RIGHT: explicitly targets column axis
result = df.loc[:, col_mask]
```

#### Confusion 3: `.str.contains()` vs. `.str.match()`
| Feature | `.str.contains()` | `.str.match()` |
| :--- | :--- | :--- |
| **Match Location** | Searches anywhere within the string. | Strictly matches from the start of the string (`^`). |
| **Underlying Function** | Python `re.search()`. | Python `re.match()`. |
| **Default Regex** | `regex=True`. | `regex=True`. |
| **Typical Use Case** | Keyword / substring matching in descriptions. | Strict format validation (e.g., zipcodes, phone numbers). |
| **Side-by-Side Code Comparison**:
```python
s = pd.Series(['error_404', '404_error', 'no_err'])

# Matches both 'error_404' and '404_error'
s.str.contains('error', na=False) # -> [True, True, False]

# Matches ONLY 'error_404' (must start with 'error')
s.str.match('error', na=False)    # -> [True, False, False]
```

#### Confusion 4: `.str.startswith()` vs. `.str.contains('^...')`
| Feature | `.str.startswith('pattern')` | `.str.contains('^pattern')` |
| :--- | :--- | :--- |
| **Engine Used** | Fast native C Python string prefix check. | Regular expression compiler (`re`). |
| **Performance** | Significantly faster (no regex engine compilation). | Slightly slower due to regex overhead. |
| **Literal Characters** | Treats all characters literally (`$`, `.`, `*`). | Requires regex escaping for special characters. |
| **Case Sensitivity** | Strictly case-sensitive. | Can toggle `case=False`. |
| **Side-by-Side Code Comparison**:
```python
s = pd.Series(['$100', '100', '$200'])

# Fast literal check (no regex parsing needed)
s.str.startswith('$', na=False)

# Regex anchored check (requires escaping '$')
s.str.contains(r'^\$', regex=True, na=False)
```

### 7. Interview Traps (10 Traps)

#### Trap 1: "How do you filter for rows where a column equals `NaN`?"
- **Naive Answer**: "Just use `df[df['col'] == np.nan]`."
- **Trap Unveiled**: In IEEE 754 floating-point standards, `NaN` is not equal to anything, including itself (`np.nan == np.nan` evaluates to `False`). The naive code returns an empty DataFrame with 0 rows every time.
- **Winning Staff-Level Response**: "You must never use equality comparisons with `np.nan`. Instead, use the dedicated missing-value method `df[df['col'].isna()]` or `df[df['col'].isnull()]`, which inspects the null bitmask under the hood."

#### Trap 2: "Does `df[mask]` return a view or a copy?"
- **Naive Answer**: "It always returns a copy."
- **Trap Unveiled**: In older Pandas, boolean indexing usually returned a copy, but sometimes returned a view depending on memory consolidation. In Pandas 2.0+ with Copy-on-Write (CoW) enabled, it returns a shallow reference (view-like) that shares the underlying data buffer until a write mutation occurs.
- **Winning Staff-Level Response**: "Under legacy Pandas, boolean indexing produces an independent copy because row filtering extracts non-contiguous memory slices. However, under modern Pandas 2.0+ with Copy-on-Write enabled, it returns a reference with shared data buffers, deferring physical copies until mutation. To avoid ambiguity when writing code, never rely on view vs copy assumptions for assignments—always use `.loc[mask, col] = val`."

#### Trap 3: "Why did my `.str.contains('A|B')` fail when the column had missing values?"
- **Naive Answer**: "Because `|` is not supported in `.str.contains()`."
- **Trap Unveiled**: `|` is a completely valid regex alternation token in `.str.contains()`. The failure is caused by missing values: `.str.contains()` returns `NaN` for null elements by default, and passing a Series containing `NaN` into square bracket indexing raises `ValueError: Cannot mask with non-boolean array containing NA / NaN values`.
- **Winning Staff-Level Response**: "The issue is not the regex syntax; it is null propagation. By default, string accessor methods return `NaN` when evaluating null cells. Pandas boolean indexers disallow ternary logic and require strict booleans. Adding `na=False` explicitly converts all null evaluations to `False`, resolving the exception."

#### Trap 4: "Can you filter a DataFrame using a list of column names inside single square brackets?"
- **Naive Answer**: "Yes, `df['colA', 'colB']`."
- **Trap Unveiled**: Single square brackets with comma-separated names evaluates as a Python tuple `('colA', 'colB')`. Pandas searches for a single column whose exact name is the tuple `('colA', 'colB')` (used in MultiIndex columns), raising a `KeyError`.
- **Winning Staff-Level Response**: "No. Single square brackets expect a single key or a list of keys. To select multiple columns, you must pass a Python list of strings: `df[['colA', 'colB']]`. Alternatively, using `.loc[:, ['colA', 'colB']]` is the explicit 2D indexing standard."

#### Trap 5: "What happens when you filter a DataFrame with a boolean mask created from a different DataFrame?"
- **Naive Answer**: "It filters the rows matching `True` positionally."
- **Trap Unveiled**: If the boolean mask is a Pandas Series, Pandas aligns indices by label, not position. If the index labels do not match, the mask is reindexed, filling missing labels with `NaN` (which coerce to `False`), yielding an empty DataFrame.
- **Winning Staff-Level Response**: "Pandas adheres to strict label alignment. If `mask` has a different index, Pandas aligns the mask labels to the target DataFrame's index. Unaligned rows receive `NaN` and are dropped. If positional filtering is required without alignment, one must pass `mask.to_numpy()` or `mask.values`."

#### Trap 6: "How do you filter rows where a numerical column is between 10 and 20 without using the `&` operator?"
- **Naive Answer**: "You can't do it without `&`."
- **Trap Unveiled**: The `.between()` method encapsulates interval boundary checking cleanly.
- **Winning Staff-Level Response**: "You use the built-in vectorized method `df[df['col'].between(10, 20, inclusive='both')]`. This is cleaner, faster, and avoids the syntax boilerplate and precedence pitfalls of compound bitwise operators."

#### Trap 7: "What is the result of `(df['price'] > 100).sum()` versus `len(df[df['price'] > 100])`?"
- **Naive Answer**: "They do the exact same thing with identical performance."
- **Trap Unveiled**: While both return the same numerical count, `len(df[...])` allocates an entire filtered DataFrame in memory (allocating row indexes and column blocks), which is extremely wasteful on large datasets.
- **Winning Staff-Level Response**: "Both yield the same integer count, but `(df['price'] > 100).sum()` evaluates in $O(1)$ auxiliary memory by summing the 1D boolean array directly in C. In contrast, `len(df[df['price'] > 100])` creates an intermediate DataFrame slice, incurring unnecessary heap allocation and garbage collection overhead."

#### Trap 8: "Why does `df[df['name'].str.contains('?')` crash with a `re.error`?"
- **Naive Answer**: "Because `?` is not an allowed character in Pandas."
- **Trap Unveiled**: By default, `.str.contains()` has `regex=True`. In regular expressions, `?` is a quantifier meaning 'zero or one occurrence' of the preceding token. Starting a regex with `?` without a preceding token raises `re.error: nothing to repeat`.
- **Winning Staff-Level Response**: "Because `.str.contains()` interprets the pattern as a regular expression by default. To search for a literal question mark, you must either escape it (`r'\?'`) or set `regex=False` to perform a fast literal substring search."

#### Trap 9: "How do you filter a DataFrame for rows where a column is NOT equal to 5, and what happens to `NaN` values?"
- **Naive Answer**: "`df[df['col'] != 5]`, and it keeps all rows except those with 5."
- **Trap Unveiled**: Under IEEE 754 standards, `NaN != 5` evaluates to `True`. Therefore, rows containing `NaN` are retained by `!= 5`. If the business intent was to only retain valid numbers that are not 5, `NaN` rows will slip through.
- **Winning Staff-Level Response**: "Writing `df['col'] != 5` retains both non-5 values AND `NaN` values, because `NaN != 5` is `True`. If null values must also be excluded, the condition must explicitly check `df['col'].notna() & (df['col'] != 5)`."

#### Trap 10: "Can you filter a DataFrame's columns using a lambda function?"
- **Naive Answer**: "No, lambdas only work on rows with `.apply()`."
- **Trap Unveiled**: `.loc` accepts a callable along both the row axis and the column axis.
- **Winning Staff-Level Response**: "Yes. `.loc[:, lambda df: [c for c in df.columns if df[c].dtype == 'float64']]` accepts a callable along the column axis. The callable receives the DataFrame as its argument and returns an iterable of column labels or a boolean mask."

- **Problem Statement**: The developer attempts to flag delinquent users with negative balances, but in production the flag is never saved to `df`, and a warning is logged.
- **Broken Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({'user': ['A', 'B'], 'balance': [-10, 50], 'flag': ['NONE', 'NONE']})
  df[df['balance'] < 0]['flag'] = 'DELINQUENT'
  ```
- **Expected Behavior**: The `'flag'` column for user `'A'` should be updated to `'DELINQUENT'` in `df`.
- **Corrected Code**:
  ```python

  ```
- **Root Cause Analysis**: `df[df['balance'] < 0]` creates an intermediate temporary slice. Applying `['flag'] = 'DELINQUENT'` mutates that temporary object, which is immediately discarded by Python's garbage collector. Using `.loc` ensures direct single-pass mutation on the original DataFrame.

##### Buggy Snippet 2: Crashing on Null Strings in URL Filter
- **Broken Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({'url': ['https://example.com/api/v1', None, 'https://test.com']})

  ```
- **Expected Behavior**: Extract row 0 without raising an unhandled exception.
- **Corrected Code**:
  ```python

  ```
- **Root Cause Analysis**: The `None` value in row 1 causes `.str.contains()` to output `NaN` for that position. When a Series containing `NaN` is used as a filter mask, Pandas raises `ValueError: Cannot mask with non-boolean array containing NA / NaN values`. Passing `na=False` forces missing values to boolean `False`.

##### Buggy Snippet 3: Index Error When Filtering Columns by Boolean Array
- **Broken Code**:
  ```python
  import pandas as pd
  df = pd.DataFrame({'a': [1, 2, 3], 'b': [4, 5, 6], 'c': [7, 8, 9]})
  keep_cols = [True, False, True]
  subset = df[keep_cols]
  ```
- **Expected Behavior**: Select columns `'a'` and `'c'` across all rows.
- **Corrected Code**:
  ```python
  subset = df.loc[:, keep_cols]
  ```
- **Root Cause Analysis**: Passing a list into `df[keep_cols]` defaults to **row-level** slicing. Since `df` has 3 rows and `keep_cols` has 3 items, it happens to slice rows positionally instead of columns. If the row count differed, it would crash with `IndexError`. ### 14. Section-Specific Pandas Interview Cheat Sheet

#### Core Methods & Syntax
| Method / Syntax | Primary Purpose | Return Type | Memory Behavior |
| :--- | :--- | :--- | :--- |
| `df[mask]` | Row-level boolean filtering | DataFrame | CoW View / Deferred Copy |
| `df.loc[mask, cols]` | Simultaneous row filtering & column projection | DataFrame / Series | CoW View / Direct Mutation Target |
| `df.select_dtypes(include=...)` | Filter columns by data types | DataFrame | Shallow View of column blocks |
| `s.str.contains(pat, na=False)` | Substring / regex pattern search | Series (bool) | Allocates 1D boolean array |
| `s.str.startswith(pat, na=False)` | Prefix pattern verification | Series (bool) | Allocates 1D boolean array |
| `s.str.endswith(pat, na=False)` | Suffix pattern verification | Series (bool) | Allocates 1D boolean array |
| `s.str.len()` | Calculate string character count | Series (int64) | Allocates 1D integer array |
| `s.between(left, right)` | Closed/open numerical boundary testing | Series (bool) | Allocates 1D boolean array |

#### Crucial Parameters & Defaults
- `na=False` in `.str` methods: Mandatory in production to coerce null cells to `False`. Default is `np.nan`.
- `case=False` in `.str.contains()`: Toggles case-insensitive matching. Default is `True`.
- `regex=False` in `.str.contains()`: Disables regex parsing for fast literal string lookups. Default is `True`.
- `inclusive='both'` in `.between()`: Options are `'both'`, `'neither'`, `'left'`, `'right'`.
- `drop=True` in `.reset_index()`: Prevents the old index from being inserted as a new DataFrame column.

#### Primary Anti-Patterns to Dodge
- **Anti-Pattern 1**: `df[df['col'] == np.nan]` $\rightarrow$ Always returns empty DataFrame. Use `df['col'].isna()`.
- **Anti-Pattern 2**: `df[mask]['col'] = val` $\rightarrow$ Chained assignment bug. Use `df.loc[mask, 'col'] = val`.
- **Anti-Pattern 3**: `~df['val'] > 5` $\rightarrow$ Operator precedence bug. Use `~(df['val'] > 5)`.
- **Anti-Pattern 4**: `len(df[mask])` $\rightarrow$ Unnecessary intermediate DataFrame allocation. Use `mask.sum()`.

### 16. Questions That Test Understanding (Perturbations)

##### Perturbation 1: Mask Reindexing with Unaligned Custom Labels
- **Scenario**: You have `df` with custom index `['x', 'y', 'z']` and a boolean mask `mask = pd.Series([True, True, False], index=['a', 'b', 'c'])`.
- **Perturbation**: What is the output of `df[mask]`?
- **Computational Mechanics**: Pandas aligns indices by label. Because none of `['a', 'b', 'c']` exist in `['x', 'y', 'z']`, reindexing the mask produces all `NaN` booleans, which Pandas treats as non-matches.
- **Result**: An empty DataFrame with index `[]` and 0 rows. To filter positionally without alignment, you must pass `mask.to_numpy()`.

##### Perturbation 2: Floating-Point Tolerance Perturbation
- **Scenario**: A column contains computed float values: `df = pd.DataFrame({'val': [0.1 + 0.2, 0.3]})`.
- **Perturbation**: Candidate runs `df[df['val'] == 0.3]`.
- **Computational Mechanics**: Due to IEEE 754 binary floating-point representation, `0.1 + 0.2` evaluates to `0.30000000000000004`. The exact equality `== 0.3` evaluates to `False` for row 0.
- **Result**: Only row 1 matches. In production, numerical filtering on computed floats must use `np.isclose(df['val'], 0.3)`.

##### Perturbation 3: Scalar Inversion vs Series Inversion
- **Scenario**: Compare `not (df['age'] > 18)` vs `~(df['age'] > 18)`.
- **Perturbation**: Why does the first expression crash while the second succeeds?
- **Computational Mechanics**: `not` is Python's logical operator that calls `__bool__()` on the operand, requiring a single scalar truth value. Because a Series has multiple elements, it raises `ValueError: The truth value of a Series is ambiguous`. In contrast, `~` calls `__invert__()`, executing element-wise bitwise inversion across the array buffer.

### 18. Cross-Concept Bridges

#### NumPy Bridge
- A Pandas boolean Series is backed by a 1D NumPy `ndarray` of `dtype('bool')` (or Apache Arrow boolean bitmask).
- When executing `df[condition]`, Pandas calls `np.nonzero(mask.values)[0]` or an optimized internal `take()` routine to resolve integer row offsets.
- Converting a mask via `mask.to_numpy()` strips index metadata, allowing positional filtering without label alignment conflicts.

#### SQL Bridge
- `df[df['salary'] > 50000]` maps directly to:
  ```sql
  SELECT * FROM df WHERE salary > 50000;
  ```
- `df.loc[df['dept'] == 'IT', ['emp_name', 'salary']]` maps directly to:
  ```sql
  SELECT emp_name, salary FROM df WHERE dept = 'IT';
  ```
- `df.select_dtypes(include=['number'])` maps to selecting specific column data types from `INFORMATION_SCHEMA.COLUMNS`.

#### Scikit-Learn Bridge
- In Scikit-Learn pipelines, separating the feature matrix $X$ from the target vector $y$ often utilizes column filtering:
  ```python
  X = df.loc[:, df.columns != 'target_label']
  y = df['target_label']
  ```
- Filtering out invalid records or outliers must happen before `fit_transform()` to prevent distribution distortion in scalers and encoders.

#### Python Native Bridge
- Python's scalar `if condition:` relies on `__bool__()`. Because a Pandas Series contains multiple elements, evaluating `if df['col'] > 0:` raises `ValueError`.
- Python's native `filter(lambda x: x > 0, list)` iterates element-by-element with heavy interpreter overhead. Pandas boolean indexing runs compiled SIMD instructions across memory blocks, achieving 100x–1000x speedups.

### 20. What a Fresher Should Understand (Computational Mechanics)

1. **Label Alignment During Masking**: Pandas aligns boolean masks to the target DataFrame using index labels, not array positions. Unaligned labels produce `NaN` (coerced to `False`), silently dropping rows.
2. **Copy-on-Write (CoW)**: Modern Pandas 2.0+ shares memory buffers on filtered subsets. Copies are created lazily only when a write/mutation occurs.
3. **Floating-Point NaN Incomparability**: Relational comparisons with `NaN` evaluate to `False` under IEEE 754. Neither `col > 10` nor `col <= 10` retains `NaN` rows.
4. **Vectorized String Dispatch**: The `.str` accessor delegates element-wise string calls across underlying C pointer arrays without explicit Python loops.

### 24. Final 2-Minute Revision Summary

- **Core Concepts**:
  - Filtering in Pandas evaluates element-wise boolean Series over column blocks, compiling to fast C/SIMD vector routines.
  - Standard square brackets `df[mask]` default to row filtering. Column-level boolean filtering requires `df.loc[:, col_mask]`.
  - Always use `.loc[mask, 'col'] = val` for conditional in-place modification to prevent `SettingWithCopyWarning`.
  - For text filtering, always supply `na=False` to `.str.contains()`, `.str.startswith()`, and `.str.endswith()` to prevent `ValueError` crashes.
- **Top 5 Traps to Dodge**:
  1. Never test for nulls with `df['col'] == np.nan`; use `df['col'].isna()`.
  2. Never write `~df['x'] > y` without parentheses; always write `~(df['x'] > y)`.
  3. Never use Python `and`/`or` keywords for Series filtering; use bitwise `&`/`|`.
  4. Never use `len(df[mask])` to count matches; use `mask.sum()`.
  5. Never omit `regex=False` when searching for literal strings containing `$`, `?`, or `.`.
- **Must-Know Code Snippet**:
  ```python
  import pandas as pd

  # 1. Row filter with numerical boundary & string null safety
  mask = (df['price'].between(10, 100)) & (df['desc'].str.contains('sale', case=False, na=False))

  # 2. Simultaneous extraction with column projection
  clean_subset = df.loc[mask, ['item_id', 'price', 'desc']].reset_index(drop=True)

  # 3. Safe in-place conditional mutation
  df.loc[df['price'] > 500, 'tier'] = 'Premium'
  ```
