### 1. Section Overview

#### What This Section Is About
Section 14.2 focuses on the extraction, decomposition, and transformation of calendar and temporal components from Pandas `Series` and `DatetimeIndex` structures via the specialized `.dt` accessor. It covers extracting discrete temporal units—`year`, `month`, `day`, `hour`, `minute`, `second`, `dayofweek`, and `quarter`—as well as rich calendar helpers including `day_name()`, `month_name()`, `isocalendar()`, `days_in_month`, `is_leap_year`, and boundary boolean flags (`is_month_start`, `is_quarter_end`, etc.).

#### Why These Pandas Concepts Matter
In real-world data pipelines, raw timestamps alone cannot be directly ingested into machine learning models or aggregated into managerial dashboards. Machine learning algorithms cannot calculate linear weights directly on raw timestamps like `'2026-05-14 15:30:00'`; timestamps must be engineered into cyclic or categorical features such as hour of day, day of week, month, and fiscal quarter. Furthermore, business analytics workflows require grouping metrics by quarter for executive scorecards, analyzing hourly diurnal web traffic patterns, or filtering transactions that occur strictly on weekends. Mastery of the `.dt` accessor ensures that these extractions execute as vectorized C-level operations directly over contiguous memory arrays rather than through slow Python string slicing or loop iterations.

#### Where They Are Used in Real Projects
1. **Machine Learning Feature Engineering**: Decomposing event timestamps into `hour` (diurnal features), `dayofweek` (weekday vs weekend effects), `month` (seasonality), and sinusoidal cyclic transformations ($\sin(2\pi \cdot \text{hour}/24)$, $\cos(2\pi \cdot \text{hour}/24)$).
2. **Financial Reporting & Accounting**: Grouping multi-asset revenue, depreciation schedules, and quarterly tax liabilities using `.dt.quarter` and `.dt.year`.
3. **Retail & E-Commerce Demand Forecasting**: Evaluating weekly foot traffic and weekend shopping surges using `.dt.dayofweek` (0=Monday to 6=Sunday) and `.dt.day_name()`.
4. **DevOps & Cloud Telemetry**: Analyzing peak traffic hours and server load spikes across global time zones by slicing logs on `.dt.hour` and `.dt.minute`.
5. **Human Resources & Payroll Systems**: Identifying month-end payroll execution cycles and leap year calendar adjustments using `.dt.is_month_end` and `.dt.is_leap_year`.

#### What a Fresher Should Be Able to Do
- Access any component of a `datetime64` Series using the vectorized `.dt` accessor without resorting to Python loops or `.apply()`.
- Identify the exact numeric encoding and indexing conventions: `month` (1–12), `day` (1–31), `hour` (0–23), `minute` (0–59), `second` (0–59), `dayofweek` (0=Monday to 6=Sunday), and `quarter` (1–4).
- Leverage string and calendar accessors (`day_name()`, `month_name()`, `isocalendar()`) with proper locale settings.
- Accurately predict and handle the behavior of `.dt` accessors when operating on missing values (`pd.NaT`), avoiding silent type upcasting bugs.
- Construct temporal grouping and filtering pipelines using extracted boolean properties (`is_quarter_start`, `is_month_end`, `is_year_start`).

### 2. Topic-Wise Interview Concepts

#### 2.1 The `.dt` Accessor Architecture & Mechanics
In Pandas, a `Series` containing datetime data (`datetime64[ns]` or modern Arrow timestamp dtypes) does not expose datetime methods directly on the Series object. Instead, Pandas employs the **Accessor Pattern** via the `.dt` namespace.

```
       Pandas Series (dtype: datetime64[ns])
                         │
                    .dt Accessor
                         │
    ┌────────────────────┼────────────────────┐
    ▼                    ▼                    ▼
Discrete Units       Named Helpers        Boolean Flags
.year                .day_name()          .is_leap_year
.month               .month_name()        .is_month_start
.day                 .isocalendar()       .is_month_end
.hour                .days_in_month       .is_quarter_start
.minute                                   .is_quarter_end
.second                                   .is_year_start
.dayofweek                                .is_year_end
.quarter
```

Under the hood:
- The `.dt` accessor is a property descriptor returning a `CombinedDatetimelikeProperties` object.
- Accessing an attribute like `s.dt.year` invokes high-performance C/Cython routines in `pandas._libs.tslibs` that unpack the 64-bit nanosecond integer into Gregorian calendar fields using modular arithmetic and lookups.
- Attempting to call `.dt` on a Series with `dtype='object'` or numeric types immediately raises `AttributeError: Can only use .dt accessor with datetimelike values`.

#### 2.2 Mathematical Formulations & Component Ranges
When extracting components, each temporal unit maps to an exact discrete integer domain:

| Component | Accessor | Mathematical Range | Representation / Rules |
| :--- | :--- | :--- | :--- |
| **Year** | `s.dt.year` | $[1678, 2262]$ (for `ns`) | Gregorian calendar year integer |
| **Month** | `s.dt.month` | $[1, 12]$ | $1 = \text{January}, 12 = \text{December}$ |
| **Day** | `s.dt.day` | $[1, 31]$ | Calendar day of current month |
| **Hour** | `s.dt.hour` | $[0, 23]$ | 24-hour clock ($0 = \text{Midnight}$) |
| **Minute** | `s.dt.minute` | $[0, 59]$ | Minutes past the hour |
| **Second** | `s.dt.second` | $[0, 59]$ | Seconds past the minute |
| **Day of Week**| `s.dt.dayofweek` | $[0, 6]$ | $0 = \text{Monday}, 6 = \text{Sunday}$ (ISO standard index) |
| **Weekday** | `s.dt.weekday` | $[0, 6]$ | Identical alias to `dayofweek` |
| **Quarter** | `s.dt.quarter` | $[1, 4]$ | $\lceil \text{month} / 3 \rceil$ (Q1: Jan–Mar, Q2: Apr–Jun, ...) |
| **Day of Year**| `s.dt.dayofyear` | $[1, 366]$ | Day count since Jan 1 ($1 = \text{Jan 1}$) |

#### 2.3 Named Components: `day_name()` and `month_name()`
Unlike integer properties, `day_name()` and `month_name()` are methods that return localized string representations:
- `s.dt.day_name(locale=None)`: Returns string names (`'Monday'`, `'Tuesday'`, ...).
- `s.dt.month_name(locale=None)`: Returns string names (`'January'`, `'February'`, ...).
- If a row contains `pd.NaT`, both methods return `np.nan` (or `float('nan')`), preserving missingness without raising exceptions.

#### 2.4 ISO Calendar Deconstruction (`isocalendar()`)
The International Organization for Standardization (ISO 8601) defines weeks starting on Monday, where the first week of the year contains the first Thursday:
```python
iso_df = s.dt.isocalendar()
# Returns a DataFrame with 3 UInt32 columns:
# - year: ISO year (can differ from Gregorian year at year boundaries!)
# - week: ISO week number [1, 53]
# - day: ISO day of week [1, 7] (1 = Monday, 7 = Sunday)
```
> **CRITICAL INTERVIEW TRAP**: Notice that `s.dt.dayofweek` uses $0 = \text{Monday}$, whereas `s.dt.isocalendar().day` uses $1 = \text{Monday}$!

#### 2.5 Calendar Boundary Flags & Leap Year Detection
Pandas provides pre-computed boolean indicators for business cycle logic:
- `s.dt.is_month_start`: True if day is the 1st of the month.
- `s.dt.is_month_end`: True if day is the last calendar day of the month ($28, 29, 30, \text{ or } 31$).
- `s.dt.is_quarter_start`: True if the date is Jan 1, Apr 1, Jul 1, or Oct 1.
- `s.dt.is_quarter_end`: True if the date is Mar 31, Jun 30, Sep 30, or Dec 31.
- `s.dt.is_year_start`: True on Jan 1.
- `s.dt.is_year_end`: True on Dec 31.
- `s.dt.is_leap_year`: True if the year is divisible by 4 (and not divisible by 100 unless divisible by 400).

### 3. Fresher Interview Questions

#### 3.1 20 Basic Interview Questions (4-Part Structure)

##### Q1: What is the purpose of the `.dt` accessor in Pandas?
- **Concept**: Accessor pattern for vectorized datetime operations on Series.
- **Why It Matters**: Standard Python datetime functions are scalar. The `.dt` accessor exposes datetime attributes across entire Series via optimized C loops.
- **Code**:
  ```python
  import pandas as pd
  s = pd.Series(pd.to_datetime(['2026-05-14 10:30:00']))
  print(s.dt.year.iloc[0])  # 2026
  ```
- **Interview Trap**: Calling `.dt` on a column that is still `dtype='object'` raises `AttributeError`. You must convert via `pd.to_datetime()` first.

##### Q2: How do you extract the year from a datetime Series?
- **Concept**: `Series.dt.year`.
- **Why It Matters**: Essential for year-over-year (YoY) financial analysis and annual cohort segmentation.
- **Code**:
  ```python
  s = pd.Series(pd.date_range('2025-01-01', periods=3, freq='YE'))
  print(s.dt.year.tolist())  # [2025, 2026, 2027]
  ```
- **Interview Trap**: `s.dt.year` returns standard Gregorian calendar years. For ISO calendar years at December/January boundaries, use `s.dt.isocalendar().year`.

##### Q3: How do you extract the month number from a datetime Series?
- **Concept**: `Series.dt.month`.
- **Why It Matters**: Decomposes dates into annual seasonal buckets ($1$ through $12$).
- **Code**:
  ```python
  s = pd.Series(pd.to_datetime(['2026-05-14']))
  print(s.dt.month.iloc[0])  # 5
  ```
- **Interview Trap**: Months are 1-indexed ($1 = \text{January}, 12 = \text{December}$). Do not confuse with 0-indexed C libraries or JavaScript.

##### Q4: How do you extract the month name as a string?
- **Concept**: `Series.dt.month_name()`.
- **Why It Matters**: Generates human-readable labels for plots, reports, and dashboards.
- **Code**:
  ```python
  s = pd.Series(pd.to_datetime(['2026-05-14']))
  print(s.dt.month_name().iloc[0])  # 'May'
  ```
- **Interview Trap**: `month_name()` is a method (requires parentheses `()`), whereas `month` is an attribute (no parentheses). Calling `s.dt.month_name` returns a method bound object.

##### Q5: How do you extract the calendar day of the month?
- **Concept**: `Series.dt.day`.
- **Why It Matters**: Used for day-of-month billing triggers (e.g., 1st or 15th) and monthly billing cycle validations.
- **Code**:

  ```python
  print(s.dt.day.iloc[0])  # 14
  ```
- **Interview Trap**: Do not confuse `s.dt.day` (day of month, 1–31) with `s.dt.dayofweek` (day of week, 0–6) or `s.dt.dayofyear` (1–366).

##### Q6: How do you extract the hour from a timestamp Series?
- **Concept**: `Series.dt.hour`.
- **Why It Matters**: Critical for diurnal cycle modeling, peak traffic detection, and fraud scoring.
- **Code**:

  ```python
  print(s.dt.hour.iloc[0])  # 18
  ```
- **Interview Trap**: Hours follow the 24-hour clock ($0$ to $23$). $0$ represents midnight; $23$ represents 11 PM.

##### Q7: How do you extract the minute component from a timestamp Series?
- **Concept**: `Series.dt.minute`.
- **Why It Matters**: Minute-level binning for SLA telemetry, trading ticks, and micro-batch ETL pipelines.
- **Code**:

- **Interview Trap**: Minutes range from $0$ to $59$.

##### Q8: How do you extract the second component from a timestamp Series?

##### Q9: How do you extract the day of the week as an integer in Pandas?

##### Q18: What is the return type of `Series.dt.date`?
- **Concept**: `Series.dt.date`.
- **Why It Matters**: Extracts date components without time, often used for daily grouping.

  ```python
  s = pd.Series(pd.to_datetime(['2026-05-14 15:30:00']))
  ```

##### Q20: What happens when you call a `.dt` accessor on a Series containing `pd.NaT`?
- **Concept**: Missing value propagation through `.dt`.
- **Why It Matters**: Ensures robust pipeline execution without throwing null pointer exceptions.
- **Code**:
  ```python
  s = pd.Series(pd.to_datetime(['2026-05-14', None]))
  print(s.dt.year.tolist())  # [2026.0, nan]
  ```
- **Interview Trap**: In standard NumPy-backed Pandas, integer accessors like `s.dt.year` upcast to `float64` because standard NumPy integer arrays cannot hold `NaN`! Modern nullable integer dtypes (`Int32`) solve this in Pandas 2.0+.

#### 3.2 20 Intermediate Interview Questions

##### Q21: What is the exact difference between `s.dt.dayofweek` and `s.dt.isocalendar().day`?
- **Answer**: `s.dt.dayofweek` uses 0-based indexing ($0 = \text{Monday}, 6 = \text{Sunday}$). `s.dt.isocalendar().day` conforms strictly to ISO 8601, which uses 1-based indexing ($1 = \text{Monday}, 7 = \text{Sunday}$). Offsetting code by 1 is one of the most common date manipulation bugs.

##### Q22: Why does `s.dt.year` sometimes differ from `s.dt.isocalendar().year`?
- **Answer**: Under ISO 8601, a week belongs to the year in which the majority of its days (or its Thursday) fall. Therefore, if January 1 falls on a Friday, the previous days of that week (Monday through Thursday) belong to the final week of the *previous* ISO year. For example, `2027-01-01` (Friday) falls into ISO year 2026, week 53! Thus `s.dt.year` is 2027, but `s.dt.isocalendar().year` is 2026.

##### Q23: How do you extract microsecond and nanosecond sub-second precision using `.dt`?
- **Answer**: Use `s.dt.microsecond` (returns $[0, 999999]$) and `s.dt.nanosecond` (returns $[0, 999]$). Note that `s.dt.nanosecond` represents only the remainder nanoseconds within the microsecond, not the total elapsed nanoseconds since epoch.

##### Q24: How can you filter a DataFrame to include only weekend transactions using `.dt`?
- **Answer**: Filter where `df['timestamp'].dt.dayofweek >= 5` (or `df['timestamp'].dt.dayofweek.isin([5, 6])`). Since 5=Saturday and 6=Sunday, this vectorially selects all weekend rows.

##### Q25: How do you extract localized day names in a non-English language (e.g., German or French)?
- **Answer**: Pass the IETF language tag to the `locale` parameter of `day_name()`:
  ```python
  s.dt.day_name(locale='de_DE.utf8') # Returns 'Donnerstag'
  s.dt.day_name(locale='fr_FR.utf8') # Returns 'Jeudi'
  ```
  Note that the corresponding OS locale package must be installed.

##### Q26: What is the computational cost of accessing multiple `.dt` properties consecutively?
- **Answer**: Each call to `.dt.<property>` (e.g., `s.dt.year`, `s.dt.month`, `s.dt.day`) recalculates Gregorian fields from scratch across the entire array. When extracting 5+ components, constructing a temporary DataFrame or unpacking `isocalendar()` is significantly faster than repeatedly calling distinct `.dt` accessors.

##### Q27: How do you calculate the week number of the year in modern Pandas?
- **Answer**: In modern Pandas, calling `s.dt.week` or `s.dt.weekofyear` is deprecated. The recommended, future-proof method is `s.dt.isocalendar().week`, which returns an ISO 8601 compliant `UInt32` Series.

##### Q28: How do you determine if a given timestamp falls during standard business hours (9 AM to 5 PM)?
- **Answer**: Combine `s.dt.dayofweek < 5` with `s.dt.hour.between(9, 16)`:
  ```python
  is_biz_hour = (df['ts'].dt.dayofweek < 5) & (df['ts'].dt.hour >= 9) & (df['ts'].dt.hour < 17)
  ```

##### Q29: How do you group data by both Year and Month using `.dt` accessors?
- **Answer**: Group by multiple extracted properties simultaneously:
  ```python
  monthly_summary = df.groupby([df['ts'].dt.year, df['ts'].dt.month])['revenue'].sum()
  ```
  Alternatively, convert to period format: `df.groupby(df['ts'].dt.to_period('M'))['revenue'].sum()`.

##### Q30: What is the difference between `s.dt.to_period('M')` and extracting `s.dt.month`?
- **Answer**: `s.dt.month` extracts an integer $[1, 12]$ stripped of year context, merging January 2025 and January 2026 into the same bucket. `s.dt.to_period('M')` creates a `Period` object (`'2026-05'`) that preserves the unique Year-Month coordinate, preventing multi-year collision.

##### Q31: How do you identify whether a timestamp falls on the first business day of the month using `.dt`?
- **Answer**: `.dt.is_month_start` only detects day 1 of the calendar month (which could be a Sunday). To detect the first *business* day, compute:
  ```python
  first_bday = df['ts'].dt.is_month_start & (df['ts'].dt.dayofweek < 5)
  # For rigorous detection:
  df['is_first_bday'] = df['ts'].dt.date == (df['ts'] - pd.offsets.MonthBegin(1)).dt.date
  ```

##### Q32: Can the `.dt` accessor be used on a `DatetimeIndex` directly?
- **Answer**: No, a `DatetimeIndex` does not require `.dt`! Attributes are exposed directly on the index object itself: `df.index.year`, `df.index.month`, `df.index.dayofweek`. Calling `df.index.dt.year` raises an `AttributeError`.

##### Q33: How does `.dt.normalize()` differ from `.dt.floor('D')`?
- **Answer**: They are functionally identical for daily resolution: both truncate intraday hours, minutes, and seconds to midnight (`00:00:00`). However, `.dt.normalize()` is purpose-built and faster for midnight truncation, while `.dt.floor('freq')` accepts arbitrary frequencies (e.g., `'15min'`, `'2h'`).

##### Q34: What happens if you try to modify a component directly via assignment, like `s.dt.year = 2027`?
- **Answer**: It raises `AttributeError: can't set attribute` or `TypeError`. The `.dt` properties are read-only views generated dynamically from underlying 64-bit integer buffers. To modify dates, use offset arithmetic (`s + pd.DateOffset(years=1)`).

##### Q35: How do you extract timezone offsets from a timezone-aware Series?
- **Answer**: Use `s.dt.tz` to get the timezone name or object, or `s.dt.utcoffset` to get the current UTC offset as a `pd.Timedelta`.

##### Q36: How do you count the number of business days elapsed in the current month for each row?
- **Answer**: Combine `s.dt.day` iteration or custom vectorized lambda with `np.busday_count`:
  ```python
  import numpy as np
  # Vectorized calculation using numpy busday_count
  b_days_elapsed = np.busday_count(
      s.dt.to_period('M').dt.start_time.values.astype('datetime64[D]'),
      s.values.astype('datetime64[D]')
  )
  ```

##### Q37: How do you extract the fiscal year if the fiscal year begins in October?
- **Answer**: Add 3 months to the date before extracting the year:
  ```python
  fiscal_year = (df['ts'] + pd.DateOffset(months=3)).dt.year
  ```
  Dates in October, November, and December 2025 will correctly evaluate to Fiscal Year 2026.

##### Q38: How do you compute the hour difference between local time and UTC using `.dt`?
- **Answer**:
  ```python
  offset_hours = df['aware_ts'].dt.utcoffset.dt.total_seconds() / 3600.0
  ```

##### Q39: What is the memory footprint of extracting `.dt.month` vs `.dt.month_name()`?
- **Answer**: `s.dt.month` generates an array of 32-bit or 64-bit integers (4–8 bytes per row). `s.dt.month_name()` generates Python string objects or string dtypes (~50+ bytes per row with object pointer overhead). Numeric extractions are ~10x more memory-efficient.

##### Q40: How do you extract whether a date is a leap day (February 29)?
- **Answer**:
  ```python
  is_leap_day = (s.dt.month == 2) & (s.dt.day == 29)
  ```

```python
import pandas as pd

def extract_temporal_features(df: pd.DataFrame, ts_col: str) -> pd.DataFrame:
    df = df.copy()
    dt = df[ts_col].dt
    df['year'] = dt.year
    df['month'] = dt.month

    df['hour'] = dt.hour
    df['dayofweek'] = dt.dayofweek
    df['quarter'] = dt.quarter
    df['is_weekend'] = dt.dayofweek >= 5
    return df
```

##### Q42: Code Snippet — Cyclic Encoding of Temporal Features

### 4. Top Questions to Definitely Prepare

#### 4.1 Must-Know Core Questions

##### Q4.1.1: What is the syntax for accessing datetime attributes on a Pandas Series versus a DatetimeIndex?
- **Answer**: On a `Series`, you must access datetime attributes through the `.dt` accessor (e.g., `s.dt.year`, `s.dt.month`). On a `DatetimeIndex`, attributes are accessed directly without `.dt` (e.g., `idx.year`, `idx.month`). Attempting to call `.dt` on a `DatetimeIndex` raises `AttributeError: 'DatetimeIndex' object has no attribute 'dt'`.

##### Q4.1.2: How does `s.dt.dayofweek` number days of the week, and how does it compare to Python's `datetime.weekday()`?
- **Answer**: Both `s.dt.dayofweek` and Python's `datetime.weekday()` follow the ISO convention of 0-based indexing where Monday is 0, Tuesday is 1, ..., and Sunday is 6. This differs from US spreadsheet conventions (Excel) where Sunday is day 1.

##### Q4.1.3: What is the difference between `s.dt.day_name()` and `s.dt.dayofweek`?
- **Answer**: `s.dt.dayofweek` returns an integer Series ($[0, 6]$), which is optimal for numeric masks and ML features. `s.dt.day_name()` is a method returning string representations (`'Monday'`, `'Tuesday'`, etc.), suitable for categorical labeling and display.

##### Q4.1.4: How does `s.dt.quarter` partition the calendar year?
- **Answer**: It calculates $\lceil \text{month} / 3 \rceil$, partitioning the year into 4 calendar quarters:
  - Q1: January, February, March ($1–3$)
  - Q2: April, May, June ($4–6$)
  - Q3: July, August, September ($7–9$)
  - Q4: October, November, December ($10–12$)

##### Q4.1.5: Why does extracting `s.dt.year` from a Series with `pd.NaT` result in a `float64` Series in NumPy-backed Pandas?
- **Answer**: Standard NumPy integer arrays (`int64`, `int32`) cannot store `NaN` sentinels. When `pd.NaT` is evaluated through the `.dt` accessor, Pandas must represent missing values as `np.nan`, which forces an automatic upcast of the entire integer array to `float64`. This is mitigated in Pandas 2.0+ by using nullable integer dtypes (`Int32`, `Int64`).

##### Q4.1.6: What is the performance pitfall of calling `s.dt.date` instead of `s.dt.normalize()`?
- **Answer**: `s.dt.date` constructs a Series of Python standard library `datetime.date` scalar objects wrapped in an `object` dtype. This destroys contiguous memory storage and C-vectorization. `s.dt.normalize()` zeros out the intraday hours, minutes, and seconds while preserving the high-performance `datetime64[ns]` memory buffer.

##### Q4.1.7: What columns are produced by `s.dt.isocalendar()`?
- **Answer**: It returns a 3-column DataFrame with `UInt32` dtype:
  1. `year`: ISO 8601 calendar year.
  2. `week`: ISO 8601 week number ($1–53$).
  3. `day`: ISO 8601 day of week ($1 = \text{Monday}, 7 = \text{Sunday}$).

##### Q4.1.8: How do you identify whether a date is in a leap year using `.dt`?
- **Answer**: Access the boolean attribute `s.dt.is_leap_year`. It returns `True` for leap years (e.g., 2024, 2028) and `False` otherwise, correctly following the 400-year Gregorian leap year rules.

##### Q4.1.9: What does `s.dt.days_in_month` return, and does it account for leap years?
- **Answer**: It returns an integer Series representing the total number of days in the respective month ($28, 29, 30, \text{ or } 31$). It dynamically accounts for leap years, returning 29 for February in leap years (e.g., 2024) and 28 in non-leap years (e.g., 2025, 2026).

##### Q4.1.10: Can you set or overwrite components directly using `.dt` (e.g., `s.dt.hour = 5`)?
- **Answer**: No. Properties on `.dt` are read-only views generated on-the-fly from the underlying nanosecond integer buffer. Attempting to assign to them raises an `AttributeError`. Component modifications must be performed via offset arithmetic or date replacement.

#### 4.2 Good-to-Know Differentiating Questions

##### Q4.2.1: Under what circumstance does `s.dt.year` NOT equal `s.dt.isocalendar().year`?
- **Answer**: During the first few days of January or the last few days of December when a week crosses the calendar year boundary. Under ISO 8601, a week belongs to the year containing its Thursday. If January 1 falls on a Friday, Saturday, or Sunday, those days belong to Week 52 or 53 of the *previous* ISO year. For example, `2027-01-01` is in Gregorian year 2027, but ISO year 2026.

##### Q4.2.2: How do `s.dt.is_month_start` and `s.dt.is_month_end` behave on non-normalized timestamps?
- **Answer**: They evaluate strictly based on the calendar day component (`day == 1` for start; `day == days_in_month` for end), regardless of the intraday hour, minute, or second. A timestamp of `2026-05-31 14:22:10` evaluates `s.dt.is_month_end` to `True`.

##### Q4.2.3: How does `s.dt.dayofyear` handle leap years?
- **Answer**: In a common year, `dayofyear` ranges from $1$ to $365$. In a leap year, December 31 evaluates to $366$, and all days after February 28 are shifted by $+1$ relative to non-leap years.

##### Q4.2.4: Why was `s.dt.week` deprecated in Pandas?
- **Answer**: `s.dt.week` and `s.dt.weekofyear` were deprecated because their behavior was ambiguous and inconsistent across platforms regarding whether they implemented ISO 8601 weeks or US Sunday-starting weeks. Users are instructed to use `s.dt.isocalendar().week` for explicit, unambiguous ISO compliance.

##### Q4.2.5: How do you extract the hour component as a continuous cyclic feature for machine learning models?
- **Answer**:
  ```python
  sin_hour = np.sin(2 * np.pi * s.dt.hour / 24.0)
  cos_hour = np.cos(2 * np.pi * s.dt.hour / 24.0)
  ```
  This preserves the cyclic geometric proximity between 23:00 (11 PM) and 00:00 (midnight).

##### Q4.2.6: How do you extract the fiscal quarter for a corporation whose fiscal year begins in July?
- **Answer**: Shift the dates by $-6$ months (or $+6$ months depending on fiscal calendar definition) before extracting the quarter:
  ```python
  fiscal_q = (s - pd.DateOffset(months=6)).dt.quarter
  ```

##### Q4.2.7: What is the computational cost of extracting 8 components via `.dt` separately vs using `isocalendar()` or a single pass?
- **Answer**: Each independent `.dt` access traverses the entire Series and recalculates date fields from the nanosecond integer. For massive Series (10M+ rows), calling 8 properties means 8 complete passes over memory. Extracting components in a single custom Cython/C loop or utilizing `isocalendar()` for year/week/day reduces memory bandwidth consumption.

##### Q4.2.8: How do you extract the start of the week for every date in a Series using `.dt`?
- **Answer**: Subtract the day of the week as a timedelta:
  ```python
  week_start = s.dt.normalize() - pd.to_timedelta(s.dt.dayofweek, unit='D')
  ```

##### Q4.2.9: How does `s.dt.tz_localize()` differ from `s.dt.tz_convert()`?
- **Answer**: `s.dt.tz_localize()` attaches timezone metadata to a naive datetime Series without altering the local wall-clock numbers. `s.dt.tz_convert()` takes an already timezone-aware Series and translates the timestamps to a different timezone, shifting the wall-clock components (`hour`, `day`) according to the UTC offset difference.

##### Q4.2.10: What is `s.dt.total_seconds()` and why is it not available on a `datetime64[ns]` Series?
- **Answer**: `s.dt.total_seconds()` exists exclusively on `Timedelta` Series (`timedelta64[ns]`), not `datetime64[ns]`. A datetime represents an absolute point in time (for which total seconds since epoch is ambiguous without specifying epoch), whereas a Timedelta represents a duration.

#### 4.3 Advanced / Senior / Architect-Level Questions

##### Q4.3.1: How are `.dt` properties implemented in Pandas C/Cython source code?
- **Answer**: In `pandas/_libs/tslibs`, timestamps are unpacked via the `npy_datetimestruct` struct. Functions like `pandas_datetime_to_datetimestruct` perform integer division and modulo operations against fixed constants ($10^9$ for seconds, $60$ for minutes/hours, $86400$ for days) and query precomputed Gregorian cycle lookup tables (400-year cycle = 146,097 days) to extract year, month, and day without calling standard Python library functions.

##### Q4.3.2: How do you perform high-throughput temporal feature extraction in PyArrow-backed DataFrames in Pandas 2.0+?
- **Answer**: In Pandas 2.0+, PyArrow-backed datetime columns (`dtype='timestamp[ns][pyarrow]'`) route `.dt` property calls to Arrow compute kernels (`pyarrow.compute.year`, `pyarrow.compute.month`, etc.). These compute kernels are written in multi-threaded C++ with SIMD vectorization, executing 2x to 5x faster than legacy NumPy/Cython unpacking routines while retaining nullable integer types natively.

##### Q4.3.3: How do you handle Daylight Saving Time (DST) transitions when extracting the `hour` component?
- **Answer**: When timestamps are timezone-aware, `.dt.hour` returns the local wall-clock hour. During a "fall-back" transition (e.g., 2:00 AM repeats), `.dt.hour` will yield identical values for two consecutive hours unless disambiguated by `.dt.tz` or by inspecting UTC elapsed time. For continuous time-series modeling, always extract UTC hours or use UTC epoch timestamps.

##### Q4.3.4: How do you design an ultra-fast vectorized categorization of business days without using `apply`?
- **Answer**: Use `s.dt.dayofweek < 5` combined with a precomputed searchsorted lookup against a sorted array of holiday integers:
  ```python
  is_weekday = s.dt.dayofweek < 5
  is_holiday = s.dt.normalize().isin(holiday_series)
  is_business_day = is_weekday & (~is_holiday)
  ```
  This executes entirely at C-speed over contiguous arrays.

##### Q4.3.5: What are the memory implications of creating 10 individual temporal feature columns on a 100-million row DataFrame?
- **Answer**: 100 million rows of 64-bit integers (`int64`) consume 800 MB per column. 10 extracted columns consume 8.0 GB of RAM. To optimize memory:
  - Downcast `month`, `day`, `hour`, `minute`, `second`, `dayofweek`, `quarter` to `int8` (100 MB each).
  - Downcast `year` to `int16` (200 MB).
  - Total memory drops from 8.0 GB to ~1.0 GB (an 87.5% memory reduction).

### 5. Common Beginner Mistakes (10 Mistakes)

#### Mistake 1: Forgetting the `.dt` Accessor on a Series
- **Why it happens**: Users expect Series to behave like scalar `Timestamp` objects.
- **Wrong Code**:
  ```python
  s = pd.Series(pd.to_datetime(['2026-05-14']))
  print(s.year)  # AttributeError: 'Series' object has no attribute 'year'
  ```
- **Correct Code**:
  ```python
  print(s.dt.year)
  ```
- **Production Tip**: Always remember: `Timestamp.year` is scalar, but `Series.dt.year` is vectorized.

---

#### Mistake 2: Calling `.dt` on a Non-Datetime Column
- **Why it happens**: Loading CSVs without parsing dates leaves date columns as `object` (string) dtype.
- **Wrong Code**:
  ```python
  df = pd.DataFrame({'date': ['2026-05-14']})
  df['month'] = df['date'].dt.month
  # AttributeError: Can only use .dt accessor with datetimelike values
  ```
- **Correct Code**:
  ```python
  df['date'] = pd.to_datetime(df['date'])
  df['month'] = df['date'].dt.month
  ```
- **Production Tip**: Run `pd.to_datetime()` during ingestion and assert datetime dtype before extracting features.

---

#### Mistake 3: Omitting Parentheses on `day_name` and `month_name`
- **Why it happens**: `year`, `month`, `day`, and `hour` are attributes (no parentheses), while `day_name()` and `month_name()` are methods (require parentheses).
- **Wrong Code**:
  ```python
  df['day_name'] = df['date'].dt.day_name  # Stores bound method objects!
  ```
- **Correct Code**:
  ```python
  df['day_name'] = df['date'].dt.day_name()
  ```
- **Production Tip**: If a `.dt` accessor accepts arguments (like `locale`), it is a method and requires `()`.

---

#### Mistake 4: Assuming `dayofweek` Starts on Sunday (Excel Bias)
- **Why it happens**: In Excel and US calendars, Sunday = 1. In Pandas/Python, Monday = 0 and Sunday = 6.
- **Wrong Code**:
  ```python
  # Trying to filter Sunday transactions
  sundays = df[df['date'].dt.dayofweek == 0]  # Actually selects Mondays!
  ```
- **Correct Code**:
  ```python
  sundays = df[df['date'].dt.dayofweek == 6]  # 6 = Sunday
  ```
- **Production Tip**: Remember: `0=Mon, 1=Tue, 2=Wed, 3=Thu, 4=Fri, 5=Sat, 6=Sun`.

#### Mistake 5: Using `.dt.date` for Grouping Instead of `.dt.normalize()`

### 6. Section-Adaptive Pandas API Confusions

#### Confusion 1: `s.dt.dayofweek` vs `s.dt.weekday` vs `s.dt.isocalendar().day`
| Feature / Dimension | `s.dt.dayofweek` | `s.dt.weekday` | `s.dt.isocalendar().day` |
| :--- | :--- | :--- | :--- |
| **Indexing Base** | 0-indexed | 0-indexed | 1-indexed |
| **Monday Value** | `0` | `0` | `1` |
| **Sunday Value** | `6` | `6` | `7` |
| **Return Type** | `int32` / `int64` | `int32` / `int64` | `UInt32` |
| **Standard Origin** | Python / NumPy standard | Exact alias to `dayofweek` | ISO 8601 specification |
| **Best Practice** | Recommended for numeric logic | Supported for compatibility | Use when building ISO pipelines |

#### Confusion 2: `s.dt.date` vs `s.dt.normalize()`
| Dimension | `s.dt.date` | `s.dt.normalize()` |
| :--- | :--- | :--- |
| **Underlying Dtype** | `object` (Python `datetime.date`) | `datetime64[ns]` |
| **Memory Buffer** | Disparate heap pointers (~56B/item)| Contiguous 64-bit integers (8B/item) |
| **Vectorized Operations**| Broken (falls back to Python loops) | Fully preserved (SIMD / C-speed) |
| **Subsequent `.dt` Calls**| Impossible (raises `AttributeError`)| Valid (all `.dt` properties accessible)|
| **Production Recommendation**| Use only at final export/display | Use for all pipeline transformations |

#### Confusion 3: `s.dt.month` vs `s.dt.month_name()`
| Dimension | `s.dt.month` | `s.dt.month_name()` |
| :--- | :--- | :--- |
| **Nature** | Property attribute (no `()`) | Method (requires `()`) |
| **Output Type** | Integer ($[1, 12]$) | String (`'January'`, `'February'`, ...) |
| **Locale Support** | Irrelevant (language-agnostic) | Accepts `locale=` parameter |
| **ML Feature Utility** | Direct numerical feature | Requires categorical encoding |
| **Memory Footprint** | 4–8 bytes per row | 50+ bytes per row |

#### Confusion 4: `s.dt.day` vs `s.dt.dayofyear` vs `s.dt.days_in_month`
| Dimension | `s.dt.day` | `s.dt.dayofyear` | `s.dt.days_in_month` |
| :--- | :--- | :--- | :--- |
| **Range** | $[1, 31]$ | $[1, 366]$ | $[28, 31]$ |
| **Definition** | Calendar day of current month | Elapsed days since Jan 1 | Total days in current month |
| **Leap Year Impact** | None | Dec 31 becomes 366 | Feb returns 29 |
| **Common Use Case** | Day-of-month billing triggers | Astronomical / Seasonal modeling | Daily revenue proration |

### 8. Real-World Pandas Engineering Questions

#### Scenario 1: The Multi-Gigabyte Memory Spike in ML Feature Store Ingestion
- **Context**: A feature engineering pipeline extracts temporal components (`year`, `month`, `day`, `hour`, `minute`, `second`, `dayofweek`, `quarter`) from 150 million rideshare ride records. The cluster nodes repeatedly crashed with Out-Of-Memory (OOM) errors.
- **Root Cause**: The developer extracted all 8 features into default `int64` Series, creating 8 * 8 bytes * 150M = 9.6 GB of raw integers, plus an un-vectorized `df['ts'].dt.date` column adding an extra 10+ GB of Python heap objects.
- **Diagnostic Code**:
  ```python
  import pandas as pd
  n = 1000000
  s = pd.Series(pd.date_range('2026-01-01', periods=n, freq='min'))
  df_features = pd.DataFrame({
      'year': s.dt.year,
      'month': s.dt.month,
      'day': s.dt.day,
      'hour': s.dt.hour,
      'dayofweek': s.dt.dayofweek
  })
  print(f"Memory unoptimized: {df_features.memory_usage(deep=True).sum() / 1e6:.2f} MB")
  ```
- **Architectural Fix**:
  ```python
  dt = s.dt
  df_features = pd.DataFrame({
      'year': dt.year.astype('int16'),
      'month': dt.month.astype('int8'),
      'day': dt.day.astype('int8'),
      'hour': dt.hour.astype('int8'),
      'dayofweek': dt.dayofweek.astype('int8')
  })
  print(f"Memory optimized: {df_features.memory_usage(deep=True).sum() / 1e6:.2f} MB")
  ```
- **Post-Mortem Policy**: Downcast all discrete temporal features to their minimal valid integer representation (`int8` for month/day/hour/dow; `int16` for year). Ban `s.dt.date` in feature stores.

#### Scenario 2: The Silent Sunday Revenue Misattribution in Executive Scorecard

#### Scenario 3: The Broken January Billing Cycle Due to ISO Calendar Inversion
- **Context**: An enterprise SaaS subscription billing job generated incorrect customer invoices for the first week of January 2027, assigning charges to the previous year's accounting ledger.
- **Root Cause**: The billing engine paired Gregorian `df['ts'].dt.year` with ISO `df['ts'].dt.isocalendar().week`. On January 1, 2027 (Friday), the system recorded `Year: 2027` and `Week: 53`. The ERP system rejected `2027-W53` because 2027 only has 52 weeks.

### 10. "Explain This Code" Questions

#### Challenge 1: The Year Boundary ISO Mismatch
```python
import pandas as pd
s = pd.Series(pd.to_datetime(['2027-01-01', '2027-01-04']))
print(s.dt.year.tolist())
print(s.dt.isocalendar().year.tolist())
```
- **Line-by-Line Mechanics**:
  1. `pd.to_datetime(['2027-01-01', '2027-01-04'])` creates a Series of two dates: Friday, Jan 1, 2027, and Monday, Jan 4, 2027.
  2. `s.dt.year` accesses the standard Gregorian year integer directly, yielding `[2027, 2027]`.
  3. `s.dt.isocalendar().year` computes the ISO 8601 calendar year. Under ISO 8601, a week belongs to the year containing its Thursday. Since Jan 1, 2027 is a Friday, that weekend belongs to Week 53 of the *previous* year (2026). Jan 4, 2027 is a Monday containing the first Thursday of 2027, so it belongs to ISO year 2027.
- **Output**:
  ```text
  [2027, 2027]
  [2026, 2027]
  ```
- **Perturbation**: If the first date was `'2026-01-01'` (Thursday), both Gregorian and ISO year would evaluate to `2026`.

#### Challenge 2: Null Upcasting in Component Extraction
```python
import pandas as pd
s = pd.Series(pd.to_datetime(['2026-05-14', None]))
res = s.dt.month
print(res.dtype, res.tolist())
```
- **Line-by-Line Mechanics**:
  1. `s` contains a valid `Timestamp` and a `pd.NaT` missing value.
  2. `s.dt.month` extracts the month integer for valid dates ($5$).
  3. For `pd.NaT`, the missing month must be represented as `np.nan`.
  4. Because standard NumPy integer arrays cannot store `NaN`, Pandas upcasts the entire resulting Series from `int32/int64` to `float64`.
- **Output**: `float64 [5.0, nan]`
- **Perturbation**: If `res = s.dt.month.astype('Int8')` was invoked, the dtype would be nullable `Int8` and print `[5, <NA>]`.

#### Challenge 3: Vectorized Week Start Slicing
```python
import pandas as pd

week_start = s.dt.normalize() - pd.to_timedelta(s.dt.dayofweek, unit='D')
print(week_start.tolist())
```
- **Line-by-Line Mechanics**:
  1. `s.dt.normalize()` snaps both timestamps to midnight (`2026-05-14 00:00:00`, `2026-05-17 00:00:00`).
  2. `s.dt.dayofweek` yields `3` for Thursday and `6` for Sunday.
  3. `pd.to_timedelta(..., unit='D')` creates timedeltas of `3 days` and `6 days`.
  4. Subtracting 3 days from Thursday May 14 gives Monday May 11; subtracting 6 days from Sunday May 17 gives Monday May 11.
- **Output**: `[Timestamp('2026-05-11 00:00:00'), Timestamp('2026-05-11 00:00:00')]`
- **Perturbation**: If `s.dt.normalize()` was omitted and timestamps had intraday times (e.g. 15:30), the resulting Monday would preserve the 15:30 time offset.

- **Back**: `s.dt.dayofweek` is 0-indexed (Mon=0, Sun=6); `s.dt.isocalendar().day` is 1-indexed (Mon=1, Sun=7) per ISO 8601.

### 15. Fresher Answer Evolution Patterns

#### Pattern 1: "How do you extract the day of the week from a date column?"

- **Junior Answer**: "You use the vectorized accessor `df['date'].dt.dayofweek`. Monday is 0 and Sunday is 6. If you want the name, you call `df['date'].dt.day_name()`."
- **Senior Answer**: "You use `df['date'].dt.dayofweek`, which executes at C-speed over the underlying `datetime64[ns]` contiguous buffer. It returns a 0-indexed integer where 0=Monday and 6=Sunday. In contrast, if conforming strictly to ISO 8601 external data contracts, use `df['date'].dt.isocalendar().day`, which is 1-indexed (1=Monday, 7=Sunday). In production ML feature stores, downcast `dayofweek` to `int8` to prevent wasting 7 bytes of unneeded memory per row."

#### Pattern 2: "How do you group transactions by date when timestamps include hours and minutes?"
- **Freshman Answer**: "You can convert the dates to strings using `df['date'].astype(str).str[:10]` and then group by that string column."
- **Junior Answer**: "You extract `df['date'].dt.date` and group by that column so you don't have to parse strings."
- **Senior Answer**: "Using `df['date'].dt.date` is an anti-pattern because it instantiates millions of heap-allocated Python `datetime.date` objects wrapped in an `object` Series, destroying C-level vectorization and causing massive memory overhead. The production solution is `df['date'].dt.normalize()`. This zeroes out the intraday hours, minutes, and seconds to midnight while preserving the high-performance `datetime64[ns]` integer buffer, allowing multi-threaded C-level hash aggregations."

#### Pattern 3: "How do you handle end-of-year week numbering?"
- **Freshman Answer**: "You call `df['date'].dt.week` and combine it with `df['date'].dt.year`."

- **Senior Answer**: "Calling `df['date'].dt.isocalendar().week` while pairing it with `df['date'].dt.year` introduces a critical silent bug at year boundaries. Pairing Gregorian `dt.year` with ISO `week` produces non-existent combinations like `'2027-W53'`. #### Project 1: High-Frequency Rideshare Demand Feature Engineering
- **Problem**: Ingest 50 million rideshare GPS pings and engineer temporal features for an XGBoost surge pricing model under strict 2-second SLA.

  ```python
  import pandas as pd
  import numpy as np

  def build_surge_features(df: pd.DataFrame) -> pd.DataFrame:
      dt = df['pickup_time'].dt
      # 1. Vectorized integer extraction with downcasting
      df['hour'] = dt.hour.astype('int8')
      df['dayofweek'] = dt.dayofweek.astype('int8')

      df['sin_hour'] = np.sin(2 * np.pi * df['hour'] / 24.0).astype('float32')

      # 3. Peak commute hours flag (Mon-Fri 7-9 AM, 5-7 PM)
      is_weekday = ~df['is_weekend']
      morning_rush = df['hour'].isin([7, 8])
      evening_rush = df['hour'].isin([17, 18])
      df['is_peak_rush'] = is_weekday & (morning_rush | evening_rush)
      return df
  ```

#### Project 3: Automated Payroll Month-End Execution Pipeline
- **Problem**: An enterprise HR platform must schedule salary disbursements on the last business day of every month, taking into account leap year Februarys.

  ```python
  import pandas as pd

  def identify_payroll_dates(year: int) -> pd.DatetimeIndex:
      all_days = pd.date_range(f'{year}-01-01', f'{year}-12-31', freq='D')
  ```

### 19. What a Fresher Should Memorize (Section-Specific)

- **Accessor Namespace**:
  - Must use `.dt` on `Series`; do NOT use `.dt` on `DatetimeIndex`.
- **Numeric Ranges**:

  - `day`: $[1, 31]$
  - `hour`: $[0, 23]$
  - `minute`: $[0, 59]$

### 24. Final 2-Minute Revision Summary

#### Core Concepts
- `.dt` exposes vectorized calendar properties (`year`, `month`, `day`, `hour`, `quarter`) and methods (`day_name()`, `isocalendar()`).
- Indexing: `dayofweek` is 0-indexed (Monday=0, Sunday=6); `isocalendar().day` is 1-indexed (Monday=1, Sunday=7).
- Grouping: Always use `s.dt.normalize()` instead of `s.dt.date` to preserve `datetime64[ns]` contiguous C-speed execution.
- Missing values: `pd.NaT` forces integer accessors to `float64` in NumPy Pandas; cast to `Int32` or `Int8` to preserve integer typing.
- Week numbering: Always pair `isocalendar().week` with `isocalendar().year` to avoid year-boundary bugs.

#### Top 5 Traps to Dodge
1. **Calling `.dt` on `DatetimeIndex`**: Raises `AttributeError`. Access properties directly on the index (`idx.hour`).
2. **Missing Parentheses on Methods**: `day_name()` and `month_name()` require `()`; omitting them stores bound method objects.
3. **Assuming Sunday is 0**: Sunday is 6, Monday is 0. Filter weekends via `dayofweek >= 5`.
4. **Using `.dt.date` in Pipelines**: Creates slow Python object arrays. Use `.dt.normalize()`.
5. **Direct `.dt` Assignment**: Properties are immutable read-only views. Use offset arithmetic to modify dates.

#### Must-Know Production Code Template
```python
import pandas as pd
import numpy as np

def extract_production_temporal_features(df: pd.DataFrame, col: str) -> pd.DataFrame:
    df = df.copy()
    dt = df[col].dt
    # Memory-optimized discrete components
    df['year'] = dt.year.astype('int16')
    df['month'] = dt.month.astype('int8')
    df['day'] = dt.day.astype('int8')
    df['hour'] = dt.hour.astype('int8')
    df['dayofweek'] = dt.dayofweek.astype('int8')
    df['quarter'] = dt.quarter.astype('int8')
    df['is_weekend'] = dt.dayofweek >= 5
    # Continuous cyclic encoding
    df['sin_hour'] = np.sin(2 * np.pi * df['hour'] / 24.0).astype('float32')
    df['cos_hour'] = np.cos(2 * np.pi * df['hour'] / 24.0).astype('float32')
    return df
```

This demonstrates that you write production pipelines built for efficiency, scale, and memory safety.
