#### 1. Vector Embeddings & Similarity Metrics

- **Target Folder:** `GEN AI/7. Vector Database/01_embeddings_similarity_metrics/`
- **Core Topics & Math:** High-dimensional vector spaces, dense representations vs. sparse lexical representations (BM25, SPLADE), L2 normalization ($\|v\|_2 = 1$).
- **Distance Metrics:** Euclidean distance ($L_2$), Manhattan distance ($L_1$), Cosine Similarity ($\cos(\theta) = \frac{u \cdot v}{\|u\|_2 \|v\|_2}$), Cosine Distance ($1 - \text{sim}$), Dot Product / Inner Product ($\langle u, v \rangle$). Equivalence of Dot Product and Cosine Similarity under unit L2 normalization.
- **Embedding Models:** OpenAI (`text-embedding-3-small/large`), Sentence-Transformers (`all-MiniLM-L6-v2`), BGE, Cohere; dimensionality truncation via MRL (Matryoshka Representation Learning).
- **RAG Use Cases:** Selecting the correct distance metric for an embedding model, diagnosing distance vs. similarity metric mismatches in production search.

#### 2. Vector Database Architecture & Core Data Modeling

- **Target Folder:** `GEN AI/7. Vector Database/02_architecture_data_modeling/`
- **Core Topics & Concepts:** Vector Database vs. Relational SQL vs. Inverted Index Search Engines (Elasticsearch/OpenSearch). Primitives: Vectors, Document payloads, Metadata dictionaries, Unique IDs, Collections/Namespaces, Indexes.
- **Lifecycle & Operations:** CRUD operations: Insert, Read, Update, Upsert, Delete (tombstoning/soft-deletes vs. index rebuilds), Batch insertion.
- **Storage Engines:** In-memory storage vs. Persistent disk storage, Write-Ahead Logs (WAL), immutable segment merging, eventual consistency vs. read-after-write consistency in distributed clusters.
- **RAG Use Cases:** Designing collection schemas, choosing between relational DBs with vector extensions vs. purpose-built vector engines for enterprise scale.

#### 4. Vector Querying & Similarity Search Mechanics

- **Target Folder:** `GEN AI/7. Vector Database/04_querying_search_mechanics/`
- **Core API & Query Engine:** `collection.query(query_texts=..., query_embeddings=..., n_results=..., where=..., where_document=...)`, `collection.get(ids=..., where=...)`.
- **Search Mechanics:** Exact k-Nearest Neighbors (k-NN) vs. Approximate Nearest Neighbors (ANN), Top-$K$ retrieval, score normalization, distance threshold filtering.
- **Response Parsing:** Deconstructing query result dicts (`ids`, `documents`, `metadatas`, `distances`, `embeddings`), handling multi-query batch requests.
- **RAG Use Cases:** Retrieving top-$K$ candidate chunks, tuning similarity thresholds to prune irrelevant context before calling the LLM.

#### 5. Metadata Filtering & Multi-Tenancy Architecture

- **Target Folder:** `GEN AI/7. Vector Database/05_metadata_filtering_tenancy/`
- **Filtering Syntax:** Operators: `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`. Logical conjunctions: `$and`, `$or`. Document content filters: `where_document={"$contains": "..."}`.
- **Filtering Architectures:**
  - _Post-filtering:_ Vector search first $\to$ filter metadata (can return fewer than $K$ results if candidates are filtered out).
  - _Pre-filtering:_ Filter metadata first $\to$ vector search on subset (slow if metadata index is unindexed).
  - _Single-stage / Iterative graph traversal filtering:_ Filtering directly during HNSW graph traversal.
- **Multi-Tenancy & Security:** Metadata-based tenant isolation (`where={"tenant_id": user_tenant}`) vs. physical collection-per-tenant isolation, Role-Based Access Control (RBAC).

#### 6. ANN Indexing & Graph Algorithms (HNSW, IVF, Trees)

- **Target Folder:** `GEN AI/7. Vector Database/06_ann_indexing_hnsw_ivf/`
- **Algorithmic Foundations:** The curse of dimensionality, why brute-force linear scan ($O(N \cdot D)$) cannot scale to millions of vectors.
- **Hierarchical Navigable Small World (HNSW):** Multi-layer skip-list graph architecture. Hyperparameters: `M` (maximum number of bi-directional links per node), `efConstruction` (size of the dynamic candidate list during build), `efSearch` (size of candidate list during query time). Speed vs. Recall vs. Index size trade-offs.
- **Inverted File Index (IVF):** Voronoi partitions/cells, centroid clustering via K-Means, `nlist` (number of clusters), `nprobe` (number of adjacent clusters searched).
- **Tree & Projection Algorithms:** KD-trees, Random Projection Trees (Annoy), ScaNN.

---

#### 7. Vector Quantization & Memory Optimization

- **Target Folder:** `GEN AI/7. Vector Database/07_quantization_memory_optimization/`
- **Scalar Quantization (SQ):** Mapping FP32 (32-bit floats) to INT8 (8-bit integers) or INT4, achieving $4\times$ memory reduction with minimal recall degradation.
- **Product Quantization (PQ):** Decomposing high-dimensional vectors into $m$ low-dimensional sub-vectors, clustering each subspace to create codebooks, Asymmetric Distance Computation (ADC).
- **Binary Quantization (BQ):** 1-bit thresholding ($\ge 0 \to 1, < 0 \to 0$), enabling Hamming distance calculation via bitwise XOR and POPCNT CPU instructions ($32\times$ memory reduction and ultra-fast search).
- **Engineering Trade-offs:** Index construction latency, memory footprint vs. Recall@K trade-offs, disk-offloading with memory-mapped files (MMAP).

#### 8. Document Processing, Chunking & Ingestion Pipelines

- **Target Folder:** `GEN AI/7. Vector Database/08_chunking_ingestion_pipelines/`
- **Chunking Strategies:**
  - Fixed-size character/token chunking with sliding window overlap.
  - Recursive Character Text Splitting (hierarchical separators: `\n\n`, `\n`, ` `, `""`).
  - Sentence-based & Paragraph-based chunking.
  - Semantic Chunking: Measuring cosine distance between consecutive sentence embeddings and creating chunk splits at statistical distance spikes.
  - Document-structure-aware chunking (Markdown headers, HTML tags, code blocks).
- **Trade-offs:** Chunk size ($N$ tokens) vs. Chunk overlap ($M$ tokens), small chunks (high semantic precision, low context) vs. large chunks (high context, diluted embedding signal).
- **Hierarchical / Parent-Child Chunking:** Indexing small leaf chunks for vector retrieval while passing the linked parent document chunk to the LLM.

#### 9. Hybrid Search & Rank Fusion Algorithms

- **Target Folder:** `GEN AI/7. Vector Database/09_hybrid_search_fusion/`
- **Hybrid Search Architecture:** Combining Dense Semantic Search (embedding cosine similarity) with Sparse Lexical Search (BM25 / SPLADE keyword scoring).
- **Score Normalization & Fusion:**
  - Convex Combination / Alpha-weighting: $\text{Score} = \alpha \cdot S_{\text{dense}} + (1 - \alpha) \cdot S_{\text{sparse}}$.
  - Reciprocal Rank Fusion (RRF): $\text{RRF\_Score}(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$ (where $k$ is a smoothing constant, typically 60).
- **Use Cases:** When lexical keyword search outperforms dense search (part numbers, error codes, legal statute IDs, acronyms) vs. when dense search outperforms lexical (synonyms, conceptual intent).

---

#### 10. Advanced Retrieval Strategies (MMR, HyDE, Multi-Query)

- **Target Folder:** `GEN AI/7. Vector Database/10_advanced_retrieval_mmr_hyde/`
- **Maximum Marginal Relevance (MMR):**
  $$\text{MMR}(q, D, R) = \arg\max_{d \in D \setminus R} \left[ \lambda \cdot \text{Sim}_1(d, q) - (1 - \lambda) \max_{d_i \in R} \text{Sim}_2(d, d_i) \right]$$
  Balancing query relevance with candidate diversity to prevent redundant, near-duplicate chunks.
- **Hypothetical Document Embeddings (HyDE):** Prompting an LLM to generate a hypothetical answer $\to$ embedding the hallucinated answer $\to$ retrieving real documents.
- **Multi-Query Retrieval & Query Expansion:** Generating $N$ prompt re-phrasings via LLM, querying vector database across all variations, and reciprocal rank fusion.
- **Self-Querying Retrievers:** Using an LLM to parse a natural language query into a vector search string + structured metadata filter predicates.

#### 11. Two-Stage Retrieval & Reranking Pipelines

- **Target Folder:** `GEN AI/7. Vector Database/11_two_stage_retrieval_reranking/`
- **Bi-Encoder vs. Cross-Encoder:**
  - _Bi-Encoders:_ Independent vector representations, precomputed embeddings, ultra-fast vector search ($O(N)$ with ANN), lower cross-attention interaction.
  - _Cross-Encoders:_ Full token-to-token cross-attention between query and document ($O(K \cdot L^2)$), computationally expensive, significantly higher accuracy.
- **Two-Stage Pipeline:** Stage 1 (Fast ANN retrieval of top 50–100 candidates) $\to$ Stage 2 (Cross-Encoder / Cohere Rerank / BGE-Reranker scoring and filtering to top 3–5).
- **Production Trade-offs:** Latency budget (adding 50–150ms for reranking), API cost, and measurable improvements in Context Precision.

#### 12. Vector Database Ecosystem & Engine Benchmarking

- **Target Folder:** `GEN AI/7. Vector Database/12_vectordb_ecosystem_benchmarking/`
- **Database Taxonomies & Architectural Trade-offs:**
  - _ChromaDB:_ Lightweight, embedded, SQLite-backed metadata with ClickHouse/C++ HNSW bindings; ideal for rapid prototyping and local agents.
  - _FAISS:_ High-performance in-memory library (GPU/CPU) from Meta; core index algorithms without database features (no metadata filtering, no persistence server).
  - _pgvector:_ PostgreSQL extension; co-locating relational business data, ACID transactions, and vector search (IVFFlat and HNSW index support).
  - _Qdrant:_ Rust-based, payload-first architecture, hardware-optimized SIMD filtering, on-disk HNSW.
  - _Pinecone / Weaviate / Milvus:_ Distributed cloud systems, horizontal sharding, multi-tenant clustering, high QPS workloads.
- **Benchmarking Dimensions:** Queries Per Second (QPS), p95/p99 Latency, Recall@K, Index Build Time, Memory/Disk footprint.

---

#### 13. RAG Security, Context Placement & Prompt Injection Defense

- **Target Folder:** `GEN AI/7. Vector Database/13_rag_security_prompt_injection/`
- **Context Window Dynamics:** The "Lost in the Middle" phenomenon (LLMs attend better to information placed at the extreme beginning and end of the context window rather than the middle).
- **Security Vulnerabilities:**
  - _Indirect Prompt Injection:_ Attackers embedding malicious override instructions in documents stored in the vector database that hijack the LLM upon retrieval.
  - _Data Poisoning:_ Injecting adversarial embeddings to artificially boost malicious chunks into top-$K$ search results.
  - _PII & Data Leakage:_ Ingesting sensitive unmasked customer data into shared collections.
- **Defense Strategies:** Retrieval sanitization, canary tokens in prompt templates, strict metadata tenant authorization checks before query execution.

---

#### 14. Evaluation Metrics & Production Telemetry

- **Target Folder:** `GEN AI/7. Vector Database/14_evaluation_metrics_monitoring/`
- **Information Retrieval (IR) Metrics:**
  - _Precision@K & Recall@K:_ Proportion of retrieved chunks that are relevant vs. proportion of all relevant chunks retrieved.
  - _Mean Reciprocal Rank (MRR):_ $\text{MRR} = \frac{1}{|Q|} \sum_{i=1}^{|Q|} \frac{1}{\text{rank}_i}$ (evaluating where the first relevant hit appears).
  - _Normalized Discounted Cumulative Gain (NDCG@K):_ Graded relevance with logarithmic position discounting.
- **RAG Triad Metrics (Ragas / TruLens):**
  - Context Relevance (is the retrieved context focused on the query?).
  - Faithfulness / Groundedness (is the LLM response factually supported by the retrieved context?).
  - Answer Relevance (does the answer address the user's actual prompt?).
- **Production Telemetry:** Vector drift monitoring, embedding cache hit ratios, latency percentiles across embedding vs. vector search vs. LLM generation.
